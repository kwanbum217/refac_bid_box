# 보안 문서 인덱스

> **작성일**: 2026-07-31
> **상태**: 설계

---

## 보안 문서 작성 원칙

1. **실제 비밀값은 기록하지 않는다.** API 키, 비밀번호, 시크릿은 어떤 문서에도 평문으로 기록하지 않습니다.
2. **코드 근거를 명시한다.** 보안 주장은 코드 경로(`file:line`)로 근거를 제시합니다.
3. **검증 수준을 분리한다.** "설계 의도" vs "구현 검증 완료"를 명확히 구분합니다.
4. **잔여 위험을 공개한다.** 알려진 미해결 위험은 숨기지 않고 명시합니다.

## 절대 저장하지 않는 정보

| 정보 | 처리 |
| --- | --- |
| `GEMINI_API_KEY` 실제 값 | `.env` 전용, 문서에는 키명만 |
| DB 비밀번호 | `.env` 전용 |
| 소셜 로그인 클라이언트 시크릿 | `.env` 전용 |
| Harness API 키 | `.env` 전용 |
| `DJANGO_SECRET_KEY` / `APP_SECRET_KEY` | `.env` 전용 |

## 기존 시스템 보안 이슈 (개선 대상)

> 상세 개선안은 [`security_hardening_guide.md`](security_hardening_guide.md) 참조

| 이슈 | 심각도 | 개선 |
| --- | --- | --- |
| `.env`에 실제 API 키 평문 저장 | 높음 | `.env` Git 제외 확인, 시크릿 매니저 도입 검토 |
| `AUTH_PASSWORD_VALIDATORS` 전체 주석 | 높음 | 검증기 활성화 |
| `SECRET_KEY` 기본값 하드코딩 | 높음 | 환경변수 강제, 기본값 제거 |
| `DEBUG` 기본 True | 중간 | 운영 환경에서 False 강제 |

## 문서 갱신 시점

다음 경우 보안 문서를 갱신합니다:

- 새 환경변수(시크릿) 추가 시
- 인증/인가 로직 변경 시
- 외부 API 연동 추가 시
- 취약점 발견/해결 시
