## 1. 개요 및 목적

본 작업은 `refac_bid_box` 서비스의 인증 경계를 보강하고 서비스 거부(DoS) 및 교차 사이트 요청 위조(CSRF) 위험을 차단하기 위해 수행되었습니다.

**핵심 과업:**
1. **비활성 계정의 선택적 인증 경로 차단**: `get_current_user`에서 `user.is_active` 검증 누락으로 인해 챗봇 등 선택적 인증 경로에서 비활성 계정이 인증 사용자로 처리되던 문제 해결.
2. **로그인 시도 제한 (Rate Limiting)**: PBKDF2(600,000회) 해싱 연산의 CPU 점유 DoS 공격을 방어하기 위해 IP 축 및 계정 축 시도 제한을 구현하고, 임계 초과 시 429 응답 및 fail-open 정책 적용.
3. **설정값 외부화**: 시도 제한 임계값, 잠금 시간, 요청 본문 크기 상한을 `Settings`에 등록하여 환경변수로 조정 가능하도록 구성.
4. **요청 본문 크기 상한 (413 Payload Too Large)**: 대용량 페이로드로 인한 메모리 고갈을 방지하기 위해 진입 지점에 미들웨어를 구축하고, SSE 스트리밍 응답에는 간섭하지 않도록 분리.
5. **GET 로그아웃 제거 및 POST 전용 전환**: 최상위 GET 이동을 통한 CSRF 로그아웃 통로를 제거하고 UI와 테스트를 POST 기반으로 전면 전환.

## 2. 상세 변경 내역

### 2.1 비활성 계정 처리 보강
- **대상 파일**: `src/app/api/v1/accounts.py`
- **변경 내용**: `get_current_user` 함수에서 세션 역직렬화 후 `user.is_active`가 `False`인 경우 즉시 `None`을 반환하도록 수정했습니다.
- **영향**: `/api/v1/chatbot/chat`, `/api/v1/chatbot/chat/stream`, `/`, `/bids/` 등 `get_current_user`를 사용하는 모든 선택적/필수 인증 경로에서 비활성 계정이 익명(미인증) 사용자로 올바르게 처리됩니다.

### 2.2 로그인 시도 제한 (IP 축 & 계정 축)
- **대상 파일**: `src/app/core/security.py`, `src/app/api/v1/accounts.py`, `src/app/api/ui.py`
- **구현 내용**:
  - `LoginRateLimiter` 클래스를 신규 의존성 없이 표준 라이브러리와 기존 Redis 인프라(`RedisConnection`)만을 활용하여 구축했습니다.
  - IP 키(`auth:ratelimit:ip:<ip>`)와 계정 키(`auth:ratelimit:account:<username>`) 두 축으로 실패 횟수를 기록합니다.
  - 임계 초과 시 `429 Too Many Requests`를 반환하며 남은 잠금 시간은 노출하지 않습니다.
  - 로그인 성공 시 해당 계정의 실패 카운터를 즉시 리셋합니다.
  - Redis 장애 시 로그인을 차단하지 않고 제한만 건너뛰는 fail-open 정책을 적용하여 인증 가용성을 보장했습니다.

### 2.3 설정 등록 (Settings)
- **대상 파일**: `src/app/core/config.py`
- **추가된 설정 필드**:
  - `AUTH_RATE_LIMIT_IP_MAX_ATTEMPTS: int = 10` (IP 축 최대 허용 횟수, 기본 10회)
  - `AUTH_RATE_LIMIT_ACCOUNT_MAX_ATTEMPTS: int = 5` (계정 축 최대 허용 횟수, 기본 5회)
  - `AUTH_RATE_LIMIT_LOCKOUT_SECONDS: int = 300` (잠금 유지 시간, 기본 300초 = 5분)
  - `MAX_REQUEST_BODY_SIZE: int = 10 * 1024 * 1024` (요청 본문 상한, 기본 10MB)

### 2.4 요청 본문 크기 상한 미들웨어
- **대상 파일**: `src/app/main.py`
- **구현 내용**:
  - `LimitRequestBodySizeMiddleware` ASGI 미들웨어를 구현하고 `create_app`에 등록했습니다.
  - `Content-Length` 헤더 선행 검사로 대용량 페이로드를 조기 차단하며, 청크/스트리밍 수신 시에도 누적 바이트 수를 검사하여 초과 시 `413 Payload Too Large`를 반환합니다.
  - 수신(receive) 스트림만 계측하고 송신(send) 스트림은 일절 건드리지 않아 SSE(Server-Sent Events) 스트리밍 응답이 온전히 전달됩니다.

### 2.5 GET 로그아웃 제거 및 POST 전환
- **대상 파일**: `src/app/api/ui.py`, `src/app/templates/base.html`, `tests/test_ssr_session_store.py`, `tests/test_ui_ssr.py`
- **변경 내용**:
  - `src/app/api/ui.py`에서 `@router.get("/accounts/logout/")` 라우트를 제거하고 `@router.post("/accounts/logout/")`만 유지했습니다.
  - `src/app/templates/base.html`의 사이드바(97행) 및 헤더(142행) 로그아웃 요소를 POST 폼 전송 방식으로 변경했습니다.
  - 기존 테스트의 GET 로그아웃 호출을 POST로 갱신하고, `GET /accounts/logout/`이 `405 Method Not Allowed`를 반환하는 음수 검증 테스트를 추가했습니다.
