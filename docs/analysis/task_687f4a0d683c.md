## 1. 개요 및 배경

2026-09-04 외부 진단 보고서 및 코디네이터 재현에 의해, 기존 공급망 보안 판정 스크립트([scripts/filter_npm_audit.py](../../scripts/filter_npm_audit.py), [scripts/filter_trivy_results.py](../../scripts/filter_trivy_results.py))가 단순 JSON 구문 유효성만 확인할 뿐 스키마 및 입력 계약을 엄격히 검증하지 않는 P0 결함이 확인되었습니다.

### 1.1 기존 결함 양상
1. **스캐너 오류를 담은 JSON 통과**:
   - `npm audit` 에 `{"error": {"summary": "registry unavailable"}}` 가 주어지면 vulnerabilities 키가 없어 빈 딕셔너리로 처리되어 "취약점 0건"으로 통과되었습니다.
   - `trivy` 에 `{"Error": "scanner failed"}` 가 주어지면 Results 키가 없어 빈 목록으로 처리되어 "취약점 0건"으로 통과되었습니다.
2. **빈 객체 `{}` 통과**:
   - 필수 필드가 전혀 없는 빈 객체를 두 스크립트 모두 "취약점 0건"으로 오인해 통과시켰습니다.
3. **최상위 `list` 오타입 시 비정상 트레이스백 종료**:
   - Trivy 입력으로 `[]` 가 들어오면 진단 메시지 없이 `AttributeError` 트레이스백으로 비정상 종료되었습니다.
4. **전이 의존성 미해소 HIGH 누락**:
   - `npm audit` 에서 `via` 에 문자열만 존재하는 HIGH 항목이 원인 패키지가 vulnerabilities 맵에 없거나 advisory 가 없는 경우 검사에서 완전히 누락되었습니다.
5. **CI 워크플로의 stderr 유실**:
   - `.github/workflows/ci.yml` 의 `Scan JavaScript dependencies` 스텝이 `npm audit ... 2>/dev/null` 로 표준 에러를 버려 레지스트리 장애 원인이 기록되지 않았습니다.

본 작업에서는 이러한 결함을 해결하기 위해 판정 로직을 "단순 JSON 구문 파싱"에서 "엄격한 입력 계약(Input Contract) 검증"으로 전면 확장했습니다.

## 2. 주요 개선 및 구현 내용

### 2.1 npm audit 판정 스크립트 강화 ([scripts/filter_npm_audit.py](../../scripts/filter_npm_audit.py))
- **`validate_npm_audit_contract` 도입**:
  - 최상위 구조가 객체(`dict`)인지 검증 (list 등 오타입 시 거부).
  - `error` 키 존재 시 스캐너 장애로 즉시 판정하여 종료 코드 1 및 진단 메시지 출력.
  - `auditReportVersion` 필수 필드 존재 여부 검증.
  - `vulnerabilities` 매핑 객체 유효성 검증.
  - `metadata.vulnerabilities` 매핑 및 `high`, `critical` 정수 카운트 검증.
- **`metadata` 건수와 파싱 결과 정합성 교차 검증**:
  - `metadata.vulnerabilities` 의 `high + critical` 건수와 파서가 추출한 취약점 건수가 일치하지 않으면 계약 위반으로 종료 코드 1 차단.
- **문자열 `via` 미해소 전이 의존성 차단**:
  - `via` 에 문자열만 있는 경우, 원인 패키지가 `vulnerabilities` 에 실제 advisory(dict)를 가진 상태로 존재하는지 확인.
  - 해소된 경우 원인 패키지가 독립적으로 검사되므로 중복 등록 방지.
  - 원인 패키지가 부재하거나 advisory 를 갖지 못해 미해소된 경우 `UNKNOWN` 합성 식별자로 fail-closed 등록(allowlist 등록 불가로 확실하게 차단).

### 2.2 Trivy 판정 스크립트 강화 ([scripts/filter_trivy_results.py](../../scripts/filter_trivy_results.py))
- **`validate_trivy_contract` 도입**:
  - 최상위 구조 객체(`dict`) 검증 (최상위 list 입력 시에도 트레이스백 없이 명확한 진단 문구와 종료 코드 1 반환).
  - `Error` 키 존재 시 스캐너 장애로 즉시 판정하여 종료 코드 1 및 진단 메시지 출력.
  - `SchemaVersion` 지원 범위(2) 검증.
  - **결과 없음과 정상 0건의 엄격한 분기**:
    - `Results` 키 자체가 누락된 경우: 스캐너가 결과를 생성하지 못한 상태로 판정하여 종료 코드 1 차단.
    - `Results` 가 빈 리스트(`[]`)인 경우: 정상적으로 취약점이 0건인 스캔으로 판정하여 종료 코드 0 통과.
  - `Vulnerabilities` 필드가 존재하는 경우 반드시 리스트 타입이어야 함을 검증(오타입 차단).

### 2.3 CI 워크플로 시정 ([.github/workflows/ci.yml](../../.github/workflows/ci.yml))
- `npm audit` 표준 에러를 `/dev/null` 로 버리던 동작을 제거.
- `2>/tmp/npm_audit_stderr.log` 및 `>/tmp/npm_audit_stdout.json` 으로 출력 및 에러 분리 보존.
- 에러 로그가 존재할 경우 `cat /tmp/npm_audit_stderr.log >&2` 로 즉시 출력하여 레지스트리 장애 상세가 CI 로그에 남도록 보장.
- 취약점 발견 시 비정상 종료(exit != 0)하는 기존 흐름을 온전히 보존하면서 `--input` 파일 인자로 판정 스크립트에 전달.
