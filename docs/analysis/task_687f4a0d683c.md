## 1. 개요 및 배경

공급망 보안 판정 스크립트([scripts/filter_npm_audit.py](../../scripts/filter_npm_audit.py), [scripts/filter_trivy_results.py](../../scripts/filter_trivy_results.py))가 단순 JSON 구문 유효성만 확인할 뿐 스키마 및 입력 계약을 엄격히 검증하지 못해, 스캐너 장애가 "취약점 0건"으로 통과되던 결함을 시정하는 작업입니다.

이전 1차 시도(`task_687f4a0d683c`)에서 독립 리뷰어(grok-4.6)가 지적하고 코디네이터가 재현한 네 가지 반려 사유를 본 2차 작업(`task_3223bcf9aaef`)에서 전면 해결하였습니다.

### 1.1 해결 대상 결함 및 반려 사유
1. **Trivy `Results[].Error` 미검사 (잔여 보안 구멍)**:
   - `SchemaVersion: 2`이고 `Results`가 `[{"Target": "...", "Error": "..."}]`인 타깃 단위 스캐너 실패가 취약점 0건으로 통과되던 결함.
2. **npm audit `errors` 배열 미검사 (잔여 보안 구멍)**:
   - 최상위 `error` 키 없이 `errors` 배열만 두고 빈 `vulnerabilities`를 반환하는 레지스트리 오류가 깨끗한 스캔으로 통과되던 결함.
3. **npm metadata 개수 집계 단위 불일치 (거짓 차단)**:
   - `metadata.vulnerabilities` 수치는 패키지 단위인데 파서는 advisory를 개별 집계하여, 단일 패키지에 2개 이상의 advisory가 있거나 전이 의존성 링크가 존재할 때 정상 출력이 차단되던 결함.
4. **Trivy SchemaVersion 실측 기준 정립 및 워크플로 실행 강제**:
   - 핀된 `aquasecurity/trivy-action@v0.36.0`이 실제로 출력하는 `SchemaVersion: 2` (Results 키: `Class`, `Packages`, `Target`, `Type`)를 명확히 하고 미지 스키마 fail-closed를 유지함. 워크플로에서 npm exit code와 무관하게 항상 판정 스크립트를 거치도록 강제함.

## 2. 주요 개선 및 구현 내용

### 2.1 npm audit 판정 스크립트 강화 ([scripts/filter_npm_audit.py](../../scripts/filter_npm_audit.py))
- **`validate_npm_audit_contract` 보강**:
  - 최상위 구조 객체(`dict`) 검증.
  - 최상위 `error` 객체 및 `errors` 배열(비어있지 않은 오류 목록) 존재 시 즉시 종료 코드 1로 차단.
  - `auditReportVersion`, `vulnerabilities`, `metadata.vulnerabilities` 정수 카운트 검증.
- **`metadata` 설명 가능성 (Explainability) 검증 도입**:
  - `metadata.vulnerabilities`의 `high + critical` 수치와 `vulnerabilities` 맵 내 대상 패키지 수의 일치를 확인.
  - 단일 패키지에 복수의 advisory가 존재하는 경우에도 모든 advisory를 파싱하여 allowlist와 대조(거짓 차단 해소).
  - 전이 의존성(`via: ["cause-pkg"]`)은 재귀적 원인 패키지 추적(`is_cause_resolved`)을 통해 유효한 원인 패키지가 검사 대상이 되는지 확인하고, 미해소 시 `UNKNOWN`으로 fail-closed 차단.
  - 파서가 모든 대상 패키지를 유효한 advisory 또는 전이 체인으로 완전히 설명하는지 교차 검증.
- **진단 강화**:
  - `--stderr-file` 인자를 추가하여 레지스트리 장애 등 스캐너 stderr 로그가 존재할 경우 실패 시 상세 진단 메시지를 stderr에 연계 출력.

### 2.2 Trivy 판정 스크립트 강화 ([scripts/filter_trivy_results.py](../../scripts/filter_trivy_results.py))
- **`validate_trivy_contract` 보강**:
  - 최상위 구조 객체(`dict`) 검증 (최상위 list 등 오타입 시 트레이스백 없이 종료 코드 1 반환).
  - 최상위 `Error` 키 검사.
  - **개별 `Results[].Error` 검사 추가**: 타깃 단위 스캐너 실패 객체가 존재하는 경우 즉시 종료 코드 1 및 진단 메시지로 차단.
  - `SchemaVersion` 지원 범위 검사: 핀된 `aquasecurity/trivy-action@v0.36.0` 실측 기준(`SchemaVersion: 2`)을 엄격히 강제하고 미지 스키마 fail-closed 유지.
  - **결과 없음과 정상 0건 분기**: `Results` 키 부재 시 결과 미생성 차단, `Results: []`인 경우 정상 0건 통과.
  - `Vulnerabilities` 필드의 리스트 타입 검증.

### 2.3 CI 워크플로 시정 ([.github/workflows/ci.yml](../../.github/workflows/ci.yml))
- `Scan JavaScript dependencies` 스텝에서 `if [ "$EXIT_CODE" -eq 0 ]; then exit 0; fi` 조기 종료를 제거.
- `npm audit` 의 자체 종료 코드와 관계없이 항상 `filter_npm_audit.py`를 실행하여 스키마 및 입력 계약 검증을 강제.
- `npm audit` 표준 에러를 `/tmp/npm_audit_stderr.log`로 보존하고 `--stderr-file` 인자로 판정 스크립트에 전달.

### 2.4 정책 문서 개정 ([docs/ops/supply_chain_policy.md](../../docs/ops/supply_chain_policy.md))
- 버전 1.3.0 개정 반영.
- 제 9장 "판정 스크립트 입력 계약 (Fail-Closed)" 보강:
  - Trivy `Results[].Error` 거부 조건 추가.
  - npm audit `errors` 배열 거부 조건 추가.
  - npm audit `metadata` 패키지 수 대비 파서 설명 가능성 규정 명시.
  - Trivy 액션 핀 실측 기준 및 fail-closed 원칙 명시.
