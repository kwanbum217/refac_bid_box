## 1. 요약 (결론)

1. **수집 누락은 표본에서 0건이다.** 재조사 표본 25건(9/26 표본 5건 + 신규 20건) 전부에서 DB 에 결과가 없었고, 조달청 API 조회에서도 결과가 없었다. 즉 API 에는 있는데 DB 에 없는 "수집 누락"은 표본 25건 중 0건(0.0%)이다.
2. **9/26 표본 5건은 2일이 지나도 늦게 등록되지 않았다.** 9/26 에 API 부재로 판정했던 5건(R26BK01589082, R26BK01589060, R26BK01648907, R26BK01659726, R26BK01661664)은 9/28 재조회(공고게시일 기준)에서도 전부 부재다. 늦게 등록된 건수는 0건이다.
3. **신규 표본 20건도 전부 API 부재다.** 개찰 2026-08-18~08-28 대형 용역 20건(개찰일 분산)을 공고게시일 기준으로 조회한 결과 API 부재가 20/20 이다. 이 20건의 개찰 경과일은 31~41일로, 9/26 이 관측한 정상 도착 구간(개찰 후 6~30일, 30일 초과는 4~12%)을 이미 넘겼다.
4. **대형 용역 매칭률은 9/26 이후 사실상 동결이다.** 08-17 주 179/469(38.2%), 08-24 주 188/468(40.2%), 08-31 주 159/419(37.9%), 09-07 주 99/431(23.0%)는 9/26 보고서 값과 한 건도 다르지 않다. 09-14 주만 61→62건(11.8%→12.0%)으로 늦은 도착 1건이 있었다. 09-27 이후 신규 도착 대형 용역 결과는 2일간 1건뿐이다.
5. **판정: 상류 영구 누락 우세.** 표본 전수 API 부재 + 매칭률 동결 + 정상 도착 구간 초과를 종합하면, 이 공백은 "상류가 늦게라도 등록 중"인 지연이 아니라 조달청 API 에 등록되지 않는 영구 누락 성분이 지배적이다. 잔여 지연 성분(09-14 주 1건, 관측 최대 도착 지연 39일)은 소수다. 이 추세면 경고는 시간이 지나도 스스로 해소되지 않는다.
6. **전망: 경고 자동 해소 불가.** 상류가 등록하지 않으면 DB 로 회수될 경로가 없어 경고는 유지된다. 나라장터 화면 대조로 "API 미반영"과 "실제 미등록"을 구분하는 후속 확인이 필요하다(9/26 R2 와 동일).

### 3.2 신규 표본 20건 (선택 질의)

개찰 2026-08-17~2026-08-30, 추정가격 2.3억 이상, 취소공고 제외 용역 중 `bid_results` 에 같은 공고번호·분류 결과가 전혀 없는 공고를 개찰일별로 2~3건씩 분산 선택했다. 취소공고가 차수로 남은 공고(예: 나중 차수가 취소공고)는 오염을 막기 위해 공고번호 단위로 제외했다.

선택 질의(재현용):

```sql
WITH cancelled AS (
  SELECT DISTINCT bid_ntce_no FROM bid_announcements
  WHERE category='Servc' AND ntce_kind_nm='취소공고'
), missing AS (
  SELECT a.bid_ntce_no, MIN(DATE(a.openg_dt)) AS od
  FROM bid_announcements a
  LEFT JOIN bid_results r ON r.bid_ntce_no=a.bid_ntce_no AND r.category=a.category
  WHERE a.category='Servc' AND a.presmpt_prce>=230000000
    AND a.openg_dt >= '2026-08-17 00:00:00' AND a.openg_dt < '2026-08-31 00:00:00'
    AND (a.ntce_kind_nm IS NULL OR a.ntce_kind_nm <> '취소공고')
    AND r.bid_ntce_no IS NULL
    AND a.bid_ntce_no NOT IN (SELECT bid_ntce_no FROM cancelled)
  GROUP BY a.bid_ntce_no
), ranked AS (
  SELECT bid_ntce_no, od, ROW_NUMBER() OVER (PARTITION BY od ORDER BY bid_ntce_no) AS rn FROM missing
)
SELECT od, bid_ntce_no, rn FROM ranked
WHERE rn <= 2 OR (rn = 3 AND od IN ('2026-08-18','2026-08-19'))
ORDER BY od, bid_ntce_no
```

```sql
  ON r.bid_ntce_no=a.bid_ntce_no AND r.category=a.category

   = RIGHT(CONCAT('000',TRIM(LEADING '0' FROM r.bid_ntce_ord)),3)
WHERE a.category='Servc' AND a.presmpt_prce>=230000000
  AND a.openg_dt>='2026-08-17 00:00:00' AND a.openg_dt<'2026-08-31 00:00:00'
  AND (a.ntce_kind_nm IS NULL OR a.ntce_kind_nm<>'취소공고')
GROUP BY wk ORDER BY wk;
```

### 4.3 판정

| 항목 | 결과 | 비율 |
| --- | --- | --- |
| 수집 누락 (API 있음·DB 없음) | 0 / 25 | 0.0% |
| 상류 부재 (API·DB 모두 없음) | 25 / 25 | 100.0% |
| 9/26 표본 5건 늦은 등록 | 0 / 5 | 0.0% |
| 신규 표본 20건 API 부재 | 20 / 20 | 100.0% |

- **수집 누락은 검출되지 않았다.** 표본 25건 어디에도 "API 에는 있고 DB 에는 없는" 사례가 없다. 수집기·적재 경로는 이 표본 범위에서 결함을 보이지 않았다.
- **공백은 상류(조달청 API)에 있다.** 그리고 그 상류 공백은 **지연이 아니라 영구 누락 성분이 지배적**이다. 근거는 (1) 표본 전수 API 부재, (2) 대형 용역 매칭률 9/26 이후 동결(신규 도착 2일 1건), (3) 신규 표본의 경과일 31~41일이 9/26 이 관측한 정상 도착 구간(6~30일, 30일 초과 4~12%)을 이미 초과함이다.
- 잔여 지연 성분은 소수다. 09-14 주 1건 증가, 관측 최대 도착 지연 39일(08-17~08-30 개찰분, `last_collected=2026-09-26`)은 "아주 늦게라도 도착하는" 경로가 존재함을 보여주지만, 결손 규모(08-17~08-30 대형 용역 결과 없는 공고번호 492건)에 비하면 미미하다.

### 4.4 수집 누락 원인 가설 (해당 없음 및 한계)

수집 누락이 0건이므로 특정 원인(수집 창, `MAX_CATCHUP_DAYS` 클램프, 차수 정규화)을 지목할 근거는 이 표본에 없다. 다만 다음 한계를 남긴다.

- 표본은 창(08-17~08-30) 대형 용역 후보 394건 중 20건(약 5%)이다. 클램프로 인한 영구 구멍이 표본 밖 특정 날짜에만 존재할 가능성은 이 표본으로 배제되지 않는다. 9/26 4.5절의 구조적 위험(`collector_service.py` 의 `MAX_CATCHUP_DAYS=7` 클램프)은 그대로 유효하다.
- 차수 불일치로 "결과는 있으나 차수가 달라 매칭 실패"로 보이는 행이 있다. 창 937 행 중 공고번호+분류 조인 성립은 402 행, 정규화 차수까지 일치하는 행은 367 행으로 35 행 차이다. 이는 상류 부재와 별개인 매칭 정의 문제이며, 수집 누락(API 있고 DB 없음)과는 다르다.

### 4.5 전망과 권고

전망: 현재 추세(2일 신규 도착 1건)가 유지되면 용역 대형 경고(2026-09-28 기준 보정 38.5%, 다주 기저 51.2%)는 **스스로 해소되지 않는다.** 상류가 등록하지 않는 한 DB 로 회수될 경로가 없다.

## 5. 재현 방법

본 보고서의 모든 DB 수치는 `uv run python scripts/db_readonly_query.py --sql "<질의>"` 로 재현한다. API 수치는 `get_service_key()` 로 키를 읽어 `inqryDiv=2` 1일 창으로 조회해 재현하되, 인증키·전체 URL 은 출력하지 않는다.

- 모집단/표본: 3.2절 선택 질의, 4.1절 `result_rows` 질의.
- 주간 매칭률·최근 도착: 4.2절 두 질의.
- 창 집계: 아래 질의.

```sql
SELECT COUNT(DISTINCT a.bid_ntce_no) AS total_notices,
       COUNT(DISTINCT CASE WHEN r.bid_ntce_no IS NULL THEN a.bid_ntce_no END) AS missing_notices
FROM bid_announcements a
LEFT JOIN bid_results r ON r.bid_ntce_no=a.bid_ntce_no AND r.category=a.category
WHERE a.category='Servc' AND a.presmpt_prce>=230000000
  AND a.openg_dt>='2026-08-17 00:00:00' AND a.openg_dt<'2026-08-31 00:00:00'
  AND (a.ntce_kind_nm IS NULL OR a.ntce_kind_nm<>'취소공고');
```

결과: `total_notices = 861`, `missing_notices = 492`.
