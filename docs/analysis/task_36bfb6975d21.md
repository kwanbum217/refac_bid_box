## 2. 기존 문제점 분석

1. **HTTP 요청 경로 내 동기 블로킹**:
   - `get_bid_dataset_summary`에서 stale 감지 시 `rebuild_bid_dataset_summary`를 동기 호출.
   - 공고(`announcement`) 데이터셋 기준 전체 재집계 실측 477초 동안 사용자의 HTTP 요청이 타임아웃되거나 블로킹됨.
2. **분산 락 부재로 인한 중복 집계**:
   - 동시 요청 A, B, C가 동시에 stale을 인지할 경우 각자 전체 집계를 개시하여 데이터베이스 연결 풀 고갈 및 서버 과부하 유발.
3. **캐시 고정 문제**:
   - stale 상태에서 계산된 통계가 24시간 장기 캐시에 저장될 경우, 비동기 재집계가 완료되더라도 캐시 만료 전까지 구 데이터가 노출되는 문제.

## 3. 구현 내용

1. **조회 경로 논블로킹 전환**:
   - `get_bid_dataset_summary`는 스냅샷이 존재하면 무조건 기존 스냅샷을 즉시 반환.
   - stale 판정 시 `is_stale = True` 속성을 설정하고, 비동기 큐 등록 함수 `enqueue_rebuild_dataset_summary(dataset)`를 호출.
2. **Arq 백그라운드 재집계 태스크 신설**:
   - [src/tasks/summary_tasks.py](../../src/tasks/summary_tasks.py)에 `rebuild_dataset_summary_task` 작성.
   - [src/tasks/worker.py](../../src/tasks/worker.py)의 `WorkerSettings.functions`에 등록 (`cron_jobs`는 미변경).
   - 데이터셋별 고정 job ID(`rebuild_dataset_summary:{dataset}`)를 부여하여 큐 내 중복 적재 차단.
3. **최초 상태 분산 락 적용**:
   - 스냅샷이 전혀 없는 최초 상태에 한하여 동기 집계를 허용하되, Redis 분산 락(`lock:bid_dataset_summary:init:{dataset}`, 600초)을 획득하도록 구현.
   - Redis 미가용 시 fail-open을 차단하기 위해 프로세스 락(`threading.Lock`)으로 단일 실행 통제.
4. **stale 응답 60초 단기 캐싱**:
   - stale 상태일 때는 `:stale` 분리 캐시 키 및 60초 단기 TTL(`DASHBOARD_STATS_STALE_CACHE_TTL = 60`)을 적용하여 24시간 고정을 방지하고 thundering herd 차단.
