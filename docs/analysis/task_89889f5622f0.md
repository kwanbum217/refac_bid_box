## 1. 과업 개요 및 목적

기존 CI 환경에서는 브라우저 E2E 테스트(31개 시나리오)가 `cross-platform-test`의 Ubuntu 3.11 매트릭스 내부에서 전량 pytest와 혼합 실행되었습니다. 이로 인해 다음과 같은 문제점이 존재했습니다:
1. **화면 추적성 결여**: E2E 테스트 실패 시 DOM 화면이나 네트워크 상태를 확인할 수 없어 오직 텍스트 로그로만 원인을 분석해야 했습니다.
2. **매트릭스 러너 부하 및 지연**: 단위/통합 테스트 중심의 매트릭스에 브라우저 설치 및 실행이 섞여 전체 매트릭스 파이프라인 지연을 초래했습니다.
3. **아티팩트 부재 및 비효율 방지 필요**: 실패 시 증적(Trace/Screenshot)을 남기되, 성공 시 매 실행마다 아티팩트가 업로드되는 비용 낭비를 방지해야 했습니다.

본 과업에서는 GitHub Actions에 **독립된 `e2e-browser-test` Job**을 구축하고, 실패 시에만 Playwright Trace와 스크린샷 아티팩트를 보존하며, 0건 skip 게이트 및 실행 시간 예산을 엄격히 수립하였습니다.

## 2. 주요 변경 사항 명세

### 2.1 GitHub Actions 워크플로 (`.github/workflows/ci.yml`)

1. **`cross-platform-test` 매트릭스 최적화**:
   - `Install Playwright Chromium` 스텝을 매트릭스에서 완전히 제거하였습니다.
   - pytest 실행 마커를 `-m "not data_assets and not e2e"`로 수정하여 E2E 테스트와의 중복 실행을 원천 차단하였습니다.
   - E2E 제외 후에도 코드 커버리지는 **85.09%**를 기록하여 하한선(80%)을 안정적으로 통과함을 실측 확인하였습니다.

2. **`e2e-browser-test` 독립 Job 신설**:
   - 러너 환경: `ubuntu-latest`, Python `3.11`, Node.js `22`, Playwright `chromium`.
   - 전용 실행: `uv run pytest tests/e2e -m e2e -v` 단독 실행.
   - **0건 Skip 엄격 게이트**: 출력 문자열에 `SKIPPED` 또는 `skipped` 감지 시 즉시 종료 코드 1로 실패 처리하는 검증 쉘 스크립트 적용.
   - **조건부 아티팩트 업로드**: `if: failure()` 조건을 적용하여 테스트 실패 시에만 `test-results/` 아티팩트를 `playwright-e2e-failure-artifacts` 명칭으로 업로드(보존 기간 7일). 테스트 성공 시에는 무비용으로 업로드를 생략합니다.

### 2.2 E2E 테스트 Fixture 및 훅 고도화 (`tests/e2e/conftest.py`)

1. **실패 감지 훅 등록**:
   - `pytest_runtest_makereport` 훅을 구현하여 각 테스트의 실행 단계(`call`, `setup`) 결과 리포트를 기록.
   - `_is_test_failed(request)` 헬퍼를 통해 테스트 실패 여부를 정확히 판정.
2. **Playwright Trace 및 스크린샷 자동 수집**:
   - `context`, `authenticated_context`: 컨텍스트 생성 시 `tracing.start(screenshots=True, snapshots=True, sources=True)`를 비동기로 시작. 실패 시 `test-results/{test_name}_trace.zip`에 저장하고 성공 시 메모리에서 폐기.
   - `page`, `authenticated_page`: 실패 시 `test-results/{test_name}.png`로 전체 페이지 스크린샷 저장.
3. **기존 skip 정책 100% 보존**:
   - 브라우저 부재, npm 부재, 프론트엔드 빌드 실패 시의 `pytest.skip(...)` 로직은 단 한 줄도 임의로 실패(fail)로 변경하지 않고 원형을 그대로 유지하였습니다.

### 2.3 React SPA 의존성 처리 방침 및 근거

- **판단**: `e2e-browser-test` Job에 Node.js 22 설치 및 `frontend` 디렉터리의 `npm ci && npm run build` 스텝을 포함합니다.
- **근거**:
  1. Phase 3에서 완성한 5개 React SPA 탭 인터랙션 시나리오(`tests/e2e/test_react_spa.py`)를 CI에서 누락 없이 100% 실기 검증해야 합니다.
  2. 만약 npm 의존성을 설치하지 않으면 conftest의 방어 정책에 의해 5건이 skip 처리되며, 이는 독립 Job의 0-skip 게이트 원칙에 정면 위배됩니다.
  3. `npm ci && npm run build` 소요 시간은 실측 **3.60초**에 불과하여 CI 실행 시간에 미치는 영향이 극히 미미합니다.
