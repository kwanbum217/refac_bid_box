## 1. 개요 및 결함 분석

### 1.1 결함 현상 (R-03)
기존 `src/tasks/worker.py`의 `_redis_queue_length()`는 Arq 큐의 길이를 측정하기 위해 `client.llen(ARQ_QUEUE_KEY)`를 호출하였습니다.
그러나 Arq의 작업 큐(`arq:queue`)는 Redis List 자료형이 아니라, 작업 ID와 실행 예정 시각(밀리초)을 점수(score)로 저장하는 **정렬 집합(Sorted Set, ZSET)** 자료형입니다.

이로 인해 실제 운영 환경에서 다음 문제들이 발생하였습니다:
1. **자료형 불일치 (WRONGTYPE)**: 정렬 집합 키에 `llen` 명령을 수행하면 Redis는 `WRONGTYPE Operation against a key holding the wrong kind of value` 오류를 반환합니다.
2. **지표 영구 미기록**: 내부 `except Exception`이 예외를 삼켜 `None`을 반환하였고, `record_worker_heartbeat()`는 `queue_length is not None`일 때만 `QUEUE_BACKLOG_KEY`를 기록하여 적체 지표가 영구히 기록되지 않았습니다.
3. **가짜 Redis 테스트의 전제 왜곡**: 기존 단위 테스트(`tests/test_worker_heartbeat.py`)의 `FakeRedis`가 정렬 집합이 아닌 `llen` 메서드를 제공하여 잘못된 전제를 통과시키고 결함을 은폐하였습니다.
4. **관측 실패와 적체 0건 혼동**: 관측이 실패한 경우와 실제로 대기 작업이 0건인 경우가 모두 "기록 없음/None"으로 동일하게 처리되었습니다.

## 2. 적체의 의미(Semantics) 정의 및 근거

Arq의 정렬 집합 score는 작업의 실행 예정 시각(Unix Timestamp 밀리초)입니다:
- `score <= now_ms`: 즉시 워커가 가져가서 실행할 수 있는 대기 작업 (`pending` / `ready`)
- `score > now_ms`: 특정 시점까지 실행이 지연된 미래 예약 작업 (`deferred`)
- 전체 작업 수: 큐에 존재하는 모든 작업의 총합 (`total`, `zcard`)

워커의 과부하 및 병목 현상을 파악하기 위한 진정한 큐 적체 지표는 미래 예약 작업이 아니라 **지금 즉시 실행 대기 중인 작업 수(`pending`)**입니다.
따라서 본 개선에서는 다음 설계를 확정하였습니다:

| 메트릭 키 | 측정 기준 | Redis 명령 | 의미 |
| --- | --- | --- | --- |
| `pending` | `score <= now_ms` | `zcount(ARQ_QUEUE_KEY, "-inf", now_ms)` | 즉시 실행 대기 작업 수 (핵심 적체 지표) |
| `total` | 전체 집합 크기 | `zcard(ARQ_QUEUE_KEY)` | 큐 내 전체 작업 수 |
| `deferred` | `score > now_ms` | `max(0, total - pending)` | 미래 예약 작업 수 |

이로써 단순 `zcard` 사용 시 미래 예약 작업이 적체로 오인되는 문제를 원천 차단하고, `pending`과 `total`, `deferred`를 모두 페이로드에 포함하여 풍부한 관측성을 제공합니다.

## 3. 관측 실패와 실제 0건의 분리

큐 적체 관측 상태는 명시적인 상태 플래그를 통해 구분됩니다:

1. **정상 관측 시 (`status: "ok"`)**:
   - 실제 대기 작업이 0건인 경우:
     `{"status": "ok", "pending": 0, "total": 0, "deferred": 0, "observed_at": "..."}`
   - 대기 작업이 존재하는 경우:
     `{"status": "ok", "pending": 2, "total": 3, "deferred": 1, "observed_at": "..."}`
2. **관측 실패 시 (`status: "unavailable"`)**:
   - Redis 장애 또는 조회 실패 시:
     `{"status": "unavailable", "pending": None, "total": None, "deferred": None, "observed_at": "..."}`
3. **워커 생존 시각 기록 차단 방지 (`heartbeat_not_blocked`)**:
   - `record_worker_heartbeat()` 내에서 `WORKER_HEARTBEAT_KEY` 기록과 `QUEUE_BACKLOG_KEY` 기록을 독립적인 블록으로 격리하여, 큐 적체 관측 실패나 예외가 워커 생존 기록을 방해하지 않도록 보장하였습니다.
