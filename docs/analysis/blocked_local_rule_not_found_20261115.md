### 2.1 원인 A: 세부유형 규칙이 전 시·도 공통으로 없음 (47건)

`_METHOD_SERVICE_MARKERS` 는 `LEASE`(임대차, `:2098`), `REPAIR_INSPECTION`(수리, `:2096-2097`), `DEMAND_AGENCY`(수요기관 지정형, `:2099`), `ACADEMIC`(학술연구, `:2100`)를 세부유형으로 인식한다. 그런데 `LOCAL_RULES` 에는 이 네 값을 가진 `_local_rule` 이 한 건도 없다. `evaluation_rules_local.py` 에서 `service_type="LEASE"`, `"REPAIR_INSPECTION"`, `"DEMAND_AGENCY"`, `"ACADEMIC"` 은 0건이다.

2. `candidates = [rule for rule in region_rules if rule.service_type == service_type]`(`:2532`)가 빈 목록이 된다.
3. `GENERAL` 로 대체하려 해도(`:2555-2559`) `46`·`12`·`27`·`36` 에는 `GENERAL` 규칙이 없어 대체가 성립하지 않는다.

## 4. 확인하지 못한 것

1. **원문 미확보 69건의 별표 유무와 산식 값.** `46`·`44`·`27`·`36` 의 조례·별표 원문이 저장소에 없다. `docs/analysis/local_rule_not_found_types_20261018.md` 4.2·4.3·4.5·4.6절의 별표 목록은 수집 문서 근거이며 원문 직접 확인이 아니다. 그래서 해당 유형이 원문에 실제로 없는지, 있다면 기준비율·계수·통과점수·낙찰하한율이 얼마인지 확정하지 못했고 추측값도 적지 않았다.
2. **원문 확인 9건의 원본 대조.** `12`·`29` 9건은 위 조사 문서 4.1·4.4절의 기록(예규 번호·별표 구성·준용 조항)을 근거로 분류했다. 이 워크트리에서 조례 원본 파일을 다시 열어 대조하지는 않았다. (2026-11-15 정정: 4.1·4.4절의 `준용 근거 확인` 기록은 조달청 준용이 아닌 것으로 정정되었다. 따라서 이 문서의 분류를 떠받친 "조달청 준용" 전제는 성립하지 않는다. 1a·2a 의 원문 근거는 각 행의 정정 표기를 따른다.)
3. **판정 함수 실행 재현.** 캡슐 규칙에 따라 `resolve_evaluation_rule_from_raw_data` 를 직접 호출하지 않았다. 2절의 경로는 코드 줄과 DB 값으로 추적한 결과이며, 79건 전체를 실행해 차단 코드를 재출력해 비교하지는 않았다.
4. **원인 C 보완의 실제 해소 여부.** 교육 계열 판정에 `국립` 을 포함하면 `3793-3796` 경로로 조달청 여객 육상운송 규칙(`evaluation_rules.py:1459-1474`)이 매칭될 것으로 코드상 판단했으나, 실행으로 확인하지 않았다. 낙찰방법명과 조달청 별표 식별 문자열의 매칭은 판정 함수만이 정본이다.
5. **통합 이후 옛 시·도 코드 잔존의 영향 범위.** 신안군·소방본부 4건이 `46` 으로 잡히는 현상은 이번 79건의 차단 원인이 아니어서, 다른 유형·다른 공고에서 실제로 어떤 차단 코드를 만드는지는 세지 않았다.
6. **원장 시점 차이.** 참조 원장은 2026-11-11 생성본(27,791건, 차단 8,724건)이고, 이번 대상 목록은 2026-11-15 실행분(27,638건, 차단 8,670건)에서 나왔다. 건수와 기관별 내역이 일치해 같은 79건으로 판단했지만, 두 실행 사이에 추가·취소된 공고가 있을 수 있다.
