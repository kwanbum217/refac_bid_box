## 1. 개요 및 구현 목적

F3 선행 와일드카드 실측 조사([`task_f3_ngram_fulltext_probe.md`](file://../../docs/analysis/task_f3_ngram_fulltext_probe.md)) 결과에 따라, 집계 레이턴시가 대폭 개선되는 두 경로(`dminstt_nm` 18.99배 가속, `bidwinnr_nm` 2.85배 가속)에만 MySQL `ngram` FULLTEXT 선행필터를 선택 적용할 수 있도록 Feature Flag와 안전 폴백(Fallback) 구조를 구현했습니다.

운영 DB에 FULLTEXT 인덱스가 아직 생성되지 않았거나 비활성화된 상태에서도 코드가 무장애로 배포될 수 있도록 기본값 `False`의 안전 격리를 보장하며, 문제 발생 시 플래그 off만으로 즉각 기존 LIKE 단독 경로로 100% 원복됩니다. 본 Task는 운영 DB에 어떠한 DDL(인덱스 생성/수정/삭제)도 실행하지 않았습니다.

## 2. 세부 구현 내역

### 2.1 Feature Flag 추가 (`src/app/core/config.py`)
- `Settings` 모델에 `NGRAM_PREFILTER_ENABLED: bool = False` 필드를 추가했습니다.
- 기본값은 `False`로 고정되어 환경변수 명시 지정 없이 활성화되지 않습니다.

### 2.2 ngram 선행필터 안전성 판정 함수 (`src/rag/structured_data.py`)
- `is_safe_for_ngram_prefilter(keyword: str | None) -> bool` 함수를 구현했습니다.
- 판정 규칙 및 근거:
  1. **길이 < 2**: MySQL 기본 `ngram_token_size=2` 환경에서 1글자 토큰('시', '청' 등)은 2-gram 역색인 토큰을 생성하지 못해 `MATCH AGAINST` 결과가 0건(조용한 누락)이 발생하므로 제외 (`is_safe_for_ngram=False`).
  2. **LIKE 와일드카드 (`%`, `_`)**: 패턴 매칭 특수 문자로 ngram 역색인 검색 범위와 불일치 발생 방지.
  3. **FULLTEXT boolean 연산자 (`+`, `-`, `*`, `>`, `<`, `(`, `)`, `~`, `@`)**: 불리언 모드 쿼리 제어자 오작동 방지.
  4. **따옴표 (`'`, `"`, `` ` ``) 및 역슬래시 (`\`)**: 구문 검색(phrase query) 파싱 왜곡 및 SQL 리터럴 오류 방지.
- **픽스처([`tests/fixtures/ngram_edge_keywords.json`](file://../../tests/fixtures/ngram_edge_keywords.json))와의 정합성 및 보수적 배제 원칙**:
  - 픽스처는 구문 검색 래핑(+'"kw"') 전제하에 `edge_04` ~ `edge_12`의 특수문자 케이스들을 `is_safe_for_ngram: true`로 기록하고 있습니다.
  - 운영 코드는 와일드카드 매칭 불일치 및 불리언 제어자 오해석 위험을 원천 차단하기 위해 픽스처보다 엄격하고 보수적으로 판정하며, 코드의 안전 집합은 픽스처 안전 집합의 **진부분집합(strict subset)**을 이룹니다.

| 픽스처 ID | 키워드 | 픽스처 값 | 코드 판정 | 보수적 배제 근거 |
| --- | --- | :---: | :---: | --- |
| `edge_04` | `한국도로공사(본사)` | `true` | `False` | 괄호 `()`는 boolean 모드에서 하위 표현식 그룹화 연산자로 파싱되어 쿼리 구조 왜곡 위험이 있어 LIKE 단독 경로로 폴백 |
| `edge_05` | `서울-경기` | `true` | `False` | 하이픈 `-`은 boolean 모드에서 NOT(제외) 연산자로 해석되어 결과 누락을 유발할 위험이 있어 LIKE 단독 경로로 폴백 |
| `edge_07` | `K-water2026` | `true` | `False` | 하이픈 `-`이 포함되어 boolean NOT 연산자로 오작동할 위험이 있어 LIKE 단독 경로로 폴백 |

### 2.3 집계 경로 선행필터 결합 (`src/rag/structured_data.py`)
- `_result_conditions` 및 `_announcement_conditions`에 `enable_ngram_prefilter: bool = False` 키워드 인자를 추가했습니다.
- `enable_ngram_prefilter=True`이고 `settings.NGRAM_PREFILTER_ENABLED=True`이며 `is_safe_for_ngram_prefilter(institution_name)=True`인 경우에만 `MATCH(column) AGAINST(+'"keyword"' IN BOOLEAN MODE)`를 `AND`로 추가 결합합니다.
- 기존 `LIKE` 조건(`column.contains(institution_name)`)은 그대로 유지되어 위양성(False Positive)을 원천 차단합니다.
- 적용 대상:
  1. `top_winners` 실시간 집계 (`BidResult.bidwinnr_nm` GROUP BY)
  2. `top_institutions` 실시간 집계 (`BidAnnouncement.dminstt_nm` GROUP BY)
- **적용 배제 대상 (기각 원칙 준수)**:
  - `top_announcements` (`bid_ntce_nm` 집계): 25%~2500배 성능 악화가 확인되어 선행필터 적용 배제.
  - `recent_results`, `sample_announcements`, 단건 ID 조회, 시계열 집계, 요약 카운트: 선행필터 미적용.
