## 1. 개요 및 목적

로컬 Claude Code CLI(/opt/homebrew/bin/claude 2.1.259)의 Claude Pro 구독 기반으로 `claude-sonnet-5` (effort medium) 워커를 안전하게 probe하고, Orca `worker-start`로 감독 기동할 수 있도록 모델 라우터(`scripts/orca_model_router.py`)와 Task 제어 도구(`scripts/orca_taskctl.py`)의 dispatch 경로를 갱신했습니다.

주요 과제 및 제약:
1. **Antigravity Claude 와 로컬 Claude Pro 분리**: Antigravity 경로(`agy`)를 사용하는 기존 항목(`claude-opus-thinking` 등)에 회귀를 유발하지 않아야 합니다.
2. **리뷰어 계열 분리 유지**: `provider_for_model`은 리뷰어 독립성 검증에 사용되는 모델 패밀리 값(`claude`)을 유지해야 합니다.
3. **Gemini 주력 정책 보존**: Gemini TIER_POLICY 자동 배정은 그대로 유지하며, Claude Pro Sonnet 5는 `WORKER_MODEL_NOTICE` 후 명시 배정하는 수동 보조 워커로 운용합니다.
4. **dispatch 추론 등급(effort) 전달 및 방어**: `worker-start`는 `--effort`를 지원하므로 `taskctl dispatch`에 `--effort` 옵션을 추가하고, 모델 없이 effort만 단독 지정하는 잘못된 호출을 fail-closed로 차단합니다.

## 3. 설계 및 구현 변경 내역

### 3.1 모델 패밀리 Provider와 Probe 전송 경로 분리 (`scripts/orca_model_router.py`)

기존에는 `provider_for_model`과 `PROBE_CONFIG`가 동일한 provider 키(`claude`)를 공유하여, Claude 계열 모델은 모두 `agy`를 호출했습니다. 이를 다음과 같이 분리했습니다:

1. **`PROBE_CONFIG["claude-cli"]` 신설**:
   - 로컬 Claude Code CLI 전용 probe 명령 템플릿 등록:
     `["claude", "-p", "ping", "--model", "{model}", "--effort", "medium", "--output-format", "json", "--tools", "", "--no-session-persistence", "--safe-mode"]`
   - 타임아웃: 30초
2. **`MODEL_POOL["claude-sonnet"]` 갱신**:
   - `id`: `claude-sonnet-5` (종전 `claude-sonnet-4-6`에서 교체)
   - `provider`: `claude` (모델 패밀리 유지)
   - `probe_provider`: `claude-cli` (probe 전송 경로만 로컬 CLI로 분리)
   - `max_tokens`: 1,000,000
   - `notes`: 로컬 Claude Pro 전용 풀 명시
3. **`probe_model` 해석 로직 보강**:
   - 풀 정보에서 `probe_provider`(또는 `probe_transport`)를 우선 참조하여 전송 채널을 선택합니다.
   - 미등록 fallback에서도 `claude-sonnet-5` 또는 `claude-sonnet`은 `claude-cli`로 분기합니다.
   - `claude-opus-thinking` 등 Antigravity Claude 모델은 기본 `claude`(`agy`) 경로를 유지하여 회귀를 원천 차단합니다.
4. **`provider_for_model` 불변성 보장**:
   - `claude-sonnet` 및 `claude-sonnet-5` 모두 provider family `claude`를 반환합니다.

### 3.2 Task Dispatch 추론 등급 연계 및 Fail-Closed 방어 (`scripts/orca_taskctl.py`)

1. **`worker_start` 함수 인자 확장**:
   - `effort: str | None = None` 인자를 추가하고, 인자 존재 시 CLI 명령어에 `["--effort", effort]`를 전달합니다.
2. **`taskctl dispatch` CLI 옵션 추가**:
   - `dsp.add_argument("--effort", help="...")` 추가.
3. **`--effort` 단독 지정 차단 (Fail-Closed)**:
   - `--model` 없이 `--effort`만 단독으로 지정된 경우, 즉시 종료 코드 2(`effort_without_model`)로 기동을 거부합니다.
4. **worker-start 기동 연계**:
   - `args.effort`가 `worker_start` 호출 시 정확히 전달되어 하위 `orca orchestration worker-start` 명령으로 전파됩니다.
