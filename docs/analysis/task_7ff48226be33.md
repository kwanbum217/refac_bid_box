## 1. 배경 및 목적

### 1.1 배경
격리 워크트리에는 gitignore 대상인 `data/model_files/*/model.bin` 및 `chroma_db/` 디렉터리가 존재하지 않으므로, `tests/test_data_preservation.py`의 2건 테스트(`test_model_bin_files_exist`, `test_chroma_db_exists`)가 실패하는 것이 정상 동작입니다.
그러나 Task Intent의 `verification_commands`에 `uv run pytest tests/ -q`와 같이 `-m 'not data_assets'` 마커가 누락된 전량 테스트 명령이 선언될 경우, 워커가 이를 결함으로 오인하여 주 저장소의 원본 모델 가중치나 벡터DB를 심볼릭 링크/복사하려 하거나 삭제 위험을 초래할 수 있습니다.

### 1.2 목적
1. `scripts/orca_taskctl.py`의 `resolve_verification_commands`에서 tests 디렉터리 전량을 대상으로 하는 pytest 명령에 `data_assets` 제외 마커가 없으면 자동으로 붙이도록 기계적 강제.
2. 특정 파일 또는 node id 대상 명령은 변경 없이 온전히 보존.
3. 기존 `-m` 마커가 선언되어 있으나 `data_assets`를 제외하지 않는 경우, 조용히 덮어쓰지 않고 `ValueError`로 거부하며 정본 형태(`BACKEND_VERIFICATION_COMMAND`)를 안내.
4. `BASE_GROUND_TRUTH`에 격리 워크트리 데이터 자산 예외 사실을 표준 항목으로 등록하여 모든 Capsule에 자동 주입.
