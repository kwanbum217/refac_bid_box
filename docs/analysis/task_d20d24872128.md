## 1. 개요 및 배경

기존 저장소에는 agy, qwen, kimi, codex 런처만 구비되어 있어 claude, opencode, grok 세 CLI 는 워커 런처 경로를 사용할 수 없었습니다. 이에 따라 선행 조사(am5_launcher_gap_survey)를 통해 확정된 기동 사양을 기반으로 신규 런처 스크립트 3종을 신설했습니다.

본 구현에서는 다음과 같은 정본 원칙과 확정 계약을 엄격히 준수했습니다:
1. **Preamble 공용 로직 재사용**: `scripts/orca_worker_launch_common.py`의 `wait_for_preamble`을 그대로 임포트하여 사용하여 파일 glob, unlink, 다중 후보 거부 로직을 중복 구현하지 않았습니다.
2. **단발 실행 모드 창 유지**: 단발 실행(`--one-shot`) 시 `subprocess.run`으로 CLI 를 완주시킨 뒤 대화형 셸(`open_interactive_shell`)로 이어받아 터미널 창과 출력을 온전히 유지하도록 구현했습니다.
3. **권한 자동 승인 인자 기본값 비활성화**: 위험한 일괄 자동 승인 인자(claude의 `--dangerously-skip-permissions`, opencode의 `--auto`, grok의 `--always-approve`)는 CLI 인자로 명시적 선택 가능하게 노출하되 기본값을 `False`로 고정했습니다.
4. **불필요한 API 표면 및 키 시퀀스 배제**: 요구되지 않은 별칭 상수나 kwargs 우회는 일체 추가하지 않았으며, 세 CLI 모두 shift+tab 키 시퀀스를 전송하지 않습니다.
5. **격리 안전망 및 미호출 단언**: 테스트 시 분리 프로세스가 실제로 뜨지 않도록 파일별 autouse 안전망을 두고 `subprocess.Popen`이 호출되지 않음을 단언했습니다.
6. **기존 taskctl 비수정**: `scripts/orca_taskctl.py`는 수정하지 않고 런처 스크립트 및 테스트 신설에 집중했습니다.
