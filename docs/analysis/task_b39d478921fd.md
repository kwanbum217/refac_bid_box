## 1. 개요 및 배경

Orca 환경에서 CLI 워커(Antigravity, Kimi Code, Qwen Code)를 기동할 때 터미널 생성 후 Preamble 주입 순서 문제를 해결하기 위해 전용 런처 스크립트(`orca_agy_launch.py`, `orca_kimi_launch.py`, `orca_qwen_launch.py`)를 사용합니다.

그러나 런처를 통해 워커를 띄울 경우 `orca_taskctl.py dispatch`를 거치지 않아 워커 권한 자동 승인 4단계가 통째로 누락되는 문제가 있었습니다. 이에 따라 Antigravity뿐만 아니라 Kimi, Qwen 워커도 파일 수정 대화창이나 터미널 권한 대화창에서 멈추어 작업이 지연되는 현상이 발생했습니다.

또한 참조 구현이었던 `orca_agy_launch.py`의 `acquire_permissions`에 실측 결함이 확인되었습니다. `prepare_worker_terminal`은 파일 편집 모드 전환에 실패(`file_edit_auto_approve.ok == False`)하더라도 최상위 `ok`를 `True`로 반환합니다. 기존 코드는 최상위 `ok`만 검사하여 `accept-edits`를 미확보한 상태로 조기 종료하는 결함이 있었습니다.

## 2. 주요 변경 사항

### 2.1 공통 권한 준비 모듈 신설 (`scripts/orca_worker_launch_common.py`)

세 런처가 동일한 불변식을 공유할 수 있도록 공통 모듈을 구현했습니다.

1. **엄격한 준비 완료 판정 (`is_terminal_ready`)**:
   - Antigravity CLI의 경우 반드시 `file_edit_auto_approve.ok == True`를 확인합니다. 최상위 `ok`는 판정 기준으로 사용하지 않습니다.
   - Kimi, Qwen 등 `shift+tab`을 지원하지 않는 CLI는 감시기(`auto_approve_watcher.ok == True`) 및 신뢰 대화창 상태를 기준으로 완료를 판정합니다.
2. **`prepare_worker_terminal` 온전한 호출**:
   - `prepare_worker_terminal(terminal, cli_type=..., model=..., launcher=...)`을 호출하여 CLI 메타데이터가 정상 기록되도록 보장합니다.
   - `force_file_edit`은 화면 생성 중 모드 오판정을 방지하기 위해 일체 사용하지 않습니다.
3. **충분한 타임아웃 및 주기**:
   - `PERMISSION_SETUP_DELAY_SEC = 10.0`
   - `PERMISSION_SETUP_DEADLINE_SEC = 600.0`
   - `PERMISSION_SETUP_INTERVAL_SEC = 15.0`
4. **자식 프로세스 독립 분리 (`spawn_permission_setup`)**:
   - `start_new_session=True`로 부모 프로세스의 exec/종료와 무관하게 동작합니다.
5. **자식 모드 인자 검증 (`run_permission_setup_child`)**:
   - 터미널 핸들이나 모델 ID가 누락/공백일 경우 즉시 종료 코드 2를 반환합니다.
6. **터미널 핸들 환경변수 검사 및 경고 (`schedule_permission_setup`)**:
   - `ORCA_TERMINAL_HANDLE`이 설정되지 않은 경우 `sys.stderr`로 경고를 출력하고 `False`를 반환합니다.

### 2.2 Antigravity 런처 리팩토링 (`scripts/orca_agy_launch.py`)

- 공통 모듈의 `acquire_permissions`, `spawn_permission_setup`, `run_permission_setup_child`, `schedule_permission_setup`을 사용하여 중복을 제거하고 최상위 `ok` 판정 결함을 해소했습니다.

### 2.3 Kimi Code 런처 이식 (`scripts/orca_kimi_launch.py`)

- `--setup-permissions` 자식 모드 분기 추가 (`cli_type="kimi"`).
- preamble 수신 후 kimi 실행 직전 `schedule_permission_setup` 호출.

### 2.4 Qwen Code 런처 이식 (`scripts/orca_qwen_launch.py`)

- `--setup-permissions` 자식 모드 분기 추가 (`cli_type="qwen"`).
- `-i`(대화형) 및 `-p`(`--one-shot` 단발) 모드 모두에서 권한 설정 자식을 기동하도록 구성.
  - 근거: 단발 모드라도 긴 작업 중 파일 수정/셸 실행 시 승인 감시기 부착과 워커 메타데이터 기록이 필수적이며, `prepare_worker_terminal`이 qwen 메타데이터를 인식해 `shift+tab`을 안전하게 건너뛰므로 부작용이 없습니다.
