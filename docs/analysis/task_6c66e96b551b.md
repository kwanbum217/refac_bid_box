## 1. 목적

외부 진단 및 코디네이터 실측에서 확인된 Orca 통제면의 3대 결함을 영구 해소합니다:
1. **역할 혼선(Role Ambiguity)**: 리뷰어에게 빌더 계약(커밋 의무, write scope 준수)을 주입해 읽기 전용 계약을 위반하고 보고 파일을 커밋하게 만들던 결함 해소.
2. **격리 파손(Isolation Breach)**: 고정 preamble 파일(`.orca/preamble.txt`) 재사용으로 이전 Task 지시가 다음 워커/리뷰어에게 전달되던 교차 오염 차단.
3. **독립 Provider 정책 우회**: 리뷰어 모델 배정 시 빌더 provider 가 select_model 에 전달되지 않거나, 명시 모델(`--model`) 지정으로 독립성 검증이 우회되던 결함 해소.

## 2. 구현 요약

### 2.1 역할별 고지문 분기 및 역할 불일치 거부 (`scripts/orca_taskctl.py`)
- `build_capsule_notice` 함수가 `role` 과 `return_contract` 매개변수를 지원하고, Capsule 내용과 고지문 인자 간의 역할 불일치를 검증합니다.
- **Reviewer**: 소스 코드 수정 금지, 커밋 생성 금지 명시, `ORCA_REVIEW_DONE_V2` 반환 계약 및 `validate_review_report.py` 사전 검증 명령만 주입합니다. 빌더용 커밋 의무(`commit_count` 검사, 0개 시 escalation), `allowed_write_files` 범위 준수 문구, `ORCA_WORKER_DONE_V2`, guard 안내는 일절 주입하지 않습니다.
- **Builder**: `allowed_write_files` 가 비어 있지 않은 경우에만 커밋 생성 의무(`commit_count` 가 0이면 escalation)와 `ORCA_WORKER_DONE_V2`/`orca_worker_done_guard.py` 안내를 주입합니다. 쓰기 범위가 없는 읽기 전용 빌더는 커밋 의무를 주입하지 않습니다.
- `cmd_dispatch`: Capsule 에 선언된 `role` 과 Intent 또는 CLI 인자로 지정된 `role` 이 상이하면 종료 코드 1(`capsule_spec_error`)로 Dispatch 를 즉시 중단합니다.

### 2.2 시도 단위 고유 Preamble 수명주기 및 격리 파손 방지 (`scripts/orca_taskctl.py`, `scripts/orca_agy_launch.py`)
- `cmd_dispatch`: 고정 파일명 대신 `preamble_{task_id}_{dispatch_id}_{nonce}.txt` 형태의 시도 단위 고유 파일명을 생성하여 워크트리 `.orca/` 디렉터리에 기록합니다.
- `find_unconsumed_preambles`: Dispatch 진입 시 워크트리에 소비되지 않은 잔여 preamble 파일(`preamble_*.txt`)이 남아 있으면 이전 지시문 격리 파손 위험으로 새 Dispatch 를 종료 코드 2(`unconsumed_preamble_exists`)로 거부합니다.
- `scripts/orca_agy_launch.py`:
  - `wait_for_preamble` 이 워크트리 내의 고유 preamble 파일을 감지하여 내용을 읽은 즉시 삭제(`unlink`)하고 `"preamble 소비 완료"` 동기화 표지를 출력합니다.
  - **다중 후보 거부**: 워크트리에 `preamble_*.txt` 후보가 둘 이상 발견되면 어느 것도 조용히 고르거나 소비하지 않고, 남아 있는 후보 목록을 표준 에러로 출력한 뒤 `ValueError` 로 즉시 기동을 거부합니다.
  - 레거시 고정 preamble(`.orca/preamble.txt`)만 홀로 남아 있는 경우 격리 파손 위험으로 즉시 `ValueError` 거부합니다.

### 2.3 리뷰어 독립 Provider 강제 및 명시 모델 우회 차단 (`scripts/orca_taskctl.py`, `scripts/orca_model_router.py`)
- `scripts/orca_taskctl.py` 의 `resolve_dispatch_model`:
  - 리뷰어 배정 시 계산된 `builder_provider` 를 `select_model` 의 `builder_provider` 인자로 직접 전달합니다.
  - 위험도가 `medium` 또는 `high` 인 리뷰어 Task 에서 `builder_provider` 가 부재(None, 빈 문자열, 공백/탭, "unknown")한 경우 경고가 아닌 오류(`ModelRoutingError`)로 fail-closed 처리합니다.
  - 명시 모델(`--model`) 지정 검증: `MODEL_POOL` 미등록 모델 거부, 코디네이터 전용 모델(`codex`) 거부, 리뷰어인 경우 빌더와 동일한 provider 모델 거부(`ModelRoutingError`).
- `scripts/orca_model_router.py`:
  - `select_model`: `builder_provider` 를 strip 정규화하여 `None`, 빈 문자열, 공백/탭(`\t`, `\n`)을 `unknown` 으로 처리하고, 위험도가 `medium` 이상이거나 쓰기 범위가 있는 경우 fail-closed 로 `ModelRoutingError` 예외를 발생시킵니다.
  - `route_model`: `explicit_model` 지정 시에도 `MODEL_POOL` 등록 여부, 코디네이터 전용 여부, 리뷰어 독립 provider 일치 여부를 엄격히 검증하여 우회를 차단합니다.
