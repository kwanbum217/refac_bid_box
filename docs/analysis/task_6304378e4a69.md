## 1. 개요 및 목적

### 1.1 문제 배경
런처 경로 Dispatch는 대상 터미널이 사전에 런처 스크립트(`scripts/orca_agy_launch.py` 등)를 실행하여 preamble 파일 생성을 기다리고 있는 상태를 전제로 동작합니다.
그러나 대상 터미널이 런처를 `--command`로 지정하지 않은 일반 빈 셸 상태이거나 비정상 종료된 경우에도 기존에는 `orca orchestration dispatch --return-preamble`을 실행하고 워크트리에 preamble 파일을 기록한 뒤에야 픽업 시한 초과(`launcher_pickup_timeout`, 종료 코드 3)로 실패했습니다.

이로 인해 다음과 같은 결함이 발생했습니다:
1. 이어받을 주체가 없는 빈 터미널 워크트리에 미소비 preamble 파일이 남아 이전 지시문 격리가 파손됩니다.
2. 불필요하게 30초의 픽업 시한을 전부 소진한 뒤에야 실패가 드러납니다.
3. 대상 터미널이 실제로 런처를 실행 중인지 사전에 알지 못한 채 권한 자동 승인 감시기와 Dispatch 컨텍스트가 등록됩니다.

### 1.2 구현 목적
런처 경로 Dispatch 시 preamble 파일을 워크트리에 쓰기 전에 대상 터미널의 화면 출력을 검사하여, 대상 터미널이 실제로 런처를 실행 중인지(preamble 대기 상태인지) 폴링으로 확인하고 대기 중이 아니면 preamble 파일을 작성하지 않고 즉시 fail-closed(종료 코드 2)로 거부하도록 구현합니다.

## 2. 설계 및 구현 세부사항

### 2.1 4번째 선행 거부 분기 배치
[`scripts/orca_taskctl.py`](../../scripts/orca_taskctl.py)의 `cmd_dispatch` 내 런처 경로(`if args.terminal and launcher_mode:`)는 기존에 3단계의 선행 거부 검사를 가지고 있었습니다:
1. `launcher_worktree_unresolved`: 워크트리 경로 미확인 시 거부
2. `launcher_main_repo_write_forbidden`: 주 저장소 쓰기 시도 시 거부
3. `unconsumed_preamble_exists`: 미소비 preamble 파일 잔류 시 거부

이번 변경으로 미소비 preamble 검사 직후, 권한 감시기 부착 및 preamble 파일 작성 직전에 4번째 선행 거부(`launcher_terminal_not_waiting`)를 배치했습니다.

### 2.2 기존 헬퍼 재사용 및 검사 로직
새로운 헬퍼를 중복 생성하지 않고 기존의 견고한 화면 판정 헬퍼들을 직접 재사용했습니다:
- `terminal_tail(handle)`: 터미널 최근 출력 조회
- `terminal_read(handle)`: 터미널 전체 버퍼 조회
- `instruction_observed(text, markers)`: ANSI 제거 및 공백 정규화 대조
- `LAUNCHER_WAIT_MARKERS`: `("preamble 대기 중", "preamble 대기 중:", "wait_for_preamble")` 표지 튜플

### 2.3 폴링 대기 및 Fail-closed 거부 사양
- **상수 정의**:
  - `DEFAULT_LAUNCHER_READINESS_WAIT_SECONDS = 20.0` (기본 대기 시한 20초)
  - `DEFAULT_LAUNCHER_READINESS_POLL_INTERVAL_SEC = 1.0` (폴링 간격 1초)
- **즉시 통과**: 터미널이 이미 대기 표지를 출력하고 있으면 추가 대기 없이 즉시 통과합니다.
- **늦은 표지 감지**: 터미널 기동 직후 파이썬 환경 초기화 중일 경우 폴링 루프를 통해 최대 20초간 표지 출현을 대기합니다.
- **화면 미조회와 표지 부재의 구분**:
  - 화면 출력을 아예 읽지 못한 경우: `reason="unreadable"`로 fail-closed 거부 (통과 금지)
  - 화면 출력은 읽었으나 표지가 없는 경우: `reason="not_waiting"`으로 거부
- **오류 응답 규격**:
  - 종료 코드: `2`
  - `--json` 에러 페이로드: `error="launcher_terminal_not_waiting"`, `task_id`, `capsule`, `terminal`, `worktree`, `waited_seconds`, `reason`, `exit_code`
  - 사람이 읽는 표준오류 메시지에 원인 설명과 함께 터미널 생성 시 `--command`로 런처를 지정해야 한다는 해결책 및 명령어 예시 제공

### 2.4 우회 플래그 (`--allow-unready-launcher`)
- 플래그명: `--allow-unready-launcher` (기본값: `False`)
- 지정 시 표준오류에 기존 플래그와 동일한 형식의 경고(`경고: --allow-unready-launcher 지정으로 런처 preamble 대기 상태 검사를 건너뜁니다.`)를 출력하고 검사를 건너뛰어 계속 진행합니다.
- `worker-start` 경로(`args.terminal`이 없는 경로)는 Orca가 기동을 보증하므로 본 검사가 적용되지 않습니다.
