# BM1 협상 가격점수 원천 재계수 (2026-09-11)

> **작성일**: 2026-09-11
> **작성자**: 코디네이터 직접 측정
> **목적**: R-17(협상 가격점수) 차단 사유가 현재 데이터에서도 유효한지 전 구간으로 재확인
> **선행 문서**: [`ng2a_negotiation_price_score_survey_20260910.md`](ng2a_negotiation_price_score_survey_20260910.md)

---

## 1. 결론

**차단 사유는 그대로 유효합니다.** 협상에의한계약 공고 **121,052건 전부**에서
`sucsfbidMthdAppStd` 가 비어 있습니다. 기간은 2025-01-05 부터 2026-09-09 까지
전 구간입니다.

가격점수 산식에 필요한 계수 `k` 와 통과점수 `T` 의 원천이 없으므로 R-17 은
**데이터 수집 방식이 바뀌기 전까지 착수해도 헛일**입니다.

---

## 2. 측정

읽기 전용 질의로 두 번 셌습니다.

| 범위 | 전체 | `sucsfbidMthdAppStd` 채워진 건 | 채움률 |
| --- | ---: | ---: | ---: |
| 공고 전반 (2026-01-01 이후, 해당 키 보유) | 327,874 | 68,256 | **20.8%** |
| **협상에의한계약 공고 (전 구간)** | **121,052** | **0** | **0.0%** |

협상 판별은 `raw_data` 의 `sucsfbidMthdNm` 에 `협상` 이 포함되는 조건입니다.

---

## 3. 이 측정이 필요했던 이유

**채움률만 보면 착수 가능해 보입니다.** 공고 전반에서는 20.8% 가 채워져 있어
"이제 데이터가 들어오기 시작했다" 로 읽힐 수 있습니다. 실제로 이번 확인의 첫
질의가 그 수치를 냈습니다.

**그러나 협상 공고로 좁히면 0 입니다.** 값이 있는 것은 협상이 아닌 다른
낙찰방법 공고이며, 정작 가격점수가 필요한 협상 공고에는 한 건도 없습니다.
수집 누락이 아니라 **협상 공고에만 해당 항목이 제공되지 않는 구조**로 보입니다.

따라서 이 항목의 가용성을 확인할 때는 **반드시 협상 공고로 좁혀서** 세십시오.
전체 채움률은 판단 근거가 되지 않습니다.

---

## 4. 재확인 절차

다음에 같은 판단이 필요하면 아래 한 줄이면 됩니다.

```sh
uv run python scripts/db_readonly_query.py --sql "SELECT COUNT(*) AS nego_total, SUM(CASE WHEN JSON_UNQUOTE(JSON_EXTRACT(raw_data, '\$.sucsfbidMthdAppStd')) <> '' THEN 1 ELSE 0 END) AS filled FROM bid_announcements WHERE JSON_UNQUOTE(JSON_EXTRACT(raw_data, '\$.sucsfbidMthdNm')) LIKE '%협상%'"
```

`filled` 가 0 이 아니게 되는 시점이 R-17 재검토 시점입니다.

---

## 5. 바뀌지 않은 사실

- `bid_results` 에는 낙찰자 한 명만 있어 경쟁 투찰가 의존 산식은 **사후 재현도
  불가능**합니다. 원천이 생겨도 이 제약은 따로 남습니다.
- 현재 화면은 변종별 과거 낙찰률 실측 분포를 참고값으로 제시하며, 순위와 낙찰
  여부는 계산 불가로 명시하고 있습니다. 이 동작은 유지합니다.
