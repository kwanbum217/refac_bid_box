## 3. 1차 측정에서 발견한 회귀와 시정 (가장 중요)

**첫 M1 측정은 q21 을 고쳤지만 q05 와 q08 을 깨뜨렸습니다.** 순증이 아니라 순감이었습니다.

| 지표 | 이전 정본 | 1차 M1 (회귀본) |
| --- | ---: | ---: |
| numeric | 138/144 | **132/144** |
| refusal | 93/96 | **90/96** |
| evidence recall | 0.9583 | 1.0000 |
| citation | 70/72 | 72/72 |

**검색 지표만 봤다면 전면 개선으로 오판했을 것입니다.** recall 과 citation 이 만점이 된 채로
답변 품질만 나빠졌습니다.

### 3.1 기전

`retrieve_lexical_context` 는 `dataset = "announcement"` 로만 조회하고
`attributesToRetrieve` 에 `sucsf_bid_amt`, `bidwinnr_nm`, `sucsf_bid_rate` 가 없습니다.
**낙찰 결과를 담지 않는 문서입니다.**

Lexical 포함 매칭 승격이 이 공고 전용 문서를 벡터 결과 상위로 병합했고, `top_k=5`
절단으로 결과를 담은 문서가 밀려났습니다. 96건 중 65건에서 근거 목록이 바뀌었습니다.

```
q08 이전: [bid_10168836(결과 보유, 2위), 벡터 4건]
q08 이후: [announcement 4건, bid_10168836(5위)]
   -> "낙찰업체, 낙찰금액, 낙찰률 정보가 포함되어 있지 않습니다"
```

모델은 잘못 답한 것이 아니라 정직하게 거부했습니다. 컨텍스트에 정말로 답이 없었습니다.

### 3.2 시정

`engine.py` 의 Lexical 포함 매칭 승격만 되돌리고 `vector_store.py` 의 재순위는
유지했습니다. **q21 은 벡터 재순위만으로 해결됩니다.** 1차 측정에서 `bid_10169448` 이
2위를 확보한 것이 근거입니다.

회귀를 고정하는 테스트를 추가했고, 구 코드에서 실패하고 시정본에서 통과함을 확인해
공허하지 않음을 검증했습니다. 회귀 측정 결과는
`data/benchmarks/noncanonical/blind_fixture_v2_e2b_20260830_postfix.json` 에 증거로
보존했습니다.

| **total** | **3,624.59** | **4,026.55** | **-401.97** | **12,233.43** | 5,001.94 |

**P50 기준으로 cold 가 warm 보다 402ms 빠릅니다.** 콜드 스타트 페널티가 있으리라는
가정과 반대입니다. 원인은 `llm_ms` 이며 Ollama 직렬 처리로 warm 호출이 앞선 요청의
잔여 부하를 받는 것으로 보입니다.

**콜드 페널티는 중앙값이 아니라 꼬리에 있습니다.** cold P95 는 vector 와 sql 에서
warm 대비 각각 5.0배, 49.5배입니다.

### 5.1 지목된 네 문항은 한 부류가 아니었습니다

| 문항 | cold 총 | warm 총 | 실제 원인 | 판정 |

| q08 | 6,897 | 6,123 | LLM 생성 4,742ms (전 문항 최대) | 캐시로 해결 안 됨 |
| q25 | 1,898 | 2,172 | - | **최적화 대상 아님** |
| q31 | 2,216 | 2,521 | - | **최적화 대상 아님** |

### 5.2 실제 최악은 지목되지 않았던 q01 이며 원인은 워밍업 부재입니다

q01 cold 총 27,792ms, 그중 벡터 26,097ms 로 전 구간 max 와 정확히 일치합니다.
warm 은 4,178ms 로 6.7배 떨어집니다.

**두 측정에서 교차 확인했습니다.** M1 정본에서도 q01 r1 이 28,646ms 로 96요청 중
최대였고 r2 19,620ms -> r3 11,746ms 로 단조 감소했습니다. 문항 고유 특성이 아니라
프로세스 재기동 직후 첫 요청 비용입니다.

`docs/ops/latency_gate_protocol.md` 는 warmup 제외를 요구하지만
`scripts/benchmark_rag_segments.py` 는 그 단계를 구현하지 않았습니다. **이 산출물의
P99 와 max 를 게이트 판정선으로 쓰면 안 됩니다.** 구간별 비중이라는 핵심 결론은
워밍업 여부와 무관하므로 그 부분은 유효합니다.

**12배 큰 표본에서 성능이 유지됐습니다.** 300건 평가가 낙관적이지 않았다는 뜻입니다.

### 6.1 집단별 분해가 실체입니다

| 집단 | 건수 | MAE | 0.5%p 적중 | 피복률 |
| --- | ---: | ---: | ---: | ---: |
| `with_lwlt` | 2,233 (62.2%) | **0.6288** | **79.36%** | 89.16% |
| `missing_lwlt` | 1,356 (37.8%) | **2.0943** | **35.25%** | 92.04% |

**MAE 3.3배, 적중률 2.25배 차이입니다.** 전체 MAE 1.1825 는 성질이 전혀 다른 두 집단의
평균일 뿐이며 단일 지표로는 실체를 놓칩니다.

중앙 절대오차 0.2412 와 MAE 1.1825 의 큰 차이도 같은 이야기입니다. 절반 이상이
0.24%p 안에 들어오는데 평균은 1.18%p 이고 RMSE 는 2.629 입니다. 오차가 고르게 퍼진
것이 아니라 꼬리에 몰려 있습니다.

### 6.2 재학습 판단

유효 OOS 가 재학습 게이트 3,098건을 491건 초과했으나 **성능 저하가 확인되지 않아
즉시 재학습 근거는 나오지 않았습니다.**

**개선 경로는 재학습이 아니라 낙찰하한율 결측 보전입니다.** 낙찰하한율이 있으면
MAE 0.63 으로 잘 맞히고 없으면 2.09 로 못 맞힙니다. 모델 용량 문제가 아니라 입력
데이터 문제입니다.
