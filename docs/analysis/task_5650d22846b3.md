## 1. 개요 및 배경

하이브리드 RAG 엔진의 낙찰금액·낙찰률 수치 누락 검출기(`check_numeric_omissions`)는 컨텍스트에 포함된 수치가 최종 답변에 올바르게 포함되었는지를 결정론적으로 진단하는 관측 기능입니다.

기존 구현에서는 검색 컨텍스트(`context_text`)에 등장하는 모든 `[낙찰금액]` 및 `[낙찰률]` 값을 누락 검사 대상 후보(기대 사실, expected-fact)로 간주하였습니다. 이로 인해 여러 공고가 함께 검색되거나 참조용 통계가 포함된 경우 사용자의 질의와 무관한 공고의 수치까지 누락으로 검출되는 오탐(false positive) 문제가 있었습니다.

본 작업에서는 `RetrievalPlan`(질의 의도 및 대상 공고)과 `Provenance.items`(실제 사용된 근거 항목)를 바탕으로 검사 대상 수치를 정밀하게 선별(narrowing)하도록 개선하였습니다.

---

## 2. 세부 구현 내용

### 2.1 함수 시그니처 및 하위 호환성 유지

`check_numeric_omissions`의 인자로 `plan: RetrievalPlan | None`과 `provenance: Provenance | None`을 추가하였습니다.

```python
def check_numeric_omissions(
    context_text: str,
    answer_text: str,
    trace_id: str = "",
    plan: RetrievalPlan | None = None,
    provenance: Provenance | None = None,
) -> dict[str, Any] | None:
```

- 두 인자가 모두 `None`인 경우 기존 동작을 100% 유지하여 컨텍스트 내의 모든 수치를 검사합니다.
- `settings.NUMERIC_OMISSION_DETECTION` 기본값(`False`) 및 비활성 시 조기 반환(`None`) 동작을 보존하였습니다.

### 2.2 근거(Provenance.items) 기반 유효 Source 선별

`provenance.items`가 주어지면 실제 답변 생성 근거로 등록된 `citation_label`(예: `Source [1]`, `Source [3]`) 집합을 추출합니다.

- 수치의 출처 목록(`amount_sources`, `rate_sources`) 중 최소 하나가 유효 근거 집합에 포함되어 있는 경우에만 검사 대상 수치(`expected_amounts`, `expected_rates`)로 유지합니다.
- 근거 밖 Source의 수치는 누락 검사에서 제외하고 `filtered_amounts`, `filtered_rates` 필드로 분리합니다.
- 머리글 이전 영역 등 출처를 특정할 수 없는 `unknown` 수치는 보수적으로 기대 사실에 남겨 누락 검출을 수행합니다.

### 2.3 질의 의도(RetrievalPlan) 기반 대상 공고 선별

질의에 특정 공고 식별자(공고번호 패턴 `R26BK...`, `bid_...`, 인용구 등)나 `plan.filters` 내 특정 공고 조건이 명시된 경우:

1. `_extract_target_identifiers_from_plan()`을 통해 대상 공고 식별자/명칭을 추출합니다.
2. `_find_target_matching_sources()`를 통해 `context_text` 및 `provenance.items`에서 해당 공고에 매칭되는 Source 라벨 집합을 식별합니다.
3. 대상 공고에 귀속되지 않은 다른 공고(예: 타 공고 Source)의 수치는 제외(`filtered_...`) 처리합니다.

### 2.4 제외 수치 추적 및 로깅 확장

선별 과정에서 제외된 수치들을 버리지 않고 반환 딕셔너리와 로그에 명시적으로 기록하여 사후 추적성을 확보하였습니다:

- 반환 필드: `filtered_amounts`, `filtered_rates`, `filtered_amount_sources`, `filtered_rate_sources`
- `logger.warning` 메시지 및 `extra` 딕셔너리에 제외 내역을 포함.

### 2.5 Answer Guard 호출부 연동

`_apply_answer_guard()` 시그니처에 `provenance`를 추가하고, 내부 `check_numeric_omissions` 호출 시 `plan`과 `provenance`를 전달하도록 연동하였습니다. `get_answer_sync` 및 `stream_tokens`에서도 정규 생성된 `provenance` 객체를 `_apply_answer_guard()`로 안전하게 넘기도록 구성하였습니다.
