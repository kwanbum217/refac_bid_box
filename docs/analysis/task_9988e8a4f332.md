## 1. 개요 및 배경

기존 재학습 파이프라인(`src/tasks/scheduled_tasks.py`의 `weekly_retrain_task` 및 `src/tasks/retrain_task.py`)은 카테고리(`category_code`) 없이 호출될 수 있는 구조였습니다. 이로 인해 다음과 같은 구조적 결함이 존재했습니다.

1. **전 제도 데이터 혼합 및 물품 네임스페이스 오염**:
   - `category_code`가 `None`으로 전달되면 `src/ml/dataset.py`의 `build_training_dataset`이 카테고리 필터링을 수행하지 않아 물품(Thng), 용역(Servc), 공사(Cnstwk)의 전 제도 행을 섞어서 학습 프레임으로 가져왔습니다.
   - `src/ml/training_config.py`의 `model_name_for_category(None)`이 기본값(`DEFAULT_MODEL_NAME`인 `quantum_leap_v25_pro`)을 반환하여, 전 제도 혼합 데이터로 학습된 모델 아티팩트가 물품 모델 네임스페이스에 저장되었습니다.
   - 이로 인해 승격 후보 목록에 혼합 모델이 `latest_version`으로 노출되는 위험이 있었습니다.
2. **주간 스케줄 fan-out 부재 및 단일 실패 시 전체 중단**:
   - `weekly_retrain_task`가 단일 호출로 실행되어 카테고리별 독립 실행이 이뤄지지 않았습니다.
3. **아티팩트 저장의 비원자성 (Partial Artifact 노출 위험)**:
   - `src/ml/trainer.py`의 `train_and_register`에서 학습 시작 전에 `target_dir`을 먼저 생성하고 직접 파일들을 썼기 때문에, 학습 또는 저장 도중 예외가 발생하면 불완전한 부분 아티팩트가 남아 `latest_version`으로 잘못 조회될 수 있었습니다.

## 2. 주요 변경 내역

### 2.1 카테고리 필수 가드 및 등록 카테고리 검증 (`src/ml/training_config.py`, `src/ml/dataset.py`, `src/tasks/retrain_task.py`)
- `model_name_for_category`:
  - `category_code`가 `None`, 빈 문자열, 공백이거나 `CATEGORY_MODEL_NAMES`에 등록되지 않은 코드인 경우 명시적으로 `ValueError`를 발생시키며, 오류 메시지에 등록된 카테고리 목록(`['Cnstwk', 'Servc', 'Thng']`)을 포함하도록 수정했습니다.
- `build_training_dataset`:
  - `category_code`를 필수 인자로 검증하며, `BidResult.category == code` 필터링을 강제 적용하고 산출물 캐시 파일명을 `dataset_{code}.parquet`으로 격리했습니다.
- `run_retrain_pipeline_task`:
  - 진입 시점에 `category_code`의 유효성을 검증하여 `None` 또는 미등록 코드가 학습 파이프라인으로 진입하는 것을 차단했습니다.

### 2.2 주간 재학습 카테고리별 독립 실행 (Fan-out) 및 장애 격리 (`src/tasks/scheduled_tasks.py`)
- `weekly_retrain_task`:
  - `CATEGORY_MODEL_NAMES`의 각 카테고리(`Cnstwk`, `Servc`, `Thng`)에 대해 독립적으로 `run_retrain_pipeline_task`를 순회 호출(fan-out)합니다.
  - 카테고리별 실행을 개별 `try-except` 블록으로 감싸, 특정 카테고리 재학습이 실패하더라도 다른 카테고리의 실행이 중단되지 않고 개별 결과가 기록되도록 장애를 격리했습니다.

### 2.3 아티팩트 Staging 및 원자적 이동 (`src/ml/trainer.py`)
- `ModelTrainer.train_and_register`:
  - `src/ml/promotion.py`의 검증된 패턴과 동일한 구조를 적용했습니다.
  - 임시 staging 디렉터리(`tempfile.mkdtemp(dir=str(model_dir), prefix=".train_staging_")`)를 생성하여 모든 아티팩트(`model.bin`, `model_q*.bin`, `metadata.json`) 저장을 완료한 후, `shutil.move`를 통해 `target_dir`로 원자적으로 이동합니다.
  - 저장 과정에서 오류가 발생하면 `shutil.rmtree(staging, ignore_errors=True)`로 임시 디렉터리를 즉시 정리하여, 불완전한 버전 디렉터리가 레지스트리에 남지 않도록 보장했습니다.
