# 일반용역 적격심사 실사용 시나리오

> **작성일**: 2026-09-10
> **근거**: `bid_announcements` DB 실측
> **조회 범위**: `category='Servc'`, `raw_data.srvceDivNm='일반용역'`, `bid_ntce_dt >= '2026-05-26'`
> **목적**: 규칙 레지스트리 문자열이 아니라 실제 공고의 `sucsfbidMthdNm`, `bid_ntce_no`, `base_amount`, `sucsfbidLwltRate`로 별표별 시나리오와 차단 경로를 고정합니다.

---

## 1. 실측 방법

모든 조회는 다음 읽기 전용 진입점으로 실행했습니다. `docker`, `mysql`, 운영 API 호출은 사용하지 않았습니다.

```text
uv run python scripts/db_readonly_query.py --sql "<단일 SELECT>" --limit <행수> --format json
```

별표 조회는 각 레지스트리 식별 문자열에 대해 다음 조건을 적용했습니다.

```sql
json_unquote(json_extract(raw_data,'$.sucsfbidMthdNm')) LIKE '%<실제 식별 문자열>%'
```

문서의 공고번호와 수치는 위 조건으로 반환된 행에서 그대로 옮겼습니다. `적격심사제-` 접두사는 DB 원문에 포함된 값이며, 레지스트리 `patterns`를 테스트 입력으로 복사한 값이 아닙니다.

## 4. 브라우저 확인 절차

코디네이터가 실행 중인 서비스에서 로그인한 뒤 각 공고 상세 URL을 엽니다.

1. `http://localhost:8000/bids/<공고번호>/`를 엽니다.
2. 로그인하고 `AI 투찰 금액 분석기` 아래 `공고 기준 분석`을 선택합니다.
3. 공고 화면의 기초금액과 낙찰방법 문자열이 아래 표의 DB 실측값과 같은지 먼저 확인합니다.
4. `실적`, `경영상태`, `근로조건 이행계획`, `신인도` 입력란에 공고문 증빙 기준 점수를 입력합니다.
5. 공고문 배점표의 `가격배점한도(B)`, `평점계수(k)`, `통과점수(T)`를 해당 입력란에 입력합니다. 이 세 값은 레지스트리에서 추정하지 않습니다.
6. 후보 투찰금액을 입력하고 분석을 실행합니다.
7. 결과에서 `rule_id`, `lower_bound_rate`, 공고 하한율 불일치 경고, A값 반영 최저 투찰금액, 하단·기준·상단 시나리오를 확인합니다. 점수표를 생략한 경우 `MISSING_SCORE_TABLE`과 하한금액만 확인합니다.

## 6. 회귀 테스트

`tests/test_evaluations_realuse_scenarios.py`는 운영 DB에 접속하지 않는 격리 단위·API 테스트입니다. 별표 테스트의 입력은 레지스트리 `patterns`를 읽어 조립하지 않고, 위 DB 조회 결과의 전체 원문 문자열(`적격심사제-` 접두사 포함)을 리터럴로 고정합니다.

- 별표 1~14 실제 문자열이 기대 `rule_id`로 매칭되는지 검증합니다.
- 실제 불일치 공고의 공고 하한율을 레지스트리 기본값보다 우선하고 경고하는지 검증합니다.
- `NOT_SERVC`, `NON_PRED_PRICE`, `MANUAL_EVALUATION`, `RULE_NOT_FOUND`의 실제 공고 문자열과 `MISSING_SCORE_TABLE` 입력 결손을 검증합니다.
- `PRED_PRICE_UNAVAILABLE`은 유효 별표의 DB 실측 0건을 문서화하고, 격리 DB의 결측 경로를 검증합니다.

실행 명령:

```text
uv run pytest tests/test_evaluations_realuse_scenarios.py tests/test_evaluations_api.py tests/test_evaluation_scoring.py -q
python3 scripts/validate_agent_rules.py --quiet
```
