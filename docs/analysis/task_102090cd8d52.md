## 1. 개요 및 배경

RAG 응답 생성 파이프라인의 낙찰금액·낙찰률 수치 누락 검출기(`check_numeric_omissions`)는 컨텍스트에 존재하는 핵심 수치가 최종 답변에서 누락되었는지를 결정론적으로 진단하는 관측 기능입니다.

기존 구현에서 제기되었던 주요 결함은 다음과 같습니다:

1. **검사 시점 불일치**: `_apply_answer_guard()` 시작 지점에서 검사를 수행하여, 이후 실행되는 데이터 부재 강제 교정 및 카테고리 명칭 정규화(`_normalize_category_wording`)가 반영되지 않은 미완성 텍스트를 검사하는 문제.
2. **부분 문자열 매칭 오탐·미탐**: 단순 `cand in answer_text` 방식으로 인해 `90`이 `90.1`이나 `90.1950` 내부의 부분 문자열로 매치되어 누락이 미탐되는 문제.
3. **출처(Source) 정보 상실**: `extract_numeric_context_values()`가 컨텍스트 전체에서 정규식으로 값만 추출하여 어느 `Source [n]` 블록에서 추출된 값인지 추적하지 못하는 문제.

---

## 2. 세부 구현 내용

### 2.1 최종 후처리 완료 답변 검사 시점 일원화

`_apply_answer_guard()`의 모든 반환 분기(`query_skipped`, 데이터 부재 교정, 정상 반환)에서 최종 교정 및 정규화가 완료된 문자열(`final_answer`)을 생성한 후 직전 시점에 `check_numeric_omissions()`를 호출하도록 수정했습니다.

```python
# _apply_answer_guard() 최종 반환 직전 검사
if context_text:
    check_numeric_omissions(context_text, final_answer, trace_id=trace_id)
return final_answer
```

### 2.2 경계 인식 수치 매칭 (`_contains_bounded_number`)

정규식 Negative Lookbehind `(?<![0-9,.])` 및 Negative Lookahead `(?![0-9,.])`를 적용하여 수치 앞뒤에 숫자, 쉼표, 마침표가 연속된 경우 매치로 인정하지 않도록 경계 검사를 강화했습니다.

- 예: 후보 `90`은 `90.1%`, `90.1950%`, `900,000` 안에서 매치되지 않음.
- 예: 후보 `90.1950`은 `90.1950%`에서 정상 매치됨.

### 2.3 Source 단위 컨텍스트 분할 및 출처 라벨 부여

`context_text`를 `Source [n]` 머리글 기준으로 파티셔닝하여 각 수치값의 출처 라벨을 수집하도록 개선했습니다.

- 머리글 이전 영역에 위치한 수치는 `'unknown'`으로 처리.
- 기존 호출부 호환성을 보장하기 위해 `amounts`, `rates` 키는 기존 `list[str]` 타입을 100% 유지.
- 출처 정보는 `amount_sources`, `rate_sources` (`dict[str, list[str]]`) 별도 키로 제공.
- 동일 수치가 복수 Source에 등장하는 경우 모든 출처 라벨을 리스트에 누적 기록.

### 2.4 구조화 로그 및 반환 딕셔너리 확장

`check_numeric_omissions()` 반환 dict 및 경고 로그(`logger.warning`)에 누락 값별 출처 라벨(`missing_amount_sources`, `missing_rate_sources`)을 포함하여 어느 Source의 수치가 누락되었는지 즉각적인 관측이 가능하도록 지원합니다.

## 4. 검증 결과 요약

- **경계 매칭 검증**: `90`이 `90.1`에서 매치되지 않고 누락 검출됨을 확인.
- **최종 답변 검사 검증**: 후처리를 통해 변환된 최종 텍스트가 검출기 입력으로 전달됨을 검증.
- **출처 추적 검증**: Source 머리글 및 unknown 블록에서 수치별 출처 라벨 매핑 정상 동작 확인.
- **하위 호환성 검증**: 기존 `amounts`, `rates` 키 및 기존 테스트 스위트 전량 통과 확인.
