## 1. 배경 및 목적

`scripts/orca_read_scope_audit.py`는 워커 터미널의 출력을 분석하여 Capsule의 `allowed_read_files` 및 `search_scope.allowed_globs` 범위를 벗어난 비인가 파일 접근을 사후 탐지하는 도구입니다.

기존 구현은 `orca terminal read` 호출 시 단일 화면 버퍼(tail)에만 의존하여 다음과 같은 구조적 한계가 존재했습니다:
- 긴 출력이나 스크롤 발생 시 이전 출력이 밀려나 위반 경로를 놓칠 위험 존재.
- 모듈 독스트링에 명시된 "화면 버퍼 잘림으로 인한 위반 없음의 불완전성"으로 인해 게이트 및 워커 완료 절차에 엄밀히 편입하기 어려움.

본 작업에서는 `orca terminal read`의 커서 페이지네이션(`--cursor`, `--limit`) 기능을 활용하여 보관된 전체 스크롤백을 순차적으로 읽어들이고, 호스트 보관 한도 초과로 오래된 줄이 실제로 폐기(dropped)되었을 때만 증거 불완전(`complete: False`)을 명시하도록 개선하였습니다.

---

## 2. 주요 구현 내용

### 2.1 커서 페이지네이션 및 무한 루프 방지

[`scripts/orca_read_scope_audit.py`](../../scripts/orca_read_scope_audit.py)에 `read_terminal_scrollback` 함수를 추가하였습니다:
- 커서 0부터 시작하여 응답의 `nextCursor`가 전진하지 않거나 `returnedLineCount == 0`일 때까지 순차적으로 페이지를 호출하고 줄을 결합합니다.
- `DEFAULT_MAX_PAGES`(기본 200회) 및 `DEFAULT_PAGE_LIMIT`(기본 1000줄) 모듈 상수를 정의하여 무한 루프 위험을 차단하고 테스트 주입이 가능하도록 하였습니다.
- CLI 인자로 `--max-pages`와 `--page-limit`을 추가 지원합니다.

### 2.2 증거 완전성(Evidence Completeness) 명시

결과 딕셔너리에 `evidence` 객체를 표준화하여 추가하였습니다:
- `oldest_cursor`: 첫 페이지 응답의 `oldestCursor` (0보다 크면 이전 줄 유실).
- `latest_cursor`: 마지막 페이지 응답의 `latestCursor`.
- `lines_read`: 실제로 수집하여 검사한 총 줄 수.
- `complete`: `oldest_cursor == 0`일 때만 `True`. 호스트에서 버려진 줄이 있으면 `False`.
- `--text-file` 입력 경로는 파일 내용 전체를 보존하므로 `complete: True`로 설정됩니다.

### 2.3 fail-closed 오류 처리 및 종료 코드 규약 유지

- 페이지 수집 도중 단 한 번이라도 오류(프로세스 비정상 종료, JSON 파싱 실패 등)가 발생하면 부분 결과로 판정하지 않고 즉시 종료 코드 2(도구 오류)로 실패합니다 (Fail-closed).
- 증거 불완전(`complete: False`) 상태는 판정의 신뢰도 지표이며, 그 자체로 종료 코드 규약(0 clean, 1 violations, 2 error)을 변경하지 않습니다.
- 사람이 읽는 표준 출력(`--json` 미지정 시)에 증거 완전성 여부와 유실된 줄 정보를 단일 행으로 명확히 표시합니다:
  - 완전 시: `[증거] 완전 (lines_read=...)`
  - 불완전 시: `[증거] 불완전 (oldest_cursor=... 이전 줄 유실, lines_read=...)`

### 2.4 모듈 독스트링 한계 서술 현실화

화면 조각 잘림이 아닌 호스트 보관 한도 초과 시의 유실과 `evidence.complete` 플래그를 통한 불완전성 명시 체계를 독스트링에 반영하였습니다.
