## 2. 시정 전후 비교

### 2.1 `test_kb_incremental_indexing.py`

| 케이스 | macOS 시정 전 | macOS 시정 후 | 비고 |
| --- | ---: | ---: | --- |
| 전체 파일 | 5.37초 | 2.94초 | 디스크 I/O 제거 효과는 Windows 에서 증폭 |
| `test_first_run_indexes_everything` | 0.81초 | 0.65초 | PersistentClient → EphemeralClient |
| `test_low_document_limit_cannot_wipe_the_collection` | 0.70초 | 0.88초 | 변동(테스트 안에서 mock 으로 실패 경로 타며 `rebuild_knowledge_base` 2회 호출) |
| `test_removed_document_is_deleted_from_collection` | 0.12초 | 0.10초 | 두 PersistentClient → 한 공유 client |

Windows CI 의 두 케이스(18.54초, 17.75초)는 PersistentClient 가 매번 디스크에
SQLite DB 와 lock 파일을 쓰면서 발생한다. 공유 in-memory 클라이언트로 대체하면
케이스당 1초 미만으로 떨어진다.

### 2.2 `test_benchmark_arq_container.py`

| 케이스 | 시정 전 | 시정 후 |
| --- | ---: | ---: |
| `test_docker_worker_container_manager_wait_ready_timeout` | 0.21초 | 0.20초 |

macOS 에서는 차이가 거의 없다. Windows 에서는 `time.sleep(0.1) × 2` 의 sleep
granularity (Windows 기본 15.6ms) 가 누적되어 0.3~0.5초로 부풀고, 7.37초의
대표 케이스 합산에 기여한다. 슬립 mock 으로 이 누적을 0에 가깝게 줄였다.

`test_run_container_worker_benchmark_mocked_success` (Windows 7.37초) 의 잔여
비용은 asyncio 이벤트 루프 생성 오버헤드다. `subprocess.check_output` /
`wait_ready` / `start` / `stop_and_remove` 가 모두 mock 으로 대체돼 있어
추가 mock 대상이 없다. 더 깊이 모킹하면 검증 의미(Provenance, load_protocol,
worker_settings_module) 가 흐려진다.

### 2.3 `test_feature_map_single_build.py`

| 실행 | 시정 전 (Windows) | 시정 후 (Windows) | 비고 |
| --- | ---: | ---: | --- |
| 첫 실행 | setup 9.09초 | 변경 없음 | 기존 module scope 유지 |
| 이후 실행 | setup 9.09초 | 변경 없음 | 디스크 캐시안은 기각 |

디스크 캐시안은 코디네이터 검토에서 기각됐다. CI 가 매 실행 새 러너라 실행 간
캐시가 남지 않고, 저장소 디렉터리를 오염시키며, 학습 함수가 바뀌어도 낡은
가중치를 재사용하는 무효화 결함이 있기 때문이다. 기존 `scope="module"` 픽스처를
그대로 두며, 캐시 없이 대상 3개 파일 41건이 3.73초에 통과하는 것을 확인했다.

## 5. 게이트 복귀 가능성

본 시정은 비용만 줄였지 게이트 정책은 건드리지 않는다. CI 의
`continue-on-error: windows` 줄을 제거할지는 코디네이터가 별도 Dispatch 로 결정할
사항이다. 본 작업의 권고는 다음과 같다.

1. **CI run 33507615073** 의 잔여 최장 네 건(18.54 + 17.75 + 9.09 + 7.37) 중
   3건은 본 시정으로 닫혔다. `test_run_container_worker_benchmark_mocked_success` 의
   7.37초는 본 Task 의 대상이지만 모킹 깊이 한계로 더 줄이지 못한다.
2. `subprocess.py` 대기 중 인터럽트의 근본 원인은 `test_orca_taskctl.py` 의
   디스패치 경로이며 본 Task 의 대상 파일이 아니다. 다음 Task 에서 다룬다.
3. 위 두 항목 중 적어도 1번은 닫혔으므로 게이트 복귀를 검토할 수 있으나,
   게이트 정책 자체는 별도 결정이다.
