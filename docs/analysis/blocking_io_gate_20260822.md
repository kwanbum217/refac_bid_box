# 블로킹 I/O 후속 레이턴시 게이트 측정

> **측정일**: 2026-08-22
> **측정 커밋**: `4460269`
> **규약**: [`latency_gate_protocol.md`](../ops/latency_gate_protocol.md)
> **판정**: 예측 c10 및 SSE c1은 통과, 예측 c1·c2·c4 회귀 감시는 미달하여 G3 전체 승격은 보류

---

## 1. 측정 조건

| 항목 | 값 |
| --- | --- |
| 서버 | Docker Compose `app`, Uvicorn 단일 워커 |
| 예측 GC | `PREDICTION_GC_MODE=freeze` |
| 구간 계측 | `LATENCY_SEGMENT_LOGGING=false` |
| 예측 워밍업 | 각 동시성과 같은 수, 측정 표본에서 제외 |
| 예측 반복 | 동시성별 600회, 3회, 회차 간 30초 이상 |
| SSE 워밍업·반복 | 1회 제외, 60회, 3회 |
| 데이터 보존 사전 확인 | `make migrate-verify` 통과 |

정식 게이트에서는 계측을 비활성화했습니다. 계측을 켠 `predict-price` 구간 로그는 병목 진단용이며 게이트 판정에 사용하지 않았습니다.

## 2. 예측 API 결과

대표값은 회차별 최악값입니다. 원시 응답은 [`data/benchmarks/latency_gate_20260822/`](../../data/benchmarks/latency_gate_20260822/)에 보존했습니다.

| 동시성 | P50 (ms) | P95 (ms) | P99 (ms) | Max (ms) | 오류 | 판정 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| c1 | 17.93 | 29.98 | 40.67 | 47.75 | 0 / 1,800 | 회귀 한도 17.02ms 초과 |
| c2 | 17.83 | 25.01 | 30.84 | 40.71 | 0 / 1,800 | 회귀 한도 21.77ms 초과 |
| c4 | 30.98 | 41.61 | 45.32 | 58.03 | 0 / 1,800 | 회귀 한도 36.81ms 초과 |
| c10 | 40.82 | **54.93** | 62.76 | 69.56 | 0 / 1,800 | 통과: P95 100ms 이하 |

c10의 100ms 초과는 0 / 1,800건(0.000%)이며, Wilson 95% 상한은 0.213%입니다. 따라서 규약 4.1의 관측 초과율 0.5% 이하 및 Wilson 상한 1.0% 이하를 모두 만족합니다.

예측 측정 중 14코어 기준 1분 load average의 코어당 사용률은 c10에서 중앙 16.57%, 최대 20.57%였고, c1~c4에서도 중앙 16.36~28.64%, 최대 32.71% 이하였습니다. 규약의 중앙 30%, 최대 50% 기준을 만족합니다.

## 4. 병목 진단 보조 결과

`LATENCY_SEGMENT_LOGGING=true`인 별도 진단에서 `POST /api/v1/predictions/predict-price`의 모델 호출은 약 195~363ms, 특징 생성은 약 33~90ms, DB 조회는 약 4.5~22ms로 관측되었습니다. 이는 계측 오버헤드를 포함하므로 게이트 수치와 비교하거나 판정 근거로 사용하지 않습니다. 원본은 [`predict_price_diagnostic.log`](../../data/benchmarks/blocking_io_segments_20260822/predict_price_diagnostic.log)에 보존했습니다.

## 5. 결론과 후속 조치

이번 변경으로 기본 구간 계측을 비활성화하여 정식 측정 조건을 충족했고, 예측 c10과 SSE c1 절대 목표는 통과했습니다. 그러나 c1·c2·c4의 최악 P95가 기존 승격 기준선의 +10%를 넘었으므로 규약 4장에 따라 G3를 전체 통과 또는 새 기준선 승격으로 선언할 수 없습니다.

다음 작업은 이 세 회귀 감시 지점의 재현 원인을 분리하는 것입니다. 특히 이전 기준선과의 실행 이미지·호스트 부하·요청 경로 차이를 먼저 대조한 뒤, 재현되면 `predict-price`의 모델 호출과 특징 생성 구간을 별도 최적화 대상으로 다룹니다.
