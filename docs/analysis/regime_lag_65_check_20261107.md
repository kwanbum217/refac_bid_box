## 1. 요약

### 1.1 결론

선행 감사 4.5절의 65건을 전부 재수집해 공고 첨부와 고시 원문에 대조했습니다. **65건 중 7건만 고시 부칙의 경과조치로 설명되고, 35건은 공고가 조달청 고시가 아니라 수요기관 자체 기준(공기업 적격심사 세부기준, 지방자치단체 예규)의 값을 쓴 경우입니다.** 나머지는 표기 관행 3건, 미확인 20건입니다.

핵심 판독 세 가지입니다.

1. **"공고가 개정 전 값을 썼다"는 프레임이 절반 이상에서 틀렸습니다.** 65건 가운데 35건은 수요기관이 조달청 고시가 아닌 자기 기준을 적용한 결과입니다. 한국지역난방공사 8건, 한국농어촌공사 1건, 한국공항공사 1건은 「공기업·준정부기관 계약사무규칙」에 따른 자체 적격심사 세부기준을 쓰고 있고, 그 기준값이 87.995입니다. 대구광역시 예규를 따르는 기관 9건은 대구광역시 예규 별표의 87.745를 씁니다. 값이 같다고 해서 조달청 고시의 개정 전 값과 같은 것이 아닙니다.
2. **공고 준비일 때문이라는 근거는 없습니다.** 65건 전부 `raw_data.rgstDt`(등록일)가 `bid_ntce_dt`(공고일)와 같은 날짜입니다. 첨부 PDF의 CreationDate도 확인한 40여 건에서 공고문은 공고일 당일이었고, 과업내용서 등 일부만 그 이전이었습니다. `raw_data`에 구매요청일·계약요청일 필드는 없습니다.
3. **부칙의 기준일은 "최초 입찰 공고"입니다.** 그래서 재공고·취소공고 7건은 시행일 이후에 공고됐더라도 종전 값이 정당합니다. 다만 현행 코드는 공고 차수별 공고일로 규칙을 고르므로, 이 7건에서 현행 규칙 ID를 붙입니다([`src/app/services/evaluation_rules.py:2151-2159`](/src/app/services/evaluation_rules.py:2151)). 공고값 우선 원칙 때문에 계산 결과는 같고, 규칙 ID 귀속만 부칙과 어긋납니다.

### 2.3 적용례가 코드에서 어떻게 쓰이는가

현행 코드는 공고일(각 공고 차수의 `bid_ntce_dt`)로 규칙 효력 구간을 판정합니다.

```text
_rule_applies_to_announcement(rule, announced)
  effective_date <= announced < superseded_date
```

([`src/app/services/evaluation_rules.py:2151-2159`](/src/app/services/evaluation_rules.py:2151), 같은 기준이 [`src/app/services/evaluation_rules.py:3754`](/src/app/services/evaluation_rules.py:3754) 에서 한 번 더 차단 판정에 쓰입니다)

부칙의 기준일이 "최초 입찰 공고"인데 코드는 "그 차수의 공고일"을 씁니다. 재공고에서 최초 공고일이 시행일 이전이면 두 기준이 갈리고, 이번 (가) 7건이 그 지점입니다. 최초 공고일은 `bid_announcements` 에서 같은 공고명·수요기관의 가장 이른 `bid_ntce_dt` 로 확인했습니다(3절 근거 열의 "최초 공고" 번호).

## 4. 규칙 기준일을 바꿀 경우의 영향 추정 (코드 미수정)

이 절은 계산 경로를 읽어 추정한 것이며, 어떤 값도 바꾸지 않았습니다. 이번 창의 65건은 모두 `raw_data.sucsfbidLwltRate` 가 있어 `rate_source=ANNOUNCEMENT` 입니다. 따라서 아래 어느 선택을 해도 **투찰 가능 금액·점수 결과는 바뀌지 않습니다.** 달라지는 것은 규칙 ID 귀속, 기본값, 경고 문구입니다.

### 4.1 라벨별 영향

| 라벨 | 건수 | 기준을 바꾸면 달라지는 것 | 계산 결과 |
| --- | ---: | --- | --- |
| (가) | 7 | 규칙 선택 기준일을 "최초 입찰공고일"로 바꾸면 종전 규칙으로 귀속되고 불일치 7건이 사라집니다 | 변화 없음 |
| (나) | 35 | 기관·지방 예규 값을 규칙으로 등록하거나 기관 규칙 매칭을 넓히면 불일치가 사라집니다. 등록하지 않으면 "공고값이 별표 기본값과 다르다"는 경고가 계속 남습니다 | 변화 없음 |
| (다) | 3 | 규칙값을 87.745로 바꾸면 사라지지만, 조달청 고시 기준값은 87.995이므로 고시 정합성이 깨집니다 | 변화 없음 |

### 4.2 최초 입찰공고일 기준으로 바꿀 때

- 현재 코드는 공고 차수의 `bid_ntce_dt` 로 `_rule_applies_to_announcement` 를 판정합니다([`src/app/services/evaluation_rules.py:2151-2159`](/src/app/services/evaluation_rules.py:2151)). 재공고 7건에서 현행 규칙이 선택되고, 규칙 기본값 89.995와 공고값 87.995가 어긋나 경고가 발생합니다.
- 최초 공고일 기준으로 바꾸면 이 7건은 종전 규칙(87.995)으로 귀속되어 경고가 사라집니다.
- 부작용: 같은 공고번호 안에서도 차수별로 규칙이 달라질 수 있고, 최초 공고 행이 수집 창 밖이면 최초 공고일을 알 수 없습니다. `bid_announcements` 에는 "최초 공고 여부" 필드가 없어 공고명·수요기관·추정가격으로 추정해야 합니다(이번 확인도 같은 방식).

### 4.3 기관 규칙 매칭을 넓힐 때

- 한국지역난방공사는 시설분야·여객 규칙이 이미 코드에 있고 값도 87.995입니다([`src/app/services/evaluation_rules_institution.py:1421-1450`](/src/app/services/evaluation_rules_institution.py:1421), [`src/app/services/evaluation_rules_institution.py:1577-1608`](/src/app/services/evaluation_rules_institution.py:1577)). 그런데 이번 8건은 조달청 기본 규칙으로 판정됐습니다.
- 이유는 기관 축 판정입니다. 규칙의 `institution_code`(B550373, 본사)와 공고의 `dminsttCd`(지사, 예: D325102·D325117)가 다르고, 하위 조직 접두·정확 코드 목록에 그 지사가 없으면 기관 규칙이 탈락합니다([`src/app/services/evaluation_rules.py:3013-3032`](/src/app/services/evaluation_rules.py:3013)).
- 한국농어촌공사 2026-06-16 건은 기관 규칙 시행일이 2026-06-24라 그 시점에는 적용 규칙이 없었습니다. 한국공항공사는 지사 코드 대역이 본사 코드와 다릅니다(코드 주석이 같은 사실을 적고 있습니다).
- 즉 (나) 중 공기업 10건은 값을 새로 등록할 필요 없이 **매칭만 넓히면** 조달청 기본값과의 불일치가 사라집니다. 다만 이 변경은 규칙 ID 귀속을 바꾸므로 회귀 확인이 필요합니다.

### 4.4 지방자치단체 예규 값을 규칙으로 등록할 때

- (나) 중 지방계약 예규·행정안전부 기준을 따르는 24건은 조달청 고시가 아니라 지방계약 예규를 따릅니다. 조달청 규칙에 이 값을 넣으면 조달청 기준을 쓰는 다른 공고까지 오염됩니다.
- 선택지는 ① 기관·지역 규칙으로 별도 등록, ② 공고값 우선을 유지하고 불일치를 진단 지표로만 집계, ③ 아무것도 하지 않고 경고만 남기는 것입니다.
- 지역 규칙을 새로 등록할 때는 같은 시·도의 다른 세부유형 규칙과 충돌하지 않는지 확인해야 합니다. 이번 87.745는 대구·광주·서울·부산·전북·경북에서 모두 같은 값으로 인쇄되어, 지역별 예규 값이 우연히 같을 뿐 규칙 구조가 같다는 뜻은 아닙니다.

### 4.5 경고 문구

- 이번 65건 전부에 대해 현재 코드는 "공고 하한율(공고값)이 별표 기본값(규칙값)과 일치하지 않아 공고 하한율을 우선 적용합니다." 형식의 경고를 남깁니다. 표본 5건(`R26BK01565307`·`R26BK01585377`·`R26BK01589006`·`R26BK01681756`·`R26BK01761000`)에서 87.995 대 89.995 문구를 확인했습니다.
- 최초 공고일 기준으로 바꾸면 (가) 7건의 경고가 사라지고, 기관 매칭을 넓히면 공기업 10건의 경고가 사라집니다. 나머지 48건은 그대로 남습니다.

### 6.1 재현

공고 첨부는 커밋하지 않았습니다. 재현할 때는 다음 순서를 따릅니다.

1. 65건 목록은 선행 감사 부록 A 스크립트를 `--today 2026-11-06 --months 12 --category Servc` 로 실행해 얻습니다. 이번 재현에서는 대표 공고 192,749건 중 65건이었습니다. 선행 감사의 192,191건과 차이는 감사 이후 수집된 공고 때문이고, 규칙별 65건 구성(23·7·35)은 같았습니다.
2. 공고 첨부는 `bid_announcements.raw_data` 의 `stdNtceDocUrl`, `ntceSpecDocUrl1~5` 로 내려받습니다. 변경·취소공고 행에 첨부가 없으면 같은 공고번호의 `bid_ntce_ord=000` 행 첨부를 씁니다. 1초 간격으로 내려받았습니다.
3. DB 조회는 `uv run python scripts/db_readonly_query.py --sql "<질의>"` 만 사용했습니다. `docker exec`, `mysql` 직접 호출은 없습니다. `raw_data LIKE` 스캔도 쓰지 않았습니다.
4. 첨부 텍스트는 PDF `pdftotext -layout`, HWPX `zipfile`+`section0.xml`, HWP 5.x UTF-16LE 런 스캔으로 뽑았습니다. 새 라이브러리는 설치하지 않았습니다.
5. 원자료 캐시는 `.cache/regime_lag_65/`(gitignore)에 있고, `rows.json`(65행), `attach2/`(첨부 267개), `text2/`(추출 텍스트 222개)입니다.
