## 1. 요약 (결론)

레짐 이후 기준 분포로 바꾼 뒤에도 세 분류 모두 `DRIFT_DETECTED`인 원인은 **단일하지 않으며, 세 가지 성분이 섞여 있다.**

1. **표본 크기 노이즈(과민 반응)**: 용역(n=332)에서는 노이즈만으로도 `DRIFT_DETECTED`가 **100% 보장**된다. 고카디널리티 범주형 특징(`clsfc_nm`, `sucsfbid_mthd_nm`, `mid_clsfc_nm`)이 n=178~332에서 순수 표본 변동만으로 임계값(0.2)을 넘기 때문이다. 공사(n=478)와 물품(n=800)에서는 노이즈 기여가 거의 없다(발화 빈도 0.01 / 0.00).
2. **구조적 오탐(감시 설계 문제)**: `month_sin/cos`, `weekday_sin/cos` 순환 달력 특징은 7일 평가 윈도우의 달력 구성이 기준 분포(약 4개월 혼합)와 필연적으로 다르기 때문에 PSI 3~11이 **항상** 나온다. 같은 기준 분포에서 뽑은 표본의 null p95는 0.06 이하이므로 이것은 표본 노이즈가 아니라 윈도우 설계가 낳는 상수 오탐이다.
3. **실제 변화 후보**: `is_over_notice_amt`는 세 분류 모두에서 기준 분포 대비 비율이 크게 이동했다(용역 12.3% -> 추정 35% 내외, 물품 20.4% -> 추정 55~60%). 기관 이력 특징(`inst_hist_rate`, `inst_sample_cnt`, `inst_ewm_rate`)도 null 노이즈를 크게 초과하는 실제 이동이다.

즉 "표본 크기가 작아서 생긴 과민 반응인가"에 대한 답은 **분류별로 다르다**: 용역은 표본 크기 문제가 지배적이고, 공사·물품은 7일 윈도우 구조(달력 집중, 기간 내 시간 추세)와 일부 실제 변화가 지배적이다. 임계값 자체(0.2)를 전면 완화할 근거는 약하다. 수치형 저카디널리티 특징의 null p95는 n=400에서 0.02~0.05 수준으로 0.2가 과민하지 않기 때문이다. 문제는 임계값이 아니라 **특징 종류(순환·고카디널리티)와 윈도우 구성**이다.

## 2. PSI 계산과 판정 규칙 (코드 정본)

### 2.1 수치형 PSI

운영 판정 경로는 `monitoring.py`의 인라인 계산을 사용하며 `psi.py`의 `calculate_psi`는 호출되지 않는다(양쪽 공식은 동일하다).

- 기준 분포는 baseline 생성 시 고정된 10개 동폭 구간(bin_edges)의 도수(`counts`)로 저장된다 (`monitoring.py:113`, `save_baseline_distributions`).
- 판정 시 최근 값을 기준 분포의 `bin_edges`에 넣고(`monitoring.py:306`), 경계 밖 값은 첫/마지막 구간에 포함한다(`monitoring.py:307-308`).
- PSI 공식: `sum((act_pct - exp_pct) * log(act_pct / exp_pct))` (`monitoring.py:314`), 0 분모 방지 1e-4 보정(`monitoring.py:311-312`).
- 임계값: baseline `psi_config.threshold`, 집단 분리 시 with_lwlt 0.2 / missing_lwlt 0.25 (`monitoring.py:394-426`).

### 2.2 범주형 PSI

- 기준/최근 범주의 합집합에 대해 비율을 계산하고 1e-4 보정 후 동일 공식 (`psi.py:99-113`).
- 범주 수(k)에 대한 최소 표본 조정은 없다. `min_samples=100`이 전 특징에 동일 적용된다 (`psi.py:14`, `psi.py:48`).

### 2.3 판정 규칙

- 특징별 `drift_detected = psi >= threshold` (`monitoring.py:315`, `psi.py:138`).
- 집단(전체 또는 with_lwlt/missing_lwlt)별로 **1개 특징이라도** 임계값을 넘으면 그 집단이 `DRIFT_DETECTED` (`monitoring.py:349`, `monitoring.py:354-356`, `monitoring.py:501-509`).
- 두 집단 중 하나라도 드리프트면 전체가 `DRIFT_DETECTED` (`monitoring.py:501-509`).
- 집단별 최소 표본 100건 미만이면 그 집단은 `INSUFFICIENT_DATA`이지만 다른 집단의 드리프트로 전체 판정은 유지된다 (`monitoring.py:441-452`, `monitoring.py:510`).
- `drift_feature_count`는 두 집단의 합이므로 같은 특징이 두 번 셀 수 있다 (`monitoring.py:491-499`, `monitoring.py:528-530`). 실제로 용역 31 = with_lwlt 16 + missing_lwlt 15이고 13개가 양쪽에 겹쳐 **고유 특징은 18개**다. 물품 22 = 15 + 7이고 7개가 겹쳐 **고유 특징은 15개**다.
- 평가 윈도우: `[now-7일, now)` 반열림, `BidResult.rl_openg_dt` 기준 (`scheduled_tasks.py:757-759`, `docs/ops/psi_drift_monitoring.md:23-30`).
- 알림: `DRIFT_DETECTED`면 `notify_drift_detected` 발신 (`scheduled_tasks.py:820-830`). 자동 재학습은 없다.

## 3. 실험: 같은 기준 분포에서 무작위 표본을 뽑았을 때의 가짜 드리프트

### 3.1 방법

운영 코드와 동일한 절차로 null(귀무) 분포를 Monte Carlo로 추정했다.

- 각 모델의 baseline `feature_distributions_v1.json`에서 특징별 기준 확률 벡터를 만든다. 수치형은 히스토그램 도수 비율, 범주형은 범주 도수 비율.
- n건을 기준 분포에서 iid로 뽑는 행위를 다항(multinomial) 표본으로 재현한다. 이는 "기준 분포와 동일한 분포에서 뽑은 최근 표본"의 PSI를 직접 계산하는 것과 동치다(구간화된 도수만 다루므로).
- PSI는 `monitoring.py:301-314`(수치형), `psi.py:99-113`(범주형)과 동일한 공식과 1e-4 보정을 사용한다.
- 임계값은 baseline `psi_config` 그대로(with_lwlt 0.2, missing_lwlt 0.25), 집단별 최소 표본 100건, 집단 배분은 실제 판정의 집단 비율(용역 178/154, 공사 400/78, 물품 452/348)을 유지한다. 100건 미만 집단은 운영과 같이 `INSUFFICIENT_DATA`로 제외한다.
- 재현성을 위해 시드 20260926, 500회 시행(특징별 상세표는 2,000회)을 썼다.
- 한계: 이 null은 **최근 윈도우의 표본 노이즈**만 측정한다. 실제 7일 윈도우는 iid 표본이 아니라(달력 집중, 시간 추세) 그 차이가 아래 4장의 "구조적 성분"으로 분리된다.

### 4.3 두 개의 특기 사실

1. **`is_post_regime_shift`의 기준 분포에 0이 약 7% 남아 있다.** 용역 baseline은 0=1,539건/1=20,766건(평균 0.931), 공사 0=2,342/1=31,285(0.930), 물품 0=1,197/1=16,872(0.934)다. 최근 7일 윈도우가 전부 1이면 PSI는 `(1-0.93)ln(1/0.93) + (0.0001-0.07)ln(0.0001/0.07)` 약 0.46이 되는데, 실제 PSI(0.29~0.57)와 일치한다. 즉 이 특징의 드리프트는 "레짐 이후" 기준 분포 안에 레짐 플래그가 0인 행(공고일 기준이 레짐 이전인 행 추정)이 섞여 있어 나오는 **기준 분포 구성 문제**이지 최근 데이터의 변화가 아니다. baseline 구간 시작일과 `REGIME_SHIFT_DATE`(2026-05-26, `src/ml/features.py`)의 적용 컬럼(개찰일 vs 공고일)이 어긋나 있을 가능성이 있다.
2. **`is_over_notice_amt`는 세 분류에서 동시에 크게 이동했다.** 기준 비율은 용역 0.123, 공사 0.215, 물품 0.204인데, 실제 PSI를 2분류 PSI 역산하면 최근 비율은 용역 약 0.35, 공사 약 0.25 수준, 물품 약 0.55~0.60 수준이다. 세 분류가 같은 방향으로 움직였다는 것은 시장 변화이거나, 최근 윈도우의 `notice_amt`(추정가격) 결측·파이프라인 변화 같은 공통 원인이 있다는 뜻이다. **추가 확인 권고**(원인 코드 변경 없이 최근 윈도우 해당 컬럼 결측률 대조).

판정 `DRIFT_DETECTED`를 구성하는 성분을 분류별로 정리하면:

| 성분 | 용역(31) | 공사(15) | 물품(22) |
| --- | --- | --- | --- |
| 순수 표본 노이즈(고카디널리티 범주형) | 지배적(clsfc_nm 등 3~5개, 발화 보장) | 거의 0 | 0 |
| 구조적 오탐(달력 순환 특징, 7일 윈도우) | 8개(4특징 x 2집단) | 4개 | 11개(4+3 x 2집단 계산) |
| 구조적(기준 분포 내 레짐 잔혤포함) | is_post_regime_shift 2 | 2 | 2 |
| 실제 이동(기간 내 추세: 기관 이력군) | inst_* 6 | inst_* 3 | inst_* 5 |
| 실제 이동(기타) | log_price, notice_duration, is_over_notice_amt 등 | cntrct/sucsfbid_mthd, is_over_notice_amt 등 | log_price, is_over_notice_amt 0.71 등 |

고유 특징 수 기준으로 보면 용역 18개 중 노이즈+구조적이 약 10개, 실제 이동이 약 8개다. 공사 15개 중 구조적 6개, 실제 이동 9개. 물품 15개 중 구조적 7개, 실제 이동 8개.

질문에 대한 직접 답변:

- **"최근 7일 표본 크기와 PSI 임계값에서 오는 과민 반응인가?"** 용역(332건)에 대해서는 그렇다. clsfc_nm(k=162~180) 하나만으로도 n=800까지 100% 발화하므로 용역의 DRIFT_DETECTED는 표본 크기·카디널리티 문제가 지배적이다. 공사(478)·물품(800)에 대해서는 아니다. 노이즈 기대치가 0에 수렴한다.
- **"실제 분포 변화인가?"** 부분적으로 그렇다. 기관 이력 특징군(inst_hist_rate, inst_sample_cnt, inst_ewm_rate)과 is_over_notice_amt, log_price 등은 null 노이즈를 10~100배 초과하므로 실제 이동이다. 단, 기관 이력 특징은 "최근 7일(기준 구간 말미) vs 4개월 혼합" 비교 구조가 낳는 기간 내 추세 성분이 포함되어 있어 재학습 트리거로 읽어야 할지는 별도 판단이 필요하다. 달력 순환 특징과 is_post_regime_shift의 드리프트는 실제 변화가 아니라 감시 설계와 기준 분포 구성이 낳는 상수 오탐이다.
- **"판정이 계속 참이면 경보로서 의미를 잃는다"** 는 우려는 타당하다. 현재 판정은 (a) 매일 같은 구조적 특징 4~8개를 다시 보고하고, (b) 용역은 표본 노이즈만으로 발화하므로, 실제 변화 신호(is_over_notice_amt 3배 이동 등)를 파묻는다.
