# 재무제표 PDF 자동 입력(지시서 B안) 제품·기술 설계 보고서

> **작성일**: 2026-10-12
> **기준 커밋**: `47e97dfb` (브랜치 `kwanbum217/r3-financial-pdf-design`)
> **작성 역할**: Orca Worker (설계 Task). 코드 변경 없음.
> **목적**: 재무제표 PDF 를 올려 적격심사 계산에 필요한 재무 값을 미리 채우는 기능의 범위 선택지를 정리하고, 사용자가 결정할 질문을 남긴다.
> **표기 원칙**: 사실(코드·원문 인용)과 추정을 구분한다. 확정하지 못한 것은 추정으로 적는다.

## 1. 결론 요약

1. **현재 서비스가 계산하는 적격심사에서는 재무 값이 쓰이지 않는다.** 이 저장소의 적격심사 엔진은 조달청 일반용역 14종을 다루고, 그 경영상태 항목은 신용평가등급만 입력으로 받는다. 부채비율·유동비율·매출액·자기자본을 입력으로 받는 경로는 코드에 없다(2.1).
2. **원문도 이를 뒷받침한다.** 조달청 일반용역 적격심사 세부기준 제7조③은 경영상태를 별표 10(신용평가등급)으로 평가하도록 정하고, 등급이 확인되지 않으면 재무비율이 아니라 최저등급으로 평가한다(2.2). 따라서 "신용평가등급이 없는 업체의 경영상태 평가"라는 대체 경로에 재무비율이 들어가는 것이 아니다.
3. **재무 값(부채비율·유동비율)이 실제로 필요해지는 곳은 공사다.** 조달청 시설공사 적격심사 별표 6, 지방자치단체 입찰시 낙찰자 결정기준의 공사 재무비율 평가방법이 대표적이다(2.3). 이 두 계산 경로는 현재 코드에 없다.
4. **그래서 B안은 "제품 결정" 문제다.** 지금 범위에서는 채울 입력칸 자체가 없으므로, (A) 범위 제외, (B) 수동 입력 보조만, (C) 텍스트 PDF 표 추출, (D) C+OCR, (E) 공사 적격심사 확장과 함께 도입 중에서 사용자가 범위를 골라야 한다(4).
5. **확장을 택하더라도 선행 조건이 있다.** 재무제표는 표 구조가 복잡하고 원본 미저장·개인정보 고지 원칙을 건드리므로, 정확도 실측(합성 픽스처만, 실물 커밋 금지)과 DB 변경 범위(추가만) 결정이 먼저다(5).

## 2. 재무 값의 사용처

### 2.1 코드 근거: 재무 값 사용처 없음

- 경영상태 항목은 배점표 선언에서 **신용평가등급**으로만 정의된다. 항목 키는 `QUANT_ITEM_MANAGEMENT`, 원문 항목명은 `"경영상태(신용평가등급)"`, 입력 방식은 `QUANT_LIMIT_KIND_CREDIT_GRADE` 다.
  - 근거: `src/app/services/evaluation_rules.py:3941-3952` (항목 키 정의), `src/app/services/evaluation_rules.py:4108-4135` (별표 1~5의2·7 의 `_performance_section`), `src/app/services/evaluation_rules.py:4446` (별표 8), `src/app/services/evaluation_rules.py:4486` (별표 9).
- 별표 10 은 등급 → 점수표이며, 코드도 그렇게 선언한다.
  - 근거: `src/app/services/evaluation_rules.py:3911-3914` 주석 "별표 10 경영상태(신용평가등급) 점수표: 187-198행".
- 원자료 저장 계층에 재무 값 컬럼이 없다.
  - 근거: `src/app/models/company_profiles.py:119-135` — `AccountQualificationFact` 는 `credit_grade`, `credit_evaluated_on`, `reputation_items`, `non_price_quant_score` 만 갖는다.
- 입출력 스키마에도 재무 값 필드가 없다.
  - 근거: `src/app/schemas/evaluations.py:66-102` (`QualificationInput`), `src/app/schemas/evaluations.py:630-670` (`RecommendationOverrides`).
- 모듈 전체 검색(`부채비율|유동비율|매출액|자기자본|재무|financial|debt_ratio|current_ratio`)에서 `src/app` 안에 재무비율을 참조하는 코드가 나오지 않는다. 유일한 "재무" 유사 표현은 `경영상태`(신용평가등급)다.

**판정**: 조달청 일반용역 적격심사 계산 경로에 재무 값 입력은 없다.

### 2.2 원문 근거: 용역 경영상태는 신용평가등급

- 조달청 일반용역 적격심사 세부기준(조달청공고 제2026-390호, 시행 2026-07-27) **제7조③**: "경영상태 평가는 [별표 1]부터 [별표 5의2], [별표 7], [별표 8]은 [별표 10]을 적용하고, [별표 9]는 [별표 9]에서 정한 경영상태 평가기준을 적용한다."
  - 출처: https://law.go.kr/admRulLsInfoP.do?admRulId=33121 (본문), 동일 문서 PDF 미러 https://bidnara.com/library/21/files/29/download
- **별표 10 "신용평가등급에 의한 경영상태 평가기준"**: 회사채·기업어음·기업신용평가등급을 배점한도별(25점/10점/5점) 평점으로 환산한다. 주2는 "적격심사대상자로부터 제출받은 '신용평가등급 확인서'로도 확인되지 않는 경우에는 **최저등급으로 평가**"한다고 정한다. 주6은 "추정가격이 고시금액 미만인 입찰에 참여하는 소기업·소상공인, 창업기업에 대해서는 ... **만점**을 부여한다. 이 경우 신용평가를 받지 않아 신용평가등급이 확인되지 않는 경우에도 ... 만점을 부여한다"고 정한다.
  - 출처: https://law.go.kr/flDownload.do?flSeq=132885927 (일반용역 적격심사기준에 관한 훈령 [별표 5])
  - **핵심**: 등급이 없는 업체의 대체 평가는 재무비율이 아니라 최저등급(또는 소기업·창업기업 만점)이다. 즉 "등급 없음 → 재무비율" 경로는 이 기준에 없다.
- 인접 기준 교차 확인: 조달청 중소기업자간 경쟁물품에 대한 계약이행능력심사 세부기준 제6조②3 은 "경영상태평가는 '신용평가등급에 따른 평가방법'에 따르며"라 하고, 별표 1 의 경영상태(배점한도 30점)는 신용평가등급 표다. 등급이 확인되지 않으면 최저등급, 고시금액 미만 소기업·소상공인·창업기업은 만점.
  - 출처: https://www.law.go.kr/flDownload.do?flSeq=148006613

### 2.3 원문 근거: 재무비율이 필요해지는 곳(공사)

- 조달청 **시설공사 적격심사세부기준 [별표 6]**(추정가격 100억원 미만 50억원 이상인 공사의 경영상태 평가기준)은 경영상태를 재무비율로 평가한다.
  - 가. 최근년도 부채비율 = **부채총계 / 자기자본(자본총계)**
  - 나. 최근년도 유동비율 = **유동자산 / 유동부채**
  - 두 비율을 업체평균(업종 평균) 비율과 비교해 A~E 등급으로 환산한다. 주1~6은 0 이하·분모 0·분자 0 처리 규칙을 정한다.
  - 출처: https://law.go.kr/flDownload.do?flSeq=130015617
- **지방자치단체 입찰시 낙찰자 결정기준**(행정안전부예규): "경영상태 평가는 공사·용역 규모별 경영상태평가표에 따르되, **공사의 경우** '재무비율 평가방법', '신용평가방법' 및 '종합평가방법'(재무비율과 신용평가등급으로 각각 평가한 점수를 3:7로 합산) 중에서 적격심사 대상자가 선택"한다. 재무비율 방식이 열려 있는 것은 공사다.
  - 출처: https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=2100000258416

### 2.4 정리: 평가 유형별 재무 값 필요 여부

| 평가 유형 / 기준 | 경영상태 평가 입력 | 재무 값 필요 | 이 저장소 구현 여부 |
| --- | --- | :---: | :---: |
| 조달청 일반용역 적격심사 (별표 1~5의2, 7, 8) | 신용평가등급(별표 10) | 아니오 | 구현됨 (`evaluation_rules.py`) |
| 조달청 일반용역 수요기관 지정형 (별표 9) | 신용평가등급(별표 9 상대 감점) | 아니오 | 구현됨 |
| 조달청 중소기업자간 경쟁물품 이행능력심사 | 신용평가등급 | 아니오 | 미구현 |
| 조달청 시설공사 적격심사 (별표 6 등) | 재무비율(부채비율·유동비율) 또는 신용평가 | 예 | 미구현 |
| 지방자치단체 낙찰자 결정기준 — 공사 | 재무비율/신용평가/종합평가 선택 | 예 | 미구현 |
| 지방자치단체 낙찰자 결정기준 — 용역 | 규모별 경영상태평가표 | 추정: 아니오 (공사만 선택 조항) | 미구현 |

- 4행·5행의 재무 값 필요는 원문으로 확정한다(2.3).
- 마지막 행은 "공사의 경우"라는 한정 문구에 근거한 추정이며, 용역 규모별 경영상태평가표 원문을 직접 확보해 확인해야 확정된다.

### 2.5 재무 값이 필요해질 때 요구되는 재무제표 계정

- 부채비율 = 부채총계 / 자기자본(자본총계)
- 유동비율 = 유동자산 / 유동부채
- 따라서 최소 필요 값은 **부채총계·자본총계·유동자산·유동부채** 4개(재무상태표 숫자)다. 추가로 업종 평균비율(공고에서 명시)이 있어야 점수가 확정된다.

## 3. 입력 문서 양식 조사

### 3.1 문서 종류 (사실)

- **표준재무제표증명**(정식 명칭 표준재무제표증명원): 종합소득세·법인세 신고 시 부속서류로 제출한 표준재무제표를 국세청이 증명한다. 홈택스 민원증명에서 전자 발급되며, 통상 **표준대차대조표(표준재무상태표)와 표준손익계산서**로 구성된다.
  - 출처: https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=12100000326 , https://www.nts.go.kr/nts/na/ntt/selectNttInfo.do?nttSn=1002331&mi=2240
- **감사보고서**(외부감사 대상): **재무상태표, (포괄)손익계산서, 자본변동표, 현금흐름표, 주석** 5종과 감사인의 감사의견으로 구성된다.
- **회계사 검토 재무제표**: 위 재무제표와 유사한 구성을 갖는다.

### 3.2 PDF 형식과 표 구조 (추정)

- **텍스트형/이미지형**: 홈택스·DART 등에서 전자 발급한 본은 전자문서라 텍스트 레이어를 가질 가능성이 높으나, 인쇄·스캔·이미지 저장본도 유통된다. 따라서 텍스트형과 이미지형 두 갈래를 모두 가정해야 한다.
  - 이 저장소의 기존 등급확인서 경로가 같은 이유로 **텍스트 우선 → OCR 폴백**을 둔다: `src/app/services/document_extraction/credit_certificate.py`(정규식 파서), `src/app/services/document_extraction/pdf_text.py`(pdfplumber 메모리 처리), `src/app/services/document_extraction/ocr.py`(rapidocr, 신뢰도 상한 medium).
- **표 구조**: 재무상태표는 통상 `[계정과목 | 당기 | 전기]` 형태의 격자와 자산·부채·자본 구획으로 되어 있다. `pdfplumber` 의 `extract_table` 로 격자를 얻을 수 있는 경우가 있으나, 병합셀·줄바꿈 계정명·괄호 음수 표기·단위(원/천원/백만원)·연도 열 구분 때문에 정규식만으로는 취약하다. **실측 전에는 정확도를 단정하지 않는다.**
- **검증 불가 항목**: 위 3.2 는 문헌·구조 추정이며, 실제 적중률은 합성 픽스처와(사용자 제공 시) 로컬 실물로만 측정한다.

### 3.3 원본 미저장·개인정보 원칙 (기존 성질 유지)

- 기존 등급확인서 경로는 업로드 원본을 메모리(`io.BytesIO`)로만 처리하고 디스크·Redis·DB·로그에 저장하지 않는다. 재무제표는 영업비밀 성격이 더 강하므로 같은 원칙을 유지한다.
  - 근거: `src/app/api/v1/documents.py`(라우터 주석·메모리 처리), `src/app/services/document_extraction/ocr.py`(원본 미저장 주석).
- 이용약관/개인정보처리방침에 등급확인서 자동 입력 고지가 있다. 재무제표를 다루면 **같은 고지에 항목을 추가**해야 한다.
  - 근거: `src/app/templates/accounts/terms_content.html` 개인정보처리방침 "등급확인서 자동 입력(선택)".

| **D. C + OCR 폴백** | C + 이미지형 재무제표를 로컬 OCR 로 판독 | 높음(OCR 오인식, 표 재구성 난이도) | 매우 큼 | 없음(rapidocr 재사용) | C와 동일 | C와 동일 |
| **E. 공사 적격심사 확장과 함께 도입** | 시설공사·지자체 공사 적격심사 규칙·배점표까지 신규 구현 + 재무 값 입력 | 높음(새 규정 원문 확정 필요) | 최대 | 없음(원칙) | 새 테이블·기준선 추가 | 재무 값 저장·고지 확대 |

- A 는 "사용처가 없다"는 2.1·2.2 결론을 그대로 제품 결정으로 옮긴 것이다. 정상 결과다.
- C·D 는 채울 대상 칸이 있어야 의미가 있다. 일반용역만 다루는 동안에는 C·D 를 넣어도 채울 곳이 없으므로, **E(공사 확장)와 묶지 않으면 효용이 없다.**
- B 는 채울 대상이 생기기 전에도 "재무 값을 사용자가 직접 관리"하는 토대가 되지만, 정작 그 값을 쓰는 계산 경로가 없으면 화면에 죽은 입력이 된다.

## 5. 권장안과 단계별 구현 계획

### 5.1 권장안

- **지금 범위(일반용역)에서는 A(범위 제외)를 권장한다.** 재무 값 사용처가 없으므로 C·D 는 채울 칸이 없다. 이는 결론이 "기능을 만들지 말자"가 아니라 "지금은 대상이 없다"는 뜻이다.
- **사용자가 공사 적격심사(시설공사·지자체 공사) 확장을 함께 승인하면 B → C → D 순으로 단계 도입**한다. 각 단계는 이전 단계의 실측이 통과해야 다음으로 간다.
- 모든 단계에서 **기존 테이블·컬럼의 이름·타입 변경 없이 추가만** 하고, 업로드 원본은 저장하지 않는다(G1 보존).

### 5.2 단계별 계획 (파일 단위)

**Phase 0 — 선행 결정(사용자)**: 범위(E 포함 여부), 저장 여부, 대상 문서 우선순위, 업종 평균비율 확보 방식.

**Phase 1 — 수동 입력 보조(B안)**
- `src/app/models/company_profiles.py`: 재무 원자료 모델 **추가**(예: `AccountFinancialFact` — user_id, fiscal_year, total_liabilities, total_equity, current_assets, current_liabilities, source, version, created_at/updated_at). 기존 모델 변경 없음.
- `migrations/`: 새 alembic revision(테이블 추가만). G1 기준선 재생성은 신규 테이블 추가에 한정.
- `src/app/schemas/`: 재무 원자료 입출력 스키마 추가.
- `src/app/api/v1/`: 회원 재무 원자료 CRUD 엔드포인트 추가(기존 문서 추출 엔드포인트와 분리).
- `src/app/templates/accounts/mypage_edit.html`: 재무 값 입력 블록 추가.
- `src/app/templates/accounts/terms_content.html`: 개인정보처리방침에 재무 값 처리 고지 추가.
- CSP 규칙 준수: 인라인 이벤트 금지, `nonce` 규칙 준수.

**Phase 2 — 텍스트 PDF 표 추출(C안)**
- `src/app/services/document_extraction/financial_statement.py` **신규**: 재무상태표 격자에서 부채총계·자본총계·유동자산·유동부채를 뽑는 순수 함수 파서(LMM·외부 API 미사용). 기존 등급확인서 파서와 동일한 신뢰도·근거 반환 규약을 따른다.
- `src/app/api/v1/documents.py`: 문서 종류 분기 추가(또는 신규 엔드포인트). 기존 5MB·10쪽·10초·원본 미저장 계약 유지.
- `src/app/static/js/doc-autofill.js`: 재무 필드 채우기 확장. 서버 문자열은 `textContent` 로만 넣는다.
- `src/app/services/document_extraction/pdf_text.py`: 재사용(변경 없음).

**Phase 3 — OCR 폴백(D안)**: `src/app/services/document_extraction/ocr.py` 재사용. OCR 값의 신뢰도 상한(현재 medium) 규칙을 재무 값에도 적용.

**Phase E — 공사 적격심사 확장**: `src/app/services/evaluation_rules.py` 에 시설공사/지자체 공사 규칙·배점표 추가. 이때 재무 비율 계산도 함께 넣는다. 원문 확정 없는 추측 값은 넣지 않는다.

### 5.3 시험 계획

- **합성 픽스처만** 사용한다. **실물 재무제표 PDF 는 커밋 금지**(개인정보·영업비밀, 공개 저장소).
- 파서 시험: 표 격자 변형, 단위(원/천원), 괄호 음수, 항목 누락, 다중 연도 중 최근 연도 선택.
- 계산 시험: 부채비율·유동비율 경계(0 이하, 분모 0/분자 0) 규칙.
- 회귀 시험: 기존 등급확인서 추출 경로 무영향.
- G1 시험: 기존 테이블·컬럼 무변경, 신규 테이블 추가만 확인.
- 실물 적중률은 로컬에서만 측정하고 수치만 기록한다.

## 6. 사용자 결정이 필요한 질문

1. **목표 범위**: (a) 일반용역 현행 유지(A안, 권장), (b) 공사 적격심사(시설공사·지자체 공사)까지 확장, (c) 그 밖의 기관·평가유형. — 2.4 표의 "재무 값 필요" 행이 (b) 에서만 열린다.
2. **자동화 수준**: PDF 표를 자동 추출(C·D)할지, 수동 입력 보조·검산(B)만 할지.
3. **저장 정책**: 재무 값을 DB 에 저장(새 테이블/컬럼 추가)할지, 요청 내 메모리만 쓸지. 저장 시 보관기간·암호화·약관 고지 변경에 동의하는지.
4. **대상 문서 우선순위**: 표준재무제표증명(홈택스) / 감사보고서 / 회계사 검토 재무제표 중 무엇부터 지원할지.
5. **업종 평균비율 확보**: 재무비율 평가방법은 업종 평균비율이 있어야 점수가 난다. 우리가 평균비율 데이터를 확보·관리할지, 사용자가 공고에서 입력하는 값만 쓸지.
6. **기준일 규칙**: 최근 사업연도 확정 규칙(결산 전후, 심사기준일=입찰공고일)을 어떻게 정의할지.
7. **정확도 목표·실측 방법**: 합성 픽스처 정확도 목표치와, 사용자가 로컬 실물로 실측하는 절차에 합의할 수 있는지.
8. **실물 표본 제공**: 로컬 실측을 위해 실물 재무제표를 제공할 수 있는지(제공 시에도 저장소 커밋은 금지).
