## 4. 코드 적용 경로에서 확인된 결함 (판정과 별개)

**기준비율 값 88 은 맞지만, 그 88 이 실제 가격점수 계산에 반영되지 않습니다.**

`evaluation_rules.py:3991-4002` 는 `RuleResolutionResult` 를 `replace` 로 바꿔 `base_rate=Decimal("0.88")` 을 넣습니다.

```python
3998:        result = replace(
3999:            result,
4000:            base_rate=Decimal("0.88"),
4001:            warnings=[*result.warnings, MOIS_TECH_BASE_RATE_WARNING],
4002:        )
```

그러나 88 을 실제로 쓰는 배점표 경로는 `result.base_rate` 를 읽지 않습니다.

- `evaluations.py:414` — `base_rate=resolution.base_rate or rule.base_rate`. 여기서 `resolution` 은 `resolve_score_params` 가 만든 `ScoreParamResolution` 이고(`evaluations.py:366-373`), 그 `base_rate` 는 `price_band.base_rate` 로 채워집니다(`evaluation_rules.py:718`). 즉 `SERVC_TECH_QUAL_ANNOUNCEMENT_LWLT` 의 `price_bands` 에 선언된 0.90 이 그대로 들어옵니다. `result.base_rate` 는 이 식에 등장하지 않습니다.
- `predictions.py:366` — `base_rate = _decimal_or_none(rule_result.rule.base_rate)`. 여기서도 `rule_result.base_rate` 가 아니라 `rule_result.rule.base_rate`(규칙 객체의 0.90)를 읽습니다.
- `RuleResolutionResult.base_rate`(`evaluation_rules.py:3406`)를 읽는 운영 코드 경로는 `grep -rn "\.base_rate" src` 로 확인한 범위에서 없습니다.
