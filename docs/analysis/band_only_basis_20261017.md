## 2. 조사 방법

1. 모집단 선별은 읽기 전용 조회기만 썼습니다.
   - `uv run python scripts/db_readonly_query.py --sql "..."` 단일 SELECT 문장. `docker exec`·`mysql` 직접 호출 없음.
   - 모집단: `category='Servc' AND bid_ntce_dt >= '2025-10-17'` 이고 `JSON_UNQUOTE(JSON_EXTRACT(raw_data,'$.sucsfbidMthdNm'))` 가 9종 띠 표기 중 하나인 공고.
   - 주의: `raw_data` 는 한글을 `\uXXXX` 로 이스케이프해 저장하므로 한글 `LIKE` 검색은 0건이 됩니다. 낙찰방법명은 반드시 `JSON_EXTRACT` 로 꺼내야 합니다.
2. 표본은 표기별로 최대 5건을 골랐습니다. 수요기관이 겹치지 않게 하고, 첨부 파일명에 `적격심사`·`공고문/공고서`·`세부기준` 이 있는 공고를 우선했습니다. `추정가격 100억원 이상인 용역` 은 조회 창 안에 2건뿐이라 2건 전량을 봤습니다.
3. 첨부는 `raw_data` 의 `ntceSpecDocUrl1` ~ `ntceSpecDocUrl5` 를 그대로 내려받았습니다. 목록·압축·이미지 첨부는 제외했고, 공고당 최대 4개를 받았습니다.
4. 텍스트 추출은 새 의존성을 추가하지 않고 저장소에 있는 도구만 재사용했습니다.
   - PDF: `pdfplumber` (업로드 검증 경로에서 이미 쓰는 라이브러리).
   - HWP·HWPX: `scripts/extract_score_params.py` 의 `extract_document_text` 함수를 import 해 그대로 호출.
   - 바이너리 HWP 표는 일부 글자가 깨집니다. 같은 공고에 PDF 사본이 있으면 PDF 쪽 인용을 골랐습니다.
5. 인용문은 공고문(또는 공고 첨부 기준 문서) 원문 문자열 그대로입니다. 출처 파일은 `.cache/band_only_basis/raw/<공고번호>/<순번>.txt` 이며 커밋하지 않습니다.

- 공고문 띠 표기 6종은 이 표의 구간명과 문자열이 사실상 일치합니다. `2억원 미만인 용역`, `5억원 미만 2억원 이상인 용역`, `15억원 미만 5억원 이상인 용역` 은 제2호~제4호 이름 그대로이고, `30억원 미만 15억원 이상`, `100억원 미만 30억원 이상`, `100억원 이상` 은 제1호(15억원 이상) 안에서 공고문이 더 세분해 적은 구간명입니다.
- 고시 전문에는 `30억`·`100억` 문자열이 0건입니다(사본 2종 확인). 즉 세분 구간명은 고시 별표에 인쇄된 이름이 아니라 공고문 쪽 표기입니다. 다만 6종 모두 같은 고시의 같은 별표를 지목하므로 판정은 `특정 별표로 대응` 입니다.
- 고시 버전은 공고문이 밝힌 것이 두 가지입니다. R25BK01228030 은 `제2024-287호`, R26BK01284982 는 `제2025-165호(2025.10.01., 시행 2025.10.7.)` 를 인용합니다. 표본이 확인한 구간명·통과점수는 두 버전에서 같았습니다.

### 5.2 비폐기물 계열의 기준 분기

- 행안부 예규 제2장의2 기술·학술연구용역 적격심사 세부기준 [별표 4] 학술연구용역 평가기준 표는 열 머리가 `추정가격 2억이상 / 추정가격 2억미만 1억이상 / 추정가격 1억미만` 3개입니다. 비폐기물 띠 표기 3종은 이 열 머리와 문자열이 일치합니다.
- 같은 띠라도 계약목적물에 따라 적용 장이 갈립니다. `2억미만 1억이상` 표본에서 학술연구용역은 제2장의2를, 물품성 검사 용역은 제4장 물품 적격심사 세부기준을, 조달청 계약은 조달청 일반용역 적격심사 세부기준을 지목했습니다.
- 조달청 일반용역 적격심사 세부기준을 지목한 공고(R25BK01248793)는 별표를 `[별표 1] 학술연구용역 (추정가격 5억 원 미만)` 로 적었습니다. 같은 공고의 추정가격은 154,545,455원으로 띠의 `2억미만 1억이상` 과 조달청 별표의 `5억원 미만` 축이 서로 다릅니다.

### 5.3 낙찰하한율과 통과점수

- 첨부된 환경부고시 전문에는 `낙찰하한율`·`통과점수`·`종합평점` 문자열이 0건입니다. 표에서 적은 하한율·통과점수는 4.1절 인용문에 나온 대로 **공고문이 적은 값**입니다.
- 폐기물 계열에서 확인된 값은 구간이 커질수록 낮아집니다. 87.745%(2억원 미만) → 86.745%(5억원 미만 2억원 이상) → 85.495%(15억원 미만) → 82.995%(30억원 미만 15억원 이상) → 77.995%(100억원 미만 30억원 이상) → 72.995%(100억원 이상). 통과점수는 95점(15억원 미만 이하 구간), 90점(100억원 미만 30억원 이상), 85점(100억원 이상)입니다.
- 같은 하한율·통과점수가 서로 다른 기관 공고에서 반복 확인됩니다. 85.495%·95점은 경찰청·국토교통부·기후에너지환경부·경기도교육청·한국농어촌공사 공고에서, 77.995%·90점은 김천시·광명시·서산시·서울주택도시개발공사·서울아리수본부 공고에서 같았습니다.

## 6. 코드 반영 시 필요한 것 (제안, 구현하지 않음)

1. 띠 표기를 하나의 문자열 패턴으로 묶지 말고 **기준 문서별 구간 식별자**로 나눠 등록해야 합니다.
   - `SERVC_QUAL_WASTE_*` 계열: 환경부고시 [별표] 제1호~제4호 4개 구간을 각각 규칙으로 두고, `30억원 미만 15억원 이상`·`100억원 미만 30억원 이상`·`100억원 이상` 세분 표기는 제1호 구간의 별칭으로 흡수합니다.
   - `SERVC_QUAL_LOCAL_ACADEMIC_*` 계열: 행안부 예규 제2장의2 [별표 4] 의 `2억이상`·`2억미만 1억이상`·`1억미만` 3개 열을 구간으로 둡니다.
2. 표기별로 지금 계산에 필요한 값이 어디서 오는지가 다릅니다. 폐기물 계열은 공고문이 통과점수·낙찰하한율을 명시하므로 공고문 파싱으로 확보할 수 있으나, 배점한도 B·계수 k·기준비율은 [별표] 원문(별지 서식 포함)을 읽어야 합니다. 등록 전에 고시 버전(제2024-287호, 제2025-165호)별 별표 값 차이를 확정해야 합니다.
3. `2억미만 1억이상` 처럼 기준 문서가 갈리는 표기는 단일 규칙으로 닫을 수 없습니다. 공고 첨부에서 기준 문서명을 먼저 판별하는 단계가 필요하며, 판별 실패 시 기존처럼 `RULE_NOT_FOUND` 로 남기는 편이 안전합니다.
4. 등록 검증에는 이 문서 4절의 표본 공고번호를 회귀 표본으로 쓰는 것이 좋습니다. 표본이 지목한 별표·호·통과점수·하한율이 곧 기대값입니다.

```sh
# 1) 띠 표기 모집단과 기관 분포 (raw_data 한글은 \uXXXX 로 저장되므로 JSON_EXTRACT 로 꺼낸다)

  WHERE category='Servc' AND bid_ntce_dt >= '2025-10-17'

# 2) 표본 공고의 첨부 URL 확보 (ntceSpecDocUrl1..5)
uv run python scripts/db_readonly_query.py --format json --limit 0 --sql \

  WHERE category='Servc'
    AND JSON_UNQUOTE(JSON_EXTRACT(raw_data,'\$.sucsfbidMthdNm')) = '적격심사제-추정가격 15억원 미만 5억원 이상인 용역'
  ORDER BY bid_ntce_dt DESC"

# 4) 텍스트 추출: PDF 는 pdfplumber, HWP·HWPX 는 scripts/extract_score_params.py 의 extract_document_text
```
