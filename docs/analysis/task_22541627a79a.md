## 1. 개요 및 목적

본 작업은 Orca 다중 에이전트 오케스트레이션에서 발생할 수 있는 계약 위반(무작업 완료, 범위 초과 커밋, 누락된 사양 복사본 간 drift, report 누락 완료 선언 등)을 사람의 주의에 의존하지 않고 실행 단계에서 기계적으로 차단하는 Fail-Closed 계약 강제 메커니즘을 구현하고 전 범위 회귀 테스트를 완료하는 것을 목적으로 합니다.

---

## 2. 주요 변경 내역

| 영역 | 대상 파일 | 주요 구현 내용 |
| --- | --- | --- |
| **스코프 가드** | `scripts/orca_scope_guard.py` | 워크트리 git config의 `orca.capsule`을 확인하여 staged 파일이 `allowed_write_files` 외부에 있거나 읽기 전용 작업일 때 커밋을 거부. Capsule 미설정 시 일반 개발 커밋 허용. Capsule 손상/누락 시 fail-closed. |
| **완료 보고 가드** | `scripts/orca_worker_done_guard.py` | `worker_done` 보고 단일 진입점. Capsule/Report 유효성, `task_id` 일치, 커밋 실존성, 실제 diff 대조, 쓰기 범위 준수를 엄격 검증 후 통과 시에만 `orca orchestration send` 실행. |
| **Task 제어기** | `scripts/orca_taskctl.py` | `required_write_files` 필드 추가, `expand_intent_to_capsule` 및 `cmd_dispatch`/`cmd_create`에서 부분집합 검증 강제. 동일 Task의 spec 사본과 canonical 사본 간 contract drift 발생 시 `capsule_spec_error`로 dispatch 거부. |
| **워크트리 준비** | `scripts/orca_prepare_worktree.py` | `--capsule` 옵션 추가 및 `git config --worktree orca.capsule` 기록 파이프라인 통합. |
| **상시 감시** | `scripts/orca_worker_watch.py` | `worker_done` 완료 메시지에 `reportPath`가 없거나 보고 파일이 실존하지 않으면 완료가 아닌 `[차단:failure]`로 분류. |
| **Pre-commit 훅** | `.pre-commit-config.yaml` | 최우선 실행 훅으로 `orca-scope-guard` 등록. |
| **규약 문서** | `docs/ops/orca_task_capsule_v2.md` | `required_write_files` 필드 정의 및 8장 Fail-Closed 계약 강제 장치 표준화. |
