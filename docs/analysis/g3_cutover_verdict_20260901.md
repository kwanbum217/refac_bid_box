## 3. c2 미달은 환경 오염이었습니다

종전 정본은 c2 P95 **22.68ms** 로 판정선 21.77ms 를 0.91ms 넘겨 유일한 미달 항목이었습니다.
이번 측정은 **19.66ms** 로 2.11ms 여유를 두고 통과합니다.

원인은 코드가 아니라 측정 환경입니다. 근거가 셋입니다.

1. **통제 A/B 에서 회귀가 없었습니다.** 2026-08-22 교차 측정에서 current 가 baseline 보다
   오히려 **0.97ms 빨랐습니다**([`../ops/predict_ab_20260822.md`](../ops/predict_ab_20260822.md) 2.1 절).
2. **그 측정의 호스트 부하가 규약 임계를 넘었습니다.** r1 회차 부하가 **42.45%** 로
   중앙 30% 기준을 초과합니다. 규약 5.3 은 "넘은 값을 그대로 쓰면서 부하가 있었다고
   적는 것은 판정 근거가 되지 않는다" 고 규정합니다.
3. **부하를 규약 안(15.8%)에서 다시 재니 통과했습니다.** 3회 모두 18.95~19.66ms 로
   판정선 아래이며 편차도 0.71ms 에 불과합니다.

> **교훈**: 미달 판정을 코드 결함으로 결론짓기 전에 그 측정이 규약을 지켰는지 확인하십시오.
> 이 항목은 3개월 가까이 "미달" 로 남아 컷오버를 막고 있었으나 실제로는 오염된 측정이었습니다.

## 4. 게이트에서 제외한 항목

| 항목 | 처리 | 근거 |
| --- | --- | --- |
| 콜드 SQL 총량 | **관찰 지표로 강등** | 동일 조건 재측정이 333.19초와 432.99초로 30% 흔들려 재현되지 않습니다([`coldsql_metric_demotion_20260901.md`](coldsql_metric_demotion_20260901.md)) |
| ngram 선행필터 개선 | **기각** | 기대한 19배 개선이 나타나지 않았습니다([`ngram_prefilter_paired_verdict_20260901.md`](ngram_prefilter_paired_verdict_20260901.md)) |

두 항목 모두 **컷오버 차단 사유가 아닙니다.** 콜드 SQL 은 캐시가 식은 상태의 첫 사용자
한 명이 겪는 비용이며 본질적으로 디스크 상태에 좌우됩니다. 지표의 변동폭이 재려는 효과보다
크면 통과·미달 판정에 쓸 수 없습니다.

## 6. 측정 함정

| 함정 | 실제 |

| 미달 = 코드 결함 | 규약(부하 임계)을 어긴 측정이면 판정 근거가 아닙니다 |
