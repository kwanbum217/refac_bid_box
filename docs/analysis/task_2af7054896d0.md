## 1. 개요 및 배경

2026-08-28 외부 감사에서 지적된 자동 승인 감시기 관련 두 가지 P1 결함을 해결하였습니다.

1. **감시기 프로세스 누적 및 고아 프로세스 발생**: `start_auto_approve()`가 터미널에 중복 호출될 때마다 새 프로세스를 무조건 띄우고, `poll_loop()`는 무한 루프로 돌아 고아 프로세스가 누적되는 문제.
2. **보안 경계 우회 위험 및 명령 분류 정합성 결함**: git 전역 옵션(`-c`, `--exec-path` 등)을 허용하여 임의 실행 취약점이 존재했고, 코드를 실제 실행하는 `pytest`가 단순 읽기 명령(`cat`, `ls`)과 동일한 신뢰 등급으로 분류되어 있던 문제.

## 2. 주요 변경 내역

### 2.1 터미널별 단일 감시기 보장 및 생명주기 관리 (`scripts/orca_taskctl.py`)

- **PID 레지스트리 기반 중복 방지**:
  - `get_watcher_pid_path(terminal)`: `tempfile.gettempdir()/orca_auto_approve/<terminal>.pid` 경로 관리.
  - `read_watcher_pid(path)` / `write_watcher_pid(path, pid)` / `remove_watcher_pid(path)`: 순수 함수로 분리하여 손상된 파일(빈 파일, 비숫자)도 예외 없이 안전하게 처리.
  - `watcher_alive(pid)`: `os.kill(pid, 0)`으로 프로세스 실존 여부 판정.
  - `start_auto_approve(terminal)`: 살아 있는 PID가 있으면 기존 감시기를 재사용하고, 없거나 죽어 있으면 새로 기동 후 PID 기록.
- **명시적 종료 절차 추가**:
  - `stop_auto_approve(terminal)`: 대상 터미널 감시기에 `SIGTERM` 시그널을 전달하고 PID 파일을 정리.
  - `finalize_task` 및 `cmd_finalize`: Task 종료 시 `stop_auto_approve`를 명시적으로 호출.

### 2.2 감시기 자체 종료 및 PID 정리 (`scripts/orca_auto_approve.py`)

- **`read(handle)` 결과 구분**:
  - 성공 시 터미널 화면 문자열 반환, 실패 시 `None` 반환.
- **`poll_loop` 자체 종료 조건**:
  - 연속 실패 상한(`MAX_CONSECUTIVE_READ_FAILURES = 5`) 초과 시 해당 터미널을 감시 목록에서 제외.
  - 감시 대상이 모두 소진되면 루프를 빠져나와 정상 반환.
  - `finally` 블록에서 감시 대상 터미널의 PID 파일을 자동 삭제.

### 2.3 Git 전역 옵션 차단 및 서브커맨드 화이트리스트

- **Git 전역 옵션 전면 금지**:
  - `git -c`, `git -C`, `git --exec-path`, `git --git-dir`, `git --work-tree`, `git --no-pager` 등 첫 인자가 `-`로 시작하는 모든 전역 옵션을 `hold` 판정.
- **서브커맨드별 명시적 화이트리스트**:
  - `status`, `diff`, `log`, `show`, `rev-parse`, `branch`, `worktree`에 대해 허용 플래그(`SAFE_GIT_OPTIONS`) 및 접두어(`SAFE_GIT_OPTION_PREFIXES`)를 엄격하게 정의.
  - 화이트리스트 밖의 옵션이 전달되면 즉시 `hold`.

### 2.4 `pytest` 및 `uv run pytest` 독립 분류 분리

- `SAFE_STANDALONE_COMMANDS`에서 `pytest`를 제거하고 `SAFE_TEST_COMMANDS`로 분리.
- 분류 식별 상수 `CATEGORY_READ_ONLY`, `CATEGORY_TEST_EXECUTION` 정의.
- 승인 사유를 `"신뢰된 워크트리 안의 테스트 코드 실행 검증 (pytest)"`로 명시하여 단순 읽기 전용 명령과 명확히 구분.
