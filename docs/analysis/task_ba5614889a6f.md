## 1. 개요 및 배경

2026-09-04 코디네이터 실측에 따르면, 공고 금액 집계 오버플로우 교정 코드(961a871)가 적용되었음에도 운영 DB의 `bid_dataset_summaries`의 announcement 행에는 이전 오버플로우 음수 값(-6,063,896,128,872,295,352)이 그대로 남아 화면에 노출되고 있었습니다.

재집계가 자동으로 촉발되지 않았던 근본 원인은 `src/app/services/dashboard.py`의 `get_bid_dataset_summary` 함수가 신선도(freshness) 판정 시 원본 데이터의 최신 수집 시각(`source_latest_collected_at`)만 대조했기 때문입니다. 즉, 원본 데이터 수집 시각의 변동이 없으면 집계 알고리즘이나 규칙이 바뀌어도 기존 사전집계 결과가 계속 유효한 것으로 처리되었습니다.

본 과업에서는 `bid_dataset_summaries` 테이블 및 ORM 모델에 `aggregation_version` 컬럼을 도입하고, 기대 알고리즘 버전과의 일치 여부를 신선도 판정 조건에 추가하여 알고리즘 변경 시 자동으로 stale 판정 및 재집계가 일어나도록 개선하였습니다. 또한 캐시 키에도 버전을 포함하여 구버전 캐시가 반환되는 결함을 방지하였습니다.

## 2. 변경 내역

  - 설명: `집계 알고리즘 버전`
- `sqlalchemy.Integer` 임포트를 추가하였습니다.

### 2.2 대시보드 서비스 수정 (`src/app/services/dashboard.py`)
- 데이터셋별 기대 알고리즘 버전 상수 `SUMMARY_ALGORITHM_VERSIONS`를 정의하였습니다.
  - `announcement`: `2` (이상치 100조 상한 배제 및 DECIMAL 누적 반영)
  - `result`: `1` (기존 알고리즘 유지)
- `_build_summary_defaults`: 생성 기본값에 `aggregation_version`을 포함하였습니다.
- `get_bid_dataset_summary`: 저장된 요약의 버전이 기대 버전과 다를 경우(`summary.aggregation_version != expected_version`) stale로 판정하여 `rebuild_bid_dataset_summary`를 호출하도록 freshness 조건을 보강하였습니다.
- `_dashboard_stats_cache_key`, `_compare_stats_cache_key`: 캐시 키 패턴에 요약의 `aggregation_version`(`v{version}`)을 포함하여 알고리즘 버전 상향 시 즉시 새로운 캐시 슬롯을 사용하도록 수정하였습니다.
- 모듈의 `__all__`에 `SUMMARY_ALGORITHM_VERSIONS`를 추가하였습니다.

### 2.3 Alembic 마이그레이션 작성 (`migrations/versions/e7f8a9b0c1d2_add_aggregation_version_to_bid_dataset_summaries.py`)
- 기존 head(`d4e5f6a7b8c9`)를 잇는 신규 리비전 `e7f8a9b0c1d2`를 작성하였습니다.
