# RAG 구간 계측 segment_metrics 정식 필드 승격 및 비스트리밍 REST 응답 노출 분석 보고서

> **작성일**: 2026-08-28
> **Task ID**: `task_dd956f60809d`
> **작업 유형**: 리팩토링 및 REST API 응답 직렬화 개선

## 1. 개요 및 배경

2026-08-28 외부 감사에서 지적된 P2 이슈를 해결하기 위해, RAG 질의 처리 구간별 소요 시간 계측치(`segment_metrics`)를 `AnswerBundle`의 정식 선택 필드로 승격하고 비스트리밍 REST 응답(`POST /api/v1/chatbot/query`)에 설정 플래그(`RAG_EXPOSE_SEGMENT_METRICS`)에 따라 선택적으로 노출되도록 개선하였습니다.

기존 구현에서는 `src/rag/schemas.py`의 `AnswerBundle`에 정식 필드가 없어 `src/rag/engine.py`에서 런타임에 `setattr`을 통해 동적 프로퍼티(`segment_metrics`)를 주입하는 방식을 취했습니다. 이로 인해 Pydantic 직렬화 과정(`model_dump()` 및 FastAPI 엔드포인트 응답)에서 해당 속성이 누락되었고, 비스트리밍 REST 응답 모델인 `ChatbotQueryResponse`에도 필드가 존재하지 않아 구간 계측 정보를 외부에 반환하지 못하는 한계가 있었습니다.

---

## 2. 주요 변경 사항

### 2.1 스키마 정식 필드 승격 (`src/rag/schemas.py`)
- `AnswerBundle` Pydantic 모델에 `segment_metrics: dict[str, float] | None = Field(default=None, description="Detailed stage latency metrics in milliseconds")` 필드를 정식 선언하였습니다.
- 기본값 `None`을 유지하여 기존 생성자 호출 및 하위 호환성을 100% 보존하였습니다.

### 2.2 동적 프로퍼티 바인딩 및 setattr 우회 제거 (`src/rag/engine.py`)
- 모듈 로드 시 실행되던 `AnswerBundle` 대상 동적 프로퍼티 바인딩(`hasattr`, `_get_segment_metrics`, `_set_segment_metrics`, `setattr`) 코드를 완전히 삭제하였습니다.
- `_bundle` 헬퍼 함수에서 `setattr(bundle, "segment_metrics", ...)` 및 `# noqa: B010` 우회 코드를 제거하고, `AnswerBundle` 생성자 인자로 `segment_metrics`를 직접 전달하도록 단순화하였습니다.
- 노출 플래그(`settings.RAG_EXPOSE_SEGMENT_METRICS`)가 비활성화되어 있거나 지표가 없는 경우 `None`을 전달하는 기존 비즈니스 로직을 유지하였습니다.

### 2.3 REST 응답 모델 및 엔드포인트 직렬화 정책 적용 (`src/app/schemas/chatbot.py`, `src/app/api/v1/chatbot.py`)
- `ChatbotQueryResponse`에 `segment_metrics: dict[str, float] | None = Field(default=None, description="RAG 처리 구간별 소요 시간 (ms, 활성화 시에만 포함)")` 필드를 추가하였습니다.
- `POST /api/v1/chatbot/query` 엔드포인트에 `response_model_exclude_none=True`를 설정하여 플래그 OFF(값 `None`) 시 JSON 응답 본문에서 `segment_metrics` 키가 아예 노출되지 않도록 직렬화 정책을 구현하였습니다.
- `query_chatbot` 함수에서 `bundle.segment_metrics`를 응답 모델에 직접 전달함으로써 API 계층에서의 불필요한 중복 플래그 검사 및 조건 분기를 배제하였습니다.
