## 2. 주요 변경 사항

### 2.1 `src/app/core/config.py`
- `RAG_EXPOSE_SEGMENT_METRICS` 불리언 설정 추가 (기본값: `False`).

### 2.2 `src/rag/engine.py`
- `_safe_perf_counter()` 안전 래퍼 함수 도입으로 타이머 조회 예외 격리.
- `_prepare_context`: `plan_ms`, `sql_ms`, `vector_ms`, `lexical_ms`, `kb_status_ms`, `assembly_ms`, `prepare_total_ms`를 밀리초 단위로 수집하여 `PreparedContext.timings`에 보존.
- `get_answer_sync`:
  - `_log_latency`에 `lexical_ms` 및 `use_lexical`을 추가하여 모든 검색/생성 채널 구조화 로깅 완비.
  - `_calc_segment_metrics`를 통해 `sql_ms`, `vector_ms`, `lexical_ms`, `llm_ms`, `total_ms`를 종합 계산.
  - `RAG_EXPOSE_SEGMENT_METRICS` 활성화 시 `AnswerBundle.segment_metrics`에 동적 노출.
- `stream_tokens`:
  - 스트리밍 응답의 `done` 이벤트에 `RAG_EXPOSE_SEGMENT_METRICS` 활성화 시 `segment_metrics` 페이로드 포함.
- `AnswerBundle`: 기존 Pydantic 스키마를 변경하지 않고 `segment_metrics` 동적 프로퍼티를 바인딩하여 역호환성 유지.

## 3. 계측 지표 요약

| 지표명 | 측정 구간 | 주요 원인 의심점 (이상치 발생 시) |
| :--- | :--- | :--- |
| `plan_ms` | 질의 분석 및 라우팅 | 복잡한 정규식 매칭 또는 키워드 분석 지연 |
| `sql_ms` | MySQL 정형 통계 조회 | 풀테이블 스캔, 대량 집계, 커넥션 풀 경합 |
| `vector_ms` | ChromaDB 벡터 검색 | 임베딩 백엔드(bge-m3) 부하, 콜드스타트, I/O 지연 |
| `lexical_ms` | Meilisearch 어휘 검색 | 키워드 검색 서버 부하, 복합 필터 오버헤드 |
| `kb_status_ms` | KB 상태 메타데이터 조회 | DB 락 또는 메타 테이블 조회 지연 |
| `assembly_ms` | 컨텍스트 합성 및 메시지 구성 | 다중 문서 병합 및 문자열 조립 오버헤드 |
| `prepare_total_ms`| 전체 검색 및 컨텍스트 준비 | 검색 채널 전반의 지연 합산 |
| `llm_ms` | 백엔드 LLM 토큰 생성 | 모델 콜드스타트 로드, `LLM_THINKING` 활성, GPU/CPU 연산 지연 |
| `guard_ms` | 답변 가드 및 수치 검증 | 대용량 텍스트 정규식 매칭 및 수치 누락 검사 오버헤드 |
| `total_ms` | 전체 종단간 처리 시간 | 질의 수신부터 최종 응답 번들 생성까지 총 소요 |
