## 1. 개요 및 목적

기존 G1 데이터 무손실 검증(`scripts/verify_migration.py`)은 테이블 존재 여부(`EXPECTED_TABLES`)와 2개 핵심 테이블의 최소 행 수 하한 비율(`MIN_ROW_COUNT_RATIO`)만 확인하여, 테이블 컬럼 추가·삭제, 데이터 타입 변형, nullable 제약 변경, 기본키·외래키·인덱스 변형 등의 스키마 수준 데이터 손실 및 비정합성을 사전에 감지하지 못하는 한계가 있었습니다.

본 작업에서는 다음과 같은 핵심 요구사항을 구현하여 G1 검증의 범위를 실질적으로 강화했습니다:
1. 전 테이블 스키마 서명(컬럼명, 데이터 타입, nullable, 기본키, 외래키, 인덱스) 생성 및 SHA-256 해시 계산.
2. 스키마 정의 순서에 무관한 결정론적(Deterministic / Order-Independent) 정렬 및 서명 정규화.
3. 기준 서명 부재 시 실패하지 않고 신규 기준선으로 자동 기록하여 최초 실행 안정성 확보.
4. 기준 서명과의 항목별(컬럼 추가/삭제/타입변경/nullable변경/제약조건 변경) 상세 차이 검출 및 출력.
5. 실행 일시, HEAD 커밋 SHA, 각 단계별 상세 판정 결과가 포함된 검증 보고서(JSON) 파일 자동 생성.
6. 엄격한 읽기 전용(Read-Only) 보장 (어떤 DDL/DML도 실행하지 않음).
7. 기존 4단계 검증의 통과 조건 및 행 수 하한 검사 로직 100% 보존.

## 2. 설계 및 구현 세부사항

### 2.1 스키마 서명 생성 (`generate_schema_signature`)

SQLAlchemy `inspect` API를 활용하여 각 테이블에 대해 다음 메타데이터를 정규화하여 추출합니다:

| 항목 | 추출 필드 및 정규화 규칙 |
| --- | --- |
| **컬럼** | `name`, `type`(대문자 표준 문자열 정규화), `nullable`(bool), `primary_key`(bool), `default`(문자열)를 추출한 후 `name` 기준 오름차순 정렬 |
| **기본키** | 제약조건 내 컬럼명 목록을 추출하여 오름차순 정렬 |
| **외래키** | `referred_table`, `constrained_columns`, `referred_columns`, `name`을 추출하여 복합 키 기준으로 오름차순 정렬 |
| **인덱스** | `name`, `column_names`(복합 인덱스 컬럼 순서 유지), `unique`를 추출하여 정렬 |

단일 테이블 서명과 전체 스키마 서명은 `json.dumps(..., sort_keys=True, separators=(",", ":"))` 기반의 정규 JSON 직렬화 후 SHA-256 해시를 계산하므로, DDL 선언 순서나 Inspector 반환 순서가 달라져도 동일한 스키마에 대해 항상 동일한 서명 해시를 보장합니다.

### 2.2 기준선 관리 및 차이 검출 (`compare_schema_signatures`)

- **최초 실행 시**: `schema_signature_baseline.json`이 존재하지 않으면, 현재 추출된 스키마 서명을 기준선으로 신규 기록하고 `PASS`로 판정합니다 (최초 실행 실패 방지).
- **이후 검증 시**: 기준선 서명과 현재 서명의 해시를 비교하고, 불일치 시 다음 항목을 단계별로 검출하여 상세 보고합니다:
  - 누락 테이블 및 신규 추가 테이블
  - 컬럼 추가 / 삭제
  - 컬럼 타입 변경 (`VARCHAR` -> `TEXT` 등)
  - 컬럼 `nullable` 속성 변경
  - `primary_key`, `foreign_keys`, `indexes` 제약조건 변경

### 2.3 검증 보고서 생성 (`generate_verification_report`)

검증 실행 결과를 `data_preservation_report.json`으로 저장하며 다음 필드를 포함합니다:
- `generated_at`: ISO 8601 UTC 타임스탬프
- `head_commit`: 현재 Git HEAD 커밋 SHA
- `overall_verdict`: 전체 통과 여부 (`PASS` / `FAIL`)
- `passed_count` / `total_count`: 통과 항목 수 및 전체 항목 수
- `results`: 각 단계별 이름, 통과 여부(`status`), 상세 메시지(`message`)

## 4. 안전성 및 불변 원칙 준수 확인

- **읽기 전용(Read-Only) 보장**: SQLAlchemy Inspector 메타데이터 읽기 전용 함수만 사용하며, DDL/DML 쿼리 실행 경로가 전혀 없습니다.
- **데이터 무손실(G1) 보존**: 기존 4단계(ML 가중치, ChromaDB, DB 스키마 존재, 행 수 하한) 검증 로직 및 임계치를 완화하지 않았습니다.
- **행 수 하한 검사 유지**: 수집 증가분에 따른 정상 동작을 위해 `MIN_ROW_COUNT_RATIO` 하한 검사를 그대로 유지했습니다.
- **허용 범위(Scope) 준수**: `allowed_write_files`에 명시된 파일(`scripts/verify_migration.py`, `tests/test_g1_schema_signature.py`, `docs/analysis/task_a2659e1332c4.md`) 외의 파일은 수정하거나 생성하지 않았습니다.
