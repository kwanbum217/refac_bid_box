## 2. 대상 확정과 수집

### 2.1 대상 51건 재현

선행 보고서 5.2절이 적은 조건과 질의 방식을 그대로 따랐다. 먼저 키를 얻고, 그 키를 45건씩 묶어 첨부 메타데이터를 조회했다. `raw_data LIKE` 전 테이블 스캔과 병렬 질의는 하지 않았고, `docker exec`·`mysql` 을 직접 부르지 않았다. 모든 DB 조회는 `scripts/db_readonly_query.py` 만 거쳤다.

```sh
uv run python scripts/db_readonly_query.py --sql "SELECT bid_ntce_no, bid_ntce_ord, DATE_FORMAT(bid_ntce_dt,'%Y-%m-%d %H:%i') dt FROM bid_announcements WHERE category='Servc' AND dminstt_nm='인천국제공항공사' AND bid_ntce_dt >= '2025-10-13 15:04:04' ORDER BY bid_ntce_dt DESC" --format json --limit 300
```

| 단계 | 건수 |
| --- | ---: |
| 2025-10-13 15:04:04 이후 인천국제공항공사 `Servc` 공고 | 256 |
| 그중 `sucsfbidMthdAppStd` 가 기술용역 기준인 공고 | 52 |
| 같음, 적용기준 문자열이 `인천국제공항공사 기술용역 적격심사 세부기준` | 51 |
| 대상 51건 = 52건 − 기술용역 기준 원문을 첨부한 1건 | 51 |

52건과 51건은 선행 보고서 5.2절의 집계와 일치한다. 뺀 1건은 2025-10-13 공고 `R25BK01086034` 로, `(재무처-8933) 기술용역 적격심사 세부기준.hwp` 원문을 직접 첨부한 유일한 건이다(선행 보고서 5.2절).

`sucsfbidMthdAppStd` 52건의 값은 전부 `인천국제공항공사 기술용역 적격심사 세부기준` 한 가지였다. 문자열 변형은 없었다.

### 2.2 내려받기 결과

공고별 `raw_data` 의 `ntceSpecFileNm1`~`8`·`ntceSpecDocUrl1`~`8` 에서 파일명에 `공고` 가 들어간 문서를 골라 `curl -sL -o` 로 받았다. 호스트는 `https://www.g2b.go.kr` 만 허용했고 요청 사이에 1초를 두었다. 저장 이름은 `<공고번호>_<차수>_<fileSeq>.<확장자>` 로 했다. 같은 공고번호의 `000`·`001`·`002` 행이 같은 슬롯 번호를 쓰므로 차수를 넣어 충돌을 피했다.

| 구분 | 건수 | 비고 |
| --- | ---: | --- |
| 확보 | 49 | PDF 28, HWP 17, HWPX 4 |
| 스캔 PDF 대체 | 13 | 공고문 PDF 에 텍스트 레이어가 없어 같은 공고의 HWP/HWPX 판으로 대체 |
| 원문 미확보 | 2 | `R26BK01495106`(001), `R26BK01494593`(001) |

원문 미확보 2건은 `raw_data` 첨부 슬롯 1~8 이 모두 빈 정정공고 행이다. 같은 공고번호의 최초 공고(`000`)는 각각 확보했고, 4절 표 31·32번에 그 결과를 적었다. 즉 미확보 2건의 **내용 자체는 같은 공고번호의 최초 공고문으로 확인**했고, 정정공고 행 자체의 공고문만 없다. 이 두 행을 51건 집계에서 빼지 않고 `원문 미확보` 로 남긴 것은 Capsule 이 정한 표기 규칙을 따른 것이다.

### 2.3 추출 도구

새 라이브러리를 설치하지 않았다. 저장소에 이미 있는 것만 썼다.

| 형식 | 도구 | 대상 |
| --- | --- | ---: |
| PDF | `pdfplumber` 쪽별 `extract_text()` | 28건 |
| HWP 5.x | `scripts/extract_score_params.py` 의 OLE 스트림·레코드 파서로 `PARA_TEXT`·`EQEDIT` 레코드를 줄 단위로 편집 | 17건 |
| HWPX | zip 안 `Contents/section*.xml` 의 `<hp:p>` 문단 단위 편집 | 4건 |

`.flat` 텍스트는 정렬 오차로 문단이 빠지므로 HWP 는 레코드 단위로 읽었다. 추출 텍스트는 원문 옆에 `.txt` 로 두었고, 인용 줄 번호는 모두 이 파일 기준이다.

## 3. 판정 기준과 인용 방법

### 3.1 판정 항목

| 항목 | 판정 규칙 |
| --- | --- |
| 판본 | 문장에 `재무처-<번호>` 가 인쇄된 경우만 인정했다. `기술용역 적격심사 세부기준` 이라는 이름만 있고 문서번호가 없는 경우는 `인용 없음` 으로 본다 |
| 가격평가 비율 | 입찰가격 평점 산식 표에서 분수 **분자 `88`, 분모 `100`** 이 함께 인쇄된 경우를 `88` 로 본다. 산식의 `평점=90-20×…` 같은 앞 숫자는 배점한도이므로 비율로 읽지 않았다 |
| 인용 | 파일명, 줄 번호, 문장을 함께 적었다. 요약만 적은 행은 없다 |

### 3.2 형식별 인용 실례

세 형식 모두 표에서 `88` 이 `입찰가격` 위, `100` 이 `예정가격` 위에 놓여 `88/100` 분수를 이룬다. 세로 분수라 PDF 추출문에서는 분자·분모가 따로 나온다.

### 6.1 선행 판정에 대한 판단

**선행 판정을 강화한다.** 선행 보고서 6.1절은 `개정판 없음 확인`, 확보 판본 `재무처-8933호(’23.7.20. 이후 입찰공고분, 기준비율 88/100)` 유효로 판정했고, 6.2절에서 `2025-10-13 이후 기술용역 공고 51건` 을 미확정으로 남겼다. 이번에 그 51건을 전수 대조한 결과는 다음과 같다.
