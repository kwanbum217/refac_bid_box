# Task a48917d63a07 분석 및 조치 보고서: 공급망 보안 검증 CI 복구

## 1. 개요

- **Task ID**: `task_a48917d63a07`
- **목적**: main CI의 `공급망 보안 검증` job을 초록(정상 통과)으로 복구하고, 취약점 게이트의 fail-closed 원칙을 훼손하지 않는 상태로 유지합니다.
- **주요 대상 파일**:
  - `.github/workflows/ci.yml`
  - `.github/vulnerability-allowlist.yml`
  - `docs/ops/ci_supply_chain.md`
  - `docs/analysis/task_a48917d63a07.md`

## 2. 문제 상황 및 코디네이터 지시 검토

2026-09-04 코디네이터 실측에 따르면 main CI가 4회 연속 실패(run 33829413176, 33826578141, 33824753851, 33780911757)하였으며, `공급망 보안 검증` job이 12초~22초 만에 비정상 종료하였습니다. 로그 마지막 줄은 다음과 같았습니다.

```text
Trivy failed but result file not found: trivy-results.json
##[error]Process completed with exit code 1.
```

코디네이터는 실측을 통해 원인을 확정하고 추측으로 고치지 말 것과, 취약점 게이트를 약화시키지 말 것(continue-on-error 금지, 파일 부재 통과 금지, CRITICAL/HIGH 심각도 축소 금지, 근거 없는 allowlist 추가 금지)을 계약으로 확정하였습니다.

## 3. 실측 기반 원인 확정

`gh run view --job 100888992801 --log` 실행 로그 분석 및 로컬 환경 재현을 통해 다음과 같이 원인을 확정하였습니다.

### 3.1 1차 실패: Scan Python dependencies 단계의 PyYAML 부재 (로그 라인 940-943)

로그 근거:
```text
Traceback (most recent call last):
  File "<string>", line 1, in <module>
ModuleNotFoundError: No module named 'yaml'
##[error]Process completed with exit code 1.
```

`Scan Python dependencies` 스텝의 인라인 파이썬 명령 `IGNORE_ARGS=$(python3 -c "import yaml; ...")` 실행 시, GitHub Actions 러너(`ubuntu-latest`)의 기본 시스템 `python3`에는 `PyYAML` 모듈이 설치되어 있지 않아 `ModuleNotFoundError`가 발생하였습니다. `set -e` 정책에 의해 스텝이 즉시 exit code 1로 종료되었으며, 실제 `pip-audit` 명령은 실행조차 되지 못했습니다.

이전 시도(task_a48917d63a07)에서 `pip-audit`의 `--strict` 플래그가 존재하지 않는다는 오판으로 플래그를 제거하였으나, `pip-audit -S, --strict`는 실재하는 정규 옵션(`fail the entire audit if dependency collection fails`)이었습니다.

### 3.2 2차 결과: 후속 단계 건너뜀 및 Trivy 미실행

1차 실패로 인해 `Scan JavaScript dependencies`, `Build application image`, `Scan container image` (id: trivy-scan) 단계가 모두 skipped 처리되었습니다. 따라서 Trivy 스캔은 실행되지 않았고 `trivy-results.json` 파일도 생성되지 않았습니다.

### 3.3 3차 결과: Filter Trivy results against allowlist 단계의 착시 실패

`Filter Trivy results against allowlist` 단계는 `if: always()` 조건으로 설정되어 있어 실행되었습니다. 스크립트는 `steps.trivy-scan.outcome`이 `"success"`가 아니므로(`"skipped"` 상태) 파일 검사로 넘어갔고, 파일이 없어 `Trivy failed but result file not found: trivy-results.json`를 출력하고 종료 코드 1로 끝났습니다.

### 3.4 잠재 결함: Scan JavaScript dependencies 경로 및 PyYAML 의존성

`Scan JavaScript dependencies` 단계는 `working-directory: frontend`로 설정되어 있어 allowlist 파일 경로를 `../.github/vulnerability-allowlist.yml`로 참조해야 하며, 인라인 파이썬 파싱 명령 역시 러너 시스템 `python3` 대신 uv 가상환경의 `uv run python -c`로 실행해야 PyYAML 모듈 누락 오류를 방지할 수 있습니다.

## 4. 조치 내역

### 4.1 `.github/workflows/ci.yml` 수정

1. `Scan Python dependencies`, `Scan JavaScript dependencies`, `Filter Trivy results against allowlist`의 인라인 파이썬 명령을 `uv run python -c`로 일괄 전환하여 PyYAML 모듈 로드를 보장하였습니다.
