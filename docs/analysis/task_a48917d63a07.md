## 2. 문제 상황 및 코디네이터 지시 검토

2026-09-04 코디네이터 실측에 따르면 main CI가 4회 연속 실패(run 33829413176, 33826578141, 33824753851, 33780911757)하였으며, `공급망 보안 검증` job이 12초~22초 만에 비정상 종료하였습니다. 로그 마지막 줄은 다음과 같았습니다.

## 3. 실측 기반 원인 확정

`gh run view --job 100888992801 --log` 실행 로그 분석 및 로컬 환경 재현을 통해 다음과 같이 원인을 확정하였습니다.

### 3.1 1차 실패: Scan Python dependencies 단계의 문법 오류

로그 근거:
```text
공급망 보안 검증	UNKNOWN STEP	2026-09-04T02:25:04.1817407Z uvx --from pip-audit pip-audit -r /tmp/requirements.txt --strict $IGNORE_ARGS
공급망 보안 검증	UNKNOWN STEP	2026-09-04T02:25:04.3172050Z ##[error]Process completed with exit code 1.
```

`pip-audit` 명령에 전달된 `--strict` 옵션은 `pip-audit` CLI에 존재하지 않는 플래그입니다. `pip-audit`의 argparse는 알 수 없는 플래그인 `--strict`를 위치 인자 `project_path`로 파싱하며, `-r` 옵션과 `project_path`가 동시에 주어지면 상호 배타 제약에 의해 다음과 같이 실패합니다.

```text
pip-audit: error: argument project_path: not allowed with argument -r/--requirement
```

### 3.2 2차 결과: 후속 단계 건너뜀 및 Trivy 미실행

1차 실패로 인해 `Scan JavaScript dependencies`, `Build application image`, `Scan container image` (id: trivy-scan) 단계가 모두 skipped 처리되었습니다. 따라서 Trivy 스캔은 실행되지 않았고 `trivy-results.json` 파일도 생성되지 않았습니다.

### 3.3 3차 결과: Filter Trivy results against allowlist 단계의 착시 실패

`Filter Trivy results against allowlist` 단계는 `if: always()` 조건으로 설정되어 있어 실행되었습니다. 스크립트는 `steps.trivy-scan.outcome`이 `"success"`가 아니므로(`"skipped"` 상태) 파일 검사로 넘어갔고, 파일이 없어 `Trivy failed but result file not found: trivy-results.json`를 출력하고 종료 코드 1로 끝났습니다.

### 3.4 잠재 결함: Scan JavaScript dependencies 경로 문제

`Scan JavaScript dependencies` 단계는 `working-directory: frontend`로 설정되어 있었으나, 파이썬 필터 스크립트가 `.github/vulnerability-allowlist.yml`을 읽고 있어 `frontend/.github/vulnerability-allowlist.yml`을 찾지 못해 `FileNotFoundError`가 발생하는 잠재 결함이 존재하였습니다.

- `CVE-2026-24049` (`wheel`): 임의 코드 실행 취약점. 외부 wheel 파일 다운로드/설치 경로 차단으로 악용 가능성 없음.
