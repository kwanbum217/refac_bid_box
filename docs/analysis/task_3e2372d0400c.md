## 1. 개요 및 배경

2026-08-31 외부 감사에서 확인된 결함에 따라, 빌더와 리뷰어가 동일한 모델 계열(Provider)로 배정되어 상호 검증의 독립성이 훼손되는 문제를 원천 차단하는 작업을 수행하였습니다.

- **문제점 1 (리뷰어 독립성 미보장)**: 기존 `select_model`은 `role`, `risk`, `exclude` 등만 인자로 전달받아 해당 Task 빌더가 어느 Provider 계열이었는지 알지 못했습니다. 이로 인해 주 모델 장애/probe 실패 시 fallback 경로에서 빌더와 동일한 모델 계열로 수렴할 수 있었으며, 독립 Provider가 소진되었을 때 조용히 동일 계열이 배정되는 취약점이 존재했습니다.
- **문제점 2 (commit_count 타입 우회 가능성)**: `commit_count`에 대한 엄격한 정수 타입 검증이 누락되어 문자열 `"0"`, 불리언(`True`/`False`), 실수형 등의 비정상 형식이 들어올 경우 무작업 완료(`succeeded`) 감시를 우회할 위험이 있었습니다.

## 2. 주요 변경 내역

### 2.1 Provider 판정 및 제외 로직 (`scripts/orca_model_router.py`)
1. **Provider 판정 함수 추가**:
   - `MODEL_PROVIDER_PREFIXES` 매핑 정의 및 `provider_for_model(model_or_pool: str, strict: bool = True) -> str` 구현.
   - `MODEL_POOL` 등록 정보와 접두사 매핑을 기반으로 Provider 계열(`gemini`, `qwen`, `claude`, `codex`, `cursor`, `opencode`, `cerebras`, `kimi-openrouter` 등)을 단일 진실 원천으로 판정.
   - 알 수 없는 모델 ID가 전달될 경우 `strict=True`에서 `ValueError`를 발생시키고, `strict=False`에서는 `'unknown'`을 반환하여 임의 기본값으로 침묵 통과하지 못하도록 차단.
2. **`ModelRoutingError` 확장**:
   - `exclude_providers` 인자를 받아 예외 객체에 보존.
3. **`select_model`에 `exclude_providers` 인자 추가 및 Fail-Closed 강제**:
   - 주 모델(`primary`)과 대체 모델(`fallback`) 선정 시 지정된 Provider 계열을 후보에서 완전 배제.
   - Provider 제외 적용 후 사용 가능한 후보가 없으면 즉시 `ModelRoutingError`를 발생시켜 조용한 동일 계열 fallback을 차단.
   - `TIER_POLICY`의 정본 값은 변경하지 않고 유지.
4. **`route()` 및 CLI 명령어 연동**:
   - `route()` 함수 및 CLI(`classify`, `route`)에 `--exclude-provider` 지원 추가.

### 2.2 리뷰어 배정 배선 및 `commit_count` 검증 (`scripts/orca_taskctl.py`)
1. **`validate_commit_count` 함수 구현**:
   - `isinstance(commit_count, bool)` 및 비정수형(`str`, `float` 등) 입력 시 `타입 위반`으로 판정.
   - 음수(`commit_count < 0`) 입력 시 `값 위반`으로 판정.
   - 쓰기 작업에서 `status == "succeeded"`인데 `commit_count == 0`인 경우 `규약 3.3 위반`으로 처리.
2. **리뷰어 배정 시 빌더 Provider 제외 배선**:
   - `resolve_dispatch_model`: `role == "reviewer"`일 때 빌더 Provider(`builder_provider` 또는 `builder_model` 파생값)를 추출하여 `exclude_providers`에 주입. 빌더 Provider를 알 수 없는 경우 `warning` 및 `builder_provider="unknown"`을 명시 기록. 독립 Provider 제외 후 후보 소진 시 `ModelRoutingError`로 fail-closed.
   - `finalize_task`: `reviewer_model`이 미지정(`None`)인 경우 빌더의 메타데이터/Capsule/보고서에서 Provider를 조회하여 `select_model(role="reviewer", risk=risk, exclude_providers=[b_provider])`로 독립 리뷰어 모델을 자동 선택 후 `orca_run_reviewer.py`에 전달.
