# CSRF 토큰 검증 도입 보고

## 적용 범위

SSR 브라우저 폼인 `/accounts/login/`, `/accounts/signup/`, `/accounts/logout/` 화면에 서명 토큰을 발급하고, 상태 변경 SSR 요청 중 로그아웃 제출을 서버에서 검증합니다. 로그인·회원가입은 세션이 아직 없는 인증 진입 경로이며 기존 비자바스크립트 소비자 호환을 위해 서버 강제를 하지 않고 폼에는 토큰을 포함했습니다.

브라우저 폼이 없는 순수 JSON API(`/api/v1/accounts/*`, 챗봇, 예측, 자동화, 입찰 수집)는 기존 API 소비자를 깨뜨리지 않도록 CSRF 강제 대상에서 제외했습니다. 워커가 `X-BIDBOX-CALLBACK-TOKEN`으로 인증하는 `/api/v1/automation/job/{job_id}/callback`도 기계 간 인증 경로이므로 명시적으로 제외했습니다.

## 구현

토큰은 `settings.SECRET_KEY`와 전용 salt를 결합한 SHA-256 HMAC 및 타임스탬프 형식으로 발급하고, 쿠키와 폼 값을 상수 시간 비교 후 서명·만료를 검증합니다. `CSRF_PROTECTION_ENABLED`는 기본값 `True`이며 비활성화 시 SSR 검증을 건너뜁니다. 세션 쿠키 속성과 CORS 설정은 변경하지 않았습니다.
