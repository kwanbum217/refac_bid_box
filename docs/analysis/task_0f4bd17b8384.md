## 1. 과업 개요

워커 터미널의 권한 자동 승인 감시기(`scripts/orca_auto_approve.py`)에서 `$( )` 명령 치환과 `while read` / `for in` 루프가 섞인 안전한 읽기 전용 조사 명령이 화이트리스트를 벗어나 통째로 보류되던 결함을 해결하였습니다.
단순히 형태를 열거하여 예외 처리하는 대신, 명령 치환 및 루프 본문의 내부 명령까지 동일한 보안 정책 테이블과 방어선(DANGEROUS 정규식, SECRET_PATH, REDIRECT_DENY)으로 재귀 판정하도록 고도화하였습니다.

## 2. 주요 변경 내역

### 2.1. 명령 치환 `$( )` 안전 추출 및 재귀 판정
- `UNSPLITTABLE_METACHARS`: 백틱(`` ` ``)과 프로세스 치환(`<( )`, `>( )`)은 무조건 보류를 유지하면서, `$( )`는 `extract_command_substitutions`를 통해 안전하게 추출하도록 분리하였습니다.
- `extract_command_substitutions`: 작은따옴표 안의 리터럴은 보존하고 큰따옴표 및 따옴표 밖의 최상위 `$( )`를 추출하여 안전한 자리표시자(`__SUBST__`)로 치환합니다.
- 재귀 검증: 추출된 내부 명령 각각을 `classify_command(inner, depth=depth+1)`로 판정하여, 내부와 외부가 모두 승인일 때만 최종 승인합니다.
- 안전 장치: `MAX_SUBSTITUTION_DEPTH = 3` 상한 설정 및 괄호 불일치(`$(` 미폐쇄) 시 fail-closed 보류 처리하였습니다.

### 2.2. `git merge-base` 화이트리스트 등록
- `SAFE_GIT_SUBCOMMANDS`에 `merge-base`를 추가하고, 허용 옵션(`--all`, `-a`, `--fork-point`, `--octopus`, `--independent`, `--is-ancestor`)을 등록하여 `git log --oneline $(git merge-base main HEAD)..HEAD` 형태의 조사가 정상 승인되도록 지원하였습니다.

### 2.3. 루프 구조 토큰 및 셸 내장 `read` 지원
- `SAFE_SHELL_BUILTINS`: `read`, `true`, `:`, `break`, `continue` 지원.
- `check_loop_structure_balance`: `while/for`, `do`, `done`의 구조적 균형(토큰 쌍 일치)을 검증하여 미완성 루프로 인한 터미널 블로킹을 방지합니다.
- `classify_segment`:
  - `while <cond>`: 조건 명령을 `classify_command`로 재귀 검증.
  - `do <body...>`: 본문 명령을 `classify_command`로 재귀 검증.
  - `done`: 루프 종료 토큰 단독 사용 시 승인.
  - `for <var> in <items...>`: 변수명 식별자 유효성, `in` 키워드 강제, items 내 비밀 경로 및 위험 패턴 차단.
- 본문/조건 중 단 하나라도 위험 명령(`rm -rf`, `git push` 등)이나 보류 대상이 있으면 전체 루프가 보류됩니다.

### 2.4. 사양 외 기능 차단 불변조건 유지
- `if/then/else/fi`, 함수 정의, 서브셸 `( )`는 종전대로 무조건 보류됩니다.
- 백틱 및 프로세스 치환은 정규식 수준에서 차단됩니다.
- `PIPELINE_SEPARATORS`, `DANGEROUS`, `REDIRECT_DENY`, `SECRET_PATH` 상수는 약화 없이 그대로 유지되었습니다.
