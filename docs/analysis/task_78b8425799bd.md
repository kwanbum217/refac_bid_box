## 1. 개요 및 결함 원인

### 1.1 현상
- Wave AI 조율 중 정상 작업 중인 워커 화면에 Dispatch 지시문(preamble) 템플릿이 남아있을 때, 감시기(`scripts/orca_worker_watch.py`)가 이를 실제 `worker_done` 보고로 오인하여 `[차단:실패 정체] worker_done 완료 메시지에 reportPath 가 누락됨`으로 오탐하는 문제가 발생했습니다.

### 1.2 근본 원인 분석
1. **Preamble 지시문 미제외**:
   - 코디네이터가 워커에 전달하는 Dispatch 지시문은 `=== CLI COMMANDS ===`부터 `=== TASK ===`까지 CLI 사용법 템플릿을 포함합니다. 이 템플릿 구간이 차단 신호 감지 대상에서 제외되지 않았습니다.
2. **줄 단위 파싱으로 인한 백슬래시(`\`) 연결 단절**:
   - `orca orchestration send` 명령 템플릿이 여러 줄에 걸쳐 백슬래시로 이어져 있어, `--type worker_done`이 위치한 줄과 `--report-path`가 위치한 줄이 분리되었습니다. 기존 코드는 줄 단위로만 검색하여 `--report-path`를 찾지 못하고 누락으로 판정했습니다.
3. **꺾쇠 자리표시자(`<...>`) 미구분**:
   - `<short status>`, `<optional: path to the full artifact>`와 같은 자리표시자 템플릿 값을 실제 실행된 명령으로 취급했습니다.
4. **단순 키워드 매칭의 과도한 범위**:
   - `check_worker_done_report`에서 `"worker_done" in line.lower()`로 검사하여, 일반 대화나 작업 설명(예: "worker_done 오탐 수정")에 해당 단어가 포함되기만 해도 보고 명령으로 오인했습니다.

## 2. 구현 내용

### 2.1 Preamble 제외 (`strip_preamble`)
- `=== CLI COMMANDS ===`부터 `=== TASK ===`까지의 구간을 정규식으로 탐지하여 감시 대상 텍스트에서 제거합니다.

### 2.2 백슬래시 줄 결합 (`join_continuation_lines`)
- 터미널 출력에서 백슬래시(`\`)로 끝나는 연속 줄을 하나의 논리적 명령 줄로 결합합니다.
- 이를 통해 다중 줄 명령에서도 `--type worker_done`과 `--report-path`가 동일한 명령으로 온전히 분석됩니다.

### 2.3 템플릿 및 자리표시자 필터링 (`is_placeholder_command`, `is_placeholder_value`)
- `<...>` 형태의 꺾쇠 자리표시자가 포함된 명령은 템플릿으로 판별하여 차단 판정에서 제외합니다.
- 추출된 `target_path`가 자리표시자인 경우 실제 파일 경로로 취급하지 않습니다.

### 2.4 실제 worker_done 신호 줄 엄격 판별 (`is_worker_done_signal_line`)
- `--type worker_done`, `{"type": "worker_done"}`, `worker_done_guard`, `send ... worker_done` 등 실제 전송 명령/구조화 메시지만 선별하여, 자연어 문장에 단어가 포함된 경우를 무시합니다.

### 2.5 진짜 양성(True Positive) 보존
- 워커가 `--report-path` 없이 실제로 `worker_done`을 전송한 경우(`test_worker_done_missing_report_path_classified_as_blocked`)는 여전히 `failure`로 탐지됩니다.
- 지정된 보고서 파일이 디스크에 실존하지 않는 경우(`test_worker_done_nonexistent_report_file_classified_as_blocked`)도 여전히 `failure`로 탐지됩니다.
