## 3. 계산 가능 후보와 근거

### 3.1 수동 평가 8,413건에 공고 명시 기준으로 계산할 부분 집합은 없다

**판정: 0건.**

근거는 세 가지다.

1. **명시 신호가 없다.** 2.1절대로 `app_std` 는 `관리규정외(기타)` 8,261건과 `None` 152건뿐이다. 2026-11-15 사용자 결정이 쓴 조건 "공고 `raw_data.sucsfbidMthdAppStd` 가 `조달청 일반용역 적격심사 세부기준` 을 명시"([handoff_20261115_rules_wave.md](../handoff/handoff_20261115_rules_wave.md) 2절)을 만족하는 행이 하나도 없다.
2. **판정 순서상 먼저 막힌다.** 수동 평가 검사는 `_resolve_by_method_name` 의 3단계다(`evaluation_rules.py:4323-4332`). 공고 명시 조달청 기준 분기는 `LOCAL_RULE_NOT_FOUND` 를 받은 뒤에 도는 4단계 이후 분기다(`:4044`, `:4072`). 수동 평가 공고는 3단계에서 조기 반환하므로 그 분기에 도달하지 않는다.
3. **낙찰방법명이 자체 기준을 지목한다.** 8,413건 전량이 `적격심사제-관리규정외 수기심사(총점입력)` 이다. `관리규정외` 는 "관리규정 외"라는 뜻이고, 적용 기준 값도 `관리규정외(기타)` 다. 표준 별표를 적용한다고 적힌 공고가 아니다.

따라서 사용자 결정의 적용 범위를 수동 평가까지 넓히더라도 대상이 0건이라 효과가 없다. 이 사실은 규칙 보완 우선순위 판단에 직접 영향을 준다.

### 3.2 수동 평가 차단은 정당하다

**판정: 정당하다. 차단을 유지해야 한다.**

1. **차단 근거가 코드에 명시돼 있다.** `evaluation_rules.py:4324-4331` 이 `관리규정외 수기심사` 를 만나면 "발주기관 자체 기준이 적용되므로 공고문 확인이 필요하여 계산을 차단합니다"로 반환한다. 설계 문서도 같은 순서를 적는다([servc_qualification_evaluation_design_20260909.md](../design/servc_qualification_evaluation_design_20260909.md) 3절 3항 "계산 차단, 공고문 확인 요구").
2. **필요한 값이 공고 데이터에 없다.** 계산에는 가격배점한도(B)·평점계수(k)·기준비율·통과점수 네 값이 필요하다. 그런데 나라장터 입찰공고 OpenAPI 응답 필드 113개에 B·k·T 가 없다는 실측이 있다([20260930_score_params_acquisition.md](20260930_score_params_acquisition.md) 3.1절, "B·k·T 필드 없음"). 같은 문서가 `sucsfbidMthdAppStd` 를 "적용 기준 문서명, 별표 식별 문자열. B·k 값 아님"으로 규정한다.
3. **하한율이 흩어져 표준 배점표로 환원되지 않는다.** 2.6절 표본과 [servc_qualification_evaluation_design_20260909.md](../design/servc_qualification_evaluation_design_20260909.md) 2.2절이 같은 결론이다. 별표 기본값을 강제하면 틀린 점수가 나온다.
4. **이미 사용자 입력 경로가 있다.** API 는 이 차단에 대해 B·k·기준비율·통과점수를 입력받아 계산하는 경로를 갖고 있다(`evaluations.py:550`, `:1904-1914`). 네 값이 다 없으면 부족 항목을 안내하고 차단을 유지한다. 즉 "계산 불가"가 아니라 "자동 계산 불가, 입력 대기"다. 이 구분은 선행 문서 [blocked_reason_breakdown_20261106.md](blocked_reason_breakdown_20261106.md) 1.2절 4항이 이미 지적했다.

### 3.3 기타 차단 117건 중 산식 계산 후보는 최대 13건이다

공개 기준을 명시한 117건을 차단 코드별로 나누면 아래와 같다.

| 차단 코드 | 공개 기준 명시 | 실제 계산 가능성 | 근거 |

| `NON_PRED_PRICE` | 104 | **불가** | 비예가 104건 전량. 예정가격이 없어 가격점수 분모를 확정할 수 없다 |
| `RULE_NOT_FOUND` | 5 | **불가** | 조달청 여객 고시금액 미만 별표 없음. 근사 금지(D17) |
| `LOCAL_SERVICE_TYPE_UNRESOLVED` | 4 | **불가** | 용역 세부유형 미확정. 사용자 선택이 있어야 확정 |
| `LOCAL_RULE_NOT_FOUND` | 3 | **부분 가능** | 공고 명시 조달청 기준 분기가 이미 존재하나 3건 모두 통과하지 못함 |

**`RULE_NOT_FOUND` 5건은 다른 축의 결함이다.** 5건 모두 낙찰방법명이 `적격심사제-화물 육상운송용역 적격심사 추정가격 고시금액미만` 이고 적용 기준은 `조달청 일반용역 적격심사 세부기준` 이다. 그런데 조달분류가 `도로여객운송서비스` 라 `correct_passenger_method_name`(`evaluation_rules.py:2147`)이 화물을 여객으로 교정하고, 여객에는 고시금액 미만 별표가 없어 `:4232` 에서 차단된다. 적용 기준을 명시해도 풀리지 않는다. 별표 자체가 레지스트리에 없기 때문이다. 선행 문서 [blocked_misc_rules_20261115.md](blocked_misc_rules_20261115.md) 2절 원인 C 가 같은 판정이다.

**`LOCAL_RULE_NOT_FOUND` 3건은 이미 존재하는 분기를 3건 모두 통과하지 못한다.** 세 건 모두 적용 기준이 `조달청 일반용역 적격심사 세부기준` 이다.

세 건 모두 공고일이 통합특별시 지침 시행일(2026-07-16) 이후다. 그런데 `_is_jngj_pps_stated_announcement`(`evaluation_rules.py:3084`)는 통합 지역 축을 요구하므로 세종 공고는 대상이 아니다. 전남 두 건은 통합특별시 축이 맞지만, 학술연구는 전남 준용에서 제외되고(`:3068` `return service_type != "ACADEMIC"`), 보험은 지침에 별표가 없다. 즉 **공고 명시 기준 분기가 존재함에도 3건 모두 다른 조건에서 걸린다.** 이 3건은 "공고 명시 기준을 더 넓히면 풀린다"가 아니라 "별표를 추가 적재해야 풀린다"에 가깝다.

**`LOCAL_SERVICE_TYPE_UNRESOLVED` 4건은 사용자 선택 대기다.** 적용 기준이 `학술연구용역 적격심사 세부기준` 3건, `건설폐기물처리용역 적격업체 평가기준` 1건이다. 차단 사유가 "용역 세부유형을 선택해 주십시오"이므로(`evaluation_rules.py:2513-2521`, `:2587-2593`), 적용 기준 명시와 무관하게 사용자 입력이 있어야 확정된다.

**`RULE_REGIME_MISMATCH` 1건은 차단 유지 결정 대상이다.** `R26BK01375736`(전남광주통합특별시교육청 AI교육원)은 공고일이 2026-03-06 인데 적용 기준이 조달청 일반용역 기준이다. 여객 5억원미만 별표의 시행일이 공고일보다 늦어 차단된다(`evaluation_rules.py:4256-4269`). 선행 문서 [blocked_misc_rules_20261115.md](blocked_misc_rules_20261115.md) 2절 원인 D 와 [handoff_20261115_rules_wave.md](../handoff/handoff_20261115_rules_wave.md) 4절이 "차단이 정당, 유지"로 적었다.

## 5. 확인하지 못한 것

1. **첨부 원문을 열지 않았다.** 이번 조사는 판정 덤프와 `raw_data` 필드만 봤다. `관리규정외(기타)` 8,261건의 첨부에 자체 심사기준표가 실제로 실려 있는지, 실려 있다면 B·k·기준비율·통과점수를 기계적으로 읽을 수 있는 비율이 얼마인지는 확인하지 않았다. 선행 문서 [manual_eval_extraction_pilot_20261106.md](manual_eval_extraction_pilot_20261106.md)가 규칙이 적용된 공고 120건에서 잰 추출률(B 11.70%, k 6.32%)은 수동 평가 8,413건에 그대로 적용할 수 없다고 그 문서 스스로 2.4절 3항에 적었다.
2. **수동 평가 8,413건의 하한율 분포를 전량 재지 않았다.** 2.6절은 등간격 50건 표본이다. 선행 문서의 "1~100 제각각" 서술과 방향은 같지만 전량 분포는 이번에 세지 않았다.
3. **`관리규정외(기타)` 값의 생성 주체를 확인하지 못했다.** 이 값이 나라장터가 주는 원본인지 수집 과정에서 채운 값인지 코드와 문서에서 확인되지 않았다. `grep` 으로 `src/`·`scripts/`·`docs/` 를 뒤졌으나 이 문자열을 만드는 코드나 정의를 찾지 못했다. 필드 의미 해석에는 영향이 없으나(자체 기준 표기라는 점은 `mthd_nm` 이 뒷받침한다), 값의 출처는 확인이 필요하다.
4. **세종·전남 지침 원문을 직접 열지 않았다.** 3.3절의 "별표 없음" 판정은 `evaluation_rules_local.py` 의 규칙 선언 목록(2.5절)에 근거한다. 원문에 별표가 있는데 적재하지 않은 것인지, 원문에도 없는 것인지는 구분하지 못했다.
5. **`docs/context/CURRENT_STATE.md` 의 8,420건 수치를 재검증하지 않았다.** 이번 입력 자료는 차단 8,591건이고 그중 수동 평가 8,413건과 `LOCAL_RULE_NOT_FOUND` 3건·`LOCAL_SERVICE_TYPE_UNRESOLVED` 4건이 사용자 입력 경로가 있다. 8,413 + 3 + 4 = 8,420 이라 산술은 맞으나, 그 경로가 실제로 전량 계산에 도달하는지는 API 를 실행해 확인하지 않았다(캡슐이 서비스 모듈 호출을 금지한다).
