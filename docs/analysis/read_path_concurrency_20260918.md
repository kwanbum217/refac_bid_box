## 1. 한 줄 요약

G3 상시 과제로 미측정 읽기 경로를 훑은 결과 단일 요청 웜에서는 전 경로가 20ms 이하였으나, 동시성 c10 에서 낙찰 목록 P95 가 219.69ms 로 튀었습니다. 원인은 목록 직렬화가 행마다 공고를 조회하는 N+1 이었고, 일괄 조회로 바꾼 뒤 3회 재측정 중앙값 79.16ms 를 얻었습니다.

## 2. 왜 지금 쟀는가

`AGENTS.md` 는 G3 스택 최적화를 일회성 과업이 아니라 상시 과제로 규정합니다. 정본 레이턴시 게이트는 예측 API 와 RAG SSE, 대시보드 통계에 걸려 있고, 공고·낙찰 목록과 홈 컨텍스트는 게이트 대상이 아니어서 실측 기록이 없었습니다. 이 문서는 그 공백을 메운 회차입니다.

## 5. 원인: 목록 직렬화의 공고 조회 N+1

호출 사슬은 다음과 같았습니다.

| 위치 | 동작 |
| --- | --- |
| `src/app/api/v1/bids.py` 목록 응답 | `page_obj.object_list` 의 행마다 `_serialize_result(db, row)` 호출 |
| `_serialize_result` | `result.display_winning_rate(db)` 호출 |
| `src/app/models/bids.py` `display_winning_rate` | `reference_basis_winning_rate` 를 거쳐 `matching_announcement(db)` 호출 |
| `matching_announcement` | 행마다 공고를 **최대 두 번** 질의 |

두 번인 이유는 차수 탐색이 2단이기 때문입니다. 먼저 `bid_ntce_ord` 등치로 찾고, 없으면 같은 조건을 다시 조회해 차수 앞의 0 을 떼어 정규화 비교합니다. 인스턴스 캐시(`_matching_announcement_cache`)가 있지만 같은 인스턴스를 다시 물었을 때만 듣기 때문에 목록의 N+1 을 줄이지 못합니다.

20행 목록이면 공고 질의가 최대 40회 추가됩니다. 단일 요청에서는 이 비용이 14ms 안에 묻히지만, 동시 10 요청이면 커넥션 풀(`pool_size=10`, `max_overflow=20`)을 놓고 경합이 생깁니다.

## 6. 조치

`419274cd` 로 병합했습니다.

| 항목 | 내용 |
| --- | --- |
| 새 함수 | `preload_matching_announcements` 가 `(bid_ntce_no, category)` 복합 키를 `tuple_().in_()` 으로 일괄 조회 |
| 캐시 선채움 | 각 행의 `_matching_announcement_cache` 를 미리 채워 기존 호출부를 그대로 둠 |
| 2단 탐색 재현 | 등치 일치 -> 선행 0 제거 정규화 일치 순서를 메모리에서 동일하게 재현 |
| 적용 경로 | 낙찰 목록, 홈 컨텍스트, 낙찰 상세 관련 결과, 공고 상세 과거 결과 |
| 테스트 | `tests/test_bid_result_serialization_batch.py` 8건 |

**값 동등성이 이 변경의 합격 조건이었습니다.** `display_winning_rate` 는 공고의 `prediction_reference_amount` 로 재계산한 값이고 공고를 못 찾으면 `sucsf_bid_rate` 로 떨어지므로, 일괄 경로가 단건 경로와 다른 공고를 고르면 조용히 틀린 낙찰률이 화면에 나갑니다.

독립 리뷰가 확인한 사항입니다. 2 차 정규화 탐색에서 원본은 정렬 없는 `limit(10)`, 새 경로는 차수 정렬 후 앞 10건이라 후보 집합이 갈릴 수 있었습니다. 리뷰어가 공고 10건 초과 공고군과 그에 걸친 낙찰 11건을 찾아 대조한 결과, 원본의 무정렬 `LIMIT 10` 도 유니크 인덱스 순서로 `000`~`009` 를 돌려주어 두 경로가 같은 공고를 고릅니다. 1 차 등치는 `(bid_ntce_no, bid_ntce_ord, category)` 유니크 제약 때문에 최대 한 건이라 정렬 추가의 영향이 없습니다.

| 경로 | 병합 전 | 병합 후 중앙값 | 변화 |

**이 변화율을 개선 효과로 그대로 읽으면 안 됩니다.** 이번 변경과 무관한 대조군 두 경로도 함께 줄었습니다. 병합 전 측정은 워커 3대가 돌던 중의 1회 표본이고 병합 후는 조용한 상태의 3회이므로, 두 측정의 배경 부하가 다릅니다. 대조군 감소폭을 배경 잡음으로 보면 낙찰 목록의 순개선은 -38%p 에서 -54%p 사이로 보수적으로 잡아야 하며, 정확한 크기는 이 표본으로 확정할 수 없습니다.

**반면 질의 수 감소는 표본과 무관하게 확정입니다.** `tests/test_bid_result_serialization_batch.py` 의 `test_batch_query_count_does_not_scale_with_rows` 가 질의 수를 직접 세어 행 수에 비례하지 않음을 검증합니다. 레이턴시 개선의 크기는 미확정이고, 개선의 방향과 기전은 확정입니다.

**확정값이 필요하면 A/B 로 다시 재야 합니다.** 같은 머신 같은 시각에 선채움을 켠 경로와 끈 경로를 번갈아 재는 방식이며, 이번 세션에서는 수행하지 않았습니다.
