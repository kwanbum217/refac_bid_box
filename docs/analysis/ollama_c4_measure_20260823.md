## 5. Ollama 다중화 시 자원 점유 및 직렬화 거동 분석

### 5.1 관측된 자원 점유 및 큐잉 거동

1. **단일 모델 인스턴스 직렬화**:
   - Ollama는 단일 슬롯 환경에서 동시 다중 요청이 유입될 때 LLM 토큰 생성을 내부적으로 직렬화(Queueing)합니다.
   - 단일 스트림 요청 시 첫 토큰 지연은 1.1~1.8초대로 안정적이나, 다중 SSE 요청이 동시 진입하면 선행 요청의 생성이 끝날 때까지 후속 요청이 대기하여 First-Token Time(TTFT)이 급격히 증가(과거 c4 동시 스트리밍 시 최대 18초 관측)하는 병목 기전이 확인되었습니다.
2. **정형 ML 예측 vs LLM 추론의 부하 분리**:
   - 반면 정형 데이터 낙찰가 예측 API는 FastAPI 인프로세스 싱글톤 모델과 `PREDICTION_GC_MODE=freeze`를 통해 동시성 4(c4) 환경에서도 P50 26.8~28.3ms, P95 36.5~38.2ms로 100ms 대비 60ms 이상의 안정적인 마진을 보였습니다.
   - 따라서 LLM 다중화(c4 이상 동시성) 지원을 위해서는 `OLLAMA_NUM_PARALLEL` 설정 또는 모델 인스턴스 복제 풀링 인프라가 필수적입니다.

3. 실측된 지표와 직렬화 거동 분석을 토대로 정본 c4 기준선을 공식 확정합니다.
