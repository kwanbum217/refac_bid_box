## 1. 결론 요약

| 필드 | 획득 가능 여부 | 확정 경로 | 비고 |
| --- | :---: | --- | --- |
| T (통과점수) | **가능** | 첨부 공고문 본문 또는 적격심사 세부기준 제10조의 "종합평점이 N점" 문구 | 문서가 기계 판독 가능할 때 |
| B (가격 배점한도) | **조건부 가능** | 공고에 첨부된 적격심사 [별표] 의 "입찰가격" 배점한도 표 | 별표가 첨부되고 표 구조가 복원될 때만 |
| k (평점계수) | **조건부 가능** | 같은 [별표] 의 "입찰가격 평점 계산식" | 상동 |

**핵심 판정: B·k·T 는 나라장터 OpenAPI 응답과 공고 상세 페이지에는 없다. 공고에 첨부된 적격심사 세부기준 [별표] 문서에만 있다. 그 첨부가 존재하고 기계 판독 가능한 형식(HWPX/HWPML/HWP)일 때만 추출할 수 있다. 스캔 이미지 PDF 첨부는 추출 불가다.**

기존 정본의 기재("가격배점과 계수와 통과점수는 별표마다 다른데 공고 데이터에 들어 있지 않습니다", `src/app/schemas/evaluations.py`)는 **OpenAPI 응답과 공고 본문에 한해** 정확하다. 본 Task 는 그 위에 **첨부 별표 문서**라는 새 경로를 실측으로 추가한다.

## 2. 배경

`src/app/services/evaluation_scoring.py` 의 가격점수 산식은 다음과 같다.

```
x = ROUND_HALF_UP(입찰금액 / 예정가격, 소수점 4자리)
P = B - k * |(기준비율 - x) * 100|
적격 = 결격사유 없음 AND 입찰금액 <= 예정가격 AND (Q + P) >= T
```

B·k·T 는 별표마다 다르며, 현재는 `QualificationInput` 으로 **사용자가 직접 입력**한다. 본 Task 는 이 셋을 공고에서 자동으로 얻을 수 있는지 확정한다.

### 3.3 경로 C - 첨부 공고문 (spec doc / stdNtceDocUrl)

2026-09-01~15 Servc 공고에서 첨부 120건을 실제로 내려받아 분류한 결과:

| 형식 | 건수 |
| --- | :---: |
| HWPX (zip) | 43 |
| 바이너리 HWP (OLE) | 39 |
| PDF | 38 |

HWPX 43건 중 27건에서 최소 한 개의 배점 관련 키워드가 나왔다. 그러나 "배점한도"가 나온 문서는 모두 **협상에의한계약** 문서였고, 그 배점한도는 "기술능력평가분야 배점한도의 85% 이상" 처럼 **기술평가 통과 기준**을 가리킨다. 적격심사의 가격 배점한도 B 가 아니다.

적격심사 공고문은 B·k 를 담지 않고 [별표] 를 참조만 한다. 실제 예(공고 R26BK01706814, 건설폐기물처리용역):

```

   낙찰자로 선정합니다.
```

- T = 95 는 본문에 있다.
- B·k 는 "별표 3" 을 가리킬 뿐 본문에 없다.

**판정: 경로 C 는 T 는 주지만 B·k 는 주지 않는다.**

### 3.4 경로 D - 적격심사 세부기준 [별표] 첨부 (핵심 발견)

#### 3.4.1 [별표 9] 에서 B·k 실측 (공고 R26BK01707844)

첨부 `[ATT3]1-1-2. (개정) [별표 9] 수요기관 지정형 적격심사(조달청 일반용역 적격심사 세부기준).hwpx` (84,808 바이트)의 표를 실제로 파싱한 값이다.

배점한도 표(발췌):

| 구 분 | 심사분야 | 심사항목 | 배점한도 - 추정가격 5억원 이상 | 배점한도 - 추정가격 5억원 미만 |
| --- | --- | --- | :---: | :---: |
| Ⅱ. 입찰가격 | ※ 입찰가격 평점 계산식 참조 | | **60** | **70** |

입찰가격 평점 계산식(발췌, 원문 그대로):

```
추정가격 고시금액 이상 : 평점(점) = 배점한도 - 2 x |(90/100 - 입찰가격/예정가격)| x 100
추정가격 고시금액 미만 : 평점(점) = 배점한도 - 4 x |(90/100 - 입찰가격/예정가격)| x 100
```

따라서 별표 9 기준으로 **k = 2(고시금액 이상) 또는 4(미만), 기준비율 = 90/100 = 0.9, B = 60(5억원 이상) 또는 70(미만)** 이다. 이는 `evaluation_scoring.py` 의 `P = B - k*|(기준비율 - x)*100|` 와 동일한 형태다.

공고 R26BK01707844 는 `sucsfbidMthdNm` 이 `... 추정가격 고시금액 이상` 이고 추정가격이 269,026,364원이므로 **B = 70, k = 2, 기준비율 = 0.9** 가 확정된다.

#### 3.4.2 T 실측

[별표 9] 본문에는 통과점수 문구가 없다. T 는 다음 두 곳에서 나온다.

- 공고문(공고 R26BK01707844 첨부 `[ATT2]1-1. 입찰공고문.hwp`): `... 종합평점이 85점 이상인 자 중에서 최고점수인 자를 낙찰자로 결정합니다.`
- 세부기준 본문(조달청공고 제2026-390호, HWPML): `제10조(낙찰자 결정) ① ... 종합평점이 85점(다만, 소프트웨어용역의 중소기업자간 경쟁제품, 여객 육상운송용역은 88점)이상이면 낙찰자로 결정한다.`

즉 일반용역 적격심사의 T 는 기본 85점, 소프트웨어(중소기업자간 경쟁제품)·여객육상운송용역은 88점이다.

## 4. 추출기 구현

`scripts/extract_score_params.py` 를 구현했다.

### 4.1 동작

1. 나라장터 OpenAPI(경로 A)로 공고 1건을 찾아 `sucsfbidMthdNm`/`sucsfbidMthdAppStd`/`presmptPrce` 와 첨부 URL 을 얻는다.
2. 첨부를 모두 내려받아 형식별로 텍스트를 뽑는다. HWPX(zip), HWPML(`<?xml`), 바이너리 HWP(OLE `BodyText`/`Section0` 스트림)를 지원하고, PDF 는 사유와 함께 건너뛴다.
3. `종합평점이 N점` 문구로 T 를, "입찰가격" 배점한도 표로 B 를, "평점 계산식" 으로 k 와 기준비율을 뽑는다.
4. 구간 선택은 `sucsfbidMthdNm` 문자열 일치와 추정가격 대비 구간 임계값(예: "5억원") 비교로 한다. 하나로 확정되지 않으면 값을 비우고 후보 목록과 사유를 남긴다.

### 4.2 사용

```sh
python3 scripts/extract_score_params.py \
  --bid-no R26BK01707844 --category Servc --bgn 20260901 --end 20260915
```

### 4.3 실측 실행 결과

| 공고 | B | k | T | 기준비율 | 비고 |
| --- | :---: | :---: | :---: | :---: | --- |
| R26BK01707844 | 70 | 2 | 85 | 0.9 | 별표 9(HWPX) + 공고문(HWP)에서 전량 획득 |
| R26BK01708399 | None | None | 85 | None | 별표가 스캔 PDF 라 B·k 불가, T 는 공고문에서 획득 |
| R26BK01709318 | None | None | None | None | 별표 6 이 스캔 PDF, 공고문에 통과점수 문구 없음 |

획득하지 못한 필드는 추측값 대신 `reasons` 에 사유가 담긴다. 예(R26BK01708399): `B/k/base_rate = "문서에서 해당 문구를 찾지 못함"`.

### 4.4 테스트

`tests/test_extract_score_params.py` 는 실측 문서에서 그대로 옮긴 문자열로 파서를 고정한다. 네트워크를 쓰지 않는다.

## 5. 획득 가능 범위 실측

2026-09-01~15 구간 OpenAPI 표본(pageNo=1, numOfRows=999) 기준이다.

| 카테고리 | 표본 | 적격심사제 | 별표/세부기준/평가기준 첨부 | 첨부 확장자 |
| --- | :---: | :---: | :---: | --- |
| Servc | 999 | 90 | **9** | hwpx 3, hwp 3, pdf 3, zip 1 |
| Thng | 999 | 196 | **12** | zip 4, pdf 4, hwp 3, hwpx 1 |

- 표본은 999건에서 잘린 값이다. 같은 구간 totalCount 는 Servc 6,390건, Thng 6,576건이므로 위 비율은 모집단의 일부만 본 것이다.
- 적격심사 공고 중 별표를 직접 첨부하는 비율은 Servc 10%, Thng 6% 수준이며, 그중 PDF 는 스캔이라 대부분 추출 불가다.
- 따라서 **자동 추출 적용 가능 건수는 적격심사 공고의 한 자릿수 퍼센트**로 추정된다.

## 6. 한계와 다음 단계

1. **PDF 스캔본**: 첨부 세부기준의 상당수가 텍스트 레이어 없는 스캔 이미지다. OCR 을 도입하면 커버리지가 늘어난다. 새 의존성 도입은 별도 합의가 필요하다.
2. **표 구조 의존**: B 는 [별표] 표에서 "입찰가격" 행과 구간 라벨 행을 순서로 맞춘다. 별표마다 표 구성이 달라 라벨 행을 찾지 못하면 값을 비운다.
3. **예외 조항**: 세부기준 제10조의 "다만, ...은 88점" 처럼 예외가 있으면 대표값 85 를 반환하고 근거 문자열에 전문을 남긴다. 소프트웨어·여객육상운송용역은 사용자가 확인해야 한다.
4. **구간 선택**: 기준비율 표기(고시금액 기준)와 배점한도 표기(5억원 기준)의 축이 다를 수 있어, 문자열 일치와 수치 비교 두 방식으로 확정하고 실패 시 비운다.

## 7. 결론

**B·k·T 는 나라장터 OpenAPI 와 공고 상세 페이지에서 얻을 수 없다. 유일하게 확인된 경로는 공고에 첨부된 적격심사 세부기준 [별표] 문서다.**

- **T**: 공고문 또는 세부기준 제10조의 "종합평점이 N점" 문구에서 얻는다. 일반용역은 85점, 소프트웨어·여객육상운송은 88점. 첨부가 기계 판독 가능하면 사실상 항상 얻는다.
- **B·k**: [별표] 의 "입찰가격" 배점한도 표와 "평점 계산식" 에서 얻는다. 별표 9 실측값은 B 60/70, k 2/4, 기준비율 0.9 였다.
- **적용 가능 건수**: 적격심사 공고 중 별표를 직접 첨부하는 비율은 실측 표본에서 Servc 9/90, Thng 12/196 이다. 첨부가 PDF 스캔이면 추출 불가이므로, 현재 추출기가 값을 내는 비율은 그보다 더 낮다.

**무엇이 있으면 좋아지는가**

1. 첨부 PDF OCR 경로 (스캔 세부기준 대응).
2. 별표 표 구조가 다른 케이스의 표 파서 확장.
3. 값이 확정되지 않을 때 사용자 입력을 유지하는 현재 UX 는 그대로 두는 것이 안전하다. 추출값은 근거 문자열과 후보 목록을 함께 주고, 확정 불가 시 비운다.
