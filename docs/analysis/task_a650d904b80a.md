# G1 기준선 fail-closed 전환 분석

> 작업: `task_a650d904b80a`
> 목적: 기준선 부재 시 현재 손상 상태가 정답으로 저장되는 경로 제거

## 변경 사항

| 영역 | 결과 |
| --- | --- |
| 스키마 기준선 검증 | `verify_schema_signature` 기본값을 `auto_save_baseline=False`로 바꾸고, 기준선 부재·메타데이터 부재를 실패 처리합니다. 검증 경로는 파일을 쓰지 않습니다. |
| reconciliation 검증 | `verify_reconciliation`도 동일한 fail-closed 계약을 적용하고, 기준선 메타데이터와 두 대상 테이블의 행 수 형식을 검증합니다. |
| 기준선 생성 | `--generate-schema-baseline` 및 `--generate-reconciliation-baseline` 전용 플래그를 추가했습니다. 생성 후 검증을 자동 수행하지 않습니다. 기존 `--update-baseline`은 명시적 생성 별칭으로 유지됩니다. |
| 출처 추적 | 생성 기준선에 UTC 생성 시각, 비밀번호를 숨긴 DB URL 식별자, 사용자, 도구 버전, Git HEAD를 기록합니다. |
| 테이블 집합 | 스키마 기본 대상은 SQLAlchemy `Base.metadata` 전체와 inspector의 DB 집합 합집합입니다. ORM 누락 테이블과 DB 전용 테이블을 양방향으로 검출합니다. |
