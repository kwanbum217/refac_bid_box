## 2. 저장소 규칙 레지스트리와의 대조 (표 2)

먼저 사실 관계다. 레지스트리에는 **행안부 시설공사 [별표 4] 규칙이 없다.**
`src/app/services/evaluation_rules.py:4-7`은 이 모듈을 "일반용역 적격심사 규칙 레지스트리"로
규정하고, 지방계약 축은 `src/app/services/evaluation_rules_local.py:29`에서
"행정안전부 예규 기본 규칙은 만들지 않습니다(0.1 D8)"라고 명시한다. 따라서 같은 별표
번호를 가진 규칙은 조달청 일반용역 [별표 4]\\(폐기물처리용역\\)뿐이다.

| 항목 | 원문: 행안부 제2장의1 [별표 4] (2026-07-01) | 레지스트리: 행안부 시설공사 [별표 4] | 레지스트리: 같은 번호 조달청 일반용역 [별표 4] 폐기물 (개정 전 / 개정 후) | 판정 |
| --- | --- | --- | --- | --- |
| 배점한도 B | 70 | 규칙 없음 | 70 / 70 | 같음(번호만 같은 다른 문서) |
| 계수 k | 4 | 규칙 없음 | 4 / 4 | 같음(위와 같음) |
| 기준비율 | `90/100` = 0.90 | 규칙 없음 | 0.88 / 0.90 | 개정 전 불일치, 개정 후 일치 |
| A 값 | 있음(7개 항목) | 규칙 없음 | 없음 | 불일치(레지스트리 산식에 A 없음) |
| 낙찰하한율 | 원문에 인쇄 없음(미확인) | 규칙 없음 | 84.245 / 86.245 | 비교 불가 |
| 적격 통과점수 | 별표에 인쇄 없음(영상은 95) | - | 85 | 비교 불가 |
| 상한 평탄 / 최저 | 91.25% 이상 65점 / 최저 2점 | 규칙 없음 | 규칙 객체에 없음 | 대응 없음 |
| 적용 대상 | 시설공사, 추정가격 10억~30억 | - | 일반용역 폐기물, 고시금액 미만 | 문서·업무 다름 |

근거:

| 레지스트리 항목 | 값 | 근거 |
| --- | --- | --- |
| 개정 전 폐기물 [별표 4] | `SERVC_QUAL_PRE_20250901_ATTACH_08`, B=70·k=4·T=85 | `src/app/services/evaluation_rules.py:223-228`(선언), `:1962-1974`(규칙 객체, `lwlt_rate=84.245`, `base_rate=0.88`) |
| 개정 후 폐기물 [별표 4] | `SERVC_QUAL_POST_20260526_ATTACH_08`, B=70·k=4·T=85 | `:470-475`(선언), `:886-897`(규칙 객체, `lwlt_rate=86.245`, `base_rate=0.90`) |
| 레지스트리 산식 | `P = B - k x |기준율 - 입찰가격/예정가격| x 100`, A 없음 | `src/app/services/price_score_verification.py:8-9`, `:89` |
| 지방계약 기준율 | 모든 밴드 기준비율 88% | `src/app/services/evaluation_rules_local.py:32` |

즉 레지스트리는 이 별표의 **B와 k는 같은 값으로 보유**하지만, **A를 표현할 수단이 없고**,
기준율은 판본별 값(0.88 → 0.90)을 별표 4 규칙에서 그대로 보여준다. 행안부 시설공사 축이
없으므로 "레지스트리 규칙으로 영상 예시를 계산"하는 것은 문서·업무가 다른 규칙의 차용이다.

## 3. 영상 예시 재현 판정 (표 3)

재현은 모두 `uv run python`으로 `src/app/services/price_score_verification.py`의
`verify_price_score`·`invert_pass_bid_range`를 호출해 계산했다. A는 원문 정의대로
`(입찰가격-A)/(예정가격-A)`가 되도록 `pred_price=예정가격-A`, `bid_price=입찰가격-A`로 넣고
금액은 A를 다시 더했다. 이 함수는 A를 별도 인자로 받지 않으므로 이렇게 우회했다.

### 3.1 예시 1

영상 값: 수행능력 29/30(경영상태 1점 부족), 적격 95 → 필요 가격점수 66, 예정가격
450,000,000원, A 20,000,000원, 투찰률 86.995%, 투찰금액 394,078,500원.

| 계산 | 값 |
| --- | --- |
| A 반영 비율(반올림 전) | `(394,078,500-20,000,000)/(450,000,000-20,000,000) = 374,078,500/430,000,000 = 0.869950` → 표시 86.995% |
| 4자리 반올림 비율 x | `0.8700` |
| 원문(기준율 90%) 평점 | `70 - 4 x |0.90-0.87| x 100 = 58.0000` → **66점 미달** |
| 원문(90%) 필요 66점 구간 | 연속 `[0.89, 0.91]`, 격자 `[0.8900, 0.9100]`, 금액 `[402,678,500, 411,321,499]` |
| 기준율 88% 가정 평점 | `70 - 4 x |0.88-0.87| x 100 = 66.0000` |
| 88% 가정 필요 66점 구간 | 연속 `[0.87, 0.89]`, 격자 `[0.8700, 0.8900]`, 금액 `[394,078,500, 402,721,499]` |

**판정**: 저장소 원문(90%)으로는 불일치한다. 기준율 88%를 적용하면 하한 금액이
**394,078,500원으로 영상 값과 원 단위까지 일치**한다. 86.995%는 4자리 반올림 뒤 87.00%가
되는 하한 경계의 반올림 전 표시값이다.

### 3.2 예시 2

영상 값: 적격 95, 수행능력 19.5/20 → 필요 가격점수 75.5, 투찰률 87.775%. 영상에는
예정가격·A가 없으므로 비율만 비교하고, 금액은 예정가격 1,000,000,000원을 가정한 예시다.

| 계산 | 값 |
| --- | --- |
| 반올림 전 비율 | `0.87775` → 표시 87.775% |
| 4자리 반올림 비율 x | `0.8778` |
| 원문(기준율 90%) 평점 | `80 - 20 x |0.90-0.8778| x 100 = 35.6000` → **75.5점 미달** |
| 원문(90%) 필요 75.5점 구간 | 연속 `[0.89775, 0.90225]`, 격자 `[0.8978, 0.9022]`, 금액(가정) `[897,750,000, 902,249,999]` |
| 기준율 88% 가정 평점 | `80 - 20 x |0.88-0.8778| x 100 = 75.6000` |
| 기준율 88% 가정 구간 | 연속 `[0.87775, 0.88225]`, 격자 `[0.8778, 0.8822]`, 금액(가정) `[877,750,000, 882,249,999]` |
| 반올림 없는 대수값(88%) | `80 - 20 x (0.88-0.87775) x 100 = 75.5000` |

**판정**: 저장소 원문(90%)으로는 불일치한다. 기준율 88%에서는 영상이 제시한 87.775%가
하한 경계와 일치하고, 4자리 반올림 때문에 점수가 75.6점으로 0.1점 높게 계산되지만
**통과 판정(>=75.5)은 일치**한다.

## 4. 86.995%의 출처 판정

후보 세 가지를 같은 입력으로 갈라 본다.

| 가설 | 검정 | 결과 |
| --- | --- | --- |
| 원문 산식 차이(기준비율) | 90%와 88%를 같은 식에 넣는다 | 90%는 66점에 89.00%(402,678,500원), 88%는 66점에 87.00%(394,078,500원) |
| A 값 처리 차이 | A를 빼지 않고 `입찰가격/예정가격`으로 계산한다 | x=0.8757, 평점 68.28점(88%) / 60.28점(90%). 필요 66점 하한 금액은 391,477,500원으로 A 반영값보다 2,601,000원 낮다 |
| 영상 오류 | 66점을 주는 값을 다시 대입한다 | 88% 가정에서 394,078,500원은 정확히 66.0000점이다. 예시 1은 오류가 아니다 |

**판정: 원문 산식 차이, 그중에서도 기준비율의 판본 차이다.**

- 86.995%는 `(394,078,500-20,000,000)/(450,000,000-20,000,000)=0.86995`의 표시값이다.
  원문의 "소수점 다섯째 자리 반올림"을 적용하면 0.8700이 되고, 기준율 88%에서 평점은
  정확히 `70 - 4 x 0.01 x 100 = 66.00`이다. 즉 영상은 **A를 올바르게 반영**했고,
  66점이 되는 원 단위 하한을 5자리로 표시한 것이다.
- 저장소 원문(2026-07-01 판)의 기준율은 90/100이다(`:5050`, 셀 r0c4/r1c4). 90%에서
  66점이 되는 비율은 89.00%이고 금액은 402,678,500원이다. 86.995%와 394,078,500원은
  90% 식에서는 나오지 않는다.
- 88%는 2026년 개정 전 값으로 정황 근거가 있다. 레지스트리의 같은 별표 4(폐기물)는
  개정 전 0.88(`evaluation_rules.py:1974`), 개정 후 0.90(`:897`)이고, 지방계약 규칙도
  전 밴드 88%다(`evaluation_rules_local.py:32`). 영상(2023-12-07)의 적용 판본 원문은
  저장소에 없어 **미확인**이지만, 두 예시가 88%로 정확히(예시 2는 0.1점 차) 재현되므로
  영상이 당시 판본의 88%를 쓴 것으로 판정한다.
- 예시 2의 0.1점 차는 영상 오류라기보다 원문의 5째 자리 반올림 규칙과 영상의 3자리
  표시(87.775%) 차이다. 반올림을 적용하지 않은 대수값은 정확히 75.5다.

## 5. 용역 추천 구현에 미치는 영향

1. **A 값은 용역 경로에 넣지 않는다.** 일반용역 원문 산식과 레지스트리 산식 모두
   `입찰가격/예정가격`만 쓴다(`price_score_verification.py:8-9`). A는 시설공사 [별표 4]·
   [별표 5]의 요소다. 지금 구조에 A를 넣으면 용역 계산이 오히려 틀어진다.
2. **공사까지 지원하려면 별도 축이 필요하다.** 현재 레지스트리에는 행안부 시설공사 규칙이
   없다(`evaluation_rules_local.py:29`). 추가한다면 최소한 다음이 필요하다.
   - [별표 4]: B=70, k=4, 기준율 0.90, A 7개 항목, 91.25% 이상 65점, 최저 2점.
   - [별표 5]: B=80, k=20, 기준율 0.90, A 7개 항목, 90.25% 이상 75점, 최저 2점.
   - A 값 입력과 `(입찰가격-A)/(예정가격-A)` 정규화. 현행 함수는 A를 받지 않는다.
3. **기준율을 0.88로 하드코딩하면 안 된다.** 같은 별표 4의 기준율이 2025-09 판 0.88,
   2026-05-26 판 0.90, 행안부 2026-07-01 판 0.90이다. 공고 시행일로 판본을 골라야 한다.
4. **영상 예시를 회귀 테스트로 쓸 때는 판본을 고정해야 한다.** 88% 픽스처로는 예시 1이
   394,078,500원, 예시 2가 87.775%로 재현된다. 2026 원문(90%) 픽스처와 섞으면 둘 다
   실패한다. 2026 원문 기준 회귀값은 예시 1이 402,678,500원(66점), 예시 2가 89.775%
   (75.5점)다.
5. **추천 로직의 하한 계산은 원 단위 경계를 그대로 써야 한다.** 88% 가정에서 영상의
   394,078,500원은 `ceil(430,000,000 x 0.86995) + 20,000,000`으로, 4자리 격자 하한
   0.8700의 반올림 경계다. 격자값만 곱해 0.87 x 430,000,000 + 20,000,000 = 394,100,000원
   으로 계산하면 영상과 21,500원 어긋난다.
