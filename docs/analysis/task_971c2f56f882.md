## 1. 개요 및 배경

공고 상세 페이지의 유사 공고 조회(`get_announcement_detail`)는 대상 공고와 동일한 카테고리(`category`) 및 발주/수요기관(`dminstt_nm`)을 갖는 공고 5건을 조회합니다.

기존 구현은 `latest_announcement_filter`를 공유하여 `bid_announcements` 전체 테이블을 대상으로 `(bid_ntce_no, category)` 파티션 랭킹(`ROW_NUMBER() OVER`)을 계산하는 파생 서브쿼리를 생성했습니다. 이로 인해 필요한 결과는 5건에 불과함에도 전체 수백만 행 테이블에 대해 윈도우 정렬이 유발되어 DB CPU 부하를 발생시켰습니다.

단순히 `dminstt_nm` 및 `category` WHERE 조건을 서브쿼리 내부로 밀어 넣는 방식은, 나중 차수에서 발주기관이 변경된 공고 그룹의 경우 이전 차수 행을 최신으로 잘못 추출하는 의미 변경(Semantics Change) 결함을 야기합니다.

본 작업에서는 후보 조건을 먼저 좁힌 뒤 동일 `(bid_ntce_no, category)` 그룹 내에 정렬 우선순위상 더 앞서는 행이 존재하지 않음을 `NOT EXISTS` 상관 서브쿼리로 판정하는 `similar_announcement_latest_filter`를 도입하여 성능을 개선하고 기존 윈도우 판정의 결과 집합 의미를 100% 보존했습니다.

## 2. 쿼리 설계 및 동치성 분석

### 2.1 정렬 및 최신 차수 판정 우선순위

기존 윈도우 함수와 완전히 동일한 사전식(lexicographical) 정렬 우선순위를 적용합니다:

1. `bid_ntce_ord DESC` (String, NOT NULL)
2. `bid_ntce_dt DESC` (DateTime, NULL 허용 - MySQL 규약상 NOT NULL이 NULL보다 최신)
3. `collected_at DESC` (DateTime, NOT NULL)
4. `id DESC` (PKBigInteger, NOT NULL)

### 2.2 사전식 비교 조건 (`_is_newer_announcement_clause`)

후보 행 $A$와 동일 그룹의 다른 행 $B$에 대해 $B$가 $A$보다 엄격하게 최신($B > A$)일 조건:

```python
or_(
    # 1. 차수가 더 높음
    other.bid_ntce_ord > current.bid_ntce_ord,
    # 2. 차수는 같고 공고일시가 더 앞섬 (NOT NULL > NULL 포함)
    and_(
        other.bid_ntce_ord == current.bid_ntce_ord,
        or_(
            and_(other.bid_ntce_dt.is_not(None), current.bid_ntce_dt.is_(None)),
            and_(
                other.bid_ntce_dt.is_not(None),
                current.bid_ntce_dt.is_not(None),
                other.bid_ntce_dt > current.bid_ntce_dt,
            ),
        ),
    ),
    # 3. 차수와 공고일시가 같고(둘 다 NULL 포함) 수집일시가 더 앞섬
    and_(
        other.bid_ntce_ord == current.bid_ntce_ord,
        or_(
            other.bid_ntce_dt == current.bid_ntce_dt,
            and_(other.bid_ntce_dt.is_(None), current.bid_ntce_dt.is_(None)),
        ),
        other.collected_at > current.collected_at,
    ),
    # 4. 차수, 공고일시, 수집일시가 모두 같고 ID가 더 큼
    and_(
        other.bid_ntce_ord == current.bid_ntce_ord,
        or_(
            other.bid_ntce_dt == current.bid_ntce_dt,
            and_(other.bid_ntce_dt.is_(None), current.bid_ntce_dt.is_(None)),
        ),
        other.collected_at == current.collected_at,
        other.id > current.id,
    ),
)
```

### 2.3 `similar_announcement_latest_filter` 구현

```python
def similar_announcement_latest_filter(stmt):
    """테이블 전체 랭킹 대신 후보 공고를 먼저 좁힌 뒤 동일 그룹 내 최신 차수 존재 여부를 NOT EXISTS로 판정합니다.
    다른 차수에서 기관이 변경된 공고를 배제하는 기존 window 함수의 결과 의미를 완전히 보존합니다.
    """
    newer_ann = aliased(BidAnnouncement)
    has_newer = (
        select(1)
        .where(
            newer_ann.bid_ntce_no == BidAnnouncement.bid_ntce_no,
            newer_ann.category == BidAnnouncement.category,
            _is_newer_announcement_clause(newer_ann, BidAnnouncement),
        )
        .exists()
    )
    return stmt.where(~has_newer)
```
