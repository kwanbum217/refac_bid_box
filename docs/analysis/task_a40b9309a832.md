## 2. 변경 내용

### 2.1 하네스 보강 (`scripts/benchmark_rag_segments.py`)

1. **상수 및 CLI 인자 추가**
   - `DEFAULT_DB_CONTAINER = "refac_bid_box-db-1"` 상수를 정의하고 `__all__`에 등록했습니다.
   - CLI 인자로 `--db-container`를 추가하여 기본값 `refac_bid_box-db-1`을 유지하되 사용자 지정이 가능하도록 했습니다.

2. **버퍼풀 상태 조회 함수 구현 (`query_db_buffer_pool_pages_data`)**
   - `cmd_fn`(기본값 `_command_output`)을 통해 다음 명령을 실행합니다:
     ```bash
     docker exec <db_container> sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -B -e "SHOW GLOBAL STATUS LIKE '\''Innodb_buffer_pool_pages_data'\''"'
     ```
   - 컨테이너 내부 환경변수 `MYSQL_ROOT_PASSWORD`를 직접 참조하여 비밀번호나 접속 정보가 명령줄 또는 산출물에 노출되지 않도록 결박했습니다.
   - 명령 실행 실패(`unknown`, 빈 문자열, 비정상 출력, 예외 발생) 시 예외를 던지지 않고 `pages_data=None` 및 명시적 실패 사유(`error`)를 반환합니다.
   - 이 정보는 canonical 게이트가 아니므로, 버퍼풀 조회가 실패하더라도 전체 벤치마크 측정을 중단시키지 않습니다.

3. **산출물 Provenance 및 Config 결박**
   - 측정 시작 시점(`start_meta`)과 종료 시점(`end_meta`)에 각각 버퍼풀 상태를 조회하여 덧붙였습니다.
   - 산출물 `provenance` 객체에 `db_buffer_pool` 필드(`start`, `end`)를 추가하고, `start_meta`와 `end_meta` 내부에도 `db_buffer_pool`, `innodb_buffer_pool_pages_data`, `db_buffer_pool_error`를 기록했습니다.
   - 기존 산출물 스키마의 모든 필수 키는 100% 보존했습니다.

### 2.2 회귀 테스트 보강 (`tests/test_benchmark_rag_segments.py`)

1. `test_query_db_buffer_pool_pages_data_success`: 정상 출력 파싱 및 정수 변환 검증
2. `test_query_db_buffer_pool_pages_data_failures`: unknown, 빈 출력, 예외 발생, 비정수 값, 미포함 항목 등 실패 시 null과 명시적 사유 기록 검증
3. `test_main_records_buffer_pool_provenance_on_success`: 측정 시작과 종료 시점의 버퍼풀 적재 페이지 수가 산출물 `provenance`에 기록되고 canonical 판정 및 비밀번호 안전성이 유지되는지 E2E 검증
4. `test_main_buffer_pool_failure_records_null_and_error_without_stopping_measurement`: 버퍼풀 조회 실패 시에도 측정이 중단되지 않고 null과 사유가 기록되며 canonical 게이트 판정이 유지되는지 검증
