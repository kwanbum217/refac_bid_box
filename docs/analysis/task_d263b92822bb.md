## 1. 개요 및 배경

### 1.1 배경 및 문제점
T1(`task_ac156735df14`) 작업을 통해 인증된 사용자 간 대화 상태의 교차 접근(IDOR)과 `user:` 접두사 메모리 키 위조가 차단되었습니다. 그러나 `user_id` 가 `None` 인 익명 사용자 요청 간에는 `None != None` 조건이 거짓으로 평가되어, 동일한 임의의 `session_key` 문자열을 지정할 경우 서로의 대화 상태를 읽거나 오염시킬 수 있는 잔여 격차가 존재했습니다.

또한 `ensure_session_key` 가 클라이언트가 제공한 비 `user:` 문자열을 그대로 영속화 저장 키로 사용하여, 공격자가 짧거나 추측 가능한 세션 키를 생성해 다른 익명 세션의 상태를 열거 및 오염시킬 수 있는 위험이 있었습니다.

### 1.2 목표
1. 익명 요청의 대화 세션 키를 서버 발급 HMAC 서명 식별자로 제한합니다.
2. 클라이언트가 임의 문자열을 보낼 경우 원본 문자열을 저장 키로 쓰지 않고 조용히 새 서명 키를 발급합니다.
3. 익명 클라이언트 간 세션 키 충돌 및 상태 공유를 원천 차단합니다.
4. 서버가 정상 발급한 서명 키를 되돌려 보낸 익명 요청은 대화 상태가 원활히 복원되도록 보장합니다.
5. 인증된 사용자가 기존에 생성한 레거시 평문 세션 키는 T1 소유자 검증을 통해 본인에 한해 안전하게 복원될 수 있도록 하위 호환성을 유지합니다.
6. `POST /api/v1/chatbot/session/new` 호출 시 서명된 새 세션 키를 반환하도록 합니다.

## 2. 설계 및 구현 세부사항

### 2.1 HMAC 기반 세션 키 서명 및 검증
`src/app/services/automation_tokens.py` 의 기존 HMAC-SHA256 패턴을 준용하여 `src/app/services/conversation_state.py` 에 세션 키 서명 및 검증 함수를 구현했습니다.

- **Salt**: `SESSION_KEY_SALT = "bidbox.chatbot.session_key"` (자동화 토큰과 독립된 고유 salt 사용)
- **형식**: `{raw_uuid}:{signature}` (base64url 인코딩, 패딩 문자 `=` 제거)
- **만료 정책**: 대화 세션의 연속성을 위해 만료 시간(TTL/max_age)을 두지 않습니다 (진행 중인 대화 끊김 방지).

```python
def sign_session_key(raw_id: str) -> str:
    digest = hmac.new(
        f"{settings.SECRET_KEY}:{SESSION_KEY_SALT}".encode(),
        raw_id.encode(),
        hashlib.sha256,
    ).digest()
    signature = base64.urlsafe_b64encode(digest).decode().rstrip("=")
    return f"{raw_id}:{signature}"
```

### 2.2 세션 키 검증 및 분기 처리 (`ensure_session_key`)
`ensure_session_key` 함수에서 `user_id` 전달 여부에 따라 분기 검증을 수행합니다.

| 요청 유형 | `user_id` | 세션 키 처리 규칙 | 비고 |
| :--- | :--- | :--- | :--- |
| **익명 요청** | `None` | `verify_session_key` 검증. 유효한 서명 키이면 유지, 서명 위조/누락/평문이면 새 서명 키 발급 | 원본 문자열 절대 저장 불가 |
| **인증 요청** | `int` | `user:` 접두사 제외한 평문/서명 키 그대로 유지 | T1 소유자 대조(`state.user_id == user_id`)로 보호, 레거시 세션 복원 |
| **신규 발급** | `POST /session/new` | 항상 서명된 새 키(`generate_signed_session_key()`) 발급 | - |

```python
def ensure_session_key(
    session_key: str | None = None,
    *,
    user_id: int | None | object = _UNSET,
) -> str:
    cleaned = (session_key or "").strip()
    if not cleaned or cleaned.startswith(USER_MEMORY_PREFIX):
        return generate_signed_session_key()

    if user_id is _UNSET:
        return cleaned

    if user_id is None:
        if verify_session_key(cleaned):
            return cleaned
        return generate_signed_session_key()

    return cleaned
```

### 2.3 API 계층 연동 (`src/app/api/v1/chatbot.py`)
`_prepare_chat` 내부에서 `ensure_session_key(payload.session_key, user_id=user_id)` 를 호출하여 익명 요청 시 클라이언트의 임의 문자열이 DB 저장 및 컨텍스트 로드 경로로 진입하지 못하도록 보장했습니다.
