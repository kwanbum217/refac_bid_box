## 1. 개요 및 배경

2026-08-28 세션 중 기존 워크트리(`path:` 선택자)에 워커를 부착하려 할 때 기동이 실패하는 현상이 발생했습니다. 당시 출력된 오류 메시지는 `"Creation and setup options apply only to new-child or new-top-level worktrees."`였고, 도구가 화면에 출력한 "실행할 명령"에는 `--name` 인자가 포함되어 있었습니다.

그러나 코디네이터가 수동으로 동일 명령을 재시도했을 때는 정상 기동되었으며, 실제 코드 상에서 `worker_start`는 `args.worktree.startswith("new-")` 조건에 따라 `name=None`을 전달하여 `--name`을 명령에 붙이지 않았습니다. 즉, 도구가 실패 시 출력한 명령 문자열이 실제 실행된 명령과 불일치하여 진단을 오도하는 문제가 확인되었습니다.

## 2. 원인 규명 및 코드 점검 결과

### 2.1 표시 명령 불일치 원인
- `scripts/orca_taskctl.py`의 `worker_start` 함수는 `name` 인자가 `None`일 경우 `--name` 플래그를 추가하지 않고 올바르게 CLI 명령을 구성했습니다.
- 반면 `cmd_dispatch` 내부(기존 2437행 부근)에서 실패 시 사용자에게 보여줄 `launch_cmd` 문자열을 수동 f-string으로 조립하면서, 조건 없이 `--name {worktree_name}`을 덧붙였습니다.
- 또한 `--terminal`을 통한 터미널 부착 경로(`dispatch_worker`)에서도 `launch_cmd`를 정적 문자열로 하드코딩하고 있어 실제 옵션(`--run`, `--json` 등)과의 잠재적 불일치 위험이 존재했습니다.

### 2.2 기존 워크트리(`path:` 선택자) 경로 점검
- 코드 수준 점검 결과, `worker_start` 함수 내부에는 `task_id`, `agent_id`, `terminal_handle`, `model`, `worktree`, `name`, `repo`, `as_json`만 제어하고 있습니다.
- `cmd_dispatch`에서 `args.worktree.startswith("new-")`일 때만 `name`을 전달하므로, `path:` 선택자 사용 시 워크트리 생성 전용 인자(`--name`)가 실행 명령에 추가되는 결함은 코드상 존재하지 않았습니다.
- 실제 발생했던 오류 메시지와 화면상 `--name` 표시는 `launch_cmd`의 수동 문자열 조립 결함으로 인한 오도였음이 확인되었습니다.
