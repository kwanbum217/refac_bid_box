## 1. 적용한 설계

| 영역 | 구현 |
| --- | --- |
| 버전 정본 | `scripts/check_release_readiness.py`가 `pyproject.toml`의 `[project].version`을 읽습니다. |
| 태그 | 읽은 버전에 `v` 접두사를 붙여 태그를 파생합니다. 워크플로에 버전 리터럴을 중복하지 않습니다. |

| 릴리스 노트 | 직전 `v` 태그 이후 커밋을 `feat`, `fix`, `docs`, `refactor`, `chore`, `test`, `ci`, 기타로 묶습니다. |
| 이미지 서명 | 구현하지 않았으며 Docker 데몬·키 관리 결정이 필요한 미결 항목으로 문서화했습니다. |

## 2. 변경 파일

- `.github/workflows/release.yml`: 준비 상태 게이트, 태그 push, GitHub Release 생성 순서를 정의했습니다.
- `scripts/check_release_readiness.py`: 버전 조회, 네 가지 게이트, GitHub Actions CI 조회, 타입별 노트 생성을 구현했습니다.

- `docs/ops/release_process.md`: 수동 릴리스 선택 근거, 운영 절차, 복구·미결 항목을 기록했습니다.
