## 1. 개요 및 배경

Antigravity 등 터미널 기반 워커 CLI는 첫 파일 편집 또는 생성 시 확인 대화창(`Accept this file edit?`, `Allow creation of this file?`)을 띄워 사용자 입력을 대기합니다.
기존 절차에서는 워커 기동 후 코디네이터 또는 사용자가 직접 `shift+tab`(`\x1b[Z`) 시퀀스를 전송해야 했으며, 이 절차가 누락될 경우 워커들이 동시에 정체되는 문제가 발생했습니다.
반면 **Cursor CLI(`cursor-agent`)에서 `shift+tab`은 Plan Mode(읽기 전용, 파일 편집 금지) 전환**이므로 무조건 전송 시 워커가 파일 편집 불가 상태로 빠지는 결함이 발생합니다.

본 작업은 `scripts/orca_taskctl.py`의 `dispatch` 경로에서 권한 자동 승인 감시기(`start_auto_approve`) 부착 직후 대상 CLI 화면을 검사하여, Antigravity 계열인 경우에만 `shift+tab` 파일 편집 자동 승인 모드 전환(`enable_file_edit_auto_approve`)을 1회 전송하고, Cursor 및 미식별 CLI는 fail-closed 원칙에 따라 전송을 차단하도록 구현했습니다.
