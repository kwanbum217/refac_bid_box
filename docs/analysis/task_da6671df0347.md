# 운영 Compose egress·readiness 변경 기록

> 작업: `task_da6671df0347`
> 기준일: 2026-09-03

## 변경 내용

운영 Compose의 네트워크를 `internal`과 `egress`로 분리했습니다. `db`, `redis`, `meilisearch`는 `internal: true` 네트워크에만 두고, `app`과 `worker`는 두 네트워크에 연결했습니다. `proxy`는 `egress`에 연결해 외부 수신과 `app` 전달 경로를 유지합니다.

`app` healthcheck는 `/api/v1/health/ready`의 `status == 'ready'`만 통과시키도록 변경했습니다. 운영 Compose가 `READINESS_REQUIRE_WARMUP=true`와 `READINESS_REQUIRE_LLM=true`를 명시적으로 주입하므로 warmup 미완료 또는 LLM 장애는 503 `not_ready`로 처리됩니다. 개발·테스트 환경을 보존하기 위해 `src/app/core/config.py`의 기본값은 변경하지 않았습니다.

워커 healthcheck에는 Redis 연결 확인과 heartbeat 신선도 확인을 함께 넣었습니다. `bidbox:worker:heartbeat`의 `last_seen_at`이 `WORKER_HEARTBEAT_MAX_AGE_SECONDS`(기본 90초)를 초과하거나 없으면 unhealthy가 됩니다.

## 검증 계획 및 결과

정적 Compose topology 테스트는 Docker 데몬을 실행하지 않고 YAML을 파싱해 데이터 계층 격리, egress 연결, strict readiness, heartbeat healthcheck 계약을 확인합니다. 운영 환경에서만 실제 `docker compose up`과 외부 API 송신 검증을 수행합니다.

검증 결과는 다음과 같습니다.

| 명령 | 결과 |
| --- | --- |
| `uv run pytest tests/test_prod_compose_topology.py -q` | exit code 0, 3 passed, 1 warning |
| `uv run pytest tests/ -q -m 'not data_assets'` | exit code 0, 3267 passed, 35 skipped, 3 deselected, 314 warnings |
| `docker compose -f docker-compose.prod.yml config -q` | exit code 0 (필수 운영 변수를 환경으로 주입한 정적 검증) |
| `python3 scripts/validate_agent_rules.py --quiet` | exit code 0, 검증 통과 19/19 건 |
| `uv run ruff check src/app/api/v1/health.py tests/test_prod_compose_topology.py` | exit code 0, all checks passed |

실제 Docker 데몬 기동과 외부 API 송신 검증은 정본 사양에 따라 코디네이터가 별도로 수행합니다. 변수 미설정 상태에서 동일한 Compose 명령을 실행하면 필수 변수 누락으로 exit code 1이 되므로, 운영 `.env`를 준비한 뒤 검증해야 합니다.
