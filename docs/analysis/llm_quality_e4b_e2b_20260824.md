## 3. 이번 지표는 생성 품질을 변별하지 못한다

품질 지표가 **소수점까지 동일**하다. 우연이 아니라 구조적인 이유가 있다.

- **근거 recall 은 임베딩이 결정한다.** 검색은 `bge-m3` 로 수행되고 생성 모델과 무관하다.
  문항별 recall 을 대조한 결과 **두 모델에서 다른 문항이 하나도 없다**.
- **numeric 팩트 일치는 recall 을 따라간다.** 근거 문서가 검색되면 두 모델 모두 그 안의
  수치를 그대로 인용하고, 검색되지 않으면 둘 다 답하지 못한다.

즉 이번 자동 채점 축(numeric, recall, citation)은 **검색 성능의 함수**이며 생성 모델의
능력을 거의 반영하지 않는다. `must_not_claim` 위반 0건도 두 모델이 검색된 문맥에
충실했다는 뜻일 뿐, 어느 쪽이 더 나은 답을 쓰는지는 말해주지 않는다.

**생성 품질을 실제로 가르는 축은 proposition 팩트인데, 문자열 일치로 채점할 수 없어
자동 채점에서 제외했다.** 응답 전문은 raw 에 보존되어 있으므로 별도 판정자가 rubric 으로
채점해야 한다.

## 4. 함께 드러난 검색 결함

**컨텍스트 충족으로 설계한 문항의 절반이 기대 근거를 검색하지 못한다.**

recall < 1.0 문항: `q02`, `q03`, `q04`, `q07`, `q08`, `q11`, `q13`, `q14` (8/16)

fixture 는 KB 에 실재하는 문서로 근거를 결박했으므로 문서는 분명히 있다.

**세션 종료 직전 진단으로 원인을 특정했다. 임베딩 능력이 아니라 의도 라우팅이다.**

| 문항 | bge-m3 직접 검색 순위 | 앱 경로 결과 |
| --- | ---: | --- |
| `q03` | **1위** | 검색 문서 **0건** |
| `q07` | **1위** | 실패 |
| `q02` | 상위 20위 밖 | 실패 |

`q03` 의 앱 응답에는 `route_reason: 정형 통계 질의`, `retrieved_docs: 0건` 이 찍힌다.
낙찰업체·낙찰금액·낙찰률을 묻는 문장이 **정형 통계 질의**로 분류되어 벡터 검색을
건너뛴다. 실제로는 특정 공고 단건의 사실 조회이므로 KB 검색이 필요하다.

`q02` 는 직접 검색에서도 상위 20위 밖이라 청킹·색인 또는 질문 표현 쪽 문제로 갈린다.

**생성 모델 능력 문제는 아니다.** 문항별 recall 이 두 모델에서 하나도 다르지 않았고,
검색된 문맥에는 두 모델 모두 충실했다(`must_not_claim` 위반 0건).

이것은 모델 승격과 별개의 **RAG 파이프라인 문제**이며 승격 판정보다 우선순위가 높다.

## 5. 판정

**승격하지 않는다.** 근거는 다음과 같다.

1. 속도 이득(P50 -43.9%, P95 -57.7%)은 크고 재현 가능하며 실재한다.
2. 그러나 "품질 저하 없음" 은 **측정하지 못한 축에 대한 진술이 아니다.** 이번 지표는
   검색이 지배하므로 두 모델이 같게 나오는 것이 당연하고, 생성 품질 비교로 읽으면 안 된다.
3. 검색 recall 이 0.5 인 상태에서 생성 모델을 바꾸면, 승격 효과와 검색 결함이 뒤섞여
   이후 회귀 판정이 어려워진다.

**다음 단계는 검색 결함 해소가 먼저다.** recall 을 올린 뒤 proposition 채점을 붙여
재측정해야 생성 품질 비교가 성립한다.
