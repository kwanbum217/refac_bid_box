## 1. 결론 (구현 Task 가 따를 결정)

**채택안: 불변 세대 디렉터리 + 파일 하나(`LIVE`)의 원자적 교체.**

승격·롤백은 완성된 트리 전체를 `data/model_files/<model>/generations/<version>/` 에 올린 뒤에야 `LIVE` 한 줄을 `os.replace` 한다. 서빙 슬롯 디렉터리 이름은 한 순간도 지우지 않는다. 심볼릭 링크·비어 있지 않은 디렉터리 위 `os.replace`·새 외부 패키지는 쓰지 않는다.

이 결정은 사용자 추가 승인 없이 구현에 넘길 수 있다. 아래 3장이 반례이고, 4장이 기각 근거이며, 5장이 레이아웃과 호출부다.

## 2. 현재 동작 (코드에서 확인한 사실)

`src/ml/promotion.py` 의 `_install_staging_into_serving` 은 서빙 슬롯이 이미 있을 때 디렉터리를 옮기지 않고, `_tree_files` 가 돌려 주는 **파일마다** `_replace_path` (`os.replace`) 를 호출한다. 서빙 경로가 사라지지 않게 하려는 `902a046` 의 선택이다. 주석이 명시한 제약과 같다.

- 비어 있지 않은 디렉터리 위 `os.replace` 는 POSIX 와 Windows 에서 실패한다.
- 심볼릭 링크는 Windows 권한과 Docker 바인드 마운트에서 깨질 수 있다.
- `shutil.move(target -> backup)` 후 `move(staging -> target)` 은 `serving_dir/<model>` 이 없는 구간을 만든다.

스테이징 검증이 끝나기 전에는 서빙 슬롯을 건드리지 않는다. 그 구간은 `tests/test_promotion_gate.py` 의 `test_promote_atomic_no_partial_serving` 이 덮는다. 문제는 검증 **이후** 파일 루프다.

`_tree_files` 는 `Path.rglob` 결과를 이름순으로 정렬한다. 대표 집합에서 교체 순서는 다음과 같다.

| 순서 | 상대 경로 |
| --- | --- |
| 1 | `metadata.json` |
| 2 | `model.bin` |
| 3 | `model_q05.bin` (있으면) |
| 4 | `model_q95.bin` (있으면) |
| 이후 | `v25_cat_final.bin`, `v25_lgbm_final.joblib` 등 나머지 |

`metadata.json` 이 **먼저** 바뀐다. 그 순간부터 디스크의 버전 문자열과 가중치 바이트는 다른 세대가 된다.

실패 시 `promote` / `rollback` 은 백업 트리로 `_restore_serving_from` 을 부른다. 복구도 같은 파일 단위 `os.replace` 다. `_install_staging_into_serving` 의 `finally` 는 스테이징을 지운다. 실패한 교체를 스테이징에서 재개할 수 없다.

## 3. 혼합 버전 반례

반례는 “부분 복사된 새 파일이 남는다”가 아니다. **한 파일만 성공해도 세트가 깨진다.**

### 3.1 프로세스 킬 (복구 코드가 실행되지 않음)

1. 서빙 슬롯에 v1 `metadata.json` + v1 `model.bin` 이 있다.
2. v2 승격이 `metadata.json` 을 v2 로 `os.replace` 한다.
3. 그 직후 프로세스가 죽는다 (`SIGKILL`, OOM, 호스트 중단).
4. 디스크는 v2 메타데이터 + v1 가중치다.

`ModelRegistry.get_served_version` 과 `load_serving_metrics` 는 `.../<model>/metadata.json` 만 읽는다. 보고 버전은 v2, 실제 `joblib.load` 는 v1 이다. 사이드카 지표 버전도 v2 에 맞춰 잘못 붙을 수 있다.

v25 처럼 파일이 여러 개인 모델은 더 잘게 섞인다. `EnsembleV25Wrapper.load` 는 `model.bin` 과 `v25_lgbm_final.joblib` 와 `v25_cat_final.bin` 을 한 세트로 연다.

### 3.2 복구 중 두 번째 실패

현재 주입 테스트는 이 창을 닫지 않는다.

`test_promote_injected_replace_failure_leaves_valid_serving` 과 `test_rollback_injected_replace_failure_leaves_valid_serving` 는 `model.bin` 의 **첫 번째** `os.replace` 만 실패시킨다. 그 시점에는 `metadata.json` 이 이미 새 내용이다. 이어서 백업 복구가 성공하고, `model.bin` 두 번째 호출(`count == 2`)은 통과한다. 테스트가 초록인 이유는 세트가 원자적이어서가 아니라 **복구가 한 번 성공해서**다.

같은 훅이 복구의 `model.bin` 도 실패하면, 또는 복구 루프가 `metadata.json` 과 `model.bin` 사이에 멈추면, 슬롯은 백업과 신버전이 섞인 채로 남는다.

### 3.3 기존 테스트가 증명하지 않는 것

| 테스트 | 실제로 보이는 것 | 보이지 않는 것 |
| --- | --- | --- |
| `test_promote_keeps_serving_path_present_during_swap` | 슬롯 디렉터리 존재 | 파일 집합의 버전 일치 |
| `test_promote_injected_replace_failure_leaves_valid_serving` | 첫 `model.bin` 실패 후 복구 성공 | 킬, 복구 중 실패, `metadata.json` 단독 커밋 |
| `test_promote_atomic_no_partial_serving` | 스테이징 검증 실패 시 슬롯 미생성 | 검증 이후 루프 |

파일별 `os.replace` 는 파일 하나에는 원자적이고, 모델 세트에는 원자적이지 않다. Capsule `why_now` 와 같다.

## 4. 선택지와 기각

| 안 | 요지 | 판정 |
| --- | --- | --- |
| A. 슬롯 디렉터리 두 번 rename | 기존 `move` 로 복귀 | 기각. 서빙 경로 부재. `902a046` 이 막은 구멍 |
| B. 심볼릭 링크 / 정션으로 슬롯을 가리킴 | 디렉터리 원자 전환처럼 보임 | 기각. Windows 권한, Docker 바인드 마운트 |
| C. 파일별 `os.replace` 유지 + 실패 시 복구 강화 | 주입 실패를 복구까지 확장 | 기각. `SIGKILL` 을 닫지 못함. 복구도 파일 단위라 같은 반례 |
| D. `metadata.json` 을 마지막에 교체 | 커밋 파일처럼 씀 | 기각. 메타데이터 커밋 직후 킬이면 새 버전 문자열 + 옛 가중치. 탐지는 가능, 혼합 상태는 남음 |
| E. 세대 디렉터리 + `LIVE` 파일 원자 교체 | 완성 트리 공개를 파일 하나 rename 에 묶음 | **채택** |
| F. 새 라이브러리(트랜잭션 FS 등) | NTFS TxF 등 | 기각. 패키지 추가 금지, 이식성 없음 |

E 가 최소인 이유: 슬롯 경로 유지와 세트 원자성을 동시에 만족하는 이식 가능한 연산은 **같은 볼륨의 파일 `os.replace` 한 번**뿐이다. 그 파일이 가리키는 대상은 이미 완성된 디렉터리여야 한다.

## 5. 채택 레이아웃

```text
data/model_files/<model>/                 # 슬롯. 이름을 바꾸거나 지우지 않는다
  LIVE                                    # 한 줄: generations 아래 디렉터리 이름
  generations/<version>/                  # 불변 트리. 공개 후에 내용을 고치지 않는다
    model.bin
    metadata.json
    model_q*.bin                          # 있을 때만
    ...
  model.bin                               # LIVE 가 없을 때만 읽는 레거시 경로
  metadata.json
```

### 5.1 `LIVE` 규약

- 일반 파일이다. 링크가 아니다.
- 내용은 개행 하나인 세대 이름이다. 예: `v_20260802_000000_000`
- 세대 이름은 기존 `_safe_registry_version` 과 같은 규칙을 통과해야 한다. `.`, `..`, 경로 구분자를 거부한다.
- 기록 절차: `LIVE.tmp` 에 쓰고 `os.replace(LIVE.tmp, LIVE)`. 같은 볼륨의 파일 교체라 POSIX rename(2) / Windows `ReplaceFile` 과 같다.
- 슬롯에 `LIVE` 가 없거나 대상 세대 디렉터리가 없으면 **레거시 슬롯 루트**를 읽는다. 원본 4모델(`v25`, `quantum_leap_v25_pro`, `ssh_hist_premium`, `v13_hybrid`)은 승격 전까지 경로가 그대로다.

### 5.2 해석 함수 (단일 공급원)

새 모듈 `src/ml/serving_layout.py` 에 둔다. `model_registry` 가 `promotion` 전체를 끌어오지 않게 한다. `src/ml/features.py` 는 읽기만 하고 이 설계의 대상이 아니다.

```text
resolve_serving_tree(slot: Path) -> Path
```

- `LIVE` 가 있고 `slot/generations/<id>/metadata.json` 이 있으면 그 세대 경로.
- 아니면 `slot` (레거시).

서빙 슬롯을 여는 코드는 이 함수만 쓴다. 구현 Task 가 바꿔야 하는 호출부:

| 위치 | 지금 | 변경 |
| --- | --- | --- |
| `src/ml/model_registry.py` `discover_models` | `model_root/<id>/metadata.json` 과 그 디렉터리를 wrapper 에 전달 | 슬롯을 나열한 뒤 `resolve_serving_tree` 결과를 전달 |
| `src/ml/model_registry.py` `get_served_version` | `model_root/<id>/metadata.json` | 해석된 트리의 `metadata.json` |
| `src/ml/promotion.py` `load_serving_metrics` | `serving_dir/<model>/metadata.json` | 해석된 트리 |
| `src/ml/promotion.py` `_metadata_version` | 인자 디렉터리의 `metadata.json` | 슬롯이면 해석 후 읽기 |
| `src/ml/model_wrappers.py` | 받은 `model_dir` 에서 `model.bin` 등을 연다 | **시그니처 유지.** 레지스트리가 이미 해석된 트리를 넘긴다 |

`retrain_task._load_champion_metrics` 는 `load_serving_metrics` 만 쓰므로 레지스트리·승격 쪽이 바뀌면 따라온다.

`get_display_name` 은 `metadata["name"]` 을 우선한다. 승격 메타데이터는 `build_serving_metadata` 가 `name` 을 넣는다. 원본 모델은 레거시 슬롯을 그대로 쓰므로 `basename(model_dir)` 후퇴 경로도 깨지지 않는다.

### 5.3 승격 절차 (`_promote_unlogged` 의 설치 구간만)

스테이징 검증(복사, `joblib.load`, `unservable_features`)은 지금과 같다. 검증 성공 후:

1. 현재 **해석된 트리**를 기존 `backup_dir/<model>` 로 스냅샷한다. `verify_migration.verify_model_weights` 가 승격 백업에서 원본 바이트를 찾는 계약을 유지한다. 슬롯 전체(다른 세대 포함)를 복사하지 않는다.
2. `slot/generations/` 를 만든다. 스테이징 디렉터리를 `slot/generations/<version>/` 로 `os.replace` 한다. 목적지는 없어야 한다. 같은 볼륨의 **새 이름**으로 디렉터리를 옮기는 연산이라 비어 있지 않은 대상 위 교체가 아니다.
3. `LIVE` 를 세대 이름으로 원자 교체한다. 이 한 단계가 세트 공개다.
4. 직전 세대와 현재 세대만 남기고 나머지 `generations/*` 는 지운다. `LIVE` 가 가리키는 트리는 지우지 않는다.

스테이징 경로는 지금처럼 `serving_dir/.promote_staging_*` 로 둔다. 서빙 루트와 같은 볼륨이어야 2번 rename 이 복사로 떨어지지 않는다.

실패 처리:

- 2번 이전: 서빙 해석 결과는 변하지 않는다. 불완전 스테이징은 지금처럼 삭제한다.
- 2번 성공, 3번 실패/킬: `LIVE` 는 옛 값(또는 없음). 고아 세대는 다음 성공 승격의 4번에서 걷힌다. 혼합 없음.
- 3번 성공 후 4번 실패: 공개는 이미 새 세대. 고아 세대가 남는 것은 정합성 문제가 아니다.

슬롯 루트의 레거시 `model.bin` / `metadata.json` 은 **같은 트랜잭션에서 파일 단위로 덮어쓰지 않는다.** 덮는 순간 3장의 반례가 레거시 경로에 다시 생긴다. 인트리 리더는 `LIVE` 만 따른다. 원본 4모델은 승격 전까지 G1 존재 검사(`tests/test_data_preservation.py::test_model_bin_files_exist`)를 그대로 통과한다. 승격 뒤에는 루트 파일이 남을 수 있으나 해석기는 쓰지 않는다. 루트 정리는 후속 작업이며 이 설계의 완료 조건이 아니다.

### 5.4 롤백

파일 단위 재설치를 제거한다.

1. 백업 스냅샷이 있으면 그것을 새 세대 디렉터리로 올리고 `LIVE` 를 그 이름으로 돌리거나,
2. 직전 세대가 `generations/` 에 남아 있으면 `LIVE` 만 직전 이름으로 교체한다.

둘 다 공개는 `LIVE` 한 파일이다. 잘못 되돌렸을 때 한 번 더 되돌리는 현재 계약은 유지한다. 직전 `LIVE` 대상과 백업 스냅샷 중 복구 가능한 쪽을 고른다. 둘 다 없으면 지금처럼 `RollbackUnavailable`.

`_restore_serving_from` → `_install_staging_into_serving` 파일 루프는 승격·롤백 공개 경로에서 삭제한다. 스냅샷용 `_snapshot_directory` 는 백업 트리 작성에만 남긴다.

### 5.5 동시 리더

세대 디렉터리는 공개 후 불변이다. `LIVE` 를 읽은 프로세스는 그 트리를 연다. 이미 메모리에 올린 wrapper 는 지금과 같이 자동 재적재하지 않는다 (`get_served_version` 주석과 동일). 교체 중에도 슬롯 디렉터리는 존재한다. 기존 `test_promote_keeps_serving_path_present_during_swap` 의 존재 불변조건은 그대로 참이어야 한다.

### 5.6 하지 않을 것

- 원본 4모델 파일을 승격 없이 세대 디렉터리로 옮기기
- `LIVE` 를 심볼릭 링크로 만들기
- 새 Python 의존성

### 7.1 반례를 닫는 테스트 (필수)

이름은 구현에서 바꿔도 된다. 단언 내용은 바꾸지 않는다.

1. **킬 창 시뮬:** 세대 디렉터리까지 만든 뒤 `LIVE` 를 쓰기 전에 예외. 해석된 `model.bin` 바이트와 `metadata.json` 의 `version` 이 승격 전과 같고 서로 같다. `LIVE` 가 없거나 옛 값이다.
2. **`LIVE` 교체 실패:** `publish_live` / `_replace_path` 를 `LIVE` 목적지에만 실패시킨다. 단언은 1과 같다.
3. **성공 공개 후 일치:** v1 승격 뒤 v2 승격. 해석된 트리에서 `metadata["version"] == "v2"` 이고 `model.bin` 이 v2 바이트다. 슬롯 디렉터리는 전 구간 존재한다.
4. **복구 중 실패가 섞지 않음:** 공개 경로에 파일 단위 루프가 남아 있으면 이 테스트는 실패해야 한다. `model.bin` 교체를 반복 실패시켜도 해석된 세트는 한 세대여야 한다.
5. **다중 파일 세트:** 스테이징에 `model.bin`, `metadata.json`, `model_q05.bin` 을 넣고 1번을 반복. 세 파일의 세대가 갈라지지 않는다.
6. **롤백:** v2 에서 롤백 중 `LIVE` 실패. 해석 결과는 v2 세트. 성공 롤백 후 v1 세트.
7. **레거시:** `LIVE` 없는 슬롯은 루트 `metadata.json` 을 읽는다. `tests/test_champion_resolution.py` 의 기존 픽스처가 통과해야 한다.

금지: 첫 `model.bin` 실패 후 복구 성공만으로 세트 원자성을 단언하는 것을 유일한 증거로 남기는 것. 그 테스트는 경로 존재·복구 성공용으로만 유지한다.

### 7.2 회귀

```bash
uv run pytest tests/test_promotion_gate.py tests/test_promotion_cli.py \
  tests/test_promotion_evidence_binding.py tests/test_champion_resolution.py \
  tests/test_serving_layout.py tests/test_verify_migration.py -q
uv run pytest tests/ -q -m 'not data_assets'
uv run mypy src
python3 scripts/validate_agent_rules.py --quiet
```

`data_assets` 마커 테스트는 격리 트리에 가중치가 없으면 실패하는 것이 정상이다. 주 저장소에서 `test_model_bin_files_exist` 만 따로 확인한다. 이 설계는 승격하지 않은 원본 경로를 옮기지 않으므로 그 단언은 유지되어야 한다.

### 7.3 구현자가 실측할 관찰

- 승격 공개 경로에 `os.replace` 대상이 `LIVE`(또는 `LIVE.tmp`→`LIVE`) 와 **존재하지 않는** 세대 디렉터리 이름뿐인지.
- `_install_staging_into_serving` 의 슬롯 내부 파일 루프가 호출 그래프에서 사라졌는지.
- `src/ml/features.py` diff 가 비었는지.

## 9. 잔여 리스크 (구현 범위 밖)

- 인트리 밖 도구가 `data/model_files/<model>/model.bin` 을 직접 열면, 승격 이후 레거시 루트가 남아 있을 때 옛 바이트를 본다. 해결은 해석 함수를 쓰거나, 별도 Task 에서 레거시 루트를 제거하는 것이다. 후자는 G1 존재 검사를 함께 고쳐야 한다.
- `ModelRegistry._discover_model_ids_on_disk` 가 점 접두 디렉터리를 모델로 세는 문제는 기존에도 있다. 구현 Task 가 점 접두를 건너뛰면  harden 이지만 X4 반례의 필수 조건은 아니다.
- 프로세스 외부에서 `generations/<version>` 을 사람이 직접 지우면 `LIVE` 가 허공을 가리킨다. 해석기는 레거시 루트로 폴백하거나 로드를 거부해야 한다. 거부(fail-closed)를 기본으로 하고, `LIVE` 가 깨진 경우에는 레거시 루트에 `metadata.json` 이 있을 때만 폴백한다.

이 문서는 구현 허가를 대체하지 않는다. 구현은 별도 Dispatch 에서 이 5장·7장·8장을 그대로 실행한다.
