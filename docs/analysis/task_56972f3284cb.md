## 1. 개요 및 배경

2026-09-02 분석 보고서(3.8)에 따라 다음 두 가지 핵심 개선 과업을 수행하였습니다:
1. **정형 질의 캐시 키별 Single-Flight 도입**: Redis cold miss 시 동일 캐시 키에 대한 동시 대량 집계 질의(최대 97초 소요)가 중복 실행되지 않도록 잠금 기반 single-flight 메커니즘을 적용하고, 참조 계수(ref count) 기반 자동 정리를 통해 무한 키 누적으로 인한 메모리 누수 방지.
2. **Readiness 엔드포인트의 Warmup 완료 상태 및 LLM 상태 반영**: 기동 시점 백그라운드 예열(warmup) 진행 여부와 LLM 가용 상태를 검사하여 응답 페이로드에 포함하고, 기본 정책에서는 `degraded`로 표시하되 `Settings` 설정(`READINESS_REQUIRE_WARMUP`, `READINESS_REQUIRE_LLM`)에 따라 하드 게이트(`not_ready` / 503)로 승격할 수 있도록 구현.

## 2. 변경 내역 및 설계

### 2.1 정형 질의 캐시 참조 계수 기반 Single-Flight (`src/rag/structured_data.py`)
- `_FlightLockEntry` 및 `_flight_master_lock`을 활용하여 키별 참조 계수를 관리하는 `_flight_lock(key)` 컨텍스트 매니저 구현.
- `_top_rows` 및 `_cached_aggregate` 진입 시 fast-path로 캐시를 먼저 조회하고, miss 발생 시 해당 키 전용 잠금을 획득하여 double-checked locking 패턴으로 캐시를 재확인한 후 실제 DB 쿼리를 1회만 실행.
- 선행 스레드 실패 시에도 context manager(`finally`)를 통해 잠금이 정상 해제되어 후속 대기 스레드가 데드락 없이 안전하게 재시도 또는 예외 처리를 진행하도록 보장.
- 마지막 대기자가 빠져나가는 시점에 `_flight_locks` 딕셔너리에서 해당 키 엔트리를 자동 제거(`pop`)함으로써 동적 SQL 리터럴 키가 무한 누적되는 메모리 누수를 원천 차단.

### 2.2 Warmup 상태 추적 및 LLM 헬스체크 (`src/app/api/v1/health.py`, `src/app/main.py`, `src/app/core/config.py`)
- `src/app/core/config.py`의 `Settings`에 `READINESS_REQUIRE_WARMUP: bool = False` 및 `READINESS_REQUIRE_LLM: bool = False` 정규 설정 필드 추가.
- `WarmupState` 클래스를 정의하여 백그라운드로 실행되는 3대 예열 태스크(`llm`, `predictor`, `vector_search`)의 완료 및 에러 상태를 스레드 안전하게 기록.
- `src/app/main.py`의 `lifespan` 진입 시 `warmup_state.start()`를 호출하고, 각 예열 태스크 완료 시 `mark_*_done()`으로 상태 전이.
- `_check_llm` 함수를 통해 LLM 백엔드(`build_backend().available()`) 가용성을 짧은 타임아웃으로 진단.
- `/api/v1/health/ready` 엔드포인트 응답에 `warmup`과 `llm` 필드를 추가하고, 기본 판정에서는 warmup 미완료 또는 LLM 미가용 시 `degraded`(200 OK)로 응답하며, 설정 활성화 시 `not_ready`(503)로 승격.
