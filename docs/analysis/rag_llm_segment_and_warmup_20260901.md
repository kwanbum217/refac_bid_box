# RAG llm 구간 조사와 기동 예열 (2026-09-01)

> **작성일**: 2026-09-01
> **결론**: llm 구간 자체는 안전한 최적화 여지가 없습니다. 실질 문제는 **콜드 비용**이며
> 기동 예열로 70% 를 제거했습니다
> **관련 판정**: [`vector_metadata_prefilter_verdict_20260901.md`](vector_metadata_prefilter_verdict_20260901.md)

---

## 1. llm 구간을 후보별로 닫았습니다

warm 구간 정본에서 llm 은 P50 2,244ms 로 전체의 62.5% 입니다. 후보 넷을 실측으로
확인했고 **모두 여지가 없습니다.**

### 1.1 SYSTEM_PROMPT 축소 — 이득 9%

프롬프트의 60% 가 매 요청 동일한 `SYSTEM_PROMPT`(1,285자)라 유력해 보였습니다.
**그러나 Ollama 가 이미 접두사를 캐시합니다.**

| 조건 | 프롬프트 | prefill |
| --- | ---: | ---: |
| 현행 SYSTEM_PROMPT | 1,381 tok | 612~703ms |
| 축소판 | 744 tok | 555~570ms |

637 토큰(46%)을 줄여도 prefill 은 **57ms(9%)** 만 줄어듭니다. 동일 접두사가 캐시로
건너뛰어지기 때문입니다. 프롬프트를 깎아 얻을 것이 없습니다.

### 1.2 컨텍스트 축소 — 이미 절제됨

`_compose_context_text` 가 벡터 문서를 **상위 3건, 각 250자**로 이미 자릅니다.
fixture 실측 컨텍스트는 평균 **846자**이며 `SYSTEM_PROMPT` 보다 작습니다.

### 1.3 `num_predict` 상한 — 응답이 이미 짧음

실제 응답이 평균 **248자**입니다. 더 조이면 답변이 잘릴 위험만 커집니다.

### 1.4 남는 것은 decode 속도

`gemma4:e2b` 가 **99 tok/s** 로 돌고 248자 응답이면 decode 에 약 2.5초가 듭니다.
이것이 llm 구간의 실체입니다. 더 작은 모델은 e4b/e2b 베이크오프에서 이미 판정이
끝났고, 임베딩처럼 캐시로 우회할 수도 없습니다.

**prefill 은 토큰 수에 선형입니다**(약 1,320 tok/s). 참고 곡선입니다.

| 프롬프트 | prefill |
| ---: | ---: |
| 3,693 tok | 2,803ms |
| 2,243 tok | 1,647ms |
| 1,163 tok | 860ms |
| 793 tok | 589ms |

## 2. 실질 문제는 콜드 비용이었습니다

이번 세션에서 콜드/웜 차이를 서로 다른 네 층에서 실측했고 전부 같은 방향입니다.

| 층 | 콜드 | 웜 | 배율 |
| --- | ---: | ---: | ---: |
| `retrieve_semantic_context` | 13,142ms | 46ms | 286배 |
| Ollama 임베딩(컨테이너 첫 연결) | 13,328ms | 45ms | 296배 |
| LLM prefill(동일 접두사) | 6,281ms | 12ms | 523배 |
| ChromaDB 첫 HNSW 질의 | 4,726ms | 3.4ms | 1,390배 |

`keep_alive` 는 Ollama 모델 상주만 보장합니다. **ChromaDB 인덱스와 프로세스의
연결·클라이언트 캐시는 그 대상이 아닙니다.**

---

## 3. 기동 예열 효과 (실측)

`app` 컨테이너를 재기동하고 healthy 직후 첫 질의를 재는 방식으로 3회씩 측정했습니다.

| 조건 | 회차별 | 중앙 |
| --- | --- | ---: |
| 예열 없음 | 45,243 / 31,398 / 31,210ms | **31,398ms** |
| 예열 있음 | 18,191 / 19,045 / 18,784ms | **18,784ms** |

같은 질의의 정상 상태는 13,292ms 입니다. 따라서 콜드 초과분은 예열 없음 18.1초,
예열 있음 5.5초이며 **예열이 콜드 비용의 약 70% 를 제거**했습니다.

`vector_warmup` 로그가 6,624ms 를 미리 소화하는 것으로 확인됩니다.

```
INFO event=predictor_warmup, status=success, elapsed_ms=3.71, models_loaded=5
INFO event=vector_warmup, status=success, elapsed_ms=6624.57
```

**결과에는 영향이 없습니다.** 같은 코드 경로를 기동 시 한 번 더 부를 뿐입니다.

## 4. 함께 고친 관측 결함

**2026-09-01 까지 `predictor_warmup` 과 `llm_warmup` 로그가 한 줄도 남지 않았습니다.**
컨테이너 루트 로거가 WARNING 이고 핸들러가 없어 `logger.info` 가 유실됐습니다.

예열은 실패해도 조용히 느려질 뿐이라 관측이 없으면 알아챌 수 없습니다. 예열 로거의
레벨과 핸들러를 보장해 세 예열 모두 로그가 남게 했습니다.

---

## 5. 남은 것과 하지 않을 것

| 항목 | 판단 |
| --- | --- |
| decode 속도(99 tok/s) | 모델·하드웨어 한계. 손대지 않습니다 |
| 모델 교체 | e2b 승격이 품질 비교로 끝난 사안입니다 |
| vector 메타데이터 필터 | 원인은 밝혀졌으나 결과 불변 해법이 없어 기각했습니다 |
| 예열 이후 정상 상태 | vector 1,296ms + llm 2,244ms 로 구조적 하한에 가깝습니다 |

**RAG 최적화는 여기서 닫습니다.** 남은 지렛대는 모델이나 하드웨어 교체이며 둘 다
이 세션의 범위가 아닙니다.

## 6. 측정 함정

| 함정 | 실제 |
| --- | --- |
| 프롬프트를 줄이면 prefill 이 준다 | 동일 접두사는 이미 캐시됩니다. 46% 를 줄여도 9% 만 줄었습니다 |
| `keep_alive` 로 콜드가 해결된다 | 모델 상주만 보장하며 인덱스·연결 캐시는 대상이 아닙니다 |
| 예열 로그가 없으면 예열이 안 된 것 | 로그 유실일 수 있습니다. 레벨과 핸들러를 먼저 확인하십시오 |
| 구간 평균이 사용자 체감 | 실질 문제는 첫 요청에 몰려 있었습니다 |
