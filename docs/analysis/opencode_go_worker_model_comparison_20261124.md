## 2. 비용 비교 기준: 캐시 읽기를 넣어야 합니다

워커 비용은 대부분 캐시 읽기입니다. 2026-11-24 워커 세션 실측(`scripts/opencode_session_stats.py`)에서
입력 토큰의 90~98% 가 캐시 읽기였고, 모델별 캐시 단가는 최대 10배 다릅니다
(`deepseek-v4.1-flash` $0.003, `glm-5.3-flash` $0.03). 캐시를 뺀 "입력 3 : 출력 1" 혼합 단가로는
실제 소모를 잘못 셉니다.

아래 기준 세션 세 가지로 계산합니다(단위 백만 토큰, 같은 날 실측).

| 기준 세션 | 캐시 읽기 | 새 입력 | 출력 | 실측 출처 |
| --- | ---: | ---: | ---: | --- |
| 일반 빌더(effort high) | 2.056 | 0.074 | 0.023 | `kb-result-cleanup` 빌더 |
| 큰 빌더(effort max) | 12.668 | 0.172 | 0.066 | `home-prefs-perf` 빌더 |
| 리뷰(effort high) | 0.364 | 0.036 | 0.006 | `search-cache` 리뷰어 |

계산식은 `캐시 읽기 × 캐시 단가 + 새 입력 × 입력 단가 + 출력 × 출력 단가` 를 Go 월 한도로 나눈
값입니다. 피크 2배, 고컨텍스트 할증(Haiku 100k, GPT-6 Luna 272k, Grok 200k 초과)은 넣지 않았습니다.
기준 세션 컨텍스트가 최대 167k 라 Haiku 를 뺀 나머지는 할증 구간 밖입니다.

허용량은 모델끼리 공유하므로 여러 모델을 섞으면 비율이 더해집니다.

외부 비교표의 "1%당 토큰"(캐시 제외) 기준과 달라지는 점은 다음과 같습니다.

  캐시 제외 기준으로는 약 2/3 효율로 보였습니다.
- 리뷰 세션은 짧아 모든 Flash 계열이 0.01~0.07% 입니다. 리뷰어 선택에서 비용은 결정 요인이 아닙니다.
- `deepseek-v4.1-flash` 는 피크 2배를 적용해도 세션당 0.06~0.2% 입니다. 피크를 피하려고 모델을
  바꾸는 이득은 작고, 전환·검증 비용이 더 큽니다.

## 4. 배정

| 역할 | 상시 | 고위험 | 한도 소진 |
| --- | --- | --- | --- |
| 빌더 | `deepseek-v4.1-flash` (effort 기본 high, 과제별 low·max) | `deepseek-v4.1-flash` max. 같은 Task 반려가 반복될 때만 `glm-5.3` 검토 | `hy4-flash-free`(낮은 위험 구현만) |
| 리뷰어 | `glm-5.3-flash` high | `glm-5.3`(병합 판정·마이그레이션·보안). 리뷰당 약 0.09% | 유료 리뷰어 유지. 무료 모델을 병합 판정 리뷰어로 두지 않습니다 |

빌더와 리뷰어는 계열을 나눕니다. 빌더를 GLM 으로 올리면 리뷰어는 DeepSeek 또는 MiMo 로 바꿉니다.
배정 정본은 [`docs/ops/orca_worker_model_pool.md`](../ops/orca_worker_model_pool.md) 와
`scripts/orca_model_router.py` 이며, 이 문서는 비교 근거입니다.

## 7. 확인하지 못한 것

- `gpt-6-luna`, `grok-4.7`, `gemini-4-argon` 은 보존 0일이 아님(`zdr: false`)까지만 확인했고 보관 기간은 확인하지 못했습니다.

- 기준 세션 세 개는 하루 실측입니다. 과제 크기에 따라 소모는 몇 배 달라질 수 있습니다.
