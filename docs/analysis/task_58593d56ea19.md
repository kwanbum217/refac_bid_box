## 1. 개요 및 배경

2026-08-29 세션에서 코디네이터가 다중 워커 기동 후 감시를 수행하기 위해 셸 스크립트로 임의의 감시 루프를 직접 작성해야 했습니다. `scripts/orca_worker_watch.py` 가 호출 시점의 1회성 스냅샷만 반환하여 주기적 감시와 종료 조건 처리가 도구 레벨에서 지원되지 않았기 때문입니다.

또한 기존 도구는 `commits=0, dirty=0` 상태를 단순히 초기 조사 가능성으로 안내할 뿐, 시간 경과 이력을 추적하지 않아 "방금 기동된 워커"와 "5분 이상 아무 변화 없는 정체 워커"를 구분하지 못했습니다.

본 작업에서는 `scripts/orca_worker_watch.py` 를 확장하여 다음을 구현했습니다:
1. **상시 감시 모드 (`--watch`)**: 지정 주기(`--interval`), 최대 반복(`--max-iterations`), 목표 커밋 수 완료 조건(`--min-commits`) 지원.
2. **차단 즉시 종료 (종료 코드 1)**: 사람 개입이 필요한 프롬프트/실패 정체 감지 시 남은 루프 없이 즉시 중단.
3. **정체 시간화 추적 (`--stall-threshold`)**: 워커별 커밋/미커밋 미변화 경과 시간을 기록하고 임계치(기본 300초) 초과 시 `[정체후보]` 로 표시 (종료 코드는 0 유지).
4. **로그 절제 (Quiet Diff Output)**: 직전 주기와 상태가 동일하면 출력을 생략하여 배경 로그 폭주 방지.
5. **무손실 및 계약 불변**: 기본 인자 없는 호출은 1회 점검(종료 코드 0/1/2) 기존 계약 100% 보존.

## 2. 주요 변경 사항

### 2.1 `scripts/orca_worker_watch.py`

- **CLI 인자 확장**:
  - `--watch`: 상시 감시 모드 활성화 플래그.
  - `--interval` / `--interval-sec`: 점검 주기 (초 단위, 기본 10.0초).
  - `--max-iterations` / `--max-iter`: 최대 반복 횟수 (기본 1-shot 은 1회, `--watch` 시 무제한 또는 지정값).
  - `--min-commits`: 감시 대상 워커 전원이 도달해야 하는 최소 커밋 수 (충족 시 종료 코드 0 으로 조기 종료).
  - `--stall-threshold` / `--stall-sec`: 정체 후보 판정 기준 시간 (기본 300.0초).
- **데이터 구조 `WorkerState` 확장**:
  - `stall_candidate: bool = False`
  - `unchanged_seconds: float = 0.0`
  - `as_dict()` 에 `stall_candidate` 및 소수점 1자리 `unchanged_seconds` 추가.
- **이력 추적 함수 `update_history()`**:
  - 각 워크트리 경로별 `commits`, `dirty` 의 마지막 변경 시각과 최초 관측 시각 기록.
  - 값이 유지된 경과 시간(`unchanged_seconds`) 계산 및 임계치 초과 시 `stall_candidate = True` 및 상세 안내 노트 추가.
- **감시 루프 `watch_loop()`**:
  - 매 주기마다 상태를 수집하고 변경 사항(`has_changes`)이 있을 때만 터미널/JSON 출력.
  - 차단 감지 시 즉시 종료 코드 1 반환.
  - `min_commits` 달성 시 즉시 종료 코드 0 반환.
  - 최대 반복 도달 시 차단 여부에 따라 0/1 반환.
