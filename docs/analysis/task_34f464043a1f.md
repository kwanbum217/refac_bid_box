## 1. 개요 및 배경

기존 `tests/conftest.py`의 `_reset_login_rate_limit` autouse fixture는 매 테스트 전후 실제 Redis 연결을 맺고 `RATE_LIMIT_IP_PREFIX` 및 `RATE_LIMIT_ACCOUNT_PREFIX` 키를 `scan_iter`로 조회하여 `delete`를 실행했습니다.

이로 인해 전체 테스트(3,400+건) 실행 시 약 34분 이상의 긴 시간이 소요되었으며, 실제 Redis가 기동되지 않은 환경이나 외부 상태 간섭에 취약한 문제가 있었습니다.

본 작업에서는 실제 Redis `scan_iter`/`delete` 의존성을 제거하고, 프로세스 내부 인메모리 Redis 대역(`_InMemoryRateLimitClient`, `_InMemoryRateLimitPipeline`)을 매 테스트마다 `login_rate_limiter._conn.client`에 주입함으로써 로그인 제한 상태를 결정론적이고 빠르게 격리했습니다.

## 2. 주요 구현 내용

### 2.1 인메모리 Rate-Limit 대역 구현 (`_InMemoryRateLimitClient`, `_InMemoryRateLimitPipeline`)
- `LoginRateLimiter`가 요구하는 최소 Redis 인터페이스 계약을 정확하게 충족합니다:
  - `client.get(key)`: 저장된 키 값(`str`) 또는 `None` 반환
  - `client.delete(*keys)`: 전달된 키들을 인메모리 딕셔너리에서 원자적으로 제거하고 삭제 개수 반환
  - `client.pipeline()`: `incr(key, amount=1)`, `expire(key, time)`, `execute()` 체이닝 및 결과 리스트 반환
- 운영 코드의 계약 및 동작 로직을 전혀 완화하거나 변형하지 않고 원형 그대로 지원합니다.

### 2.2 테스트 단위 인메모리 대역 주입 (`_reset_login_rate_limit`)
- `@pytest.fixture(autouse=True)`에서 매 테스트 실행 시 독립된 `_InMemoryRateLimitClient` 인스턴스를 생성하여 `monkeypatch.setattr(login_rate_limiter._conn, "client", lambda: fake_client)`로 주입합니다.
- 테스트 간 상태 누적 및 앞선 테스트의 로그인 실패로 인한 뒤 테스트의 429 차단 현상을 원천 방지합니다.
- `tests/test_auth_hardening.py` 등에서 자체적으로 `mock_redis_for_rate_limit` fixture나 `monkeypatch.setattr(..., lambda: None)`(fail-open 검증) 등으로 재패치하는 경우 정상적으로 오버라이드되며, 테스트 teardown 시 `monkeypatch`에 의해 깨끗하게 복구됩니다.
