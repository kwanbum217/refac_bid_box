## 1. 개요 및 취약점 원인 분석

본 조치는 2026-09-02 보완점 분석 보고서 2.1 항목에 해당하는 대화 상태 관리 모듈의 교차 사용자 접근(IDOR, Insecure Direct Object References) 취약점을 차단하기 위해 수행되었습니다.

### 1.1 발견된 취약점 구조

1. **소유권 검증 누락 (`_get_state_by_key`)**:
   - 기존 `_get_state_by_key()` 함수는 `session_key` 조건만으로 DB 행을 조회하였으며, 인자로 전달받은 `user_id`를 소유권 대조에 사용하지 않았습니다.
   - 신규 생성 시에만 `user_id`가 기록되고, 기존 행 조회 시에는 타 사용자의 세션 키이더라도 그대로 반환되었습니다.

2. **예측 가능한 사용자 메모리 키 (`user:{user_id}`) 표적 공격**:
   - `_resolve_user_memory_key(user_id)`는 `user:{user_id}` 형태의 고정 키를 생성합니다.
   - 공격자가 클라이언트 요청의 `session_key`에 임의의 `user:1` 등을 지정하면, `load_conversation_context`를 통해 피해자의 `last_query`, 필터, 요약 정보를 조회할 수 있었습니다.
   - 또한 공격자가 `remember_chat_interaction`을 호출하여 피해자의 사용자 메모리를 임의의 값으로 오염(Pollution)시킬 수 있었습니다.

3. **익명(Anonymous) 및 교차 권한 미검증**:
   - `user_id`가 `None`인 비로그인 요청도 인증된 사용자의 세션 키나 사용자 메모리 키에 접근할 수 있었습니다.
   - 미생성 상태의 타 사용자 메모리 키(`user:X`)를 다른 사용자가 선점 생성할 수 있는 위험이 존재했습니다.

## 2. 해결 방안 및 구현 상세

### 2.1 `_get_state_by_key` 소유권 강제 및 Fail-Closed 적용

`src/app/services/conversation_state.py`의 `_get_state_by_key()` 함수를 전면 개정하여 다음 원칙을 강제했습니다.

1. **소유자 일치 검증**:
   - 조회된 행의 `state.user_id`와 요청자의 `user_id`를 대조합니다.
   - 불일치 시(타 사용자 소유 또는 익명-인증 간 불일치) 즉시 `None`을 반환합니다 (Fail-Closed).
2. **사용자 메모리 키 생성 제한**:
   - `session_key`가 `user:` 접두사로 시작하는 경우, 요청자의 `_resolve_user_memory_key(user_id)`와 정확히 일치할 때만 생성을 허용합니다.
   - 타인의 메모리 키 선점 또는 익명 사용자의 `user:` 키 생성을 원천 차단합니다.

```python
def _get_state_by_key(
    db: Session, session_key: str, *, user_id: int | None = None, create: bool = True
) -> ChatSessionState | None:
    if not session_key:
        return None

    state = db.execute(
        select(ChatSessionState).where(ChatSessionState.session_key == session_key)
    ).scalar_one_or_none()

    if state is not None:
        if state.user_id != user_id:
            return None
        return state

    if not create:
        return None

    if session_key.startswith(USER_MEMORY_PREFIX):
        expected_user_key = _resolve_user_memory_key(user_id)
        if not expected_user_key or session_key != expected_user_key:
            return None

    state = ChatSessionState(session_key=session_key, user_id=user_id)
    db.add(state)
    db.commit()
    db.refresh(state)
    return state
```

### 2.2 `ensure_session_key` 정규화 및 방어 계층 추가

클라이언트가 `session_key`로 `user:` 접두사를 전달하는 경우, 이를 일반 세션 키로 인정하지 않고 안전한 신규 UUID로 재발급하도록 정규화했습니다.

```python
def ensure_session_key(session_key: str | None = None) -> str:
    cleaned = (session_key or "").strip()
    if not cleaned or cleaned.startswith(USER_MEMORY_PREFIX):
        return uuid.uuid4().hex
    return cleaned
```
