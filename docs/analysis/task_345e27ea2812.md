## 1. 작업 개요 및 목적

본 작업은 2026-09-02 보완점 분석 보고서 3.2 다 항목에 따라, **MySQL 운영 DB**, **ChromaDB 지식베이스**, **서빙 모델 및 MLOps 레지스트리**를 단일 복구 단위(Unified Recovery Unit)로 결박하는 통합 백업/복원 도구와 표준 런북을 구축하는 작업입니다.

### 핵심 원칙 및 계약 준수
1. **단일 복구 단위 결박**: DB와 ChromaDB, 서빙 모델 가중치의 시점이 분리되어 발생하는 정합성 왜곡(Train/Serve skew, 챗봇 지식베이스 인용 불일치)을 원천 방지합니다.
2. **안전 기본값 (dry-run default)**: 백업 및 복원 명령 모두 사전 점검(dry-run)이 기본값이며, 실제 실행은 `--execute` 명시 플래그를 요구합니다.
3. **복원 시 덮어쓰기 보호**: 복원 실행 시 덮어써질 대상(DB, ChromaDB 디렉토리, 모델 디렉토리)을 명시적으로 출력하고, `--confirm` 플래그(비대화형 필수) 또는 대화형 확인 없이 진행되지 않습니다.
4. **매니페스트 무결성 추적**: 백업 스냅샷마다 생성 시각, Git HEAD 커밋 SHA, 컴포넌트별 파일 경로/크기/SHA256 체크섬, DB 핵심 테이블 행 수 요약을 `backup_manifest.json`에 기록합니다.
5. **무손실 검증 도구 재사용**: 복원 완료 후 기존 [`../../scripts/verify_migration.py`](../../scripts/verify_migration.py)를 자동 호출하여 5단계(가중치 체크섬, ChromaDB 질의, DB 필수 테이블, 스키마 서명, 데이터 행 수) 무손실 검증을 수행합니다.
6. **RPO / RTO 명시 원칙**: 임의의 수치를 단정하지 않고, 운영 담당자가 비즈니스 SLA에 맞추어 기입하도록 공란 및 안내 문구를 명시했습니다.
7. **보안 및 자격 증명**: 자격 증명은 환경 변수에서 로드하며 코드와 문서에 평문 비밀번호를 절대 노출하지 않습니다. 암호화 및 오프호스트 사본은 외부 인프라 구축이 선행되어야 하므로 후속 과업으로 명시했습니다.

## 2. 주요 구현 및 변경 내역

### 2.1 통합 백업 및 복원 도구 신설 ([`../../scripts/backup_recovery.py`](../../scripts/backup_recovery.py))
- `backup`: 운영 DB 덤프(`mysqldump`), ChromaDB 디렉토리 압축, 모델/레지스트리 디렉토리 압축을 수행하고 매니페스트를 생성합니다.
- `restore`: 스냅샷 매니페스트 무결성 사전 검증 후 DB, ChromaDB, 모델을 복원하고 `scripts/verify_migration.py`를 호출합니다.
- `verify`: 스냅샷 내 각 아카이브의 존재 여부, 파일 크기, SHA256 체크섬을 매니페스트와 대조합니다.
- `list`: 등록된 백업 스냅샷 목록과 생성 시각, HEAD 커밋, 무결성 상태를 조회합니다.
