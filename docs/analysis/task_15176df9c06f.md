## 1. 개요 및 배경

Claude Code 워커 런처(`scripts/orca_claude_launch.py`)에 권한 자동 승인 옵션으로 `--dangerously-skip-permissions` 플래그가 구현되어 있었습니다. 그러나 해당 플래그는 파일 편집뿐만 아니라 셸 명령 실행을 포함한 모든 권한 검사를 전면 우회하여, 저장소의 자동 승인 감시기(`scripts/orca_auto_approve.py`)를 통한 위험 명령 차단 체계를 무력화하는 보안상 취약점을 안고 있었습니다.

선행 조사 및 리뷰어 권고에 따라, 파일 편집만 자동 승인하고 셸 명령 실행에 대한 확인 절차는 온전히 보존하는 `--permission-mode acceptEdits`로 인자를 전환하였습니다. 이를 통해 자동 승인 감시기의 화이트리스트 판정 체계가 정상 작동하도록 보장하였습니다.

## 2. 주요 변경 사항

### 2.1 `scripts/orca_claude_launch.py`

1. **`build_command` 함수 시그니처 및 로직 변경**:
   - 기존 `dangerously_skip_permissions: bool = False` 파라미터를 완전히 제거.
   - `permission_mode: str | None = None` 키워드 전용 파라미터로 대체.
   - `permission_mode`가 주어질 경우 `["--permission-mode", permission_mode]` 배열을 명령에 순서대로 추가.
   - 기본값은 `None`으로 유지하여 기본 기동 시 권한 관련 인자가 일체 붙지 않도록 보장.

2. **CLI ArgumentParser 정의 및 인자 전달 변경**:
   - `--dangerously-skip-permissions` 플래그 인자를 완전히 제거.
   - `--permission-mode` 문자열 인자(`type=str`, `default=None`)를 신설.
   - `main()` 함수에서 `args.permission_mode`를 `build_command`에 전달.

### 2.2 `tests/test_orca_claude_launch.py`

1. **`test_build_command_permission_mode` 신설**:
   - 기본 기동 명령에 `--permission-mode`가 포함되지 않음을 단언.
   - `--permission-mode acceptEdits` 지정 시 `--permission-mode`와 `acceptEdits`가 순서대로 포함됨을 단언.
   - 기본 및 옵션 지정 기동 명령 모두에서 `--dangerously-skip-permissions` 문자열이 어떤 경우에도 나타나지 않음을 단언.

2. **`test_claude_main_passes_permission_mode` 신설**:
   - `main()` 실행 시 `--permission-mode acceptEdits` 인자가 `build_command`를 거쳐 최종 실행 명령에 올바르게 전달되는지 통합 단언.
