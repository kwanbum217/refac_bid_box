# Task task_93d4fd925462 분석 기록

> 작성일: 2026-09-06
> 작업: worker_done 전송 시 --dispatch-capability 자동 해소

## 문제

2026-09-06 세션에서 워커와 리뷰어 여덟 대 이상이 첫 worker_done 전송에서
capability 누락으로 거부됐다. Capsule 지시문에 토큰 위치를 명시해도 재발했으므로
지시문이 아닌 기계적 해소 경로가 필요했다.

## 변경

| 파일 | 내용 |
| --- | --- |
| `scripts/orca_taskctl.py` | preamble 텍스트에서 `dcap_` 토큰을 추출해 워크트리 `.orca/dispatch_capabilities/<task_id>.capability` 파일에 task 별로 기록한다. 기록 지점은 런처 경로의 preamble 작성 직후, 터미널 부착 경로의 fallback 분기, Dispatch 성공 블록의 best-effort 분기다. 기록 실패는 Dispatch를 막지 않고 경고만 남긴다. 토큰 전체는 로그에 남기지 않고 앞 9자만 표시한다. |
| `scripts/orca_worker_done_guard.py` | `--send` 시 명시 `--dispatch-capability` 인자가 있으면 그대로 쓰고, 없으면 위 기록 파일에서 해소한다. 둘 다 없으면 전송하지 않고 종료 코드 2로 실패한다(fail-closed). 기존 `--from`/`--dispatch-id` 해소 동작과 오류 문구는 그대로다. |
| `tests/test_orca_worker_done_guard.py` | 신규 6건. 파일 자동 해소, fail-closed, 명시 우선, 토큰 비노출, preamble 추출, task 별 기록을 검증한다. 기존 `--send` 계열 테스트 3건은 명시 capability를 붙이도록 갱신했다. |

## 보장

- `.orca/`는 `.gitignore`에서 이미 제외되므로 토큰 파일이 커밋되지 않는다.

- 빈 값이나 자리표시자를 붙여 전송하는 경로는 없다.
