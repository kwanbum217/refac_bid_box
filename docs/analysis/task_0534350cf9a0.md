## 1. 작업 개요

본 작업은 `refac_bid_box` 서비스에서 요청 지연 및 구간별 병목을 정밀하게 진단하기 위해 벤더 독립적인 OpenTelemetry 표준 계측 인프라를 구축한 과업입니다. 백엔드 시각화/저장소가 아직 확정되지 않은 상태이므로 특정 벤더 SDK를 일절 배제하고 계측 계층만 배선하였으며, 기본값은 비활성화하여 개발 및 테스트 시 런타임 오버헤드가 발생하지 않도록 설계했습니다.

---

## 2. 추가된 의존성 및 추가 사유

코디네이터의 승인 하에 필요한 최소한의 표준 OpenTelemetry 패키지만을 `pyproject.toml`에 추가했습니다.

| 패키지명 | 버전 기준 | 추가 사유 |
| --- | --- | --- |
| `opentelemetry-api` | `>=1.27.0` | 표준 분산 추적 인터페이스 (Tracer, Span 규격) |
| `opentelemetry-sdk` | `>=1.27.0` | 트레이스 처리 및 프로세서 구현체 (TracerProvider, SpanProcessor) |
| `opentelemetry-instrumentation-fastapi` | `>=0.48b0` | FastAPI 및 ASGI HTTP 요청/응답 수명 주기 자동 계측 |
| `opentelemetry-instrumentation-sqlalchemy` | `>=0.48b0` | SQLAlchemy 데이터베이스 연결 및 쿼리 실행 구간 자동 계측 |
| `opentelemetry-exporter-otlp-proto-http` | `>=1.27.0` | 표준 OTLP HTTP 규격 내보내기 (특정 벤더 종속 배제) |

> [!NOTE]
> Datadog, New Relic, Dynatrace 등의 벤더 전용 SDK는 벤더 종속 방지 원칙에 따라 일절 추가하지 않았습니다.

## 3. 핵심 변경 및 구현 내역

### 3.1 설정 관리 (`src/app/core/config.py`, `.env.example`)
- `OTEL_ENABLED: bool = False`: 기본값 비활성. 플래그 하나로 켜고 끕니다.
- `OTEL_SERVICE_NAME: str = "refac_bid_box"`: 서비스 식별자.
- `OTEL_EXPORTER_TYPE: Literal["none", "console", "otlp"] = "none"`: Exporter 대상 유형.
- `OTEL_EXPORTER_OTLP_ENDPOINT: str = ""`: 표준 수집기 엔드포인트.
- `OTEL_SAMPLING_RATIO: float = 1.0`: 샘플링 비율.

### 3.2 관측성 코어 엔진 (`src/app/core/observability.py`)
- **무비용(Zero Overhead) 보장**: `settings.OTEL_ENABLED`가 `False`인 경우 모든 초기화 및 span 생성을 건너뛰어 런타임 오버헤드가 사실상 0입니다.
- **수집기 장애 격리 (`SafeSpanExporter`)**: 원격 OTLP 수집기 장애나 네트워크 단절 시 애플리케이션으로 예외가 전파되지 않도록 완충하며, 실패 건수와 마지막 에러 내용을 상태에 보존하고 경고 로그를 남깁니다.
- **비밀 정보 누출 방지**: `password`, `secret`, `token`, `cookie` 등 민감 키를 span 속성 주입 시 자동 필터링하고, DB 비밀번호 및 HTTP 인증 헤더가 span에 노출되지 않도록 차단했습니다.
- **Arq 워커 계측 연동**: `arq_on_job_start`, `arq_on_job_end` 라이프사이클 훅 및 `trace_worker_task` 컨텍스트 매니저를 제공하여 백그라운드 태스크의 지연과 에러를 계측합니다.

### 3.3 애플리케이션 및 워커 배선 (`src/app/main.py`, `src/tasks/worker.py`)
- `src/app/main.py`: `create_app` 내에서 라우터 등록 후 `setup_observability(app=app, engine=engine)`를 호출하여 HTTP 및 DB 질의를 자동 계측합니다.
- `src/tasks/worker.py`: `_on_startup` 시 DB 엔진 계측을 수행하고, `WorkerSettings`의 `on_job_start`와 `on_job_end`에 OTel 훅을 바인딩했습니다.

### 3.4 테스트 및 문서화 (`tests/test_observability.py`, `docs/ops/observability.md`)
- `tests/test_observability.py`: 기본 비활성화 검증, FastAPI HTTP 계측, SQLAlchemy DB 계측, Arq 워커 태스크 성공/오류 계측, 수집기 장애 내결함성, 민감 정보 노출 방지, 기존 API 무결성 등 10개 단위/통합 테스트 전량 통과.
- `docs/ops/observability.md`: 아키텍처 다이어그램, 수집 속성 목록, 보안 정책, 장애 내구성, 미결 사항을 포함한 운영 가이드 작성.
