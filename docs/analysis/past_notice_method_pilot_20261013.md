# 과거(2015~2024) 용역 공고 첨부 적격심사 기준 추출 표본 실측

> **작성일**: 2026-10-13
> **작업 브랜치**: `kwanbum217/h1-past-notice-method-pilot`
> **표본**: 2015~2024년 용역 적격심사제(`낙030001`) 공고 500건 (연도별 50건, 시드 고정)
> **산출물**: `scripts/pilot_past_notice_method_extract.py`, `tests/test_pilot_past_notice_method_extract.py`
> **결과 CSV**: `.cache/past_notice_pilot/sample_extract_results.csv`, `.cache/past_notice_pilot/year_summary.csv` (커밋 대상 아님)
> **판정**: 현 추출기만으로는 자리표시자 `공고서참조` 문제를 첨부 추출로 풀 수 없음. 전량 추출 비권고

---

## 1. 질문과 배경

`raw_data.sucsfbidMthdNm` 은 2015~2024년 전량이 `공고서참조` 자리표시자이고 2025년
이후에만 실제 낙찰방법명이 있습니다. `sucsfbidMthdCd` 는 전 기간에 있어 적격심사제
계열(`낙030001`, `evaluation_rules.METHOD_FAMILY_BY_CODE`)을 골라낼 수 있습니다.
적격심사제 계열은 약 22.7만 건입니다.

이 실측은 그 22.7만 건의 낙찰방법명 공백을 **첨부 공고서에서 적격심사 기준(기준명,
통과점수 T, 가격 배점한도 B, 평점계수 k)을 추출하는 방식으로 메울 수 있는지**를
표본 500건으로 판정합니다. 전량 추출은 하지 않았습니다.

---

## 2. 방법

### 2.1 표본 선정

DB 조회는 `scripts/db_readonly_query.py` 만 사용했습니다. 연도별 50건(합계 500건)을
시드 문자열 `h1pilot20261013` 의 MD5 순서로 뽑았습니다.

```sql
SELECT bid_ntce_no, bid_ntce_ord, bid_ntce_nm, bid_ntce_dt, presmpt_prce, raw_data
FROM ( SELECT bid_ntce_no, bid_ntce_ord, bid_ntce_nm, bid_ntce_dt, presmpt_prce, raw_data,
       ROW_NUMBER() OVER (PARTITION BY YEAR(bid_ntce_dt)
         ORDER BY MD5(CONCAT('h1pilot20261013', bid_ntce_no, bid_ntce_ord))) AS rn
       FROM bid_announcements
       WHERE category='Servc' AND bid_ntce_dt >= '2015-01-01' AND bid_ntce_dt < '2025-01-01'
         AND raw_data->>'$.sucsfbidMthdCd' = '낙030001'
         AND (COALESCE(raw_data->>'$.ntceSpecDocUrl1','') <> ''
              OR COALESCE(raw_data->>'$.stdNtceDocUrl','') <> '') ) t
WHERE rn <= 50 ORDER BY bid_ntce_dt, bid_ntce_no
```

### 2.2 다운로드와 추출

- 첨부는 나라장터 URL 에서 받았습니다. 요청 간 최소 1초, 동시 요청 1개, 실패 재시도 1회.
- 파일명이 공고서·적격심사 계열 키워드(`적격심사`, `평점`, `세부기준`, `공고문`,
  `공고서`, `입찰공고`, `낙찰자`, `평가기준`, `별표`)에 걸리는 첨부만 받았습니다.
- 추출기는 새로 만들지 않고 `scripts/extract_score_params.py` 의
  `extract_document_text`, `parse_pass_threshold`, `parse_price_formula`,
  `parse_price_limit` 을 그대로 재사용했습니다. 이 파일은 수정하지 않았고 새 라이브러리도
  추가하지 않았습니다.
- 받은 파일은 `.cache/past_notice_pilot/attachments/` 에만 두고 커밋하지 않았습니다
  (`.gitignore` 의 `*.cache` 규칙으로 제외 확인).

### 2.3 지표 정의 (CSV 로 재계산 가능)

| 지표 | 정의 |
| --- | --- |
| 첨부 있음 | `attachment_count > 0` |
| 선별 | `selected_count > 0` (키워드에 걸린 첨부가 1건 이상) |
| 다운로드 성공 | `downloaded_count > 0` |
| 판독 가능 형식 | `readable_count > 0` (`extract_document_text().ok`) |
| 기준명 추출 | `criteria_name` 비어 있지 않음 |
| T 추출 | `pass_threshold` 비어 있지 않음 |
| B·k 추출 | `max_price_score` 와 `multiplier` 가 모두 비어 있지 않음 |

## 4. 원인 분석

1. **B·k 는 표에서만 나오는데 바이너리 HWP 는 표를 복원하지 않습니다.**
   `extract_score_params._binary_hwp_document` 는 BodyText 스트림에서 본문 텍스트만
   뽑고 `rows` 를 만들지 않습니다. `parse_price_formula`/`parse_price_limit` 는 표 행
   목록을 입력으로 받으므로, 첨부가 바이너리 HWP 인 한 원리적으로 빈 결과입니다.
   표본 첨부의 92.7%(416/449 공고)가 바이너리 HWP 입니다.
2. **바이너리 HWP 본문 텍스트도 인라인 제어문자 때문에 부분적으로 깨집니다.**
   기준명·T 추출률이 판독률(431) 대비 각각 55.9%, 38.1% 에 그치는 직접 원인입니다.
3. **HWPX·HWPML 만 표를 제공합니다.** 16+2=18건에 불과했고, 그중 별표 표가 실제로
   들어 있는 경우도 일부라 B·k 추출이 1건에 머물렀습니다.
4. **기준명 상위 2종이 별표를 특정하지 못합니다.** 추출해도 규칙 귀속에 쓰기 어렵습니다.

## 5. 전량(22.7만 건) 확장 시 예상치

표본 500건 실측값을 선형 외삽했습니다. 1 req/s 직렬·선별 첨부만 다운로드 조건입니다.

| 항목 | 실측(500건) | 22.7만 건 외삽 |
| --- | ---: | ---: |
| 소요 시간 | 622.5초 | 약 282,615초 (약 78.5시간, 3.3일) |
| 요청 수 | 529 | 약 240,166 |
| 저장 용량 | 72,933,678 B (69.6 MiB) | 약 33.1 GB |

- 위 시간·용량은 공고당 평균 145,867 B, 1.245초 기준입니다.
- 키워드 선별을 하지 않고 **첨부 전량**을 받으면 요청·용량이 약 2.7배(공고당 2.84건)로
  늘어 각각 약 650,000 요청, 약 90 GB 수준이 됩니다. 반대로 선별 누락 61건은 줄어듭니다.
- 어떤 경우든 **얻는 B·k 가 사실상 0** 이므로, 시간·용량 대비 산출물이 없습니다.

## 6. 권고

**전량 추출을 진행하지 않습니다.** 표본 실측에서 자리표시자 문제의 핵심 산출물인 B·k
가 500건 중 1건(0.2%)에서만 나왔고, 그 원인이 데이터 부족이 아니라 **첨부의 92.7%가
바이너리 HWP 이고 현 추출기가 그 표를 복원하지 못하는 구조적 한계**이기 때문입니다.
기준명·T 만으로도 별표 귀속이 불가능합니다.

선행 조건이 해소되면 재평가합니다.

1. **바이너리 HWP 표 복원 파서 추가** — HWP 5.0 의 표(`DocInfo`+`Section` 레코드)를
   복원해 `parse_price_formula`/`parse_price_limit` 가 먹는 행 목록을 만들면, 표본의
   92.7%가 즉시 후보가 됩니다. 이 작업은 `extract_score_params.py` 수정 또는 별도 모듈
   추가가 필요해 별도 Task 로 분리해야 합니다.
2. **HWPX·HWPML 우선 수집 경로 확보** — 2021년 이후 일부 공고는 HWPX 를 첨부합니다.
   HWPX 비중이 높은 구간만 먼저 처리하는 것도 대안입니다.
3. **첨부 전량 다운로드로 선별 누락 61건 제거** — 다만 B·k 병목이 해소되기 전에는
   효과가 제한적입니다.
4. **`parse_pass_threshold` 오탐(`종합평점은 100점을 초과할 수 없다`) 방지** — T 추출
   정밀도 개선은 위 1·2 와 독립적으로 가능합니다.
