## 1. 배경과 결정

공고 상세의 두 목록이 현재 공고 상황과 맞지 않았습니다.

- 과거 사례는 분야(category)를 거르지 않아 용역 공고에 물품 낙찰률(99%대)이 나왔습니다.
- 추천 공고는 내용 유사도 없이 같은 기관의 최신 공고를 마감 여부와 무관하게 보여 주었고, 같은 제목이 중복되었습니다.

사용자 승인(2026-11-07)에 따라 두 목록을 분야 일치와 공고명 유사도 기준으로 다시 고릅니다. 선정은 DB 만으로 계산하며 Meilisearch 색인 상태에 의존하지 않습니다.

## 3. 선정 규칙

### 3.1 공고명 핵심어와 유사도

`bid_queries.announcement_name_tokens()` 가 공고명에서 다음을 제거한 뒤 2자 이상 토큰만 남깁니다.

- 괄호 안 표기: `(...)`, `[...]`, `{...}`
- 연도: `2026`, `2026년`, `2026학년도`, `26년`
- 차수: `1차`, `2단계`
- 조달 일반어: 용역, 공사, 구매, 구입, 입찰, 공고, 긴급, 재공고, 위탁, 사업, 연간, 단가, 물품, 건설, 외자, 계약, 제조, 납품, 설치, 교체, 선정, 안내, 모집, 공모, 시행, 규격, 가격, 동시, 소액, 수의, 전자, 견적, 제출, 유찰, 일반, 지역, 제한, 업체, 대행

`bid_queries.announcement_name_similarity()` 는 두 핵심어 집합의 `교집합 / 작은 집합 크기` 입니다. 두 목록이 같은 함수를 사용합니다.

같은 제목 중복 제거는 괄호 안 표기와 공백을 지운 정규화 키로 판정합니다.

### 3.2 비슷한 진행 중 공고

- 후보 조건: 현재 공고와 같은 `category`, 최신 차수(`similar_announcement_latest_filter`), 자기 자신 제외, `bid_clse_dt` 가 현재 시각 이후(NULL 제외).
- 차수에서 기관이 바뀐 그룹은 후보에서 제외합니다(`_institution_stable_filter`). 최신 차수 필터의 '기관 변경 차수' 의미를 다른 기관 후보 풀에서도 유지합니다.
- 후보 풀 (a): 같은 `dminstt_nm`, `bid_ntce_dt` 최신순 최대 200건.
- 후보 풀 (b): 같은 `category` 의 최근 30일, `bid_ntce_dt` 최신순 최대 500건. 이 풀에서 유사도 0 인 공고는 버립니다.
- 점수: 공고명 유사도 + 같은 기관이면 0.2. 정렬은 점수 내림차순, 동점은 `bid_ntce_dt` 내림차순, `id` 내림차순.
- 정규화 제목이 같은 항목은 하나만 남기고 최대 5건을 돌려줍니다.

### 3.3 과거 사례

- 현재 공고와 같은 `category` 로 반드시 거릅니다.
- 같은 기관 풀: 같은 `dminstt_nm`·같은 `category`, `rl_openg_dt` 최신순 최대 200건. 점수는 공고명 유사도, 동점은 `rl_openg_dt` 내림차순.
- 5건 미만이면 같은 `category` 의 최근 365일 결과(`rl_openg_dt` 최신순 최대 1,000건)에서 유사도 0.5 이상인 다른 기관 결과로 채웁니다.
- 표지: 같은 기관 결과는 `같은 기관`, 보충 결과는 `유사 기관`. 현재 공고 자신의 결과(같은 `bid_ntce_no`)는 빼지 않습니다.
- 낙찰률 계산·표시는 그대로 둡니다.

## 7. 데이터 보존과 제약

- DB 스키마·테이블·컬럼·행 수를 변경하지 않았습니다.
- 운영 DB 는 읽기 전용 세션의 `SELECT`/`EXPLAIN` 만 사용했습니다. `docker exec`, `mysql` 직접 호출, 쓰기 트랜잭션을 사용하지 않았습니다.
- 새 라이브러리나 새 의존성을 추가하지 않았습니다. 프런트엔드는 npm 을 유지했습니다.
- 템플릿에 새 tailwind 클래스를 추가하지 않아 `src/app/static/css/tailwind.css` 는 재생성 후에도 변경이 없습니다.
