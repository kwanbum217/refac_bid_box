## 1. 개요 및 배경

`retrain_task.py`의 `run_retrain_pipeline_task`는 비동기 Arq 워커 환경에서 실행되는 재학습 파이프라인 태스크입니다.
기존 구현에서는 데이터셋 빌드(`build_training_dataset`), 모델 학습 및 레지스트리 저장(`category_trainer.train_and_register`), 챔피언 지표 조회(`_load_champion_metrics`), 이력 기록(`_record`) 등의 동기 CPU/디스크/DB I/O 바운드 함수들이 비동기 이벤트 루프 스레드에서 직접 호출되어 이벤트 루프를 장시간 블로킹하는 문제가 있었습니다.

이벤트 루프가 블로킹되면 동일 워커 프로세스 내의 다른 비동기 태스크(야간 스케줄, 데이터 갱신 등) 처리가 지연되므로, 순차적 무결성을 유지하면서 비동기 워커 스레드 풀로 작업을 오프로드(`await asyncio.to_thread(...)`)하도록 리팩토링을 수행했습니다.

## 2. 주요 변경 사항

### 2.1 retrain_task.py 오프로드 적용

- **`build_training_dataset` 오프로드**: `await asyncio.to_thread(build_training_dataset, db, category_code=category_code, output_dir=output_dir, require_announcement=require_announcement)`
- **`_load_champion_metrics` 오프로드**: `await asyncio.to_thread(_load_champion_metrics, category_trainer.model_name, registry_dir=str(category_trainer.registry_dir))`
- **`train_and_register` 오프로드**: `await asyncio.to_thread(category_trainer.train_and_register, df_train)`
- **`_record` 오프로드**: 재학습 건너뜀 및 완료 시점의 동기 DB 커밋을 `await asyncio.to_thread(_record, db, ...)` 로 오프로드
- **순서 및 안전성 보장**:
  - `SessionLocal()` 인스턴스는 각 태스크 코루틴 내에서만 사용되며 `await`를 통해 순차적으로 실행되므로 스레드 간 세션 경합이 발생하지 않습니다.
  - 챔피언 지표를 모델 학습 **전에** 읽는 순서를 엄격히 유지하여 챌린저 모델과 자기 자신을 비교하는 오류를 방지했습니다.

### 2.2 검증 테스트 추가 (tests/test_task_offload_retrain.py)

`asyncio.get_running_loop()`가 비-이벤트루프 스레드(워커 스레드)에서 `RuntimeError`를 발생시키는 특성을 활용하여, 동기 함수들이 이벤트 루프 스레드 밖에서 실행되는지 검증하는 단위 테스트를 추가했습니다.

- 오프로드 적용 전: `AssertionError: 동기 작업이 이벤트 루프 스레드에서 직접 실행되었습니다`로 실패 확인.
- 오프로드 적용 후: 정상 통과 확인.
