## 1. 개요 및 목적

- **문제 배경**: Arq 비동기 워커 이벤트 루프에서 동기 스텝 러너(`_step_search`, `_step_rag`, `_step_predict`, `_step_inspect`) 및 동기 HTTP 콜백/DB 기록 함수(`_report`)가 블로킹으로 실행될 경우, 동일 Arq 워커 프로세스의 이벤트 루프가 차단되어 동시 실행 중인 다른 비동기 태스크들의 지연이 발생함.
- **해결 방안**:
  - `run_automation_pipeline` 내의 스텝 러너 실행 지점에서 동기 함수는 `await asyncio.to_thread(runner, db, **kwargs)` 로 워커 스레드 풀에 오프로드하여 실행.
  - 비동기 코루틴 러너(`_step_collect`, `_step_retrain`)는 기존과 같이 이벤트 루프에서 직접 `await` 수행.
  - 동기 HTTP I/O (`httpx.post`) 및 DB 세션 조작을 수반하는 `_report` 호출 4개 지점을 모두 `await asyncio.to_thread(_report, ...)` 로 오프로드.
