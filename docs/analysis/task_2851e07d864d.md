# 작업 분석 및 검증 보고서: task_2851e07d864d

- 작업 ID: task_2851e07d864d
- 역할: builder
- 대상 작업: taskctl dispatch 런처 자동 라우팅 배선

---

## 1. 개요 및 목적

- **배경**: `taskctl dispatch`의 런처 경로가 Antigravity(`scripts/orca_agy_launch.py`)로 고정되어 있어 다른 CLI 워커 기동 시 매번 수동으로 `--launcher` 경로를 적어야 했고, 누락 시 preamble 불일치로 인한 30초 기동 타임아웃 결함이 발생함.
- **목표**:
  1. 모델 기반으로 6개 CLI(Antigravity, Qwen, Kimi, Claude, OpenCode, Grok)에 맞는 런처 스크립트와 `cli_type`을 단일 지점에서 자동 선택.
  2. 판정 불가 시 조용히 기본값으로 떨어지지 않고 종료 코드 2로 거부 (fail-closed).
  3. 명시적 `--launcher` 지정 시 자동 판정을 덮어쓰고 명시값 우선 적용.
  4. 매핑 정보 복제 방지 (argparse const에 특정 런처 하드코딩 제거).
  5. `codex` 런처는 preamble 경로가 없으므로 매핑에서 제외.

## 2. 주요 변경 사항

### 2.1 `scripts/orca_taskctl.py`

1. **단일 매핑 및 자동 판정 함수 추가**:
   - `LAUNCHER_ROUTING_BY_PROVIDER`: 모델 제공자(provider)와 `(launcher_path, cli_type)` 튜플을 1:1 대응.
     - `gemini` -> `("scripts/orca_agy_launch.py", "antigravity")`
     - `qwen` -> `("scripts/orca_qwen_launch.py", "qwen")`
     - `kimi`, `kimi-openrouter` -> `("scripts/orca_kimi_launch.py", "kimi")`
     - `claude` -> `("scripts/orca_claude_launch.py", "claude")`
     - `opencode` -> `("scripts/orca_opencode_launch.py", "opencode")`
     - `grok` -> `("scripts/orca_grok_launch.py", "grok")`
   - `LAUNCHER_PATH_TO_CLI`: 매핑에서 자동 파생하여 런처 경로 -> cli_type 역조회 지원.
   - `resolve_launcher_and_cli(model, explicit_launcher, explicit_agent)`:
     - `explicit_launcher`가 있으면 해당 경로 채택 및 cli_type 결정 (명시값 우선). 이때 `cli_type`을 끝까지 결정하지 못하면 `antigravity`로 fallback하지 않고 `ValueError` 발생 (fail-closed 일치).
     - 없을 경우 `provider_for_model(model, strict=False)`를 재사용하여 제공자 판정 후 런처/cli_type 결정.
     - 미지원/판정 불가 모델(또는 codex)인 경우 `ValueError` 발생 (기본값 fallback 없음).
2. **`cmd_dispatch` 진입부 배선 및 fail-closed 검증**:
   - `launcher_mode` 판정 시 `getattr(args, "launcher", None) is not None`으로 처리하여 플래그 단독 지정(`args.launcher == ""`)도 런처 모드로 인식.
   - `args.terminal and launcher_mode` 진입 즉시 `resolve_launcher_and_cli`를 호출하여 검증. 실패 시 종료 코드 2 및 JSON 에러 반환.
   - 확정된 `launcher_val`과 `detected_cli`를 워커 메타데이터(`cli_type`, `launcher`)에 동시 기록.
   - 대기 실패 안내 메시지에도 판정된 `launcher_val` 및 `model` 동적 반영.
3. **`argparse` const 수정**:
   - `dsp.add_argument("--launcher", nargs="?", const="", default=None)`: 특정 런처 하드코딩 제거, 플래그 단독 전달 시 빈 문자열로 수신하여 자동 판정 로직으로 연결.

### 2.2 `tests/test_orca_taskctl.py`

- 4대 단언 및 자동 라우팅 검증 테스트 추가:
  1. `test_resolve_launcher_and_cli_six_representative_models`: 6개 CLI 각각의 대표 모델 ID로 올바른 런처 경로 및 `cli_type` 반환 단언.
  2. `test_resolve_launcher_explicit_override`: 명시적 `--launcher` 지정 시 자동 판정 오버라이드 및 메타데이터 기록 단언.
  3. `test_resolve_launcher_unroutable_model_fails_closed`: 판정 불가/미지원 모델에 대해 `ValueError` 발생 및 `dispatch` 실행 시 종료 코드 2로 거부(fail-closed) 단언.
  4. `test_resolve_launcher_no_codex_in_mapping`: `codex` 런처가 매핑에 존재하지 않음 단언.
  5. `test_cmd_dispatch_launcher_auto_routing_without_path`: 경로 없이 `--launcher`만 지정했을 때 모델에 맞는 런처가 자동 선택되어 메타데이터에 기록됨을 단언.
  6. `test_resolve_launcher_explicit_unknown_without_agent_fails_closed`: 알 수 없는 런처 경로와 모델에서 `explicit_agent` 부재 시 `ValueError` 발생 및 지정 시 통과 단언.
