## 1. 요약

- X1(직전 수정) 이후 남아 있던 OCR 실패는 등급 1건(숫자 `0` 을 문자 `O` 로 오독)과 평가일 미추출 6건이었습니다.
- 웹 공개 샘플을 다시 모아(텍스트 PDF 12건 + 합성 스캔 11건 + 실제 스캔 3건 = 26건, 확인서 23건) 수정 전후를 같은 조건으로 재측정했습니다.
- 수정 후 최종 등급 적중 **23/23 (100%)**, 평가일 적중 **19/23 (82.6%)** 입니다. 같은 표본의 수정 전은 등급 23/23, 평가일 15/23 이었습니다.
- `high` 신뢰도 오추출 0건, 등급 오추출 0건, 평가일 오추출 0건, 비확인서 오탐 0건을 그대로 유지합니다.
- 남은 평가일 미추출 4건은 OCR 이 날짜 값을 아예 유실한 표본으로, 표기 규칙만 쓰는 파서 범위에서는 더 줄이기 어렵습니다.
- 새 라이브러리는 추가하지 않았고, 등급 코드·상한(5MB·10쪽·10초)·OCR 신뢰도 상한(`medium`)·응답 형식은 그대로입니다.

## 4. 수정 내용

### 4.1 등급 끝자리 `0` → `O` 오독 정정 (D7)

- 등급 후보 정규식이 등급 끝자리 `0` 자리에 `[0O]` 를 모두 받도록 넓혔습니다.
- 정규화 단계에서 끝자리가 `O` 인 토큰은 `0` 으로 되돌린 뒤 등록 코드인지 다시 확인합니다. 되돌린 값이 등록 코드가 아니면 종전처럼 버립니다.
- 예: `AAO` → `AA0`, `AO` → `A0`, `BBBO` → `BBB0`, `BBO` → `BB0`, `BO` → `B0`.

### 4.2 평가일 라벨 부분 유실 결합 (D8)

- 쪽 전체를 이어 붙인 통합 문자열에서 `평가일` 라벨 조각(`등급평가일`, `등급평가`, `등급평`, `평가일`, `평일`, `평가`) **바로 뒤에 날짜가 붙어 있는** 경우를 평가일 후보로 수집합니다.
- 조각과 날짜 사이에 다른 글자가 끼면 잇지 않습니다. 이 규칙 덕분에 라벨이 유실되고 유효기간 값만 남은 표본(`등급평 / 일 / 등급 / 2021년 06월 30일`)은 잘못된 값을 만들지 않고 미추출로 남습니다.
- `유효기간`·`유효기한` 값 배제와 `평가일` 라벨 우선순위는 그대로입니다.

## 5. 수정 전후 재측정

`확인서 표본` 은 정답 등급·평가일이 있는 23건입니다. `비확인서` 2건(s09 파생 포함)은 등급을 만들어내지 않아야 정답이고, 쪽수 초과 1건(s10)은 거부되어야 정답입니다.

## 7. 검토했으나 채택하지 않은 대안 (OCR 렌더 배율)

- OCR 렌더 배율을 2.0 에서 3.0~5.0 으로 올리면 일부 표본의 라벨 인식이 좋아졌습니다(s03 값은 배율 5.0 에서만, s13 값은 4.0 이상에서 살아났습니다).
- 그러나 s12 파생 스캔은 배율 4.0 이상에서 오히려 값이 사라졌고, 배율 3.0 에서는 개선된 표본이 없었습니다.
- 배율을 올리면 페이지당 픽셀 수가 2 배 이상 늘어 10초 상한에 불리합니다. 순효과가 확실하지 않아 `src/app/services/document_extraction/ocr.py` 의 렌더 설정은 그대로 두고, 표기 규칙 파서에서 잇는 방식(4.2)을 택했습니다.

## 10. 결론

- 등급 끝자리 `0` 을 `O` 로 읽는 OCR 오독을 등록 코드로 정정해 등급 경로의 잔여 실패를 없앴습니다.
- 평가일 라벨이 조각나도 값이 살아 있는 표본 4건을 회복해 최종 평가일 적중이 15/23 에서 19/23 으로 올랐습니다.
- 값 자체가 유실된 4건은 미추출로 남기되, 잘못된 값을 만들지 않아 오추출 0건과 `high` 신뢰도 오추출 0건을 유지합니다.
- 등급·평가일 오추출 0건, 비확인서 오탐 0건, 쪽수 초과 거부 1/1 일치로 X1 의 안전 성질을 그대로 보존합니다.
