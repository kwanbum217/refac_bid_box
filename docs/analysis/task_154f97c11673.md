## 1. 개요 및 배경

기존 `scripts/audit_model_inventory.py`는 모델 실재 여부를 단순 조회/감사하기만 해도 `data/model_inventory_history.json`의 카운터를 즉시 갱신하거나 초기화했습니다. 이로 인해 검증 스크립트를 반복 실행하거나 여러 에이전트/워커가 동시에 감사 도구를 호출할 경우 대상 상태가 임의로 변경되는 부작용이 발생했습니다 (예: 반복 실행으로 정상 모델이 소멸 판정되는 사례).

또한, 손상된 상태 파일이 존재할 경우 기존 코드는 예외를 조용히 삼키고 빈 딕셔너리로 초기화하여 fail-open 되는 문제가 있었으며, 파일 쓰기 시 잠금 및 원자적 교체 메커니즘이 없어 다중 프로세스 동시 쓰기 경쟁 조건에 취약했습니다.

본 작업에서는 다음 핵심 요구사항을 구현하여 감사 도구의 안전성과 상태 정합성을 확보했습니다.

1. **기본 read-only 관측**: 기본 실행 시 상태 파일을 전혀 수정하지 않고 메모리 상에서만 관측 streak를 계산.
2. **명시적 커밋 옵션**: `--commit-observation` 플래그를 지정할 때만 상태 파일에 결과를 영구 반영.
3. **관측 모드 보고**: 사람이 읽는 출력 및 JSON 최상위에 `mode` 키(`read_only` 또는 `committed`)를 명시.
4. **손상 상태 파일 fail-closed**: `_load_history()`에서 손상 JSON 및 읽기 오류를 삼키지 않고 `CorruptHistoryError`를 발생시켜 `main()`이 종료 코드 2로 fail-closed 하도록 처리 (파일 부재 시는 정상 빈 dict 반환).
5. **원자적 파일 교체 및 크로스플랫폼 잠금**: POSIX(`fcntl.flock`) 및 Windows(`msvcrt.locking`) 기반 파일 잠금을 적용하고, 임시 파일 작성 후 `Path.replace`로 교체.
6. **단일 잠금 구간 일괄 커밋**: 풀마다 파일을 여닫지 않고 감사 1회당 단일 잠금 구간에서 일괄 반영.

## 2. 주요 변경 내역

### 2.1 `scripts/audit_model_inventory.py`
- `CorruptHistoryError` 사용자 정의 예외 클래스 정의.
- `_history_lock()` 컨텍스트 매니저 구현: POSIX `fcntl` / Windows `msvcrt` 크로스플랫폼 advisory lock 지원 (타임아웃 10초).
- `_atomic_save_history()` 함수 구현: 임시 파일(`.tmp`)에 직렬화 후 `replace`로 원자적 파일 교체.
- `_load_history()` 수정: 파일이 없으면 정상 `{}` 반환, `JSONDecodeError`/`OSError` 또는 딕셔너리가 아닌 데이터일 경우 `CorruptHistoryError` 발생.
- `audit_with_state()` 리팩터링:
  - 1단계: 모델 제공자 상태 관측 수집 (`observed_statuses`).
  - 2단계: `commit=False`(기본값)이면 기존 상태를 메모리 상에서 복사하여 streak 계산 및 결과 반환 (파일 미수정).
  - 2단계(커밋): `commit=True`이면 `_history_lock` 획득 후 단일 트랜잭션에서 최신 상태 로드, 모든 풀 일괄 갱신, `_atomic_save_history` 수행.
- `audit()` 함수 시그니처에 `commit: bool = False` 파라미터 추가.
- `main()` CLI 옵션 추가 및 출력 개선:
  - `--commit-observation` 플래그 추가 (기본 read-only).
  - 모드 문자열 `mode_str = "committed" if args.commit_observation else "read_only"`.
  - JSON 출력 최상위에 `"mode": mode_str` 추가.
  - 일반 텍스트 출력 헤더/요약에 `[read_only]` / `[committed]` 명시.
  - 예외 발생 시 JSON/텍스트 모드 모두 종료 코드 2 반환.
- 모듈 docstring 및 `--help` 문구를 실제 동작(기본 read-only, `--commit-observation`, 종료 코드 0/1/2 의미)에 맞게 갱신.

### 2.2 `tests/test_audit_model_inventory.py`
- 기존 테스트 케이스 중 다회차 연속 관측이 필요한 항목에 `commit=True` 및 `--commit-observation` 명시.
- JSON 출력 테스트 케이스에 `mode` 필드 검증 추가.
- 손상 파일 테스트를 기존 fail-open 검증에서 fail-closed(`CorruptHistoryError` 및 종료 코드 2 반환) 검증으로 전면 수정 (`test_corrupt_state_file_fails_closed`, `test_corrupt_state_file_non_dict`).
- 신규 테스트 추가:
  - `test_readonly_by_default_does_not_modify_state_file`: 기존 상태 파일의 내용 및 `mtime` 불변 검증, 파일 미존재 시 미생성 검증.
  - `test_commit_observation_increases_streak`: `--commit-observation` 지정 시에만 상태 파일에 streak가 증가하여 영구 기록됨을 검증.
  - `test_atomic_replacement_used_on_commit`: 상태 파일 저장 시 임시 파일 생성 및 `Path.replace` 원자적 교체 호출 검증.
