1. **원인은 환경부고시 규칙의 부재가 아닙니다.** 고시 [별표] 제1~4호 규칙 6종(`MOE_CDW_RULES`, `evaluation_rules.py:1233-1354`)이 이미 코드에 있고 B·k·통과점수·기준비율·하한율을 모두 갖고 있습니다. 2026-10-19 처리도 이 고시 규칙(`SERVC_QUAL_MOE_CDW_*`)을 썼습니다.
2. **원인은 라우팅 순서와 규칙 단위 opt-in 입니다.** 시·도 규칙이 하나라도 확정되면 `evaluation_rules.py:3598-3609` 가 결과를 `REGION` 으로 덮어쓰고, 고시 대체 분기(`evaluation_rules.py:3643-3661`)는 그 뒤에 있으면서 `_is_moe_cdw_fallback_target` 이 **차단된 결과만** 대상으로 삼습니다. 그래서 시·도 규칙을 먼저 제거하는 `cdw_exclusion` 이 유일한 진입로입니다.
3. **그 진입로가 8개 규칙 중 5개에 아예 없습니다.** 2026-10-19 에는 원문에 제외 조항이 확인된 9개 시·도 12개 규칙에만 선언했습니다. 서울·부산·제주·경남은 수집 원문에서 폐기물처리용역 정의가 확인되지 않았고, 충남은 제외 문구가 없어 선언 대상에서 빠졌습니다.
4. **선언이 있어도 공고명 문자열 조건이 7건을 놓칩니다.** `named` 계열은 공고명에 `건설폐기물` 이라는 정확한 문자열을 요구합니다(`evaluation_rules.py:2375-2376`). 그런데 51건 전부의 조달분류 `pubPrcrmntClsfcNm` 은 `건설폐기물처리서비스` 입니다. 공고명 표기보다 조달분류가 더 정확한 신호입니다.

## 3. 코드 지점

### 3.1 라우팅 순서가 시·도 규칙을 먼저 확정한다

`resolve_evaluation_rule` 은 다음 순서로 분기합니다. 51건은 3단계에서 확정되고, 4단계 고시 대체 분기에 도달하지 못합니다.

| 단계 | 위치 | 51건에서의 동작 |
| ---: | --- | --- |
| 1 | `evaluation_rules.py:3399-3409` `_resolve_by_method_name` | 띠 표기가 조달청 값 미상 규칙 `SERVC_QUAL_POST_20260526_ATTACH_12~14` 로 잡히거나(47건) `RULE_NOT_FOUND`(4건) |
| 2 | `evaluation_rules.py:3414-3433` 기관 규칙 | `contract_regime = LOCAL` 이라 기관 규칙 분기를 타지 않음 |
| 3 | `evaluation_rules.py:3502-3609` 시·도 규칙 | `_select_local_rule` 이 시·도 규칙을 확정하고 `replace(..., is_blocked=False, ...)` 로 결과를 덮어씀. `scope_stage = RULE_SCOPE_REGION` |
| 4 | `evaluation_rules.py:3643-3661` 환경부고시 대체 | `_is_moe_cdw_fallback_target(result)` 가 `False` 라 진입하지 않음 |

4단계의 판정 함수가 핵심입니다.

```python
def _is_moe_cdw_fallback_target(result: RuleResolutionResult) -> bool:
    rule_id = result.rule.rule_id if result.rule is not None else None
    if rule_id in _MOE_CDW_PPS_BAND_RULE_IDS:
        return result.block_reason_code in (None, "RULE_REGIME_MISMATCH")
    return result.is_blocked and result.block_reason_code in _MOE_CDW_FALLBACK_BLOCK_CODES
```

(`evaluation_rules.py:1375-1384`)

- 3단계가 성공하면 `result.is_blocked = False` 이고 `result.rule.rule_id` 는 시·도 규칙이므로 두 조건 모두 거짓입니다. 고시 규칙은 **차단된 결과만** 구제합니다.
- 따라서 시·도 규칙을 먼저 제거해 `LOCAL_RULE_NOT_FOUND` 를 만들어야만 4단계로 갈 수 있습니다. 그 제거가 `cdw_exclusion` 입니다.

### 3.2 `cdw_exclusion` 은 규칙 단위 opt-in 이다

```python
cdw_excluded_any = False
if select_moe_cdw_rule(method_name) is not None:
    bid_name = ""
    if isinstance(raw_data, dict):
        bid_name = str(raw_data.get("bidNtceNm") or "")

    def _cdw_excluded(rule: EvaluationRule) -> bool:
        mode = rule.cdw_exclusion
        if not mode:
            return False
        if mode == "band":
            return True
        if "건설폐기물" not in bid_name:
            return False
        if mode == "named":
            return True
        if mode == "named_except_haul":
            return "처리" in bid_name
        return False

    removed = [rule for rule in base_candidates if _cdw_excluded(rule)]
    cdw_excluded_any = len(removed) > 0
    base_candidates = [rule for rule in base_candidates if not _cdw_excluded(rule)]

region_rules = _narrow_to_current_regime(base_candidates, announced)
if cdw_excluded_any:
    return None, BLOCK_CODE_LOCAL_RULE_NOT_FOUND, _LOCAL_NOT_FOUND_MESSAGE, warnings
```

(`evaluation_rules.py:2363-2389`)

- 첫 조건 `select_moe_cdw_rule(method_name) is not None` 은 51건 모두 참입니다. 문제는 두 번째 조건입니다.
- `if not mode: return False`(`evaluation_rules.py:2370-2372`) — 선언이 없는 규칙은 절대 제거되지 않습니다. 현재 `cdw_exclusion` 이 선언된 규칙은 `LOCAL_RULES` 70개 중 **14개**뿐입니다.
- `if "건설폐기물" not in bid_name: return False`(`evaluation_rules.py:2375-2376`) — 공고명 문자열 조건입니다. 이 검사가 `named` 와 `named_except_haul` 모두에 앞서므로, 이 문자열이 없으면 두 모드가 함께 실패합니다.

- 51건의 용역 세부유형은 조달분류 문자열로 `WASTE` 로 확정됩니다(`resolve_local_service_type`, `evaluation_rules.py:2098-2102`).
