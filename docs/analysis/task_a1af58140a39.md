## 2. 주요 변경 사항

### 2.1 정본 Fixture 및 문항 지정 지원
- `--fixture`: 품질 평가 정본 fixture JSON 파일(`data/eval/llm_quality_fixture_v2.json` 등) 로드 지원.
- `--repetitions`: 문항당 반복 횟수 지정 (기본값: 1, canonical 판정 기준: 3 이상).
- `--item-ids`: 쉼표로 구분된 문항 ID 목록(예: `q03,q08,q25,q31`)을 지정해 특정 문항만 선택적으로 계측 가능.
- `--limit`: fixture 문항 수 제한 (0=전체).
- 미지정 시 기존 `--rounds` 기반 ad-hoc 질의 전송 모드로 자동 fallback하여 100% 하위 호환성 유지.

### 2.2 Cold / Warm 분해 집계
- **Cold 판정**: 각 문항의 1회차 호출(`repetition == 0` 또는 ad-hoc 최초 등장 질의)을 `cold`로 분류.
- **Warm 판정**: 각 문항의 2회차 이상 반복 호출을 `warm`으로 분류.
- 질의 전송 시 trace_id와 문항 메타데이터(item_id, repetition_index, is_cold)를 1:1 매핑.
- 로그 레코드를 cold와 warm으로 자동 분리하여 각각의 분위수(p50, p95, p99, min, max) 및 roundtrip 지연시간 집계.
- 문항별(`by_item` / `summary_by_item`)로 cold/warm/all 구간 지연시간을 세분화하여 산출물에 기록.

### 2.3 Canonical 게이트 판정 체계 연동
- `scripts/measure_llm_quality.py`의 `evaluate_canonical` 및 `CANONICAL_FIXTURE_HASHES`를 직접 임포트하여 중복 구현 없이 판정 기준 일원화.
- 판정 항목:
  1. `fixture_sha256_canonical`: 등록된 정본 fixture 해시 일치 여부
  2. `limit_zero`: 전체 문항 계측 여부 (`--limit 0`)
  3. `item_count_full`: fixture 전체 문항 완결성
  4. `repetitions_minimum`: 최소 반복 회수 (3회 이상)
  5. `no_request_failures`: HTTP 실패 0건
  6. `trace_correlation_passed`: 1:1 trace 상관 검증 통과
  7. `provenance_strict`: strict provenance 조건 충족
  8. `start_clean` / `end_clean`: Git 작업 트리 clean 여부
  9. `start_sha_known` / `end_sha_known`: 유효한 Git SHA 여부
  10. `model_match_expected`: 기대 LLM 모델 일치
  11. `port_validated`: 포트 바인딩 검증
- 산출물에 `canonical`, `canonical_success`, `canonical_rationale`, `failed_gates`, `canonical_failed_gates`를 기록.

### 2.4 기존 게이트 및 하위 호환성 100% 보존
- `assert_segment_logging_enabled` (`LATENCY_SEGMENT_LOGGING` 켜짐 사전 검증) 유지.
- `verify_trace_correlation` (응답 trace와 로그 trace 간 1:1 상관 검증) 유지.
- HTTP 실패 시 exit 1 및 `canonical_success=false` 동작 유지.
- 기존 산출물 JSON 키 전체 보존.
