## 1. 개요 및 배경

### 1.1 문제 정의
- Orca 조율 환경에서 `orca_taskctl.py`는 시도 단위 격리를 보장하기 위해 `preamble_{task_id}_{dispatch_id}_{nonce}.txt` 형태의 고유 파일명으로 preamble 지시문을 생성합니다.
- 기존 구현 상태:
  - `scripts/orca_agy_launch.py`: `.orca/` 디렉터리 내 고유한 `preamble_*.txt` 파일을 glob으로 찾아 소비(읽은 후 즉시 `unlink`)하는 완전한 격리 규약을 갖추고 있었습니다.
  - `scripts/orca_qwen_launch.py` 및 `scripts/orca_kimi_launch.py`: 고정 경로(`.orca/preamble.txt` 등)에 대한 단순 존재 여부(`path.exists()`)만 대기하고 파일을 삭제하지 않는 초기 구현 상태로 남아 있었습니다.
- 문제점: Qwen 또는 Kimi 워커를 기동할 때, 런처가 고유 파일명으로 생성된 preamble을 인식하지 못해 기동 대기 타임아웃(30초~300초)이 발생하고, 소비되지 않은 preamble 파일이 남아 후속 Dispatch까지 차단되는 장애가 발생했습니다.

## 2. 해결 방향 및 아키텍처

### 2.1 단일 진실 공급원 (SSOT) 정립
런처 공통 준비 로직을 담당하는 [`scripts/orca_worker_launch_common.py`](/scripts/orca_worker_launch_common.py)에 `DEFAULT_PREAMBLE`과 `wait_for_preamble` 함수를 공용화했습니다.

### 2.2 preamble 소비 불변식 준수
1. **고유 파일 감지 및 즉시 삭제**: `preamble_*.txt` 형태의 고유 파일을 감지하여 내용을 읽은 뒤 즉시 `unlink(missing_ok=True)`로 소비합니다.
2. **다중 후보 거부 (시도 격리 보장)**: 디렉터리 내에 둘 이상의 `preamble_*.txt` 후보가 발견되면 어느 것도 임의로 선택하여 소비하지 않고 즉시 `ValueError`를 발생시켜 기동을 거부합니다.
3. **빈 파일 경쟁 회피**: 파일이 생성되었더라도 내용이 비어 있는 경우(0바이트 또는 공백만 있는 경우) 아직 지시문 작성이 완료되지 않은 것으로 간주하고 대기를 지속합니다.
4. **옛 고정 경로 격리 파손 거부**: 기본 경로 대기 중 고유 preamble 없이 레거시 고정 파일(`.orca/preamble.txt`)만 단독으로 남아있을 경우 이전 지시문 오염 위험을 방지하기 위해 기동을 거부합니다.
5. **예외 처리 통일**: 런처 메인 진입점(`main()`)에서 `TimeoutError`뿐만 아니라 `ValueError`도 정상 포착하여 에러 로그를 출력하고 종료 코드 2를 반환하도록 통일했습니다.
