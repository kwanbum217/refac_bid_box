# Vector 메타데이터 필터 최적화 판정: 기각 (2026-09-01)

> **작성일**: 2026-09-01
> **판정**: **기각.** 결과 동등성이 구조적으로 보장되지 않습니다
> **보존 커밋**: `5fcc712` (브랜치 `kwanbum217/orca-p1-embed-reuse`, 미병합)
> **병합된 것**: `faddf0b` 임베딩 클라이언트 재사용만 (결과 불변)

---

## 1. 종전 분석이 병목을 잘못 지목하고 있었습니다

[`vector_segment_optimization_20260830.md`](vector_segment_optimization_20260830.md) 는
vector 구간의 95% 이상을 **"bge-m3 CPU 순전파(815M 파라미터) 1,200~1,900ms"** 로
추정했습니다. 그 문서는 스스로 "실측 미수행" 이라고 밝히고 있었고, 실제와 다릅니다.

**임베딩은 CPU 순전파가 아니라 Ollama HTTP 호출입니다**(`src/rag/embeddings.py`).
Ollama 가 Metal GPU 로 돌립니다.

| 항목 | 실측 (2026-09-01) |
| --- | ---: |
| Ollama 임베딩 (호스트 웜) | 44~53ms |
| Ollama 임베딩 (컨테이너 웜) | 45~52ms |
| Ollama 임베딩 (연결 재사용) | **39~41ms** |
| ChromaDB HNSW 검색 (where 없음) | **3.4ms** |
| `PersistentClient` 재생성 | 첫 133ms, 이후 1~2ms |
| `get_collection` | 0.4~0.7ms |

`bge-m3`(0.67GB)와 `gemma4:e2b`(7.0GB)는 둘 다 VRAM 에 상주하며 `expires` 가
2318 년이라 언로드되지 않습니다.

**추정을 그대로 받아 임베딩 모델을 건드렸다면 헛수고였을 것입니다.**

---

## 2. 진짜 병목은 메타데이터 where 절입니다

같은 컬렉션(526,717 건), 같은 질의, 워밍 후입니다.

| 조건 | 지연 |
| --- | ---: |
| `where` 없음 | **3.4ms** |
| `where={'category': 'Servc'}` | **1,170ms** (첫 실행 11,569ms) |
| 후보 100건 조회 후 파이썬 필터 | **8.8ms** |

`category` 필터 하나가 **344 배** 느리게 만듭니다. ChromaDB 의 `where` 는 SQLite 로
후보를 먼저 좁힌 뒤 HNSW 를 돌기 때문입니다. `institution_name` 과 `date_from/to` 는
이미 post-filter 라 `where` 가 `None` 이 되고, `category` 만 `where` 로 들어갑니다.

---

## 3. 그런데 결과가 달라집니다 (기각 사유)

넓게 받아 파이썬에서 거르는 안을 구현하고 fixture 전량으로 대조했습니다.
**32 문항 x 3 조합 = 96 건 중 6 건이 불일치**했습니다.

| 질의 | 겹침 | 상위 일치 |
| --- | :---: | :---: |
| 합포고등학교 전기공사 | 4/5 | 3 |
| 건축물대장 재정비용역 | **2/5** | 1 |
| 국도46호선 길어깨 | 4/5 | 4 |
| 빈집사업 폐기물 처리 | 4/5 | 1 |

1 위는 모두 같지만 하위 순위가 갈립니다.

**원인은 구조적입니다.** HNSW 는 근사 검색이라 `n_results` 가 달라지면 탐색 경로가
바뀝니다. where 경로는 30 건을, 넓은 조회는 300 건을 요청하므로 서로 다른 후보
집합을 봅니다. N=3,000 에서 불일치가 나던 현상이 N=300 에서도 일부 질의에
나타납니다. **후보 수를 맞출 수 없으므로 완전 동등성은 달성할 수 없습니다.**

"목표 건수를 채우면 결과가 동일하다" 는 것은 5 건 사례로 세운 가설이었고 전량
대조에서 반증됐습니다. **표본 몇 건의 일치를 동등성 보장으로 읽지 마십시오.**

## 4. 이득도 기대보다 작습니다

fixture 전량 실측에서 새 경로 평균 **324ms** 입니다. 단일 질의 실험의 8.8ms 와
크게 다릅니다. 기준선(warm P50 1,296ms) 대비 **4 배**이지 1,000 배가 아닙니다.

**위험은 구조적이고 이득은 4 배입니다.** 2026-08-30 에 같은 종류의 위험으로
numeric 138 -> 132, refusal 93 -> 90 회귀를 겪었고, 그때 교훈이 "검색 지표만으로는
회귀가 드러나지 않는다" 였습니다. 겹침 4/5 면 품질 지표는 만점을 유지할 수 있지만
밀려난 1 건이 낙찰 결과를 담은 문서라면 특정 질의가 조용히 답을 잃습니다.

## 5. 병합한 것과 보존한 것

| 항목 | 처리 | 근거 |
| --- | --- | --- |
| `faddf0b` 임베딩 클라이언트 재사용 | **병합** | 45~52ms -> 39~41ms, 반환 벡터 완전 불변 |
| `5fcc712` 메타데이터 wide-fetch | **기각, 브랜치 보존** | 96 건 중 6 건 결과 불일치 |

기각한 구현은 브랜치 `kwanbum217/orca-p1-embed-reuse` 에 남아 있습니다. 후보 수에
무관하게 동일 결과를 보장하는 방법(예: 정확 검색 모드, category 별 컬렉션 분리와
재색인)이 생기면 그때 다시 검토할 근거로 씁니다.

큽니다. vector 는 메타데이터 필터가 원인임이 밝혀졌으나 결과 불변 해법이 없습니다.
