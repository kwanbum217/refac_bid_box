# Task task_22fb73627e8c: Preamble 역할 표지 주입 및 런처 역할 우선 판정

## 1. 배경 및 문제 정의

Wave AJ2에서 워커 런처 고지문의 역할별 분기(빌더용 COMMIT_NOTICE vs 리뷰어용 REVIEWER_NOTICE)가 도입되었으나, 실제 Dispatch 경로에서 리뷰어 워커에게 여전히 COMMIT_NOTICE(커밋 강제 고지문)가 부착되는 결함이 발견되었습니다 (Wave AK2 리뷰어에서 재현).

### 근본 원인
- detect_role 함수는 지시문 텍스트 내에서 ORCA_REVIEW_DONE_V2, review_done.json, role: "reviewer" 등의 문자열을 검색하여 역할을 판정합니다.
- 그러나 orca_taskctl.py dispatch가 런처 경로를 통해 전달하는 preamble은 Orca CLI 지시문과 TASK 블록(목표 문장 및 Capsule 파일 경로)만 포함하며, Capsule의 본문은 워커가 사후에 파일로 직접 읽으므로 preamble 본문에는 위 표지들이 포함되지 않습니다.
- 따라서 detect_role이 표지를 찾지 못하고 기본값인 builder로 판정(fail-closed)하여, 리뷰어에게 커밋 강제 고지문이 부착되는 오류가 발생했습니다.

---

## 2. 해결 방안 및 설계 계약

1. 기계 판독 가능한 독립 줄 역할 표지 정의:
   - 표지 규격: `[ORCA_ROLE: builder]` 또는 `[ORCA_ROLE: reviewer]`
   - 사람이 읽어도 무해하며, 기계가 정규식(_ROLE_MARKER_RE)으로 정확히 추출할 수 있도록 독립된 줄로 구성.
2. Dispatch 런처 경로 preamble 파일 표지 주입:
   - scripts/orca_taskctl.py의 cmd_dispatch에서 preamble_file.write_text 직전에 effective_role('reviewer' 또는 'builder')을 기반으로 inject_role_marker를 호출하여 preamble 최상단에 독립된 한 줄로 표지를 주입.
3. 런처 역할 판정 우선순위 확립:
   - scripts/orca_worker_launch_common.py의 detect_role:
     1. 역할 표지(parse_role_marker)를 최우선 근거로 판정.
     2. 표지가 없는 경우 종전 레거시 문자열(ORCA_REVIEW_DONE_V2, review_done.json, role: reviewer) 검색으로 폴백.
     3. 그래도 확정할 수 없는 경우 fail-closed 원칙에 따라 builder로 판정.
   - 런처 CLI의 --role 인자는 자동 판정을 덮어쓰는 최우선 지시로 유지되며, --no-commit-notice는 모든 고지문 부착을 방지.
4. 실제 preamble 기반 회귀 테스트:
   - 임의 조작된 문자열이 아닌 taskctl dispatch가 실제로 생성하여 워크트리에 기록한 preamble 텍스트를 읽어 4가지 판정 경로(리뷰어 표지, 빌더 표지, 표지 없는 옛 형태, 확정 불가)를 단언.
