## 1. 구현 요약

본 작업은 `docs/analysis/psi_drift_wiring_20260902.md` 설계에 기반하여, 기존에 격리되어 있던 PSI 드리프트 모니터링 로직을 실제 운영 스케줄, 모델 학습 파이프라인, 알림 체계 및 이력 로깅에 연결하였습니다.

1. **학습 시 Baseline 분포 아티팩트 원자적 저장**:
   - `src/ml/trainer.py` 의 `ModelTrainer.train_and_register` 성공 시점에 `ml_registry/{model_name}/baseline/` 경로로 `feature_distributions_v1.json` 및 `metadata.json` 아티팩트를 원자적으로 저장합니다.
   - 학습 실패 시에는 baseline 이 갱신되지 않으며 임시 디렉터리(`.*staging*`)가 남지 않습니다.

2. **Arq Worker 크론 등록 및 비동기 스케줄 태스크 구현**:
   - `src/tasks/scheduled_tasks.py` 에 `drift_monitor_task` 를 추가하였습니다.
   - `src/tasks/worker.py` 의 `WorkerSettings.functions` 및 `cron_jobs` 에 매일 04:00 실행되도록 크론으로 등록하였습니다.
   - `ML_DRIFT_MONITOR_ENABLED` 플래그로 활성화를 제어하며 기본값은 비활성(False)입니다.

3. **최소 표본 수 가드(100건) 및 INSUFFICIENT_DATA 판정**:
   - `src/ml/monitoring.py` 의 `calculate_psi`, `calculate_categorical_psi`, `check_feature_drift`, `check_dataset_drift` 에 100건 최소 표본 가드를 적용하였습니다.
   - 표본 부족 시 거짓 STABLE 판정을 방지하고 `INSUFFICIENT_DATA` 로 판정을 보류합니다.

4. **판정 결과 이력 저장 및 알림 연동**:
   - DB 스키마 변경 없이 기존 `retrain_logs` 테이블을 재사용하여 `trigger_source="drift_monitor"`, `challenger_version=<baseline_version>`, `status`(`DRIFT_DETECTED` / `STABLE` / `INSUFFICIENT_DATA`), `metrics_summary` 를 기록합니다.
   - 드리프트 감지 시 `src/tasks/notifier.py` 의 `notify_drift_detected` 를 통해 조치 필요 알림을 발신합니다.
   - 계약에 따라 드리프트 감지가 자동 재학습이나 자동 승격으로 이어지지 않으며 사람의 검토로 위임됩니다.

5. **단일 특징 공급원(Single Source of Truth) 준수**:
   - 드리프트 평가 시 `src/ml/features.py` 의 `build_feature_frame` 을 반드시 거치도록 구현하여 train/serve skew 를 방지하였습니다.
