## 1. 과업 개요 및 배경

### 1.1 배경 및 문제점
`bidding_kb` ChromaDB 벡터 컬렉션의 메타데이터에는 `category`, `has_result`, `type`, `id`, `doc_hash`, `fmt` 6개 키만 존재하여, 자연어 질의 플래너가 추출한 `institution_name`(수요기관명), `date_from`/`date_to`(기간 조건) 필터가 ChromaDB `where` 절에 포함되지 못하고 제외되었습니다.

이로 인해 하이브리드 검색 질의(예: "서울 2026년 용역 공고")에서 SQL 정형 통계에는 해당 조건이 적용되나 벡터 검색 결과에는 타 지역 및 타 시점 문서가 혼입될 수 있는 불일치(scope mismatch)가 발생하였습니다.

### 1.2 핵심 변경 목표
1. **문서 본문 파서 구현**: 문서 텍스트에 포함된 대괄호 메타데이터(`[수요기관]`, `[공고일시]`, `[개찰일시]`)를 정규 표현식으로 안전하게 추출하는 파서 구축 (파싱 실패 시 예외 없이 `None` 반환).
2. **Post-filter 적용**: ChromaDB 검색 후 반환된 후보 문서들에 대해 수요기관명(부분 문자열 일치) 및 기간 조건(개찰일시 우선, 미존재 시 공고일시 기준)을 필터링.
3. **Fail-Closed 정책 준수**: 파싱 실패 문서 및 조건 불일치 문서는 즉시 제외하며, post-filter 결과가 0건이어도 필터를 완화(relax)하지 않고 빈 결과(`empty success`)로 반환.
4. **Over-fetching 배수 적용**: post-filter 활성화 시 `top_k * POST_FILTER_FETCH_MULTIPLIER` (3배수)를 요청하여 필터링 후에도 충분한 문서를 확보하고, 최종 반환은 `top_k`로 슬라이싱.
5. **Provenance 추적성 확보**: `SemanticSearchResult` 및 `as_filter_provenance()`에 `applied_post_filters`와 `post_filtered_count`를 추가하여 상위 계층(`engine.py`)에서 필터 적용 상세를 파악할 수 있도록 구현.
6. **호환성 유지**: `engine.py` 등 호출부 수정 없이 기존 인터페이스 및 동작 완벽 호환.

## 2. 세부 구현 내용

### 2.1 문서 본문 파서 (`src/rag/vector_store.py`)
- `extract_document_institution(document_text)`: `[수요기관]` 패턴 매칭 및 `_normalize_text` 적용.
- `extract_document_dates(document_text)`: `[공고일시]`, `[개찰일시]`를 `YYYY-MM-DD` 기준 `datetime.date` 객체로 파싱.
- `extract_effective_document_date(document_text)`: 개찰일시가 존재하면 개찰일시 우선, 없으면 공고일시 채택. 둘 다 없으면 `None`.
- `_matches_post_filters(doc_text, target_institution, filter_date_from, filter_date_to)`: 기관명 부분 문자열 매칭 및 `date_from <= date <= date_to` 범위 검증 (실패 시 `False` fail-closed).

### 2.2 검색 및 Post-filter 로직 (`retrieve_semantic_context`)
- `plan.filters`에서 `institution_name`, `date_from`, `date_to` 존재 여부 확인.
- Post-filter 활성화 시 `query_top_k = plan.top_k * POST_FILTER_FETCH_MULTIPLIER` (배수 3) 적용.
- Chroma 쿼리 결과 문서들에 대해 `_matches_post_filters`를 수행하여 조건 충족 문서만 `structured_documents`에 적재.
- 걸러진 문서 수를 `filtered_out_count`로 누적.
- 최종 반환 리스트를 `plan.top_k`로 제한.

### 2.3 `SemanticSearchResult` 및 프로비넌스 확장
```python
@dataclass
class SemanticSearchResult:
    ok: bool
    documents: list[dict[str, Any]] = field(default_factory=list)
    error: str | None = None
    relaxed: bool = False
    original_filters: dict[str, Any] = field(default_factory=dict)
    effective_filters: dict[str, Any] = field(default_factory=dict)
    unsupported_filters: dict[str, Any] = field(default_factory=dict)
    applied_post_filters: dict[str, Any] = field(default_factory=dict)
    post_filtered_count: int = 0

    @property
    def filter_relaxed(self) -> bool:
        return self.relaxed

    def as_filter_provenance(self) -> dict[str, Any]:
        return {
            "original_filters": dict(self.original_filters),
            "effective_filters": dict(self.effective_filters),
            "unsupported_filters": dict(self.unsupported_filters),
            "filter_relaxed": self.filter_relaxed,
            "applied_post_filters": dict(self.applied_post_filters),
            "post_filtered_count": self.post_filtered_count,
        }
```
