## 2. 콜드 SQL 원인 확정 (R-20 완료)

**세션의 가장 큰 성과입니다.** AU2 계측을 켜고 q03/q08/q25/q31 을 측정했습니다.

| 확정 사항 | 값 | 의미 |
| --- | --- | --- |
| `cursor_ms / sql_ms` | **99.9%** | 커서 실행이 전부다 |
| `residual_ms` | **85~126ms** | checkout 대기·파이썬 비용은 0.1% 미만 |
| `corrupted_probe_ms` | **36~38%** | 단일 최대 항목 |

**기각된 가설 둘**: connection checkout 대기, 파이썬 조립·직렬화. 12만 ms 중
잔여가 92ms 입니다.

### 2.1 범인

```python
corrupted_probe=select(BidAnnouncement.id).where(
    BidAnnouncement.dminstt_nm.contains(REPLACEMENT_CHAR), *announcement_conditions
)
```

`contains` 가 선행 와일드카드 `LIKE '%<U+FFFD>%'` 로 번역돼 인덱스를 쓸 수
없습니다. `.limit(1)` 이 붙어 있지만 **손상 행이 없으면 조기 종료가 없어 조건에
걸린 집합을 끝까지 훑습니다. 데이터가 깨끗할수록 느립니다.** 세 곳
(`structured_data.py` 852행, 875행, 897행)에서 같은 형태로 만들어집니다.

용도는 `dropped` 판정 하나이며 결과 값이 아니라 provenance 표시에만 쓰입니다.

### 2.2 판단이 필요한 것

**제거 가부는 `dropped` 표시를 포기할 수 있느냐입니다.** 이것은 데이터 품질
가시성 정책이지 성능 결정이 아니므로 사용자에게 물으십시오. 선택지를 고를 때
아래를 전제로 삼으십시오.

- `.limit(1)` 은 이미 있습니다. 조기 종료가 안 되는 것은 데이터가 깨끗하기 때문입니다.
- 선행 와일드카드는 일반 인덱스로 해결되지 않습니다.
- 탐침을 캐시하거나 주기 배치로 옮기는 것도 선택지입니다. 다만 그때는 값이
  뒤처질 수 있으므로 이 저장소의 파생 집계 원칙(뒤처짐 검출, fail-closed)을 따르십시오.

## 4. 코디네이터가 겪은 것

### 4.1 Codex 가 세션 중간에 말랐습니다

`gpt-5.6-luna` 워커가 `Selected model is at capacity` 로 정지했습니다. 그 직전
터미널에 `less than 5% of your monthly limit left` 경고가 있었습니다.

**WORKER_MODEL_NOTICE**: 빌더 `gpt-5.6-luna`(codex) -> `opencode/muse-spark-1.3-contributor-free`,
리뷰어 `muse-spark-1.3` -> `grok-4.6`. 사유는 Codex 용량 소진이며 사용자 승인을
받았습니다. 리뷰어를 함께 바꾼 이유는 빌더와 계열이 겹치면 독립성 검사를 통과하지
못하기 때문입니다.

복구 절차는 `worker-stop` -> `task-update --status ready` -> 새 터미널 -> 재
dispatch 였습니다. `worker-stop` 후 워크트리에 **빈 셸 터미널이 하나 남습니다.**
`orca terminal close` 로 직접 닫아야 합니다.

### 4.2 Grok 이 계약을 이탈했습니다

분석은 정확했는데 **파일을 쓰지 않고 영어로 사용자에게 되물었습니다.**
"어느 절을 다듬을까요" 로 멈춰 있었습니다. 두 번 교정 지시를 보내 복귀시켰습니다.

| 지시 | 내용 |
| --- | --- |
| 1차 | 되묻지 말 것, 한국어로 쓸 것, 보고서 파일과 worker_done.json 을 지금 쓸 것 |
| 2차 | 커밋할 것(메시지는 `docs:` 한국어), `--dispatch-capability` 를 붙여 worker_done 을 보낼 것 |

**Muse Spark 는 같은 이탈이 없었습니다.** grok 을 쓸 때는 산출물 파일 생성을
직접 확인하십시오. `worker_watch` 는 커밋 0 · 미커밋 0 을 정체로 단정하지 않으므로
이 상태를 잡지 못합니다.

### 4.3 리뷰어를 빌더 브랜치에 커밋시키면 게이트가 실패합니다

grok 에게 리뷰 문서를 커밋시켰더니 Level 1 게이트가 두 번 다 실패했습니다.

| 게이트 | 실패 사유 |
| --- | --- |
| gate2_scope | 빌더 Capsule 기준으로 리뷰 문서가 범위 초과 |
| gate6_worker_done | 빌더가 보고하지 않은 파일이 브랜치에 있음 |

**게이트는 한 브랜치에 한 Capsule 을 전제합니다.** Wave AU 의 리뷰어들은
`.orca/` 에만 쓰고 커밋하지 않아 이 문제가 없었습니다. **리뷰어에게 커밋을
시키지 마십시오.** 이번에는 `git diff --stat main...HEAD` 로 변경이 두 문서뿐이고
각각이 자기 Capsule 범위 안임을 직접 확인한 뒤 병합했습니다.

### 4.4 `/health` 는 404 입니다

app 헬스 경로는 `/api/v1/health/ready` 입니다. `/health` 로 폴링하면 영원히
404 를 받습니다.

### 4.5 `.env` 는 해시로만 비교했습니다

측정을 위해 `LATENCY_SEGMENT_LOGGING` 을 켰다가 껐습니다. 직전 세션의 사고를
