## 1. 왜 좌표 하강인가

917,629행 데이터에서 학습 1회가 12~120초입니다. 무작위 탐색으로 같은 예산을
쓰면 훨씬 적은 축만 보게 됩니다. 축 하나씩 최적값을 잡고 넘어가면 **모든 축을
최소 한 번씩** 훑을 수 있습니다.

선택 기준은 **MAE** 입니다. R2 로 고르면 잔차 비대칭 때문에 중심을 위로 밀어
올린 모델이 뽑힙니다. 이 함정은 이미 CatBoost/LightGBM 선택에서 한 번
겪었습니다 (인수인계 3.1). 0.5%p 적중률을 함께 출력해 두 기준이 어긋나지
않는지 확인했습니다.

목적함수는 운영 학습기와 같은 `huber`(alpha 1.0)로 고정했습니다. 여기서
갈리면 탐색 결과가 운영에 옮겨지지 않습니다.

### 2.1 결과

| 구분 | MAE | RMSE | R2 | 0.5%p | 1%p | 편향 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 기준선 | 1.2829 | 2.6412 | 0.6976 | 60.57% | 72.50% | +0.0253 |
| **탐색 결과** | **1.2652** | **2.6188** | **0.7027** | **60.99%** | **72.88%** | +0.0276 |

**MAE 1.4% 개선, 0.5%p 적중 +0.42%p.** 편향은 거의 변하지 않았습니다.

### 2.2 왜 `num_leaves` 만 유효한가

이 문제의 신호는 **범주 조합에 실려 있습니다.** 용역구분 x 대/중/소분류 x
계약방법 x 예가결정방법의 곱이 수천 갈래인데, 63리프로는 그 갈래를 다 못
가릅니다. 리프를 늘리면 조합을 더 잘게 자를 수 있어 바로 이득이 납니다.

반대로 트리를 늘리거나(1200/2000) 학습률을 낮추는 것은 **같은 거친 분할을 더
정교하게 맞추는 방향**이라 이 데이터에서는 도움이 안 됩니다. n_estimators
2000 은 R2 만 0.7032 로 가장 높고 MAE 와 0.5%p 적중은 오히려 나빠지는데,
1.1 절의 R2 함정이 그대로 재현된 사례입니다.

255 를 넘어서면 어떤지는 미측정입니다. 다만 7장에서 분위 모델 리프를 127 로
올렸을 때 이미 구간 폭이 나빠지므로, 511 이상을 볼 이유는 없습니다.

## 3. `subsample` 은 무효 설정이었습니다

탐색에서 `subsample` 0.6 / 0.8 / 1.0 의 MAE 가 **소수점 넷째 자리까지 같게**
나왔습니다 (1.2652). 우연이 아닙니다.

**LightGBM 은 `subsample_freq` 가 0 이면 `subsample` 을 통째로 무시하며,
기본값이 0 입니다.** 즉 운영 학습기는 지금까지 행 샘플링 없이 전량으로
학습해 왔고, 파라미터에는 0.8 이라고 적혀 있었습니다.

설정값이 실제로 적용됐는지는 **같은 축의 다른 값이 다른 결과를 내는지**로만
확인됩니다. 탐색이 아니었다면 이 설정은 계속 죽어 있는 채로 남았을 것입니다.

값을 지우지는 않았습니다. 과거 아티팩트와 파라미터를 비교할 때 키가 사라지면
이력이 어긋나기 때문이며, 대신 `trainer.py` 주석에 무효임을 명시했습니다.
`subsample_freq` 를 살렸을 때의 이득은 미측정으로 남깁니다.

## 5. 운영 경로 실측

홀드아웃 개선이 서비스 개선인지는 **운영 경로에서 다시 재야** 압니다. 서빙
배선 이전에 홀드아웃 R2 0.68 인 모델이 API 에서 MAE 6.128 을 냈던 전례가
있습니다.

승격된 신규 모델과 백업한 구 모델을 **같은 표본**에 겨루었습니다. 백업을
`servc_prev_63leaf` 라는 임시 ID 로 서빙 루트에 복제해 두 모델을 동시에
호출했고, 측정 후 제거했습니다. 2025년 하한율 보유 공고 1,000건입니다.

측정: [`scripts/eval_servc_api_path.py`](../../scripts/eval_servc_api_path.py)

| 지표 | 63리프 | 255리프 | 판정 |
| --- | ---: | ---: | --- |
| MAE | 0.9848 | 0.9768 | 0.8% 개선 |
| RMSE | 3.1195 | 3.1603 | **1.3% 악화** |
| 중앙절대오차 | 0.2631 | 0.2463 | 6.4% 개선 |
| 0.5%p 적중 | 75.2% | 75.2% | 동일 |
| 1%p 적중 | 87.0% | 86.6% | 0.4%p 악화 |
| 3%p 적중 | 92.2% | 92.1% | 동일 |
| 피복률 | 91.5% | 92.0% | 둘 다 명목 90% 충족 |
| **구간 폭** | **1.423%p** | **1.583%p** | **11.2% 악화** |

**정확도는 지표마다 방향이 엇갈려 판별되지 않습니다.** MAE 개선과 RMSE 악화가
동시에 나타나는 것은 작은 오차는 줄고 큰 오차는 커졌다는 뜻입니다.

반면 **구간 폭은 한 방향으로 확실히 나빠졌습니다.** 255리프 모델이 학습
구간에 더 잘 맞으면서 분위 구간이 좁아지자 등각예측 배율이 1.163014 ->
1.254424 로 커졌고, 그 증가가 좁아진 폭을 상쇄하고도 남았습니다. 같은
피복률을 더 넓은 구간으로 달성한 셈입니다.

## 6. 기각과 롤백

> **2026-08-05 사유 정정.** 이 장의 "정확도와 구간 폭을 맞바꿔야 한다" 는 전제는
> 두 모델이 파라미터를 공유하던 구조 때문이었습니다. 분리하면 맞바꿀 필요가
> 없습니다(9장). 리프를 올리지 않는다는 결론은 유지되나 사유가 바뀝니다.
> **구간 폭 때문이 아니라, 홀드아웃 정확도 이득이 운영 경로에서 재현되지 않기
> 때문입니다.** 255 와 127 이 모두 같은 방향으로 어긋났습니다 (9.3).

**255 를 기각하고 63 으로 되돌렸습니다.**

| 구분 | 내용 |
| --- | --- |
| 이득 | 학습기 홀드아웃 RMSE 0.44%. 운영 경로에서는 판별 불가 |
| 비용 | 구간 폭 11.2% 증가, 모델 크기 3.1배(3.9MB -> 12.2MB), 학습 시간 3.4배 |

구간 폭은 **사용자가 화면에서 직접 보는 값**입니다. 확인되지 않는 정확도
이득과 바꿀 대상이 아닙니다. 홀드아웃 지표만 보고 승격했다면 서비스는
조용히 나빠졌을 것입니다.

롤백은 `promote` 가 남긴 `data/model_backups/servc_institution_v1` 을 서빙
루트로 되돌려 수행했고, 300건 재측정에서 MAE 1.2144 / 구간 폭 1.392%p 로
승격 이전 값과 일치함을 확인했습니다. 255리프 아티팩트는 `ml_registry` 에
`v_20260804_110452_953` 으로 남아 있어 재판단이 가능합니다.

## 7. 구간 폭은 63 이 최적점입니다

6장의 기각 사유가 "리프를 늘리면 배율이 커져 폭이 되레 넓어진다" 였으므로,
**반대 방향도 재 봤습니다.** 분위 모델을 일부러 덜 적합시키면 배율이 작아져
폭이 줄어드는지가 쟁점입니다. 피복률은 등각예측이 보장하므로 **폭만 비교하면
우열이 결정됩니다.**

점 추정 모델은 건드리지 않았습니다. 분위 아티팩트만 교체하면 되므로 채택 시
반영 비용이 낮은 실험입니다.

측정: [`scripts/eval_servc_interval_width.py`](../../scripts/eval_servc_interval_width.py)

| 분위 `num_leaves` | 등각 배율 | 보정 전 폭 | **보정 후 폭** | 피복률 |
| ---: | ---: | ---: | ---: | ---: |
| 15 | 1.0928 | 1.8624 | 2.0353%p | 89.14% |
| 31 | 1.1350 | 1.6567 | 1.8803%p | 89.65% |
| **63 (현행)** | 1.1485 | 1.5437 | **1.7728%p** | 89.88% |
| 127 | 1.1926 | 1.5156 | 1.8075%p | 90.05% |

**폭이 U자를 그리며 현행 63 에서 최소입니다.** 양방향 모두 나빠집니다.

| 방향 | 원래 구간 | 배율 | 최종 |
| --- | --- | --- | --- |
| 리프를 줄이면 | 넓어짐 (1.86) | 작아짐 (1.09) | **넓어진 원폭이 지배** |
| 리프를 늘리면 | 좁아짐 (1.52) | 커짐 (1.19) | **배율 증가가 상쇄하고 남음** |

배율은 분위 모델이 검증 구간에서 얼마나 빗나가는지를 재는 값입니다. 모델이
정교해질수록 학습 구간에만 맞아 검증 구간 오차가 상대적으로 커지고, 배율이
그만큼 올라갑니다. 두 효과가 63 에서 교차합니다.

**구간 폭은 분위 모델의 용량으로 더 줄일 수 없습니다.** 폭을 줄이려면 **특징이나
데이터**를 바꿔야 합니다. 하한율 결측 구간의 폭이 보유 구간의 7배라는 점이 그
방향을 가리킵니다.

이 장의 결론은 9장 이후에도 그대로 유효합니다. 다만 적용 범위가 분위 모델로
한정됩니다. 점 추정 리프는 이 U자와 무관하며 별도 기준으로 정합니다.

## 8. 평가 기준을 운영에 맞췄습니다 (2026-08-05)

탐색 스크립트는 `apply_lower_limit` 로 예측을 절단한 뒤 지표를 냈습니다. 그런데
**학습기도 서빙 경로도 절단을 걸지 않습니다.** 탐색만 다른 기준으로 순위를
매기고 있었던 것입니다.

절단을 전 경로로 확산시키지 않고 탐색에서 제거하는 쪽을 택했습니다. 절단은 이미
측정 후 안전장치로 격하됐습니다([`servc_segment_experiment_20260803.md`](servc_segment_experiment_20260803.md)
2장, 개선 R2 +0.0001). `lwlt_rate` 가 특징으로 들어가 모델이 이미 하한율 위로
예측하므로 절단할 대상이 거의 없습니다.

순위에는 영향이 없습니다. 같은 기준선에서 절단 유무 차이가 MAE 1.2829 대
1.2838 로 0.0009 인 반면, 2장에서 축들을 가른 차이는 그보다 한 자릿수 큽니다.

## 9. 점 추정과 분위 파라미터를 분리했습니다 (2026-08-05)

6장의 255 기각에는 사각지대가 있었습니다. 학습기가 `LGB_BASE_PARAMS` 하나를
점 추정과 분위 모델에 함께 썼기 때문에, 리프를 올리면 **두 모델이 동시에**
바뀝니다. 그래서 관측된 "MAE 개선 + 구간 폭 11.2% 악화" 는 **분리되지 않은
합계**였습니다.

측정: [`scripts/eval_servc_point_quantile_split.py`](../../scripts/eval_servc_point_quantile_split.py)

| 점추정 리프 | MAE | RMSE | 0.5%p 적중 | 학습 시간 |
| ---: | ---: | ---: | ---: | ---: |
| 63 | 1.2838 | 2.6414 | 60.54% | 13.4초 |
| **127** | **1.2710** | **2.6283** | **60.97%** | 24.4초 |
| 255 | 1.2659 | 2.6191 | 60.97% | 45.4초 |

| 분위 리프 | 등각 배율 | 구간 폭 | 피복률 |
| ---: | ---: | ---: | ---: |
| **63** | 1.1485 | **1.7728%p** | 89.88% |
| 255 | 1.2595 | 1.8891%p | 89.90% |

조합표에서 **구간 폭이 점추정 리프에 대해 전혀 움직이지 않습니다.** 폭은 분위
모델만 결정하므로 두 축은 완전히 독립이며, 6장이 맞바꿔야 한다고 본 것은 구조가
묶여 있었기 때문에 생긴 착시입니다.

| 점추정 | 분위 | MAE | 0.5%p 적중 | 구간 폭 |
| ---: | ---: | ---: | ---: | ---: |
| 63 | 63 | 1.2838 | 60.54% | 1.7728 |
| 127 | 63 | 1.2710 | 60.97% | **1.7728** |
| 255 | 63 | 1.2659 | 60.97% | **1.7728** |
| 255 | 255 | 1.2659 | 60.97% | 1.8891 |

### 9.1 구조는 채택, 값은 다시 기각

127 을 후보로 삼아 재학습·승격한 뒤 운영 API 경로에서 같은 표본 1,000건으로
겨뤘습니다(2025년, 하한율 보유 건). 학습기 홀드아웃은 R2 0.6881 -> 0.6901,
RMSE 2.6757 -> 2.6670 으로 champion 을 넘었고 폴드 R2 최대 0.6862 로 누수도
없었습니다. 그런데 운영에서는 이렇습니다.

| 지표 | 리프 63 | 리프 127 | 판정 |
| --- | ---: | ---: | --- |
| MAE | **0.9848** | 0.9863 | 악화 |
| RMSE | **3.1195** | 3.1455 | 악화 |
| 중앙절대오차 | **0.2631** | 0.2646 | 악화 |
| 0.5%p 적중 | **75.2%** | 74.5% | 악화 |
| 1%p 적중 | 87.0% | 87.0% | 동일 |
| **구간 폭** | 1.423%p | **1.423%p** | **동일** |
| 피복률 | 91.50% | 91.50% | 동일 |

**구간 폭이 소수점 셋째 자리까지 그대로입니다.** 분리 전이라면 1.583%p 로
벌어졌을 값이므로, 구조 분리는 의도한 대로 작동합니다. 그러나 정확도 이득이
운영으로 옮겨지지 않아 **점 추정 리프는 63 으로 되돌렸습니다.**

### 9.2 반영

| 대상 | 값 | 비고 |
| --- | --- | --- |
| `LGB_BASE_PARAMS["num_leaves"]` | **63** (유지) | 127 은 운영 실측 후 기각 |
| `QUANTILE_PARAM_OVERRIDES` | **`{"num_leaves": 63}`** (신설) | 지금은 값이 같아 동작 불변 |

값이 같아 당장 동작은 바뀌지 않습니다. 이 상수의 값어치는 **앞으로 점 추정
용량을 건드릴 때 구간 폭이 딸려 움직이지 않는다**는 데 있습니다.

### 9.3 홀드아웃이 운영을 대변하지 못합니다

두 번 연속 같은 방향으로 어긋났습니다.

| 시도 | 홀드아웃 | 운영 |
| --- | --- | --- |
| 255 (5장) | MAE -1.4% | 판별 불가 (MAE -0.8%, RMSE +1.3%) |
| 127 (9장) | MAE -1.0% | **전 지표 악화** |

우연으로 보기 어렵습니다. 2025년 홀드아웃 96,141건과 운영 표본(하한율 보유
1,000건)의 분포가 다르고, 후자가 실제 사용자가 보는 구성에 가깝습니다.
**점 추정 용량은 홀드아웃 지표로 정하지 않습니다.** 홀드아웃은 후보를 거르는
데까지만 쓰고, 채택은 운영 경로 동일 표본 비교로 판정합니다.
