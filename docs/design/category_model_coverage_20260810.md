# 카테고리별 모델 커버리지 현황과 학습 라우팅 결함

> **작성일**: 2026-08-10
> **버전**: v1.0.0
> **상태**: 라우팅 결함 수정 완료. 공사 전용 모델 학습은 미착수
> **대상**: `quantum_leap_v25_pro`(물품), `servc_institution_v1`(용역), `v25`(공사·외자)

---

## 1. 배경

용역 모델은 열 개가 넘는 개선 축을 닫으며 집중적으로 다듬었습니다. 물품도
2026-08-06 에 34특징으로 재학습해 승격했습니다. 그 과정에서 **나머지 카테고리를
한 번도 점검하지 않았습니다.**

파일 읽기만으로 현황을 정리한 결과 세 가지가 드러났습니다.

---

## 2. 현황

| 카테고리 | 학습 데이터 | 서빙 모델 | 요구 특징 | 최근 승격 |
| --- | ---: | --- | ---: | --- |
| Servc (용역) | 917,629행 | `servc_institution_v1` | 34 | 2026-08-07 |
| Thng (물품) | 784,266행 | `quantum_leap_v25_pro` | 34 | 2026-08-06 |
| **Cnstwk (공사)** | **1,358,882행** | **`v25`** | **5** | **없음** |
| Frgcpt (외자) | 데이터셋 없음 | `v25` | 5 | 없음 |

### 2.1 가장 큰 데이터셋에 전용 모델이 없습니다

공사는 1,358,882행으로 세 카테고리 중 가장 큽니다. 용역보다 48% 많습니다.
그런데 서빙 모델은 원본 `bid_box` 에서 이식한 `v25`(2026-05-04)이고 요구 특징이
다섯 개뿐입니다.

| 모델 | 요구 특징 |
| --- | --- |
| `v25` | `log_price`, `month`, `weekday`, `month_sin`, `month_cos` |
| `servc_institution_v1` / `quantum_leap_v25_pro` | 34개 (기관 이력, 반복 발주, 제도 특징, 예가방식 등) |

용역·물품 재학습에 들어간 기관 이력과 반복 발주 이력이 공사에는 하나도
반영돼 있지 않습니다. 재학습 파이프라인이 적용된 적이 없습니다.

### 2.2 물품 승격본의 운영 실측이 없습니다

`data/model_metrics/quantum_leap_v25_pro.json` 의 측정 시각이 승격보다
앞섭니다.

| 항목 | 물품 | 용역 |
| --- | --- | --- |
| 측정된 버전 | `25.1` | `v_20260807_043210_535` |
| 현재 서빙 버전 | `v_20260806_043408_749` | `v_20260807_043210_535` |
| 측정 시각 | 2026-08-06 **03:53** | 2026-08-07 06:13 |
| 승격 시각 | 2026-08-06 **04:46** | 2026-08-07 06:11 |
| 정합성 | **측정이 53분 앞섬** | 승격 2분 뒤 측정 |

즉 물품 지표 파일은 승격 **이전** 버전을 잰 값이며, 현재 서빙 중인 모델의
운영 경로 실측은 존재하지 않습니다.

그 구버전 지표는 R2 -0.2133 이었습니다. 음수 R2 는 평균으로 찍는 것보다
나쁘다는 뜻입니다. 승격본의 홀드아웃 지표는 R2 0.3583 이라 개선됐을 것으로
보이지만 **운영 경로에서 확인된 바가 없습니다.**

| 지표 | 물품 (구버전, 운영) | 물품 (승격본, 홀드아웃) | 용역 (승격본, 운영) |
| --- | ---: | ---: | ---: |
| MAE | 5.4942 | 미측정 | 1.2009 |
| MAPE | 5.9648% | 3.4815% | 1.3216% |
| RMSE | 6.3769 | 4.7659 | 2.6596 |
| R2 | **-0.2133** | 0.3583 | 0.7038 |

홀드아웃과 운영 값은 직접 비교할 수 없습니다. 이 프로젝트에서 두 값이 어긋난
사례가 반복됐습니다(`servc_hyperparam_quantile_20260807.md`). 물품은 운영 경로
재측정이 필요합니다.

## 3. 학습 라우팅 결함 (수정함)

같은 개념의 카테고리 매핑이 두 곳에 있었고 기본값이 달랐습니다.

| 파일 | 등록된 카테고리 | 미등록 시 |
| --- | --- | --- |
| `src/ml/trainer.py` (학습) | Thng, Servc | `quantum_leap_v25_pro` (물품) |
| `src/ml/model_registry.py` (서빙) | Thng, Servc | `v25` (범용) |

서빙은 공사를 `v25` 로 올바르게 보냅니다. 문제는 학습이었습니다.

```
ModelTrainer.for_category("Cnstwk")
  -> model_name_for_category("Cnstwk")
  -> CATEGORY_MODEL_NAMES 에 없음
  -> DEFAULT_MODEL_NAME = "quantum_leap_v25_pro"
  -> 공사 학습 산출물이 물품 디렉터리에 저장되고 물품 champion 과 비교됨
```

`trainer.py` 의 `for_category` docstring 이 이 위험을 이미 적어 두었습니다.

> 분기가 없으면 용역 재학습이 물품 디렉터리에 저장되고 물품 champion 과
> 비교됩니다. 서로 다른 제도를 쓰는 두 모델이 한 이름을 공유하게 됩니다.

용역에는 분기를 넣어 해결했으나 **공사는 누락됐습니다.** 공사 재학습을 돌린
적이 없어 실제 피해는 없었지만, 착수하는 순간 물품 승격본을 덮어쓰는
경로였습니다.

### 3.1 수정 내용

두 가지를 바꿨습니다.

| 변경 | 내용 |
| --- | --- |
| 네임스페이스 선등록 | `CATEGORY_MODEL_NAMES` 에 `Cnstwk: cnstwk_institution_v1` 추가 |
| 조용한 기본값 제거 | 미등록 카테고리 코드는 `ValueError`. 카테고리 미지정(`None`/공백)만 기본값 사용 |

미등록 코드를 실패시키는 것이 핵심입니다. 외자(`Frgcpt`)처럼 아직 데이터셋이
없는 카테고리로 학습을 시도하면 이제 즉시 멈춥니다. 조용히 물품을 덮는 것보다
낫습니다.

회귀는 `tests/test_retrain_pipeline_e2e.py::test_category_model_namespaces_do_not_collide`
가 막습니다. 세 카테고리의 네임스페이스가 서로 다른지, 미등록 코드가 실패하는지,
카테고리 미지정만 기본값을 쓰는지 확인합니다.

### 3.2 서빙 매핑은 아직 옮기지 않았습니다

`cnstwk_institution_v1` 은 이름만 잡아 둔 상태이고 학습된 가중치가 없습니다.
지금 서빙 매핑을 옮기면 존재하지 않는 모델을 가리킵니다.

**두 매핑이 다른 것은 현재로서는 의도된 상태입니다.** 공사 전용 모델이 실제로
승격되는 시점에 `model_registry.CATEGORY_DEFAULT_MODELS` 도 함께 옮겨야 합니다.
그 전까지 공사 예측은 `v25` 가 계속 담당합니다.

## 4. 남은 과제

| 순위 | 작업 | 비고 |
| --- | --- | --- |
| 1 | 물품 승격본 운영 경로 재측정 | 현재 서빙 품질이 미확인. `scripts/measure_serving_model.py` |
| 2 | 공사 전용 모델 재학습·승격 | 1,358,882행에 34특징 적용. 승격 시 서빙 매핑 동시 이동 |
| 3 | 외자(`Frgcpt`) 처리 방침 결정 | 데이터셋이 없어 학습 대상이 아님. `v25` 유지가 맞는지 확인 필요 |

1번을 먼저 하는 이유는 공사 작업의 판단 기준이 되기 때문입니다. 물품이 34특징
재학습으로 실제로 얼마나 좋아졌는지 운영 경로에서 확인돼야, 같은 파이프라인을
공사에 적용할 근거가 섭니다.

**공사 재학습은 용역 기준을 그대로 쓰면 안 됩니다.** 공사는 종합심사낙찰제와
적격심사가 주력이고 예정가격 산정 방식도 다릅니다. `CATEGORY_HYPERPARAMS` 의
용역 설정(`quantile(0.5)`, `num_leaves=255`)은 용역 잔차 분포에서 고른 값이므로
공사에 그대로 옮길 근거가 없습니다.
