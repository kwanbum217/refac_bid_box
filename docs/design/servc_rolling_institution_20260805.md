# 기관 이력의 시간 가중과 평가 표본 정정

> **작성일**: 2026-08-05
> **최종 갱신**: 2026-08-06
> **버전**: v1.1.0
> **상태**: 고정 시간 창은 기각 유지, 지수감쇠는 전량 재적합 수정 후 채택 후보
> **측정 스크립트**: [`scripts/eval_servc_rolling_institution.py`](../../scripts/eval_servc_rolling_institution.py), [`scripts/compare_servc_models_paired.py`](../../scripts/compare_servc_models_paired.py)

## 1. 무엇이 문제였나

`inst_hist_rate` 는 `expanding().mean()` 입니다. `shift(1)` 을 거치므로 누수는
없지만 **10년 전 낙찰률과 지난달 낙찰률의 가중치가 같습니다.** 2026-05-26
낙찰하한율 일괄 인상 같은 제도 전환이 있는 시장에서는 오래된 표본이 최근
신호를 희석합니다.

`features.py` 의 `inst_rate_mean_30d` 는 이름만 30일이었습니다. 값이 없으면
`inst_hist_rate` 로 폴백하므로 실질적으로 기관 전체 평균과 같았습니다.

---

## 2. 고정 시간 창은 이득이 없습니다

30/90/365일 창의 평균·건수·표준편차 9종을 계산해 넣었습니다. 누수 차단은
`closed="left"` 로 하며, 창이 기준 시각 미만만 담으므로 자기 자신과 동시각
공고가 모두 빠집니다.

| 구성 | 특징 수 | MAE | RMSE | R2 | 0.5%p 적중 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 현행 (expanding 평균) | 32 | 1.2830 | 2.6408 | 0.6977 | 60.59% |
| + 30일 창 | 35 | 1.2829 | 2.6388 | 0.6982 | 60.58% |
| + 90일 창 | 35 | 1.2844 | 2.6405 | 0.6978 | 60.50% |
| + 365일 창 | 35 | 1.2858 | 2.6411 | 0.6977 | 60.41% |
| + 전체 창 | 41 | 1.2837 | 2.6407 | 0.6977 | 60.55% |

**특징을 9개 넣어도 MAE 가 오히려 미세하게 나빠집니다.** 90일과 365일은 단독
으로도 손해입니다.

## 3. 지수감쇠는 특징 하나로 이득을 냅니다

| 구성 | 특징 수 | MAE | RMSE | R2 | 0.5%p 적중 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 현행 | 32 | 1.2830 | 2.6408 | 0.6977 | 60.59% |
| **+ 지수감쇠만** | **33** | **1.2600** | **2.6220** | **0.7020** | **60.89%** |
| + 전체 창 + 지수감쇠 | 42 | 1.2625 | 2.6251 | 0.7013 | 60.87% |

**홀드아웃 MAE 1.79% 개선.** 창까지 함께 넣으면 오히려 나빠지므로 지수감쇠만
남깁니다. 다만 이 이득은 6장에서 운영 실측에 의해 뒤집힙니다.

### 3.1 왜 건수 기준인가

감쇠는 **날짜가 아니라 발주 건수** 기준입니다. 발주가 잦은 기관은 30일에 수십
건, 드문 기관은 365일에 몇 건이라 고정 창은 기관마다 표본 수가 들쭉날쭉해
집니다. 건수 기준 감쇠는 그 차이를 흡수합니다. 반감기는 20건입니다.

### 3.2 누수 차단

지수감쇠는 건수 기준이라 `closed="left"` 같은 장치가 없습니다. `shift(1)` 은
자기 자신만 뺄 뿐이어서, 같은 개찰일의 다른 공고가 정렬 순서상 앞에 있으면 그
결과를 봅니다. 운영에서는 알 수 없는 값이므로 누수입니다.

(기관, 개찰일) 그룹의 **첫 행 값**을 그룹 전체에 뿌려 시각 경계를 만듭니다.
차단 전후 MAE 는 1.2602 대 1.2600 으로 사실상 같습니다. **이득이 누수에서 나온
것이 아님이 확인됩니다.**

## 4. 평가 표본이 서비스 모집단과 달랐습니다

이 실험에서 더 중요한 것이 드러났습니다. 이득을 구간별로 갈라 보면 이렇습니다.

| 구성 | 전체 MAE | 하한율 보유 구간 | 하한율 결측 구간(역산) |
| --- | ---: | ---: | ---: |
| 현행 | 1.2830 | 0.7619 | 2.481 |
| + 지수감쇠 | 1.2600 | 0.7618 | 2.406 |
| 변화 | **-1.79%** | **-0.01%** | **-3.0%** |

**이득이 전부 하한율 결측 구간에서 나옵니다.**

그런데 운영 측정(`eval_servc_api_path.py`)은 `--require-lwlt` 로 보유 건만
채점해 왔습니다. 과거 baseline 과 조건을 맞추려던 것인데, **실제 서비스는 결측
공고도 예측합니다.**

| 구간 | 비중 | MAE |
| --- | ---: | ---: |
| 하한율 보유 | 69.7% | 0.762 |
| 하한율 결측 | 30.3% | 2.481 |

결측 구간은 전체의 30% 이고 오차가 3.3배입니다. **사용자가 겪는 나쁨은 오히려
그쪽에 몰려 있는데, 측정에서 빼고 있었습니다.** 서비스 품질이 판단 기준인
프로젝트에서 이는 측정 자체의 결함입니다.

앞으로 운영 판정은 필터 없는 조건을 기준으로 합니다. 보유 구간 한정 측정은
과거 수치와의 연속성 확인 용도로만 씁니다.

## 5. 최초 배선 (실험 후 원복)

채택을 전제로 아래처럼 배선했다가 6장 실측 후 되돌렸습니다. 재시도할 때 같은
설계를 다시 세울 수 있도록 남깁니다.

학습과 추론이 같은 정의를 써야 합니다 (AGENTS.md 6항).

| 지점 | 내용 |
| --- | --- |
| `institution_history.EWM_HALFLIFE` | 반감기 20건. 단일 정의 |
| `attach_institution_history` | 학습 프레임에 `inst_ewm_rate` 부착 |
| `trainer.NUMERIC_FEATURES` | 학습 특징으로 등록 |
| `features.build_default_feature_map` | 추론 조회. 없으면 전체 평균 폴백 |
| `institution_win_rate_stats.ewm_rate` | 집계 컬럼 |
| `rebuild_institution_stats` | 야간 갱신 때 pandas 로 계산해 저장 |

감쇠는 순서에 의존해 SQL `AVG` 로 낼 수 없습니다. 추론 때마다 최근 이력을
읽으면 레이턴시를 해치므로 갱신 시점에 계산해 두고, 조회는 기존과 같은 PK 조회
한 번으로 끝냅니다.

`institution_win_rate_stats` 는 원본에 없는 파생 테이블이라 컬럼 추가가 데이터
무손실 원칙(G1)에 저촉되지 않습니다.

갱신 실측: 38,765행 중 38,667행(99.7%)에 값이 찼습니다. 나머지는 표본이 최소
건수 미만인 기관이며 평균으로 폴백합니다.

## 6. 운영 경로 실측 — 기각

재학습은 champion 을 넘었습니다. R2 0.6939 대 0.6881, RMSE 2.6505 대 2.6757,
폴드별 R2 최대 0.6817 로 누수도 없어 승격 게이트 4개를 전부 통과했습니다.

승격 후 서비스 모집단 전체(하한율 필터 없음) 4,997건에서 쌍대 비교했습니다.

| 지표 | 평균 차이 | 표준오차 | t | 판정 |
| --- | ---: | ---: | ---: | --- |
| 절대오차 | +0.02120 | 0.00393 | **5.39** | **base 우세** |
| 제곱오차 | +0.11315 | 0.04868 | 2.32 | base 우세 |
| 구간 폭 | +0.00974 | 0.00775 | 1.26 | 판별 불가 |

| 모델 | MAE | RMSE | 0.5%p 적중 |
| --- | ---: | ---: | ---: |
| 구본 | **1.6838** | **4.1230** | **58.36%** |
| 지수감쇠 | 1.7050 | 4.1367 | 57.11% |

**홀드아웃 -1.79% 가 운영 +1.3% 로 뒤집혔습니다.** t=5.39 는 앞선 두 사례
(리프 255, 127)와 달리 확실한 신호입니다. 롤백했고 배선도 되돌렸습니다.

### 6.1 원인은 미제입니다

train/serve skew 를 의심해 `inst_hist_rate` 의 학습값과 서빙 조회값을 같은
공고에서 대조했습니다.

| 항목 | 값 |
| --- | ---: |
| 학습 기본값 폴백 비율 | 2.4% |
| 서빙 기본값 폴백 비율 | 4.4% |
| 평균절대차 | 0.00463 |
| 둘 다 실값(235건) 상관 | **0.986** |

**skew 는 없습니다.** 따라서 역전의 원인은 아직 설명되지 않았습니다. 재시도
전에 이것부터 밝혀야 합니다.

### 6.2 이 과정에서 제가 낸 오진단

중간에 "상관 0.39, skew 실재" 라는 잘못된 결론을 냈습니다. 원인은 표본 구성
이었습니다.

| 측정 방식 | 학습 기본값 비율 |
| --- | ---: |
| 전량 attach 후 2025년 (올바름) | **4.4%** |
| 2025년만 잘라 attach | 23.7% |
| 위에 앞부분 400건만 추출 | 92.0% |

`attach_institution_history` 는 `shift(1).expanding()` 이라 프레임을 연도로
자르면 각 기관의 연초 건이 최소 표본(5건)에 걸립니다. 거기서 앞부분만 뽑으면
편향이 더 커집니다. **이력 특징을 검증할 때는 반드시 전량에 붙인 뒤 잘라내야
합니다.**

## 8. 2026-08-06 재판정

6장의 기각은 서빙 모델이 최신 20%를 학습하지 않던 결함이 있는 상태에서 내린
판정입니다. `refit_on_full` 수정 후 동일 학습 상한으로 다시 평가하자 지수감쇠와
리프 255 결합이 MAE를 3.13% 낮췄고 절대오차 t=-29.62로 우세했습니다.

실제 배선과 전량 재학습 후 운영 3,999건에서도 MAE 1.4984에서 1.4471로 3.42%
개선됐고 쌍대 절대오차 t=-7.50으로 재현됐습니다. 따라서 고정 시간 창 기각은
유지하되, 지수감쇠 기각은 철회합니다. 구현과 최신 수치는
`docs/design/servc_unbiased_candidate_recheck_20260805.md`를 정본으로 봅니다.
