# 용역(Servc) 미사용 raw_data 필드 감사

> **작성일**: 2026-08-11
> **상태**: 읽기 전용 감사 완료. 학습 실험 미수행
> **결론**: 학습에 쓰이지 않는 제도 플래그 5개에서 무시할 수 없는 집단 차이를 확인했습니다

---

## 1. 배경

용역 모델의 개선 축은 대부분 닫혔습니다. 잔차 후처리 다섯 축, `quantile` alpha 조정, 분위 `num_leaves` 상향, 분포 예측 계열이 모두 기각됐습니다. 남은 방향은 **새 정보 수집**뿐입니다.

물품(Thng)에서 값이 나온 경로가 정확히 그것이었습니다. DB `raw_data` 에는 있는데 학습 특징으로 쓰이지 않는 필드를 찾는 감사입니다. 같은 감사를 용역에 적용했습니다.

---

## 2. 방법

`bid_announcements.raw_data` 의 용역 최신 30,000건에서 키별 채움률을 세고, `dataset_Servc.parquet` 의 28개 컬럼 및 `src/ml/dataset.py` 가 참조하는 키와 대조했습니다. camelCase 키와 snake_case 컬럼을 정규화해 비교했습니다.

신호 측정은 `bid_results` 와 공고번호·업무구분으로 조인한 최신 40,000건에서 낙찰률 70~110 구간만 사용했습니다. DB 는 `SELECT` 만 실행했고 parquet, 모델, 원본 데이터는 변경하지 않았습니다.

---

채움률이 높아 유망해 보였으나 기존 컬럼과 같은 값이었습니다.

## 5. 유보 — 이 수치를 이득으로 읽으면 안 됩니다

위는 **무조건부(marginal) 차이**입니다. 다음 두 가지를 확인하기 전에는 특징 추가의 이득으로 볼 수 없습니다.

1. **기존 특징에 이미 흡수됐을 수 있습니다.** 사용 중인 `cntrct_mthd_nm` 과 `sucsfbid_mthd_nm` 이 이 플래그들과 강하게 상관될 가능성이 높습니다. 예를 들어 `dsgntCmptYn=Y` 는 특정 낙찰방법에 몰려 있을 수 있고, 그렇다면 새 정보가 아닙니다.
2. **잔차 상관을 재야 합니다.** 판정 기준은 현행 모델의 잔차와 각 플래그의 관계이지 타깃과의 관계가 아닙니다.

기존 진단에서 잔차와 특징의 최대 상관이 0.105 였다는 점을 감안하면, 이 플래그들이 잔차에 남아 있을지는 아직 알 수 없습니다.

2. **1 을 통과하면 특징 추가 실험.** `src/ml/features.py` 단일 공급원에 추가하고 `src/ml/dataset.py` 가 `raw_data` 에서 뽑도록 합니다. train/serve 양쪽에 같은 경로로 들어가야 합니다
