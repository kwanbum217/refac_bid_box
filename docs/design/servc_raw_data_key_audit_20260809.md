## 2. 채움률: 공고 테이블은 온전하고 결과 테이블은 최근 2년뿐입니다

`bid_results` 는 2015~2026년 개찰 완료 933,188행이 대상입니다.

| 개찰 연도 | 행 수 | `bid_results.raw_data` | `bid_announcements.raw_data` |
| --- | ---: | ---: | ---: |
| 2015 | 61,232 | 0.00% | 99.06% |
| 2016~2023 | 각 7~10만 | 0.00% | 99.98%~100.00% |
| 2024 | 97,360 | 0.40% | 99.98% |
| 2025 | 97,220 | 99.75% | 100.00% |
| 2026 | 57,028 | 100.00% | 100.00% |
| **합계** | **933,188** | **16.55%** | **99.93%** |

**우려했던 parquet 복구분 공백은 이 축에 걸치지 않습니다.** 복구분
1,244,778행은 `bid_results` 전체의 41% 이지만, 그 구간은 낙찰률이 결측이라
애초에 학습 대상이 아닙니다. 학습에 쓰는 933,188행 기준으로 공고 `raw_data`
는 99.93% 채워져 있습니다. **이 축은 좁아지지 않았습니다.**

**정보원은 `bid_announcements.raw_data` 하나뿐입니다.** 결과 테이블
`raw_data` 는 2025년 이후에만 채워져 학습 구간의 16.55% 에 그칩니다. 게다가
담긴 20종이 전부 개찰 후에 확정되는 값이라 추론 시점에 존재하지 않습니다
(`sucsfbidRate`, `bidwinnrNm`, `prtcptCnum` 등). **특징으로 쓸 수 없습니다.**

### 2.1 채움 판정에 함정이 있습니다

`raw_data` 에는 **JSON `null` 리터럴**이 들어간 행이 있습니다. SQL NULL 이
아니므로 `IS NOT NULL` 을 통과하고, `JSON_LENGTH` 는 1을 돌려줍니다. 처음
측정에서 `bid_results` 채움률이 **100%로 잘못 나왔고**, 같은 표본에서 키가
0종으로 집계되는 모순으로 발견했습니다.

**판정은 `JSON_TYPE(raw_data) = 'OBJECT'` 로 해야 합니다.** 다른 곳에서
`raw_data` 존재 여부를 볼 때도 같습니다.

## 3. 미사용 키: 113종 중 새로 볼 것은 20종입니다

`bid_announcements.raw_data` 는 12개 연도 전 구간에서 키 구성이 **113종으로
동일**했습니다. 연도별 스키마 변동이 없다는 뜻이라, 이 단계에서 연도 안정성
때문에 탈락하는 키는 없습니다.

| 구분 | 종수 | 처리 |
| --- | ---: | --- |
| 현행 특징이 쓰는 키 | 13 | 대조군 |
| 2026-08-03 조사가 이미 훑은 후보 | 38 | 재조사 불필요 |
| 미조사 — URL·파일명·연락처·담당자명 | 27 | 제외. 신호가 없습니다 |
| 미조사 — 식별자이거나 기존 컬럼과 중복 | 15 | 제외 |
| **미조사 — 3단계 후보** | **20** | **다음 단계 대상** |

제외한 27종은 `ntceSpecDocUrl1~10`, `ntceSpecFileNm1~10`, 각종 URL 과
담당자 전화·이메일입니다. 15종은 `bidNtceNo`, `dminsttCd`, `presmptPrce`
처럼 이미 정규 컬럼으로 있거나 코드-명칭 쌍의 반대편입니다
(`sucsfbidMthdCd` 는 `sucsfbidMthdNm` 과 같은 정보입니다).

## 4. 다음 단계
