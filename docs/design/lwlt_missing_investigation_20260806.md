# 낙찰하한율 결측 조사: 복원하지 않기로 한 근거

> **작성일**: 2026-08-06
> **버전**: v1.0.0
> **상태**: 조사 완료. 구현하지 않음 (구현 후 되돌림)
> **대상**: Servc (용역) 낙찰률 예측 모델

---

## 1. 배경

`lwlt_rate`(낙찰하한율)는 용역 모델의 중요도 3위 특징(8.45%)입니다. 최근 구간에서 이 값의 결측률이 40% 에 달해, 결측을 규칙으로 복원하면 정확도가 오를 것으로 보았습니다.

조사 결과 **복원해서는 안 된다는 결론**에 이르렀습니다. 결측이 데이터 누락이 아니라 제도적 사실이기 때문입니다.

---

## 2. 결측은 레짐 전환 때문이 아닙니다

2026-05-26 낙찰하한율 2%p 인상이 원인이라는 가설을 먼저 검증했습니다. **기각되었습니다.**

| 월 | 하한율 미기재 비율 |
| --- | ---: |
| 2025-11 | 22.5% |
| 2026-01 | 43.7% |
| 2026-03 | 55.3% |
| 2026-04 | 60.5% |
| 2026-05 | 62.7% |
| 2026-06 | 61.9% |
| 2026-07 | 59.7% |

시행일(5/26) 전후에 계단이 없습니다. 오히려 이후 미세하게 감소합니다. 2025-11 부터 이어진 완만한 추세이며 제도 변경과 무관합니다.

수집 버그도 아닙니다. `raw_data` 의 `sucsfbidLwltRate` 키는 **항상 존재하며 값이 빈 문자열**입니다.

---

## 3. 레짐 전환 자체도 모델 편향을 만들지 않습니다

같은 조사에서 함께 확인했습니다. 구 제도 905,917행만 학습해 신 제도 11,712행을 예측했습니다.

| 구간 | 편향(예측−실제) | MAE |
| --- | ---: | ---: |
| 신제도 out-of-sample | +0.0615%p | 1.4384 |
| 구제도 대조군 (동일 방식) | +0.0595%p | 1.3423 |

편향이 사실상 동일합니다. `inst_hist_rate`, `repeat_prev_rate` 같은 최근 이력 특징이 새 수준을 자동으로 흡수합니다. `is_post_regime_shift` 특징의 중요도는 0.05%(34개 중 33위)로 사실상 쓰이지 않습니다.

**레짐 전환을 이유로 한 재학습·특징 변경·데이터 보정은 근거가 없습니다.**

---

## 4. 하한율 값 자체는 강력합니다

값이 있는 행에서 하한율을 인위적으로 가려 보았습니다.

| 조건 | MAE |
| --- | ---: |
| 하한율 보유 행 (참값 사용) | 0.7853 |
| 같은 행에서 값을 가림 | 1.4040 |
| 하한율 결측 행 | 2.3612 |

값을 가리면 79% 악화합니다. 3배 격차의 상당 부분이 행의 난이도가 아니라 특징 자체의 기여입니다. 여기까지는 복원의 근거가 됩니다.

---

## 5. 규칙 복원 시뮬레이션은 유망해 보였습니다

`(용역구분, 계약방법, 낙찰방법, 대분류, 추정가격 구간)` 조합의 최빈값으로 복원하되, 표본 30건 이상 그리고 순도 95% 이상인 조합에만 적용하는 설계를 시뮬레이션했습니다. 값이 있는 행을 가린 뒤 복원해 참값과 비교하는 방식입니다.

| 지표 | 값 |
| --- | ---: |
| 규칙 적용 가능 비중 | 45.2% |
| 적용된 행의 정확 복원율 | 93.3% |
| MAE (참값 / 가림 / 복원) | 0.7853 / 1.4040 / 1.2469 |
| 잃은 성능 중 회수분 | 25.4% |

이 수치를 근거로 구현에 착수했습니다.

---

## 6. 실제 결측 행에는 0.0%p 적용되었습니다

구현 후 실제 데이터로 재니 **평가 구간(2026-05 이후) 결측률이 39.6% 에서 39.6% 로 전혀 줄지 않았습니다.** 복원표를 만드는 구간을 바꿔 봐도 같았습니다.

| 복원표 생성 구간 | 조합 수 | 평가 구간 복원율 |
| --- | ---: | ---: |
| 전체의 앞 80% (~2024-08) | 21 | 0.0%p |
| 2026-05 이전 전체 | 136 | 0.0%p |

원인은 `sucsfbid_mthd_nm`(낙찰방법)의 분포가 두 집단에서 **완전히 갈린다**는 데 있었습니다.

| 낙찰방법 상위 | 하한율 있음 | 하한율 결측 |
| --- | ---: | ---: |
| 소액수의견적(2인 이상 견적) | 65.5% | - |
| 적격심사제-수기심사 | 6.2% | - |
| 제한적최저가(낙찰하한율) | 4.0% | - |
| 수의시담-수의시담 | - | 67.6% |
| 규격가격동시입찰 | - | 13.5% |
| 수의시담-일반경쟁→수의 | - | 12.0% |

**하한율이 있는 방식과 없는 방식이 서로 겹치지 않습니다.** 하한율이 기재된 건은 소액수의견적·적격심사제·제한적최저가처럼 제도상 낙찰하한율이 **존재하는** 방식이고, 비어 있는 건은 수의시담·규격가격동시입찰처럼 **존재하지 않는** 방식입니다.

5장의 시뮬레이션이 유망해 보였던 이유가 여기 있습니다. 값이 **있는** 행에서만 평가했기 때문입니다. 그 모집단에는 애초에 하한율이 존재하는 방식만 들어 있어, 규칙이 잘 맞는 것이 당연했습니다.

---

## 7. 결론

**결측 40% 는 누락이 아니라 "이 입찰에는 낙찰하한율이 없다" 는 정확한 정보입니다.** 복원은 제도적으로 존재하지 않는 값을 지어내는 일이 됩니다. `lwlt_rate_missing` 지시자가 이 사실을 이미 올바르게 담고 있습니다.

4장의 3배 MAE 격차(0.785 대 2.361)도 다시 읽어야 합니다. 하한율이 없어서 어려운 것이 아니라, **수의시담처럼 하한율이 없는 계약 방식 자체가 예측하기 어려운** 것입니다. 하한율은 그 어려움의 원인이 아니라 표식입니다.

구현했던 `src/ml/lwlt_imputation.py` 와 `dataset.py`/`predictor.py` 배선은 되돌렸습니다.

---

## 8. 남는 과제

낙찰방법이 예측 난이도를 가른다는 사실 자체는 활용할 여지가 있습니다. 수의시담 계열(MAE 2.36)과 적격심사 계열(MAE 0.79)은 사실상 다른 문제이며, 분리 학습이나 방식별 분위 구간을 검토할 만합니다.

다만 이는 학습 특징 목록과 학습기를 손대야 하므로 별도 과제로 둡니다.

---

## 9. 교훈

**결측 데이터를 다룰 때는 결측 메커니즘부터 확인해야 합니다.** 이번 조사는 값이 있는 행에서 시뮬레이션해 25.4% 회수를 예측했으나, 실제 적용률은 0% 였습니다. MNAR(비무작위 결측) 가능성을 한계로만 적어 두고 착수한 것이 잘못이었습니다. 결측 집단과 보유 집단의 **특성 분포를 먼저 비교했다면** 구현 전에 알 수 있었습니다.
