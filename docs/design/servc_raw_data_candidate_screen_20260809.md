원인은 사용 여부를 `raw_data` 에서 직접 읽는 키로만 판정한 것입니다. 수집기는
일부 키를 **정규 컬럼으로 옮겨 담고**(`src/app/services/api_collector.py:264`),

보면 쓰고 있는 키가 미사용으로 잡힙니다.

`audit_servc_raw_data_keys.py` 에 `COLUMN_MAPPED` 를 넣어 두 경로를 함께 봅니다.

### 4.1 키는 있는데 값이 없습니다

결측 100% 인 8종은 추출 오류가 아닙니다. 원본을 직접 확인했습니다.

```
rgnDutyJntcontrctRt   ""  532,511건   /  NULL  20,879건
ntceDscrptYn          ""  532,511건   /  NULL  20,879건
tpEvalApplMthdNm      ""  532,511건   /  NULL  20,879건
indutyVAT             ""  532,511건   /  NULL  20,879건
```

**G2B 가 태그는 내려보내되 내용을 비워서 줍니다.** 용역 공고에는 해당 없는
필드라 값이 채워지지 않습니다(`mnfctYn` 제조 여부만 0.2% 에 값이 있고, 이는
용역에 제조가 거의 없다는 뜻이라 역시 상수에 가깝습니다).

가장 유망하다고 봤던 `rgnDutyJntcontrctRt`(지역의무 공동도급 비율)가 여기
속합니다. **경쟁 범위를 제도적으로 좁히는 변수라 기대가 컸는데, 용역 공고에는
값 자체가 존재하지 않습니다.** 이 예상은 틀렸습니다.

### 4.2 값이 있는 것은 최근 제도이거나 예외 처리용입니다

결측 85~99% 인 키들은 채움률이 연도에 걸쳐 고르게 낮습니다(연도 폭 최대
0.0727). 특정 시점부터 생긴 제도가 아니라, **원래 소수 공고에만 붙는 항목**
이라는 뜻입니다. `chgDt`(변경 일시) 0.85%, `dcmtgOprtnDt`(설명회) 0.43%,
`pqApplDocRcptDt`(PQ 신청) 1.54% 입니다.

표본을 그 소수로 좁히면 학습 대상이 933,188행에서 수천 행으로 줄어듭니다.
**전체 모델의 특징으로는 못 쓰고, 세그먼트 모델을 따로 세울 만큼 크지도
않습니다.**

## 6. 다음

**이제 G2B API 재수집이 남은 유일한 경로입니다.** 인수인계 4.3 이 "4번까지
통과한 것이 없으면 그때 재수집 범위를 논의하라" 고 한 지점에 도달했습니다.

재수집은 측정이 아니라 **수집 설계 과업**이고 비용이 큽니다. 착수 전 담당자와
범위를 합의해야 합니다. 검토할 후보를 적어 둡니다.

| 후보 | 내용 | 비고 |
| --- | --- | --- |
| 낙찰자 정보 API | `bidwinnrBizno` 기반 업체 이력 | 결과 `raw_data` 에 있으나 2025년 이후만이고 개찰 후 확정값이라 추론에 못 씀. 별도 수집으로 **과거 이력**을 만들면 다름 |
| 참가업체 수 | `prtcptCnum` | `collect_servc_participant_count.py` 로 일부 수집한 이력이 있습니다. 커버리지 확인 필요 |
| 사전규격 API | `bfSpecRgstNo` 연결 | 공고 전 단계 정보라 추론 시점에 존재합니다 |
| 계약 API | 실제 계약 금액·기간 | 개찰 후라 추론에 못 씀. 재학습 라벨 품질용 |

**추론 시점에 존재하는가**가 첫 판정 기준입니다. 이 기준을 통과하지 못하면
연관도가 높아도 서빙에서 쓸 수 없습니다.
