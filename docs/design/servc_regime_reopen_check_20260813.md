## 1. 착수 배경과 전제 정정

착수 지시의 전제는 "2026-05-26 이후 표본이 전체의 1.276% 뿐이므로 서빙 모델이
신 제도 구간에서 편향될 수 있다" 였습니다.

**이 축은 이미 두 번 닫혀 있습니다.** `servc-model-tuning` 스킬 기각 목록에
두 항목으로 등재되어 있습니다.

| 닫힌 날 | 축 | 근거 |
| --- | --- | --- |
| 2026-08-06 | 개찰일 플래그 축 | 신제도 편향 +0.0615%p 대 대조군 +0.0595%p. 차이 없음 |
| 2026-08-10 | `lwlt_rate` 값 수준 축 | 오라클 상한 0.0079%p |

따라서 이 작업은 새 측정이 아니라 **선행 문서가 명시한 재개 조건의 재확인**으로
수행했습니다. 스킬의 지시("착수 전에 기각 목록을 먼저 읽는다")를 따른 결과입니다.

### 1.1 날짜 축은 애초에 판정 축이 아닙니다

날짜로 가르는 방식은 2026-08-06 에 이미 기각됐습니다. 옳은 축은 `lwlt_rate`
**값 수준**입니다. LightGBM 은 외삽하지 않으므로, 인상으로 생긴 수준에 학습
표본이 없을 때만 계통 오차가 납니다.

신제도 구간의 하한율 수준 분포를 보면 이 구분이 왜 중요한지 드러납니다.

| 수준 | 신제도 구간 건수 | 구제도 학습 구간 표본 |
| ---: | ---: | ---: |
| 88.000 | 4,528 | 322,935 |
| 90.000 | 961 | 92,125 |

**주류는 여전히 88.000 이고, 90.000 도 학습 표본이 92,125행입니다.** 인상이
주류 수준을 밀어낸 것이 아니며 두 수준 모두 충분히 학습돼 있습니다.

## 2. 실행한 명령

```bash
uv run python scripts/eval_servc_regime_lwlt_levels.py
```

`data/feature_store/dataset_Servc.parquet` 만 읽습니다. DB·Docker·서빙 루트를
점유하지 않습니다. 특징 프레임 생성 335.6초, 학습 2회 포함 총 약 7분입니다.

표본 구성 재확인은 다음으로 했습니다.

```bash
uv run python -c "
import pandas as pd
df = pd.read_parquet('data/feature_store/dataset_Servc.parquet',
                     columns=['bid_ntce_dt','openg_dt','winning_rate','lwlt_rate'])
lab = df['winning_rate'].notna()
for col in ['bid_ntce_dt','openg_dt']:
    d = pd.to_datetime(df[col], errors='coerce')
    post = d >= pd.Timestamp('2026-05-26')
    print(col, int((post&lab).sum()), int(lab.sum()), d.max())
"
```

| 기준일 | 신제도 표본 | 전체 | 비중 |
| --- | ---: | ---: | ---: |
| `bid_ntce_dt`(공고일) | 11,712 | 917,629 | 1.276% |
| `openg_dt`(개찰일) | 13,241 | 917,629 | 1.443% |

평가 스크립트는 `openg_dt` 를 씁니다. 학습 프레임의 시간 축이 개찰일이기
때문입니다. 착수 지시의 1.276% 는 공고일 기준이며 **두 값 모두 맞습니다.**

## 4. 판정

### 4.1 재개 조건 두 개 모두 미달

선행 문서가 결과를 보기 전에 고정한 조건입니다.

| 조건 | 임계 | 실측 | 판정 |
| --- | --- | ---: | --- |
| 2%p 인상 희소 수준 비중 | 15% 초과 | **3.26%** | 미달 |
| 학습 충분 수준과의 MAE 격차 | 0.5 초과 | **0.2422** | 미달 |

오라클 상한은 그대로 `0.0326 x 0.2422 = 0.0079%p` 입니다. 홀드아웃 분할 산포
0.0074 와 같은 크기이므로 운영 쌍대 검정에서 읽히지 않습니다.

### 4.2 신제도 전체 편향은 유의하지 않습니다

착수 지시가 물은 "편향이 한 방향으로 몰리는가" 에 대한 답입니다.

| 구간 | 전체 편향 | t | 판정 |
| --- | ---: | ---: | --- |
| 신제도 | +0.0274 | 1.13 | 유의하지 않음 |
| 구제도 대조군 | -0.0353 | -1.64 | 유의하지 않음 |

**두 구간 모두 임계 2.0 을 넘지 못하며 부호마저 서로 반대입니다.** 신제도가
한 방향으로 치우친다는 증거가 없습니다.

집단 내부의 큰 편향(학습 충분 수준 -0.3851, t -19.70)은 신제도 특유가
아닙니다. 대조군도 -0.3569, t -21.73 으로 같은 부호·같은 크기입니다. 이는
`quantile(0.5)` 가 조건부 중앙값을 겨냥하고 분포가 비대칭이기 때문에 나타나는
성질이며, 선행 문서들이 이미 확인한 내용입니다.

### 4.3 MAE 악화는 성능이 아니라 표본 구성입니다

원 격차만 보면 신제도가 나빠 보입니다.

    신제도 1.2922 - 대조군 1.2085 = +0.0837

**그러나 집단별로 보면 신제도가 오히려 낫거나 같습니다.**

| 집단 | 신제도 MAE - 대조군 MAE |
| --- | ---: |
| 학습 충분 수준 | +0.0124 |
| 하한율 결측 | **-0.0969** |

차이를 만든 것은 **하한율 결측 비중**입니다. 33.27% 에서 39.11% 로 5.84%p
올랐고, 이 집단의 MAE 는 2.3 대라 전체 평균을 끌어올립니다.

대조군의 집단 구성을 신제도의 집단별 MAE 에 적용해 표준화하면 이렇습니다.

| 값 | MAE |
| --- | ---: |
| 대조군 실측 | 1.2085 |
| 신제도 실측 | 1.2922 |
| **대조군 구성으로 표준화한 신제도** | **1.1929** |

**구성을 통제하면 격차가 +0.0837 에서 -0.0156 으로 부호가 뒤집힙니다.**
신제도 구간에서 모델이 나빠졌다는 근거가 사라집니다.

하한율 결측 비중 상승은 2025-01 원천 체제 전환의 연속이며 2026-05-26 인상과는
다른 사안입니다. 그 축은 `servc_lwlt_missing_mechanism_20260810.md` 에서 결측의
99.1% 가 제도적 부재로 규명되어 이미 닫혀 있습니다.

### 4.4 결론

**조치가 필요하지 않습니다.** 모델·특징·가중치 변경을 제안하지 않습니다.
신 제도 가중, 보정 오프셋, 재학습 어느 것도 근거가 없습니다.

> 됩니다.**

**이 전제가 지금 성립하지 않습니다.**

| 항목 | 상태 | 근거 |
| --- | --- | --- |
| 학습 프레임 최종 갱신 | 2026-08-03 (10일 경과) | parquet mtime |
| 학습 프레임 최신 개찰일 | 2026-08-03 | `openg_dt.max()` |
| 서빙 모델 학습 행 수 | 917,629 (현 parquet 와 동일) | `metadata.json` |
| 서빙 모델 승격 시각 | 2026-08-07T06:11:21 | 같은 파일 |
| 기본 Compose 주간 재학습 | `ML_WEEKLY_RETRAIN_ENABLED=false` | `docker-compose.yml:87` |

즉 **자동 해소 경로가 꺼져 있습니다.** 이 상태가 이어지면 재개 조건을 다시
재도 값이 움직이지 않습니다. 오늘 측정이 2026-08-10 과 동일했던 것이 그
증거입니다.

이것은 이 Task 의 범위(측정과 판정)를 벗어나므로 조치하지 않았고, 후속
과제로 제안만 남깁니다.

| 제안 | 내용 | 비고 |
| --- | --- | --- |
| feature store 재생성 | `src/ml/dataset.py` 경로. DB 점유 필요 | 이 Task 는 DB 사용이 금지되어 실행하지 않음 |
| 주간 재학습 활성 여부 결정 | 개발 기본값이 `false` 인 것이 의도인지 확인 | 운영 배포에서는 기본 `true` |
| 재생성 후 재확인 | 같은 명령으로 재개 조건 재측정 | 약 7분 |

**표본이 실제로 쌓이기 전에는 이 축을 다시 열 이유가 없습니다.** 다만 위
세 가지가 정리되지 않으면, 다음에 같은 질문이 올라와도 답이 오늘과 똑같아
판정 자체가 무의미해집니다.
