## 4. 판정 (적용 범위: 역사적 대리 측정)

### 4.1 재개 조건 두 개 모두 미달

선행 문서가 결과를 보기 전에 고정한 조건입니다.

| 조건 | 임계 | 실측 | 판정 |
| --- | --- | ---: | --- |
| 2%p 인상 희소 수준 비중 | 15% 초과 | **3.26%** | 미달 |
| 학습 충분 수준과의 MAE 격차 | 0.5 초과 | **0.2422** | 미달 |

오라클 상한은 그대로 `0.0326 x 0.2422 = 0.0079%p` 입니다. 홀드아웃 분할 산포
0.0074 와 같은 크기이므로 운영 쌍대 검정에서 읽히지 않습니다.

### 4.2 신제도 전체 편향은 유의하지 않습니다

착수 지시가 물은 "편향이 한 방향으로 몰리는가" 에 대한 답입니다.

| 구간 | 전체 편향 | t | 판정 |
| --- | ---: | ---: | --- |
| 신제도 | +0.0274 | 1.13 | 유의하지 않음 |
| 구제도 대조군 | -0.0353 | -1.64 | 유의하지 않음 |

**두 구간 모두 임계 2.0 을 넘지 못하며 부호마저 서로 반대입니다.** 대리 측정
범위 안에서는 신제도가 한 방향으로 치우친다는 증거가 없습니다. 평균 편향의
95% 신뢰구간이 두 구간 모두 0 을 포함한다는 것도 3.3 절에서 확인했습니다.

집단 내부의 큰 편향(학습 충분 수준 -0.3851, t -19.70)은 신제도 특유가
아닙니다. 대조군도 -0.3569, t -21.73 으로 같은 부호·같은 크기입니다. 이는
`quantile(0.5)` 가 조건부 중앙값을 겨냥하고 분포가 비대칭이기 때문에 나타나는
성질이며, 선행 문서들이 이미 확인한 내용입니다.

### 4.3 MAE 악화는 성능이 아니라 표본 구성입니다

원 격차만 보면 신제도가 나빠 보입니다.

    신제도 1.2922 - 대조군 1.2085 = +0.0837

**그러나 집단별로 보면 신제도가 오히려 낫거나 같습니다.**

| 집단 | 신제도 MAE - 대조군 MAE |
| --- | ---: |
| 학습 충분 수준 | +0.0124 |
| 하한율 결측 | **-0.0969** |

차이를 만든 것은 **하한율 결측 비중**입니다. 33.27% 에서 39.11% 로 5.84%p
올랐고, 이 집단의 MAE 는 2.3 대라 전체 평균을 끌어올립니다.

대조군의 집단 구성을 신제도의 집단별 MAE 에 적용해 표준화하면 이렇습니다.

| 값 | MAE |
| --- | ---: |
| 대조군 실측 | 1.2085 |
| 신제도 실측 | 1.2922 |
| **대조군 구성으로 표준화한 신제도** | **1.1929** |

**구성을 통제하면 격차가 +0.0837 에서 -0.0156 으로 부호가 뒤집힙니다.**
신제도 구간에서 모델이 나빠졌다는 근거가 사라집니다.

하한율 결측 비중 상승은 2025-01 원천 체제 전환의 연속이며 2026-05-26 인상과는
다른 사안입니다. 그 축은 `servc_lwlt_missing_mechanism_20260810.md` 에서 결측의
99.1% 가 제도적 부재로 규명되어 이미 닫혀 있습니다.

가중치 변경을 제안하지 않습니다.

**이 문장을 "현행 서빙 모델을 검증했더니 문제가 없었다" 로 읽지 마십시오.**
그 판정은 이 조건에서 완료하지 못했습니다. 정확한 범위는 다음과 같습니다.

| 명제 | 상태 |
| --- | --- |
| 컷 이전 학습 모델이 컷 이후 구간에서 계통 편향을 보이는가 | **아니오.** 측정으로 답했습니다 |
| 재개 조건 두 개가 충족되었는가 | **아니오.** 측정으로 답했습니다 |
| 현행 서빙 champion 이 신 제도 구간에서 계통 편향을 보이는가 | **판정 못 함.** 5장 |

---

## 5. 핵심 판정 한계 — 현행 서빙 OOS 검증은 완료하지 못했습니다

이것은 남은 위험이 아니라 **이 작업이 도달하지 못한 지점**입니다.

### 5.1 왜 완료할 수 없는가

현행 서빙 모델을 out-of-sample 로 재려면 **그 모델이 학습에 쓰지 않은 라벨 보유
행**이 있어야 합니다. 지금은 그런 행이 하나도 없습니다.

| 사실 | 값 | 확인 |
| --- | --- | --- |
| champion 학습 행 수 | 917,629 | `metadata.json` |
| 현 parquet 행 수 | 917,629 | `len(pd.read_parquet(...))` |
| champion `refit_on_full` | `true` | `metadata.json` |
| parquet 최신 개찰일 | 2026-08-03 | `openg_dt.max()` |
| parquet 최종 수정 | 2026-08-03 19:33 | 파일 mtime |

champion 은 전량 재적합 아티팩트이므로 **이 parquet 의 모든 행이 학습 구간**
입니다. 그 위에서 잰 잔차는 in-sample 낙관이 섞여 판정 근거가 되지 못합니다.

바깥에서 라벨을 가져오려면 2026-08-03 이후 개찰분이 필요한데, 그것은 DB 에만
있고 **이 Task 는 DB 점유가 금지**되어 있습니다. 즉 두 경로가 동시에 막혀
있습니다.

    parquet 안   전 행이 학습 구간이라 in-sample
    parquet 밖   DB 금지로 접근 불가

### 5.2 완료하려면 필요한 것

| 순서 | 조치 | 비고 |
| --- | --- | --- |
| 1 | feature store 재생성 (`src/ml/dataset.py`) | DB 점유 필요. 별도 Task |
| 2 | 2026-08-03 이후 라벨 보유 행 확보 확인 | 없으면 대기 |
| 3 | 그 구간만으로 champion OOS 잔차 측정 | 서빙 루트 점유 |

**표본이 실제로 쌓이기 전에는 3번을 해도 답이 나오지 않습니다.** 1번이
선행이며, 그것이 이 Task 범위 밖입니다.

### 5.3 기각 근거가 기대는 전제도 함께 흔들립니다

선행 문서의 기각 근거는 다음 문장에 기대고 있습니다.

> 희소 수준은 개찰이 쌓이면 자동으로 해소됩니다. **정기 재학습만 유지하면
> 됩니다.**

기본 Compose 는 `ML_WEEKLY_RETRAIN_ENABLED=false` 입니다
(`docker-compose.yml:87`). **자동 해소 경로가 꺼져 있습니다.** 오늘 측정이
2026-08-10 과 소수점까지 같았던 것이 그 증거입니다.

| 제안 | 내용 |
| --- | --- |
| 주간 재학습 활성 여부 결정 | 개발 기본값 `false` 가 의도인지 확인 |
| 재생성 후 재확인 | 같은 명령으로 약 7분 |
