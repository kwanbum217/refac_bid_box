# 적격심사 B·k 금액 구간 선택 설계

> 작성일: 2026-10-03
> 상태: 구현됨
> 선행: [servc_2023_53_original_attachments_20261003.md](../analysis/servc_2023_53_original_attachments_20261003.md), [servc_institution_axis_design_20261002.md](servc_institution_axis_design_20261002.md)

## 1. 문제

입찰가격 배점한도 B 와 평점계수 k 는 원문에서 금액 구간으로 갈립니다. 규칙 하나가 두 구간을 함께 덮으면 지금은 단일값을 정할 수 없어 None 으로 두고, 적격심사 분석 API 가 `MISSING_SCORE_TABLE` 로 점수 계산을 막습니다.

| 축 | 원문 기준 | 값 | 적용 별표 |
| --- | --- | --- | --- |
| B | 추정가격 5억원 이상 / 미만 | 60 / 70 | 별표 1~7 (별표 8 은 70 단일, 별표 9 는 수요기관 지정 60~70) |
| k | 추정가격 고시금액 이상 / 미만 | 2 / 4 | 별표 1·3·4·5의2·7·8·9 (별표 2·3의2·5·6 은 단일식) |

현재 축 조건부로 비어 있는 규칙(코드 실측):

| 세대 | B 조건부 | k 조건부 |
| --- | --- | --- |
| PRE_20230501, PRE_20250901 | ATTACH_01·02·03·04·05·07·09·11·15·17 | ATTACH_05·15·16·17 |
| POST_20260526, POST_20260727 | ATTACH_01·02·03·04·05·07·09·11 | ATTACH_05 |

일반 띠 ATTACH_12·13·14 는 별표 귀속 자체가 미확인이라 이 설계 범위 밖입니다.

## 2. 입력 신호 (실측 2026-10-03, 2023-05-01 이후 용역 공고)

| 신호 | 건수 | 판단 |
| --- | --- | --- |
| 낙찰방법명에 '5억원 미만/이상' 표기 | 21,174 | 공고가 스스로 밝힌 구간. 드묾 |
| 낙찰방법명에 '고시금액 미만/이상' 표기 | 6,564 (2025년 이후만) | 위와 같음 |
| 낙찰방법명 '공고서참조' 또는 구간 표기 없음 | 약 68만 | 구간 정보 없음 |
| `presmpt_prce`(추정가격) > 0 | 99% 이상 | 주 신호 |

고시금액 경계 실측: 2025·2026 년 '고시금액 미만' 표기 공고의 추정가격은 99% 이상이 2.3억 미만이고 '이상' 표기는 사실상 전부 2.3억 이상입니다(미만 표기인데 2.3억 이상 2025 년 7건, 2026 년 18건). 2023·2024 년은 낙찰방법명이 '공고서참조' 라 데이터로 검증할 수 없습니다.

## 3. 설계

### 3.1 규칙 선언 확장

`EvaluationRule` 에 조건부 값 필드를 추가하고 기존 단일값 필드는 그대로 둡니다.

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| `max_price_score_by_500m` | `tuple[Decimal, Decimal] \| None` | (5억 미만 값, 5억 이상 값). 원문 B=70/60 |
| `multiplier_by_notice` | `tuple[Decimal, Decimal] \| None` | (고시금액 미만 값, 이상 값). 원문 k=4/2 |

단일값 필드와 조건부 필드는 동시에 값을 가질 수 없게 `__post_init__` 에서 검사합니다. 별표 9 의 B(수요기관 지정 60~70)는 금액으로 정해지지 않으므로 조건부 필드에 넣지 않고 사용자 입력으로 남깁니다.

### 3.2 선택 함수

`resolve_score_params(rule, estimated_price, announced_date, method_name) -> ScoreParamResolution` 을 `evaluation_rules.py` 에 둡니다(DB 를 모르는 순수 함수).

1. 낙찰방법명에 구간 표기가 있으면 그 구간을 씁니다.
2. 없으면 추정가격으로 판정합니다. B 는 `추정가격 >= 5억` 이면 이상 구간, k 는 `추정가격 >= 고시금액(공고일 연도)` 이면 이상 구간입니다. 경계값은 '이상' 쪽입니다(원문 표기 '이상/미만').
3. 낙찰방법명 구간과 추정가격 판정이 다르면 낙찰방법명을 따르고 경고를 남깁니다.
4. 추정가격이 없거나 읽을 수 없으면 해당 필드를 결측으로 두어 지금처럼 `MISSING_SCORE_TABLE` 로 막습니다.

결과 객체는 값과 함께 판정 근거(`basis`: 'METHOD_NAME' / 'ESTIMATED_PRICE' / 'FIXED', 사용한 추정가격, 경계값)를 돌려줍니다.

### 3.3 고시금액 표

고시금액 표는 `src/ml/notice_amount.py` 에 두고 판정과 학습 특징이 함께 사용합니다. 2023·2024 년은 2.2억원, 2025·2026 년은 2.3억원이며 그 밖의 연도 기본값은 2.2억원입니다(6절 D3).

### 3.4 API 와 스냅샷

- `_score_table`(`src/app/api/v1/evaluations.py:206`)은 규칙 단일값 대신 `resolve_score_params` 결과를 선언값으로 씁니다. 사용자 직접 입력이 선언값을 덮어쓰는 현재 동작은 유지합니다.
- 응답 `score_table` 에 `max_price_score_basis`, `multiplier_basis` 를 추가해 화면이 "추정가격 3.1억 < 5억 → B=70" 처럼 근거를 보여 줄 수 있게 합니다.
- 스냅샷은 `result_json` 에 이 근거가 함께 저장되므로 스키마 변경이 필요 없습니다.

## 4. 영향

축 조건부 때문에 막히던 공고가 추정가격만 있으면 점수를 계산하게 됩니다. 이 변경은 점수를 새로 계산하게 할 뿐 기존에 계산되던 공고의 값은 바꾸지 않습니다(단일값 규칙은 그대로). 해제되는 공고 수는 구현 Task 에서 실측합니다.

## 5. 시험 계획

경계값(5억 정확히, 고시금액 정확히), 추정가격 결측, 낙찰방법명과 추정가격 충돌, 단일식 별표(2·3의2·5·6)의 k 불변, 별표 8 B 단일·별표 9 B 사용자 입력 유지, 사용자 입력 우선, 세대별 대표 규칙의 B·k 선택 결과, 기존 시험 전량 불변.
