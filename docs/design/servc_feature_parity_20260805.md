# 학습·서빙 특징 값 대조와 `inst_sample_cnt` 결함

> **작성일**: 2026-08-05
> **버전**: v1.0.0
> **상태**: 결함 1건 수정(효과 큼), 1건 부분 수정(효과 중립)
> **측정 스크립트**: [`scripts/audit_feature_parity_values.py`](../../scripts/audit_feature_parity_values.py)

---

## 1. 왜 대조했나

2026-08-04~05 에 하이퍼파라미터 두 건과 특징 한 건이 **모두 홀드아웃에서
개선되고 운영에서 뒤집혔습니다.**

| 시도 | 홀드아웃 | 운영 |
| --- | --- | --- |
| 리프 255 | MAE -1.4% | 판별 불가 |
| 리프 127 | MAE -1.0% | 제곱오차 악화 (t=2.13) |
| 지수감쇠 기관 이력 | MAE -1.79% | 악화 (t=5.39) |

세 번 연속이라 우연으로 보기 어렵고, 같은 구간에서 홀드아웃 MAE 0.76 과 운영
0.99 의 **30% 격차**도 설명되지 않았습니다.

기존 [`tests/test_serving_feature_parity.py`](../../tests/test_serving_feature_parity.py)
는 **키가 있는가**를 봅니다. 값이 맞는가는 보지 않습니다. 그래서 34개 특징
전부를 같은 공고에서 학습값과 서빙값으로 대조했습니다.

---

## 2. 결과

2025년 공고 200건, 학습은 전량에 이력을 붙인 뒤 잘라 냈습니다.

| 특징군 | 일치율 | 상관 | 판정 |
| --- | ---: | ---: | --- |
| 제도 수치 5종 (`lwlt_rate` 등) | 1.000 | 1.000 | 정합 |
| 범주형 11종 | 0.955~1.000 | - | 정합 |
| 재발주 이력 6종 | 0.945~0.965 | 0.776~0.934 | **부분 불일치** |
| `inst_hist_rate` | 0.010 | 0.856 | 근사 일치 (소수 자리) |
| **`inst_sample_cnt`** | 0.010 | NaN | **전면 불일치** |

`inst_sample_cnt` 의 평균절대차가 **761** 이고 상관이 NaN 입니다. 상관을 낼 수
없다는 것은 서빙 값에 분산이 없다는 뜻입니다.

---

## 3. `inst_sample_cnt` 는 서빙에서 항상 0 이었습니다

경로를 따라가면 이렇습니다.

| 단계 | 동작 |
| --- | --- |
| 학습 | `attach_institution_history` 가 `shift(1).expanding().count()` 로 채움 |
| 서빙 payload | `announcement_feature_payload` 는 `TRAINING_COLUMNS` 기반. 이 컬럼은 **파생이라 목록에 없음** |
| 서빙 특징 맵 | `_coerce_float(features_dict.get("inst_sample_cnt"), 0.0)` -> **항상 0.0** |

`inst_hist_rate` 는 `lookup_institution_history` 폴백이 있어 살아남았지만,
`inst_sample_cnt` 에는 **조회 폴백 자체가 없었습니다.**

이 특징의 역할은 모델이 이력값을 얼마나 신뢰할지 판단하는 근거입니다
(`trainer.py` 주석). 학습에서 "표본이 많으면 이력을 믿어라" 를 배운 모델이
운영에서는 늘 "표본 0" 을 받았습니다. 이력 자체를 무시하라는 신호입니다.

**예외가 나지 않고 성능만 조용히 무너지는 형태**이며, 이 저장소가 이미 여러 번
겪은 유형입니다 (인수인계 1장).

## 4. 수정과 실측

`lookup_institution_sample_count` 를 추가해 집계 표의 `sample_count` 를
읽습니다. 컬럼은 이미 있었으므로 스키마 변경이 없습니다.

**재학습하지 않았습니다.** 모델은 그대로 두고 입력만 학습과 맞췄으므로, 아래
개선은 전부 정합성 회복에서 나온 것입니다.

2025년 하한율 보유 1,000건, 같은 시드입니다.

| 지표 | 수정 전 | 수정 후 | 변화 |
| --- | ---: | ---: | --- |
| MAE | 0.9848 | **0.9590** | -2.6% |
| RMSE | 3.1195 | **3.0978** | -0.7% |
| 0.5%p 적중 | 75.2% | **76.2%** | +1.0%p |
| 1%p 적중 | 87.0% | **87.3%** | +0.3%p |
| **구간 폭** | 1.423 | **1.305** | **-8.3%** |
| 피복률 | 91.5% | 90.5% | 명목 90% 에 근접 |

**구간 폭 8.3% 감소가 특히 큽니다.** 그동안 구간을 좁히려 세 가지를 시도해 전부
실패했고 "분위 모델 용량으로는 더 줄일 수 없다" 고 결론지었는데
(`servc_hyperparam_search_20260804.md` 7장), 원인의 일부가 입력 불일치였습니다.

### 4.1 서비스 모집단 전체

하한율 필터 없이 4,997건을 채점하면 이득이 더 큽니다.

| 지표 | 수정 전 | 수정 후 | 변화 |
| --- | ---: | ---: | --- |
| MAE | 1.6838 | **1.5807** | **-6.1%** |
| RMSE | 4.1230 | **4.0205** | -2.5% |
| 0.5%p 적중 | 58.36% | **59.28%** | +0.92%p |
| 구간 폭 | 2.0745 | **2.011** | -3.1% |
| 피복률 | 88.23% | 88.13% | 명목 90% 미달 (수정 전과 동일) |

보유 구간 -2.6% 보다 전체 -6.1% 가 크므로 **하한율 결측 구간에서 더 크게
개선**됐습니다. 오차가 3배인 그 구간이 사용자가 가장 나쁘게 겪는 부분입니다.

피복률 88.13% 는 명목 90% 에 못 미치나 수정 전과 같습니다. 등각 보정이 전체
모집단에서는 목표를 못 맞춘다는 별개 문제이며, 보유 구간 한정으로는 90.5% 로
정상입니다.

## 5. 남은 것

### 5.1 재발주 이력 6종 (부분 수정)

일치율 94~96%, 상관 0.78~0.93 으로 **부분 불일치**였습니다. 기준 시점
필터(`t < reference_ts`)는 제대로 걸려 있습니다.

**카테고리 필터 누락을 찾아 고쳤습니다.** 학습은 카테고리별 parquet 을 보는데
`lookup_repeat_history` 의 조회에는 `category` 조건이 없어, 같은 기관의 물품·
공사 낙찰까지 용역 재발주 이력에 섞여 들어갔습니다.

| 특징 | 수정 전 상관 | 수정 후 상관 |
| --- | ---: | ---: |
| `is_repeat` | 0.898 | 0.913 |
| `repeat_cnt` | 0.915 | 0.915 |
| `repeat_hist_rate` | 0.924 | 0.936 |
| `repeat_prev_rate` | 0.884 | 0.895 |
| `repeat_hist_std` | 0.776 | 0.776 |
| `repeat_days_since` | 0.934 | 0.934 |

**개선이 미미해 근본 원인은 아닙니다.** 운영 성능도 중립입니다(MAE 0.9590 ->
0.9589). 그럼에도 유지하는 이유는 정의 일치가 성능과 무관하게 지켜야 할
원칙이기 때문입니다 (AGENTS.md 6항).

남은 5% 의 유력한 원인은 **제목 인코딩**입니다. `repeat_key` 는 공고 제목
기반인데 `bid_results` 의 제목은 과거 parquet 복구분 1,244,778행(41%)이 U+FFFD
로 깨져 있습니다. 학습 프레임과 추론 조회가 서로 다른 제목을 보면 키가
어긋납니다. `max_rows=5000` 제한도 남은 후보입니다.

### 5.2 홀드아웃·운영 격차

이 수정으로 운영 MAE 가 0.9848 에서 0.9590 으로 내려왔지만 홀드아웃 0.76 과는
여전히 차이가 있습니다. 재발주 이력 불일치와, 두 측정의 모델 구성 차이(학습
범위·검증 구간)가 남은 후보입니다.
