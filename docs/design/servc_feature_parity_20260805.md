## 1. 왜 대조했나

2026-08-04~05 에 하이퍼파라미터 두 건과 특징 한 건이 **모두 홀드아웃에서
개선되고 운영에서 뒤집혔습니다.**

| 시도 | 홀드아웃 | 운영 |
| --- | --- | --- |
| 리프 255 | MAE -1.4% | 판별 불가 |
| 리프 127 | MAE -1.0% | 제곱오차 악화 (t=2.13) |
| 지수감쇠 기관 이력 | MAE -1.79% | 악화 (t=5.39) |

세 번 연속이라 우연으로 보기 어렵고, 같은 구간에서 홀드아웃 MAE 0.76 과 운영
0.99 의 **30% 격차**도 설명되지 않았습니다.

기존 [`tests/test_serving_feature_parity.py`](../../tests/test_serving_feature_parity.py)
는 **키가 있는가**를 봅니다. 값이 맞는가는 보지 않습니다. 그래서 34개 특징
전부를 같은 공고에서 학습값과 서빙값으로 대조했습니다.

`inst_sample_cnt` 의 평균절대차가 **761** 이고 상관이 NaN 입니다. 상관을 낼 수

## 3. `inst_sample_cnt` 는 서빙에서 항상 0 이었습니다

경로를 따라가면 이렇습니다.

| 단계 | 동작 |
| --- | --- |
| 학습 | `attach_institution_history` 가 `shift(1).expanding().count()` 로 채움 |
| 서빙 payload | `announcement_feature_payload` 는 `TRAINING_COLUMNS` 기반. 이 컬럼은 **파생이라 목록에 없음** |
| 서빙 특징 맵 | `_coerce_float(features_dict.get("inst_sample_cnt"), 0.0)` -> **항상 0.0** |

`inst_hist_rate` 는 `lookup_institution_history` 폴백이 있어 살아남았지만,
`inst_sample_cnt` 에는 **조회 폴백 자체가 없었습니다.**

이 특징의 역할은 모델이 이력값을 얼마나 신뢰할지 판단하는 근거입니다
(`trainer.py` 주석). 학습에서 "표본이 많으면 이력을 믿어라" 를 배운 모델이
운영에서는 늘 "표본 0" 을 받았습니다. 이력 자체를 무시하라는 신호입니다.

**예외가 나지 않고 성능만 조용히 무너지는 형태**이며, 이 저장소가 이미 여러 번
겪은 유형입니다 (인수인계 1장).

**재학습하지 않았습니다.** 모델은 그대로 두고 입력만 학습과 맞췄으므로, 아래
개선은 전부 정합성 회복에서 나온 것입니다.

2025년 하한율 보유 1,000건, 같은 시드입니다.

## 5. 남은 것

### 5.1 재발주 이력 6종 (부분 수정)

일치율 94~96%, 상관 0.78~0.93 으로 **부분 불일치**였습니다. 기준 시점
필터(`t < reference_ts`)는 제대로 걸려 있습니다.

**카테고리 필터 누락을 찾아 고쳤습니다.** 학습은 카테고리별 parquet 을 보는데
`lookup_repeat_history` 의 조회에는 `category` 조건이 없어, 같은 기관의 물품·
공사 낙찰까지 용역 재발주 이력에 섞여 들어갔습니다.

| 특징 | 수정 전 상관 | 수정 후 상관 |
| --- | ---: | ---: |
| `is_repeat` | 0.898 | 0.913 |
| `repeat_cnt` | 0.915 | 0.915 |
| `repeat_hist_rate` | 0.924 | 0.936 |
| `repeat_prev_rate` | 0.884 | 0.895 |
| `repeat_hist_std` | 0.776 | 0.776 |
| `repeat_days_since` | 0.934 | 0.934 |

**개선이 미미해 근본 원인은 아닙니다.** 운영 성능도 중립입니다(MAE 0.9590 ->
0.9589). 그럼에도 유지하는 이유는 정의 일치가 성능과 무관하게 지켜야 할
원칙이기 때문입니다 (AGENTS.md 6항).

### 5.2 남은 5% 는 학습 쪽 누수였습니다

후보를 차례로 확인했습니다.

| 가설 | 판정 |
| --- | --- |
| 제목 인코딩 깨짐 | **기각.** 두 테이블 제목이 3,000건 표본에서 100% 일치 |
| `max_rows=5000` 제한 | **기각.** 이력 5,000건 초과 기관 0개 |
| 공고 조인 실패분 | **기각.** 931,665건 중 1,179건(0.1%) |
| **동시각 처리 차이** | **확인.** 규모 5.6% 로 관측치와 일치 |

학습(`attach_repeat_history`)은 `shift(1)` 만 써서 **같은 날 개찰된 같은 사업의
다른 공고를 이력으로 봤고**, 추론(`lookup_repeat_history`)은 `t < reference_ts`
로 올바르게 제외하고 있었습니다. 이번에는 **학습 쪽이 틀렸습니다.**

용역 917,060행 중 같은 키·같은 개찰시각이 2건 이상인 행이 51,175건(5.6%),
그중 실제로 동시각을 이력으로 쓴 행이 33,555건(3.7%)입니다.

(키, 개찰시각) 그룹의 첫 행 값을 그룹 전체에 뿌려 시각 경계를 만들었습니다.
일치율이 0.945~0.965 에서 0.975~0.980 으로 올라갑니다.

**다만 완전한 해소는 아닙니다.** 200건 표본에서는 6종이 전부 0.95 를 넘었으나
600건으로 늘리면 상관이 0.864~0.948 로 일부 미달합니다. 표본이 작을 때의
결과를 일반화하지 마십시오 (이 문서에서만 두 번째 사례입니다).

| 특징 | 200건 상관 | 600건 상관 | 평균절대차 |
| --- | ---: | ---: | ---: |
| `is_repeat` | 0.913 | 0.9250 | 0.025 |
| `repeat_cnt` | 0.915 | 0.9927 | 0.080 |
| `repeat_hist_rate` | 0.936 | 0.9479 | 0.001 |
| `repeat_prev_rate` | 0.895 | 0.9481 | 0.001 |
| `repeat_hist_std` | 0.776 | 0.9008 | 0.0002 |
| `repeat_days_since` | 0.934 | 0.8644 | 16.0일 |

평균절대차는 대부분 0.001 수준으로 작습니다. `repeat_days_since` 만 16일로
크며, 이는 동시각 경계를 넣으면서 "직전 발주" 의 기준이 바뀐 영향입니다.

### 5.3 누수 제거의 대가

학습 정의가 바뀌었으므로 재학습했습니다.

| 지표 | 누수 포함 | 누수 제거 |
| --- | ---: | ---: |
| 홀드아웃 R2 | 0.6881 | 0.6824 |
| 홀드아웃 RMSE | 2.6757 | 2.6998 |
| 운영 MAE (4,997건) | **1.5814** | 1.5867 |
| 운영 0.5%p 적중 | 59.32% | 59.24% |

쌍대 비교에서 절대오차 t=2.51 로 **누수 포함본이 근소하게 우세**합니다
(0.33%). 동시각 공고의 낙찰률이 서로 비슷하므로 그것을 보고 배운 모델이 운영
에서도 약간 유리하게 작동합니다.

**그럼에도 누수 제거본을 유지합니다.**

| 근거 | 내용 |
| --- | --- |
| 원칙 | train/serve 정의 단일화는 비협상 사항입니다 (AGENTS.md 6항) |
| 재현성 | 학습 코드를 고쳤으므로 누수 모델은 재현 불가능한 아티팩트입니다 |
| 지표 신뢰 | 대가 0.33% 로 앞으로의 홀드아웃 지표를 믿을 수 있게 됩니다 |

### 5.4 남은 불일치는 시점 차이입니다

600건 대조 기준으로 8개가 0.95 미만입니다.

| 특징 | 상관 | 평균절대차 |
| --- | ---: | ---: |
| `inst_hist_rate` | 0.9118 | 0.0045 |
| `inst_sample_cnt` | 0.8789 | 189.4 |
| 재발주 이력 5종 | 0.864~0.948 | 0.0002~16.0 |
| `ntce_kind_nm` (범주) | 0.9433 | - |

`inst_sample_cnt` 는 수정 전 평균절대차가 761 이었으므로 **75% 줄었습니다.**
남은 차이의 정체는 시점입니다.

| 경로 | 값의 의미 |
| --- | --- |
| 학습 | 그 공고 개찰일 **직전까지**의 누적 |
| 서빙 | 집계 표의 **현재 시점** 누적 |

2025년 공고를 지금 예측하면 학습은 "그때까지 500건", 서빙은 "지금까지 689건"
을 줍니다.

### 5.5 확정: 학습 계산은 정확합니다

그 공고 개찰일 이전만 SQL 로 직접 집계해 학습값과 맞춰 봤습니다. 정의가 같으므로
학습이 옳다면 일치해야 합니다.

측정: [`scripts/verify_asof_history_parity.py`](../../scripts/verify_asof_history_parity.py)

2025년 100건입니다.

| 비교 | 상관 | 평균절대차 |
| --- | ---: | ---: |
| 학습 대 **as-of 계산** (표본 수) | **0.9999** | 5.2건 |
| 학습 대 **as-of 계산** (낙찰률) | **0.9878** | 0.0017 |
| 학습 대 현재 집계 표 (낙찰률) | 0.9735 | 0.0029 |

**학습 계산이 정확합니다.** 남은 불일치는 서빙 집계 표가 현재 시점 값이라는
데서 옵니다.

그리고 **실제 운영에서는 이것이 결함이 아닙니다.** 서비스는 미개찰 공고를
예측하므로 "현재 시점까지의 이력" 이 정확합니다. 어긋나는 것은 과거 공고로
평가할 때뿐입니다.

따라서 이 문서 5.4 절의 잔여 불일치 8건은 **코드 결함이 아니라 측정
아티팩트**입니다. 다음 두 가지가 따라옵니다.

| 함의 | 내용 |
| --- | --- |
| 과제 성격 | 코드 수정이 아니라 **평가용 as-of 스냅샷 구축** |
| 측정치 해석 | 오늘 잰 운영 성능(MAE 1.5867)은 실제를 **과소평가**할 수 있습니다 |

### 5.6 홀드아웃·운영 격차

이 수정들로 운영 MAE 가 0.9848 에서 0.9590 으로 내려왔지만 홀드아웃 0.76 과는
여전히 차이가 있습니다.

5.5 에서 학습 계산이 정확함이 확인됐으므로 **특징 불일치는 후보에서 빠집니다.**
남은 후보는 둘입니다.

| 후보 | 내용 |
| --- | --- |
| 평가 시점 | 과거 공고를 현재 시점 이력으로 예측. as-of 스냅샷으로 확정 가능 |
| 모델 구성 차이 | 홀드아웃 실험은 2015~2024 로 그 자리에서 학습한 32특징 모델, 운영은 전량 학습 후 승격된 34특징 모델 |

앞의 것을 먼저 지우는 것이 순서입니다. 그것이 격차의 상당 부분을 설명한다면
뒤의 것은 볼 필요가 없어집니다.
