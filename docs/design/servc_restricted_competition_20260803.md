## 1. 제한경쟁이 진짜 약점인지 확인

R2 는 구간의 타깃 분산에 좌우되므로 R2 만으로 "나쁘다"고 말할 수 없습니다.
상대오차(RMSE / 실제 표준편차)로 다시 봅니다.

| 계약방법 | 공고 건수 | 실제 표준편차 | RMSE | **상대오차** | R2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 지명경쟁 | 2,143 | 3.579 | 1.4423 | **0.403** | 0.8375 |
| 수의계약 | 63,405 | 4.487 | 2.3309 | **0.520** | 0.7301 |
| 일반경쟁 | 6,348 | 5.397 | 3.4971 | **0.648** | 0.5800 |
| **제한경쟁** | 24,245 | 4.290 | 3.4619 | **0.807** | 0.3489 |

**상대오차로 봐도 제한경쟁이 최악입니다.** 분산 탓이 아니라 실제 약점입니다.
표본이 24,245건으로 두 번째로 많아 개선 가치도 큽니다.

## 2. 전자입찰의 두 난수

전자입찰에는 예측 불가능한 난수가 둘 있습니다.

| 난수 | 내용 | 공고 시점 가용 |
| --- | --- | --- |
| **복수예비가격** | 기초금액 ±2%(국가)/±3%(지방) 15개 중 4개 추첨 평균 | 불가 |
| **참여업체 수** | 투찰 참가자 수. 낙찰률이 하한율에 얼마나 근접할지를 결정 | 불가 |

이 둘이 각각 얼마나 잔차를 만드는지 실측했습니다. 복수예가 + 하한율 보유
705,217건에서 `gap = 낙찰률 - 낙찰하한율` 을 봅니다.

| 분위 | gap (%p) |
| --- | ---: |
| 1% | 0.000 |
| 25% | 0.039 |
| **50%** | **0.159** |
| 75% | 0.567 |
| 90% | 1.829 |
| 95% | 6.327 |
| 99% | 11.196 |

| 조건 | 비율 |
| --- | ---: |
| 낙찰률 >= 하한율 | 99.96% |
| 하한율 +0.5%p 이내 | **72.7%** |
| 하한율 +1.0%p 이내 | 84.0% |

### 2.1 복수예가 난수는 소거됩니다

예비가격 15개가 기초금액 ±2% 균등분포이면 개별 표준편차는 약 1.155% 이고,
15개 중 4개 평균의 표준편차는 유한모집단 보정을 넣어 **약 0.51%** 입니다.

그런데 이 난수는 **모든 입찰자에게 동일하게 작용합니다.** 참가자 전원이 같은
예정가격을 상대하므로, 경쟁이 존재하는 한 최저 투찰자가 하한율 경계에 붙습니다.
분모가 흔들려도 낙찰률은 하한율로 고정됩니다. gap 중앙값 0.159%p 가 그 증거입니다.

### 2.2 남는 것은 참여업체 수뿐입니다

gap 분포는 **0 에 붙은 뾰족한 봉우리 + 긴 오른쪽 꼬리**입니다. 표준편차 2.760 은
꼬리가 만듭니다.

- 업체가 많으면 하한율 바로 위를 노리는 투찰자가 반드시 존재 -> gap = 0 수렴
- 업체가 적으면 아무도 경계까지 내려가지 않음 -> gap 이 위로 튐

용역구분별 gap 이 같은 이야기를 합니다.

| 용역구분 | gap 중앙값 | gap 표준편차 |
| --- | ---: | ---: |
| 기술용역 | 0.140 | **1.501** |
| 일반용역 | 0.179 | **3.425** |

**기술용역이 잘 맞는 것은 모델의 성능이 아니라 경쟁 밀도의 결과입니다.**

### 2.3 참여업체 수 (2026-08-04 측정으로 정정)

작성 당시에는 "데이터에 부재" 로 판단했습니다. `bid_results.raw_data` 가 전 행
비어 있고 `bid_announcements.raw_data` 52개 키에도 없었기 때문입니다.

**이 판단은 틀렸습니다.** 이미 수집 중인 오퍼레이션
`getScsbidListSttusServc` 가 `prtcptCnum` 을 내려주고 있으며,
`_item_raw_data` 가 전 필드를 `raw_data` 에 담으므로 **신규 수집분에는 값이
들어옵니다.** 비어 있던 것은 과거 이관분입니다. 2025년 116,397건을 재수집한
결과 **보유율 100%** 입니다.

수집: [`scripts/collect_servc_participant_count.py`](../../scripts/collect_servc_participant_count.py)
측정: [`scripts/eval_servc_participant_effect.py`](../../scripts/eval_servc_participant_effect.py)

#### 참가자 수는 낙찰률을 강하게 가릅니다

2025년 95,175건, 하한율 초과폭(gap) 기준입니다.

| 참가자 수 | 건수 | gap 중앙값 | gap 표준편차 | 낙찰률 표준편차 |
| --- | ---: | ---: | ---: | ---: |
| 1곳 | 21,670 | **9.938** | 4.852 | 4.466 |
| 2곳 | 9,296 | 2.260 | 6.818 | 4.741 |
| 3~5곳 | 16,219 | 0.543 | 4.845 | 4.072 |
| 6~10곳 | 13,124 | 0.245 | 2.976 | 3.054 |
| 11~30곳 | 17,082 | 0.114 | 1.837 | 2.474 |
| 31~100곳 | 12,170 | 0.039 | 0.614 | 1.968 |
| 100곳 초과 | 5,614 | **0.008** | 0.269 | 1.956 |

**단독응찰이 전체의 23%** 이며 하한율보다 10%p 위에서 낙찰됩니다. 경쟁이 붙으면
하한율에 정확히 달라붙습니다. 2.2 절의 가설은 이로써 확증됩니다.

#### 그러나 모델 개선으로는 이어지지 않습니다

참가자 수는 **개찰 후에야 알 수 있습니다.** 공고 시점 예측에 그대로 넣으면
미래 정보 누수입니다. 그래서 상한(오라클)과 운영 가능한 형태(기관·중분류·
기관x계약방법별 과거 평균, 표본 10건 축소 적용)를 나눠 쟀습니다. 2025년
9월 1일 경계, 학습 65,181건 / 검증 29,994건입니다.

| 구분 | 특징 수 | R2 | RMSE | MAE | 0.5%p 적중 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기준 (참가자 수 없음) | 32 | 0.7167 | 2.5450 | 1.2182 | 62.14% |
| 이력 (운영 가능) | 35 | 0.7187 | 2.5361 | 1.2054 | 62.62% |
| 오라클 (상한, 운영 불가) | 33 | **0.7439** | **2.4197** | 1.1272 | 63.53% |

**실제 값을 그대로 줘도 RMSE 개선은 4.9% 에 그칩니다.** 단변량으로는 압도적인
신호인데 증분이 작은 것은, 하한율·계약방법·용역구분·기관 이력이 이미 경쟁
강도를 상당 부분 대리하고 있기 때문입니다. 참가자 수는 그 위에 얹히는 정보가
아니라 **대체로 겹치는 정보**입니다.

운영 가능한 이력 형태는 **오라클의 7%(RMSE 0.35%)만 회수**합니다. 10년치 재수집과
집계 테이블 신설 비용에 대해 이 이득은 정당화되지 않습니다.

**결론: 참가자 수 이력 특징은 기각합니다.** 진단 가치는 확인됐으나 예측 가치는
없습니다. 다만 수집 자체는 비용이 0 이므로(이미 내려오는 필드), 향후 세그먼트
분석과 구간 보정 검증에는 활용할 수 있습니다.

### 3.1 채택

**세부분류·공고속성 6종** (`mid_clsfc_nm`, `clsfc_nm`, `ntce_kind_nm`,
`bid_methd_nm`, `intrbid_yn`, `ppsw_gnrl_srvce_yn`).

근거는 제도 분석서 5.4 절입니다. 일반용역은 추정가격 구간이 아니라 **용역
종류별 별표**로 하한율이 갈리며(시설분야 89.995 대 보험 47.994), 대분류 11종은
그 차이를 담지 못합니다. 중분류 40종·소분류 200종이 대리합니다.

공고종류도 유효합니다. 재공고는 유찰 뒤 재입찰이라 경쟁이 약하고, 실측 낙찰률이
**94.15 대 등록공고 91.16** 입니다.

### 3.3 보류

**gap 이력 9종** (기관·소분류·기관x용역구분별 gap 평균/표준편차/건수).

전체 RMSE 를 1.4% 낮춥니다. 특징 중요도에서도 `gap_clsfc_cnt` 가 5위,
`gap_instdiv_mean` 이 7위로 실제로 쓰입니다. 경쟁 강도의 대리 변수로 작동한다는
뜻입니다.

다만 **타깃 파생 특징이라 배선 비용이 다릅니다.** 추론 시점에 계산할 수 없으므로
사전 집계 테이블 + 야간 갱신 + 추론 조회가 필요합니다.
`institution_win_rate_stats` 라는 선례가 있어 불가능하지는 않으나, 이득 1.4% 에
대해 별도 판단이 필요합니다.

## 5. 결론과 다음 단계

**제한경쟁 구간은 특징 추가로 해결되지 않습니다.** 세 갈래 시도가 모두 실패했고,
원인이 관측 불가능한 참여업체 수라는 것이 gap 분포로 확인되었습니다. 이 구간은
**본질적 한계**로 확정합니다.

대신 다음이 남습니다.

| 순서 | 작업 | 근거 |
| --- | --- | --- |
| 1 | **분위수 회귀로 예측구간 제공** | 2장. gap 분포가 비대칭이라 점 추정 하나는 구조적으로 부적절합니다 |
| 2 | ~~참가자 수 수집 검토~~ | **2026-08-04 완료 후 기각.** 2.3 참조. 오라클조차 RMSE 4.9%, 이력은 0.35% |
| 3 | gap 이력 배선 판단 | 3.3. 이득 1.4% 대 집계 테이블 신설 비용 |
| 4 | ~~서빙 경로 범주형 배선~~ | **2026-08-04 완료.** `category_levels` 를 읽습니다 |

**1번이 가장 중요합니다.** 상위 5% 구간에서 6%p 이상 틀리는데 단일 숫자를 주면
사용자가 그 값을 신뢰합니다. 난수는 없앨 수 없으므로 **표현**해야 합니다.
