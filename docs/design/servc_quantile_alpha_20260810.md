# 목적함수 축 1: `quantile` alpha 스윕

> **작성일**: 2026-08-10
> **버전**: v1.1.0
> **상태**: **기각.** 홀드아웃에서 여섯 지표가 모두 개선됐으나 운영 쌍대에서 판별 불가였습니다. `alpha=0.5` 유지
> **대상**: Servc (용역) 낙찰률 예측 모델 `servc_institution_v1`
> **선행 실험**: [`servc_excess_target_20260810.md`](servc_excess_target_20260810.md)
> **측정 스크립트**: [`scripts/eval_servc_quantile_alpha.py`](../../scripts/eval_servc_quantile_alpha.py)

## 0. 한 문장

**가설의 방향이 반대였고, 방향을 고쳐도 운영에서는 읽히지 않았습니다.** 편향을
줄이려고 `alpha` 를 올렸더니 전 지표가 나빠졌고, 반대로 내리자 홀드아웃에서
여섯 지표가 모두 좋아졌지만, 운영 9,997건 쌍대에서 MAE t=-0.44 로 판별 불가
였습니다.

---

## 1. 왜 alpha 를 건드렸는가

학습은 `quantile(0.5)` 로 **조건부 중앙값**을 겨냥하는데 승격 판정은 **0.5%p
이내 적중률**로 합니다. 두 목표가 다르다는 것을 초과분 타깃 실험이 수치로
보여 주었습니다. 중앙부를 좁히자 적중률이 +0.2687%p 올랐고 꼬리가 나빠져
RMSE 가 11% 악화됐습니다.

타깃을 바꾸는 방향은 기각됐으므로, 타깃을 그대로 두고 **목적함수만** 움직이는
쪽을 봤습니다. 근거는 현행 편향이었습니다.

| 시드 | 편향 |
| ---: | ---: |
| 42 | -0.0460 |
| 7 | -0.0472 |
| 2024 | -0.0499 |

세 시드 모두 음수로 **계통적 과소예측**입니다. `alpha` 를 0.5 보다 올리면 예측
분위가 위로 올라가 이 편향이 줄어들 것으로 보았습니다.

**`huber` 의 alpha 를 줄이는 방향은 시도하지 않았습니다.** `alpha=0.2` 가 MAE
1.7971 로 32% 나빴고 원인이 gradient 평탄화라는 실측이 이미 있습니다. 두
목적함수는 연속적으로 이어지지 않습니다.

---

## 2. 판정 기준 (결과를 보기 전에 고정)

초과분 실험에서 "MAE 악화 x 적중 개선" 칸이 비어 있어 판정 로직이 부정확한
메시지를 냈습니다. 이번에는 **네 칸을 모두** 적었습니다.

| 조합 | 판정 |
| --- | --- |
| MAE 개선 x 적중 개선 | 운영 쌍대로 진행 |
| MAE 개선 x 적중 악화 | 기각. 서비스 지표가 우선 |
| MAE 악화 x 적중 개선 | 맞바꿈. 단독 승격 불가, 별도 판단 |
| MAE 악화 x 적중 악화 | 기각 |

어느 경우든 차이가 시드 표준편차 이내면 선택 편향으로 기각합니다.

## 4. 운영 쌍대 검정: 기각

홀드아웃에서 `alpha` 를 내리는 방향이 옳았으므로 challenger 를 만들어 운영
경로에서 검정했습니다. 전량 917,629행으로 학습(540초)해 `servc_alpha045` 로
서빙 루트에 올리고 `compare_servc_models_paired.py` 를 돌렸습니다.

### 4.1 표본 3,000건 (검정력 부족)

| 지표 | base | challenger | 쌍대 평균차 | t | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| MAE | 1.3181 | 1.3241 | +0.00596 | 0.84 | 판별 불가 |
| 제곱오차 | 3.8948 | 3.8523 | -0.32961 | -2.21 | challenger 우세 |
| 0.5%p 적중 | 0.6513 | 0.6553 | - | - | 쌍대 미제공 |

이 표본이 잡을 수 있는 최소 MAE 차이가 **0.01415** 인데 홀드아웃 차이는
0.0083 입니다. **애초에 잡을 수 없는 크기**라 표본을 늘렸습니다.

### 4.2 표본 10,000건 (판정)

| 지표 | base | challenger | 쌍대 평균차 | t | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| MAE | 1.4109 | 1.4092 | -0.00171 | **-0.44** | **판별 불가** |
| 제곱오차 | 4.0677 | 4.0008 | -0.53919 | -5.60 | challenger 우세 |
| **0.5%p 적중** | **0.6399** | **0.6392** | - | - | **미세 악화** |
| 구간 폭 | 1.6917 | 1.6917 | 0.00000 | 0.00 | 동일 |

challenger 가 더 정확한 공고 비율 **49.43%**. 최소 감지 차이 0.00785 에 관측
차이 0.00171 로, 표본을 3배 늘려도 크기가 4분의 1에 그칩니다.

### 4.3 판정 근거

| 기준 | 결과 |
| --- | --- |
| 주 지표 MAE | t=-0.44. **방향을 말할 수 없음** |
| 서비스 지표 적중률 | 63.99% -> 63.92%. **홀드아웃과 반대 방향** |
| 승률 | 49.43% (절반 미만) |
| RMSE | 유의하게 개선 (t=-5.60) |

**RMSE 단독으로 승격하지 않습니다.** 이 프로젝트의 판정 지표는 MAE 와 0.5%p
적중률입니다. `quantile(0.5)` 승격 때도 홀드아웃 RMSE 악화가 운영에서 t=0.25
로 나타나지 않았습니다. RMSE 는 큰 오차에 민감해, `alpha` 를 낮춰 예측을 아래로
민 결과 상향 이탈 건의 제곱오차가 줄어든 것으로 보입니다. 중앙부 정확도는
개선되지 않았습니다.

`trainer.py` 의 `alpha` 는 0.5 로 되돌렸습니다.

## 5. 발견 1: 편향은 줄이는 것이 아니라 늘리는 쪽이 옳았습니다

가설은 "편향 -0.0477 이 계통적 과소예측이니 `alpha` 를 올려 줄이자" 였습니다.
**정확히 반대였습니다.**

| alpha | 편향 | MAE | 판정 |
| ---: | ---: | ---: | --- |
| 0.58 | +0.2235 | 1.2845 | 최악 |
| 0.52 | +0.0184 | 1.2459 | 편향은 거의 0, 그러나 악화 |
| 0.50 | -0.0477 | 1.2407 | 현행 |
| 0.45 | **-0.2128** | **1.2323** | **최선** |

**편향이 4배 커지는데 모든 지표가 좋아집니다.** 편향 0 지점(alpha 약 0.515)은
오히려 현행보다 나쁩니다.

낙찰률 분포가 위쪽으로 꼬리를 끄는 비대칭이라, 실제 최적 예측점이 조건부
중앙값보다 **아래**에 있다는 뜻입니다. 평균 편향은 그 사실의 부산물일 뿐
고쳐야 할 결함이 아닙니다.

스킬에 있던 원칙이 이번에는 반대 방향으로 확인됐습니다.

> 학습 목적함수가 조건부 중앙값을 겨냥하고 분포가 비대칭이면 평균 편향은
> 있어야 정상입니다.

**편향을 목표로 삼지 마십시오.** 잔차 오프셋 보정이 다섯 축에서 기각된 것과
같은 함정이며, 이번에는 목적함수 쪽에서 같은 교훈을 얻었습니다. 부호를 보고
방향을 정한 것이 오류였습니다.

## 6. 발견 2: 세 실험의 성격이 갈립니다

| 실험 | MAE | 적중률 | 해석 |
| --- | --- | --- | --- |
| 초과분 타깃 | 악화 | 개선 | 중앙부 집중 x 꼬리 악화의 **맞바꿈** |
| alpha 상향 | 악화 | 악화 | 맞바꿈 없이 그냥 나빠짐 |
| **alpha 하향** | **개선** | **개선** | **겨냥점이 옳은 위치로 이동** |

`alpha` 는 예측의 **위치**를 옮깁니다. 위로 올리면 나빠지고 아래로 내리면
좋아졌다는 것은, 현행 `quantile(0.5)` 의 겨냥점이 최적이 아니었다는 뜻입니다.

**이는 적중률을 위한 "중앙부 집중" 과는 다른 개선입니다.** 초과분 실험이 보여
준 맞바꿈은 여전히 열려 있고, 손실의 **모양**을 바꾸는 후보(7장)는 이 결과와
독립적으로 유효합니다.

## 6.1 홀드아웃과 운영이 또 갈렸습니다

| 구간 | 표본 | MAE 차이 | 적중률 차이 |
| --- | ---: | ---: | ---: |
| 홀드아웃 | 96,141 | **-0.0083** | **+0.1647%p** |
| 운영 쌍대 | 9,997 | -0.00171 | -0.07%p |

효과가 5분의 1로 줄고 적중률은 부호가 뒤집혔습니다.

**이번에는 조기 종료 불일치가 원인이 아닙니다.** 2026-08-07 하이퍼파라미터
탐색이 뒤집힌 이유는 탐색 스크립트가 조기 종료를 걸지 않은 것이었는데, 이번
스크립트는 운영 3단계(시간순 분할 -> 조기 종료 -> 전량 재적합)를 그대로
재현합니다.

**단서는 두 경로의 절대 MAE 자체가 다르다는 것입니다.**

| 경로 | 2025년 MAE (base 기준) |
| --- | ---: |
| 홀드아웃 (parquet 특징) | 1.2407 |
| 운영 (서빙 특징) | 1.4109 |

같은 해, 같은 모델인데 0.17 차이가 납니다. 표본 크기 차이로는 설명되지 않는
크기입니다. 특징 생성 경로가 다릅니다.

    학습    attach_institution_history 가 누수 없이 계산한 inst_hist_rate
    서빙    InstitutionWinRateStat 사전 집계 표를 조회

이 두 값이 어긋나 있다면, 홀드아웃에서 얻은 미세한 개선이 운영으로 옮겨지지
않는 **구조적 이유**가 됩니다. 2026-08-05 에 `inst_sample_cnt` 가 서빙에서 항상
0 이던 결함을 고쳐 운영 MAE 를 6.1% 낮춘 전례가 있습니다
(`servc_feature_parity_20260805.md`). 같은 종류의 괴리가 남아 있는지 확인할
가치가 있습니다.

**이것은 alpha 축을 넘어서는 문제입니다.** 학습·서빙 특징 값 대조를 다시 하면
목적함수를 아무리 다듬어도 옮겨지지 않던 이득의 원인이 드러날 수 있습니다.
다음 세션의 1순위 후보로 남깁니다.

## 7. 다음 후보: 적중 경계를 겨냥하는 커스텀 objective

`quantile` 과 `huber` 는 모두 오차 크기에 단조로운 손실입니다. 적중률은 그렇지
않습니다. ±0.5%p 안이면 만점, 밖이면 거리와 무관하게 0 점인 계단 함수입니다.

이 간극을 좁히는 방향은 경계 밖 오차의 기울기를 낮추고 경계 안쪽을 더 강하게
당기는 손실입니다. LightGBM 에 gradient 와 hessian 을 직접 넘기면 구현할 수
있습니다.

**착수 전에 확인해야 할 위험이 둘 있습니다.**

| 위험 | 내용 |
| --- | --- |
| gradient 평탄화 | `huber alpha=0.2` 가 32% 나빴던 것과 같은 함정입니다. 경계 밖 기울기를 0 에 가깝게 두면 학습 신호가 사라집니다 |
| 조기 종료 지표 | 커스텀 objective 는 검증 지표도 함께 정해야 합니다. 탐색과 운영의 조기 종료가 어긋나면 결과가 옮겨지지 않습니다 |

두 번째는 2026-08-07 하이퍼파라미터 탐색이 통째로 기각된 원인이므로 특히
주의해야 합니다.
