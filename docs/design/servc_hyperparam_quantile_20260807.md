# 용역 모델 하이퍼파라미터 재탐색 (quantile 목적함수)

> **작성일**: 2026-08-07
> **버전**: v2.0.0
> **상태**: **기각.** 홀드아웃 우세가 운영 쌍대에서 부호까지 뒤집혔습니다 (8장)
> **대상**: Servc (용역) 낙찰률 예측 모델 `servc_institution_v1`
> **분할**: 학습 2024년까지 765,150행 / 검증 2025년 96,141행
> **스크립트**: [`scripts/tune_servc_hyperparams.py`](../../scripts/tune_servc_hyperparams.py)
> **선행**: [`servc_loss_function_20260807.md`](servc_loss_function_20260807.md) (quantile 승격)

---

## 1. 왜 다시 탐색하는가

[`servc_hyperparam_search_20260804.md`](servc_hyperparam_search_20260804.md) 의
좌표 하강 17회는 **전부 `objective="huber", alpha=1.0` 아래에서** 돌았습니다.
같은 날 채택된 `num_leaves=255` 도 huber 기준으로 고른 값입니다.

2026-08-07 에 점 추정 목적함수를 `quantile(0.5)` 로 승격했으므로, 그 아래에서
최적 용량이 이동했는지는 **미측정 상태**가 됐습니다. 손실 지형이 바뀌면 최적
용량도 함께 움직이는 것이 일반적인 예상입니다.

---

## 2. 설계

| 항목 | 설정 |
| --- | --- |
| 목적함수 | `quantile(alpha=0.5)` — `CATEGORY_HYPERPARAMS` 에서 읽음 |
| 시작점 | **용역 운영 설정** (`num_leaves=255`) |
| 방법 | 좌표 하강 1회차, 8개 축 |
| 선택 기준 | MAE. 0.5%p 적중을 함께 출력해 기준 간 어긋남을 감시 |
| 판정 | 개선폭이 **시드 산포보다 큰가** (4장) |

### 2.1 시작점을 운영값으로 맞췄습니다

종전 스크립트는 `LGB_BASE_PARAMS` 에서 출발했습니다. 그 값은 `num_leaves=63`
이고 용역 운영값은 255 입니다. 좌표 하강은 시작점에 민감하므로, 기본값에서
출발하면 **운영이 실제로 선 지점이 기준선이 되지 못합니다.** 탐색이 내놓는
"개선" 이 운영 대비 개선인지 알 수 없게 됩니다.

`tune_servc_hyperparams.py` 가 시작점과 목적함수를 모두
`CATEGORY_HYPERPARAMS["Servc"]["lightgbm"]` 에서 읽도록 고쳤습니다. 값을
베끼지 않으므로 앞으로 운영 설정이 바뀌면 탐색도 자동으로 따라갑니다.

## 4. 용량 최적점은 이동하지 않았습니다

이 탐색의 출발 가설은 "목적함수가 바뀌면 최적 용량도 이동한다" 였습니다.
**반증됐습니다.**

| `num_leaves` | huber 아래 MAE | quantile 아래 MAE |
| ---: | ---: | ---: |
| 31 | — | 1.2960 |
| 63 | 1.2829 | 1.2780 |
| 127 | 1.2702 | 1.2609 |
| **255** | **1.2652** | **1.2554** |
| 511 | 미측정 | 1.2560 |

두 목적함수 아래에서 **순서가 같고 255 에서 최소**입니다. quantile 이 모든
용량에서 huber 보다 낮은 MAE 를 내지만, 그 이득은 용량과 무관하게 거의
일정합니다. 511 은 255 보다 나쁘고 0.5%p 적중은 61.49% 로 더 떨어집니다.

**2.2 절의 근거가 여기서 나옵니다.** 이 문제의 신호는 범주 조합에 실려 있고
(`servc_hyperparam_search_20260804.md` 2.2), 그 조합을 가르는 데 필요한 용량은
손실함수가 아니라 데이터 구조가 정합니다. 목적함수는 같은 분할 위에서 잔차를
어떻게 벌할지만 바꿉니다.

## 5. 남은 개선폭의 성격

두 가지가 걸립니다.

**첫째, 개선폭이 지난 탐색의 1/5 입니다.** huber 아래 첫 탐색은 0.0177 을 냈고
이번은 0.0035 입니다. 축 하나하나의 기여도 0.0004~0.0025 로, 지난 탐색에서
`num_leaves` 하나가 낸 0.0177 과 자릿수가 다릅니다.

**둘째, 두 판정 기준이 어긋났습니다.** MAE 로 고른 `n_estimators=2000` 은
0.5%p 적중이 61.95% 로 1200 의 62.01% 보다 낮습니다. 탐색 스크립트가 적중률을
함께 출력하는 이유가 이 경우이며, 지난 문서 1.1 절의 R2 함정과 같은 계열입니다.

`subsample_freq=5` 는 huber 아래에서 **이미 기각된 값**입니다 (MAE -0.0001,
학습 시간 +21%). 여기서도 이득은 0.0004 이고 학습 시간은 늘어납니다.

### 5.1 그래서 시드 산포를 먼저 쟀습니다

좌표 하강은 축마다 **가장 좋은 값을 고르는** 절차입니다. 실제 이득이 0 이어도
축을 훑는 것만으로 무작위 변동의 상단이 누적되어 홀드아웃 MAE 는 조금
내려갑니다. 축 8개면 그 누적이 작지 않습니다.

따라서 개선폭은 **같은 설정을 시드만 바꿔 돌렸을 때의 산포와 비교해야**
의미가 있습니다. 측정: [`scripts/measure_servc_tuning_noise.py`](../../scripts/measure_servc_tuning_noise.py)

판정 기준은 결과를 보기 전에 고정했습니다.

| 조건 | 판정 |
| --- | --- |
| 차이가 시드 표준편차 이내 | 선택 편향. 기각 |
| 그보다 크되 시드마다 부호가 갈림 | 기각 |
| 그보다 크고 전 시드에서 일관 | 실체 있음 |

### 5.2 결과: 실체가 있습니다

시드 3개(42, 1, 7)로 두 설정을 각각 학습했습니다.

| 시드 | 기준선 MAE | 후보 MAE | 쌍대 차이 |
| ---: | ---: | ---: | ---: |
| 42 | 1.2554 | 1.2519 | -0.0035 |
| 1 | 1.2562 | 1.2525 | -0.0037 |
| 7 | 1.2570 | 1.2532 | -0.0038 |
| **평균** | **1.2562** | **1.2525** | **-0.0037** |

| 지표 | 차이 | 시드 표준편차 | 배수 |
| --- | ---: | ---: | ---: |
| MAE | -0.0037 | 0.0008 | 4.6 |
| 0.5%p 적중 | +0.20%p | 0.10%p | 2.0 |

**3시드에서 부호뿐 아니라 크기까지 일치합니다**(-0.0035 / -0.0037 / -0.0038).
시드 42 에 맞춰진 선택이었다면 다른 시드에서 이득이 줄거나 사라져야 하는데
그렇지 않습니다. 좌표 하강의 선택 편향으로는 설명되지 않습니다.

기준선의 시드 간 폭이 0.0016 이라는 점도 함께 봐야 합니다. **단일 시드 홀드아웃
비교에서 0.001 단위 차이는 읽을 수 없습니다.** 이번 개선폭 0.0037 은 그 경계
바로 위입니다.

## 6. 홀드아웃 판정

> 이 장은 **홀드아웃 단계**의 판정입니다. 최종 판정은 8장이며 **기각**입니다.

**홀드아웃에서는 실체가 있습니다. 승격은 하지 않았습니다.**

| 기준 | 결과 |
| --- | --- |
| 홀드아웃 개선 | MAE 1.2562 -> 1.2525 (0.29%), 0.5%p 적중 +0.20%p |
| 시드 산포 초과 | 예. 4.6배이고 3시드 전부 일관 |
| 용량 최적점 이동 | **없음.** 255 가 두 목적함수에서 모두 최적 (4장) |
| 운영 경로 쌍대 검정 | **미실시** |

### 6.1 왜 여기서 멈추는가

이 축에서 홀드아웃 이득이 운영으로 옮겨지지 않은 전례가 **두 번**입니다.

| 시도 | 홀드아웃 MAE | 운영 결과 |
| --- | --- | --- |
| `num_leaves` 255 (2026-08-04) | 1.2829 -> 1.2652 (0.0177) | 판별 불가, 구간 폭 11.2% 악화로 롤백 |
| `num_leaves` 127 (2026-08-05) | 1.2838 -> 1.2710 (0.0128) | 쌍대 t=2.13 으로 악화 |

**두 번 모두 이번(0.0037)보다 3배 이상 큰 홀드아웃 이득이었고 운영에서
살아남지 못했습니다.** 이번 이득이 더 작으므로 운영 검정을 건너뛸 근거는
오히려 약합니다.

### 6.2 조기 종료 경로가 다릅니다

운영 학습기 `_train_lightgbm` 은 `early_stopping(10)` 을 걸지만 탐색
스크립트는 걸지 않고 `n_estimators` 를 전량 씁니다. 따라서 운영에서
`n_estimators=2000` 은 **상한으로만** 작동하고 실제 트리 수는
`learning_rate=0.03` 아래에서 조기 종료가 정합니다.

조합이 유효한 이유는 학습률을 낮추면 조기 종료가 늦게 걸려 트리를 더 쓰기
때문이지, 2000 그루를 쓰기 때문이 아닙니다. **탐색이 낸 0.0037 이 운영 학습
경로에서 그대로 재현된다고 보면 안 됩니다.** 재학습 지표로 확인해야 합니다.

### 6.3 `subsample_freq=5` 에 대한 유보

이 축의 기여는 0.0004 로 **시드 표준편차 0.0008 의 절반**입니다. huber 아래
탐색에서 이미 기각된 값이기도 합니다(MAE -0.0001, 학습 시간 +21%).

지금 임의로 빼지 않은 이유는 좌표 하강 결과가 **조합으로 측정된 값**이기
때문입니다. 한 축만 제거하면 측정된 적 없는 설정이 됩니다. 운영 쌍대 검정에서
조합이 우세하면 이 축만 빼고 재확인하는 것이 다음 순서입니다.

### 8.1 원인은 조기 종료입니다

6.2 절에서 유보로 적어 둔 것이 그대로 실현됐습니다.

| 경로 | 조기 종료 | `n_estimators=2000` 의 의미 |
| --- | --- | --- |
| 탐색 스크립트 | 없음 | 2000 그루 전량 사용 |
| 운영 `_train_lightgbm` | `early_stopping(10)` | 상한. 실제 트리 수는 조기 종료가 결정 |

조합의 핵심은 `learning_rate` 를 0.05 에서 0.03 으로 낮춘 것인데, 낮춘 학습률은
**더 많은 트리로 보상해야** 같은 지점에 도달합니다. 탐색에서는 2000 그루가 그
보상을 해 줬고 운영에서는 조기 종료가 그 전에 잘랐습니다. 결과적으로 운영
모델은 **덜 학습된 모델**이 됐습니다.

재학습 지표(7장)에서 이미 조짐이 보였습니다. MAPE 개선이 0.09% 로 홀드아웃
예상치보다 훨씬 작았습니다.

### 8.2 시드 검정이 막지 못한 것

5.2 절의 시드 재현성 검정은 **좌표 하강의 선택 편향**을 걸러내도록 설계했고 그
역할은 했습니다. 홀드아웃 이득 자체는 진짜였습니다.

그러나 그 검정은 **탐색 경로 안에서만** 이뤄집니다. 탐색 경로와 학습 경로가
다르면 아무리 재현성이 높아도 옮겨지지 않습니다. 이번이 그 경우입니다.

**교훈: 탐색 스크립트와 운영 학습기의 차이를 목적함수만 맞추는 것으로 끝내면
안 됩니다.** 조기 종료, 검증 분할, 재적합 방식이 모두 결과를 가릅니다. 특히
`learning_rate` 와 `n_estimators` 처럼 **서로를 보상하는 축**은 조기 종료 유무에
따라 최적 조합이 완전히 달라집니다.

## 10. 탐색 경로를 운영에 맞췄습니다

기각으로 끝내지 않고 원인을 제거했습니다. `tune_servc_hyperparams.py` 의
`evaluate` 가 운영 `train_and_register` 의 3단계를 그대로 따릅니다.

| 단계 | 내용 |
| --- | --- |
| 1 | 학습 구간을 `openg_dt` 시간순 80/20 으로 가르고 앞 80%로 학습 |
| 2 | 뒤 20%를 `eval_set` 으로 `early_stopping(10)` 을 걸어 트리 수 결정 |
| 3 | 그 트리 수로 학습 구간 전량 재적합 (`_refit_on_full` 대응) |

**검증 연도를 `eval_set` 으로 쓰지 않았습니다.** 그렇게 하면 트리 수를 검증
연도로 정하고 같은 연도에서 점수를 내게 되어 누수입니다. 분할은 학습 구간
안에서만 일어납니다.

### 10.1 실측

`reg_lambda` 축만 제한해 동작을 확인했습니다.

| 항목 | 종전 경로 | 조기 종료 경로 |
| --- | ---: | ---: |
| 기준선 MAE | 1.2554 | 1.2557 |
| 기준선 학습 시간 | 39.5초 | 49.4초 |
| `reg_lambda` 1.0 / 10.0 | 개선 없음 | 개선 없음 |

**학습이 2회로 늘어도 시행 시간은 두 배가 되지 않습니다.** 25% 증가에
그칩니다. 조기 종료가 첫 학습을 일찍 끊어 재적합 비용을 상당 부분 상쇄하기
때문이며, `n_estimators` 를 크게 잡은 설정에서는 오히려 종전보다 빨라질 수
있습니다.

기준선 MAE 가 1.2554 에서 1.2557 로 거의 같은 것은 현행 설정
(`learning_rate=0.05`, `n_estimators=600`)에서 조기 종료가 상한 근처에서
걸리기 때문입니다. **경로 차이가 드러나는 것은 `learning_rate` 를 낮춰
`n_estimators` 로 보상하려 할 때입니다.** 기각된 조합이 정확히 그 경우였습니다.

**이 변경 이전의 탐색 결과는 운영과 비교할 수 없습니다.** 3장 표의 절대값도
새 경로에서는 달라집니다. 순위만 참고하십시오.
