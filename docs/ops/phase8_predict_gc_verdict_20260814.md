## 2. 메모리 안전성

`freeze` 채택 전 필수 조건이었습니다. 10분 지속 부하(c10 연속) 중 `app`
컨테이너 메모리를 15초 간격으로 38회 샘플링했습니다.

| 모드 | 시작 | 종료 | 최대 | 변화 |
| --- | ---: | ---: | ---: | ---: |
| 기본 | 548.5 MiB | 545.9 MiB | 556.6 MiB | -2.6 MiB (-0.5%) |
| `freeze` | 446.0 MiB | 454.2 MiB | 454.8 MiB | +8.2 MiB (+1.8%) |

`freeze` 의 +8.2 MiB 는 **첫 15초 구간에서 전부 발생하고(446 -> 454) 이후 9분
이상 454 MiB 에 평평합니다.** 정상 작업 집합이며 누증 신호가 아닙니다.

**두 모드의 절대 메모리 차이(약 92 MiB)를 `freeze` 의 효과로 읽지 마십시오.**
모드별 1회 측정이므로 컨테이너 기동 간 변동(lazy 로딩 순서 등)과 구분되지
않습니다. 이 측정이 답하는 것은 **"누증하는가"** 하나뿐이고, 답은 두 모드 모두
아니오입니다.

## 3. 후보별 판정

### 3.1 `freeze` — 채택

| 항목 | 근거 |
| --- | --- |
| P99 최악값 | 108.55 -> **59.32ms**. 49.23ms 개선 |
| 100ms 초과 | 21건 -> **0건** (1,800 요청 중) |
| 최댓값 | 114.0 -> 67.9ms |
| P50 대가 | 없음 (39.47 -> 38.96ms) |
| 메모리 | 10분 지속 부하에서 평평 |
| 되돌리기 | 환경변수 하나. 즉시 가능 |

전 동시성 합계로는 **7,200 요청에서 초과 0건**이며 Wilson 95% 상한 0.053%
입니다(c1/c2/c4 각 1,800 + c10 1,800).

`gc.freeze()` 는 모델 가중치를 영구 세대로 옮겨 generation-2 순회 대상에서
제외합니다. **회수 자체를 끄지 않으므로** 새로 생기는 순환 참조는 계속
회수됩니다. 지연 개선과 메모리 안전이 동시에 성립하는 이유입니다.

### 3.2 `threshold` — 보류

초과 0건으로 기본보다 낫습니다. 그러나 P99 최악 91.63ms 로 기준까지 여유가
8.4ms 뿐이며, `freeze` 의 40.7ms 와 비교하면 회귀에 취약합니다. `freeze` 를
채택하므로 함께 쓸 이유가 없습니다. 두 모드는 배타적입니다.

### 3.3 `batch-disable` — 기각

**기본보다 나쁩니다.**

| 지표 | 기본 | `batch-disable` |
| --- | ---: | ---: |
| 100ms 초과 | 21건 (1.167%) | **30건 (1.667%)** |
| 최악 P99 | 108.55ms | **110.37ms** |
| 최댓값 | 114.0ms | **123.1ms** |

P50 은 가장 낮은데(37.2ms) 꼬리는 악화됐습니다. `gc.disable()` 후 50배치마다
몰아서 `gc.collect()` 하므로 **회수를 미룬 만큼 그 순간의 정지가 커집니다.**
후보 설계 문서가 이 모드를 "세 후보 중 위험이 가장 큰 것" 으로 적었고 실측이
그것을 확인했습니다.

`gc.disable()` 이 프로세스 전역이라는 점도 함께 기각 사유입니다. 코드는
남기되 **운영에 쓰지 마십시오.**

## 3.4 저동시성 회귀 확인 (c1/c2/c4)

각 모드 3회차, 회차당 600 요청입니다. 대표값은 규약 3장에 따라 최악값입니다.
집단마다 시작 시 컨테이너의 `PREDICTION_GC_MODE` 실제 값을 읽어 기대와 다르면
측정을 중단했습니다(5장 참조).

| 동시성 | 모드 | 최악 P50 | 최악 P95 | 최악 P99 | 최악 Max |
| ---: | --- | ---: | ---: | ---: | ---: |
| c1 | off | 12.28 | 15.42 | 16.71 | **73.48** |
| c1 | `freeze` | 12.37 | 15.47 | 17.56 | **20.85** |
| c2 | off | 17.07 | 19.60 | 24.50 | **67.77** |
| c2 | `freeze` | 17.17 | 19.79 | 25.32 | **30.39** |
| c4 | off | 28.32 | 32.66 | **75.32** | **92.96** |
| c4 | `freeze` | 28.29 | 33.46 | **39.45** | **42.76** |

| 동시성 | P50 차 | P95 차 | P95 허용상한 | 판정 | P99 차 | Max 차 |
| ---: | ---: | ---: | ---: | --- | ---: | ---: |
| c1 | +0.09 | +0.05 | 16.96 | 통과 | +0.85 | **-52.64** |
| c2 | +0.10 | +0.19 | 21.56 | 통과 | +0.82 | **-37.38** |
| c4 | -0.03 | +0.80 | 35.92 | 통과 | **-35.87** | **-50.20** |

**규약 4장의 회귀 금지 조건을 세 수준 모두 만족합니다.** P50 과 P95 는 사실상

P99 도 35.87ms 내려갑니다.

즉 `freeze` 는 저동시성에서도 중앙값 대가 없이 꼬리만 잘라냅니다. c10 결과와
같은 성격입니다.

## 5. 측정 과정에서 발견한 결함 4건

후보 구현 자체와 별개로, 도구가 동작하지 않는 상태였습니다. 넷 다 **오류 없이
그럴듯한 결과를 내는** 형태였고, 네 번째는 코디네이터가 만든 것입니다.

| 결함 | 증상 | 조치 |
| --- | --- | --- |
| `PREDICTION_GC_MODE` 가 컨테이너에 전달되지 않음 | `docker-compose.yml` 의 `environment:` 는 변수를 명시 열거합니다. 셸 환경변수가 상속되지 않아 **Docker 배포에서 기능 자체를 쓸 수 없었습니다** | `app` 서비스에 `PREDICTION_GC_MODE=${PREDICTION_GC_MODE:-}` 추가 |
| `measure_predict_rss.py` 가 RSS 를 기록하지 못함 | 없는 `/debug/pid` 엔드포인트로 PID 를 찾아 항상 `None`. 컨테이너 서버는 호스트 `ps` 로도 안 보입니다. **지연만 있고 메모리는 빈 보고서**가 나옵니다 | PID 미발견 시 경고와 대체 명령 출력 |
| 같은 스크립트의 엔드포인트·payload 계약 불일치 | `/api/v1/predictions/` (404), `presmpt_prce`/`category` (422). **전부 실패해도 지연이 기록되어 정상으로 보입니다** | 경로를 `/predict` 로, payload 를 `PredictionRequest` 계약으로 정정. 실패 건수 집계 추가 |

### 5.1 코디네이터가 만든 네 번째 결함

채택 커밋에서 compose 기본값을 `${PREDICTION_GC_MODE:-freeze}` 로 썼습니다.
**`:-` 는 빈 문자열도 미설정으로 보아 `freeze` 로 되돌립니다.** 즉 이 문서가
"되돌리려면 빈 문자열로 두십시오" 라고 적은 방법이 작동하지 않았고, 그 상태로
저동시성 대조를 돌려 **off 집단과 freeze 집단이 모두 freeze 였습니다.** 18회
측정이 무효였습니다.

| 표기 | 빈 문자열 전달 시 |
| --- | --- |
| `${VAR:-freeze}` | `freeze` (끌 수 없습니다) |
| `${VAR-freeze}` | 빈 문자열 (의도한 동작) |

조치 둘입니다.

1. compose 를 `${PREDICTION_GC_MODE-freeze}` 로 고쳐 양방향을 확인했습니다
2. 측정 스크립트가 집단 시작 시 `docker compose exec app printenv` 로 **실제
   전달된 값을 읽어 기대와 다르면 중단**합니다

무효 측정치 21개 파일은 삭제했습니다. 남기면 다음 사람이 off 로 믿고 씁니다.

무효였던 그 측정에서 하나는 건졌습니다. 두 집단이 같은 코드였으므로 그것은
`freeze` 대 `freeze` 변동폭이며, 앞서 1회차 비교에서 c2 회귀로 보였던
23.85ms 가 같은 코드 6회차 범위(19.68~20.42ms) 밖의 단일 이상치였음을
보여줍니다. **1회차 비교로 회귀를 선언하면 안 된다는 규약 3장의 실증입니다.**
