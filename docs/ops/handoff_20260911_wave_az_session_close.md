## 4. 코디네이터가 겪은 것

### 4.1 계측이 컨테이너에서 통째로 유실됐습니다

AZ1 계측을 켜고 측정하니 **12회차 전부 `no_candidate`** 였습니다. 원인은
`_enable_latency_segment_logging` 이 **`src.rag.engine` 하나만** 보강한 것입니다.
새 계측이 쓰는 `src.app.services.dashboard` 로거의 `info` 가 컨테이너 런타임의
WARNING 루트에서 전부 버려졌습니다.

**단위 테스트도 독립 리뷰도 이것을 잡지 못했습니다.** 테스트는 pytest 로그
캡처를 쓰므로 컨테이너 로거 설정과 무관하게 통과합니다. **계측을 새로 붙이면
반드시 실제 런타임에서 로그 한 줄이 나오는지 먼저 확인하십시오.**

보강 대상을 `SEGMENT_LOGGER_NAMES` 상수로 묶었고 회귀 테스트를 넣었습니다.

### 4.2 `docker compose up -d app` 은 프로세스를 다시 띄우지 않습니다

설정이 바뀌지 않으면 컨테이너를 재생성하지 않습니다. 소스가 바인드 마운트라
파일은 최신인데 **실행 중인 프로세스의 lifespan 은 옛 코드로 이미 끝나 있습니다.**
4.1 을 고친 뒤에도 로그가 안 나와 한참 헤맸습니다. 기동 시 1회 실행되는 코드를
고쳤으면 **`docker compose restart app`** 을 쓰십시오.

### 4.3 게이트를 동시에 돌려 오탐을 냈습니다

Level 1 게이트 2건을 병렬로 띄웠더니 양쪽 모두 전량 테스트에서 1건씩 실패했습니다.
단독 재실행에서는 둘 다 통과했습니다. 스킬 4.3 은 검증 병렬을 권하지만 **이
저장소의 전량 테스트는 DB 와 Redis 를 공유합니다.** 리뷰어가 활동 중일 때 돌린
게이트도 같은 이유로 실패했습니다.

**전량 테스트를 포함한 게이트는 직렬로, 다른 활동이 없을 때 돌리십시오.**

로그가 없을 때 하네스는 조용히 채우거나 버리지 않고 12회차 전부를
