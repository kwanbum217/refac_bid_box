## 1. 감시는 지시가 아니라 상시 의무입니다

Dispatch 한 순간부터 그 워커는 감시 대상입니다. 사용자가 진행을 물었을 때
비로소 확인하는 것은 감시가 아니라 보고입니다. 사용자가 차단을 먼저 발견하면
코디네이터 실패로 간주합니다.

코디네이터는 셸 스크립트로 감시 루프(`while true; do ... sleep ...; done`)를
직접 작성하지 말고, `scripts/orca_worker_watch.py` 의 **상시 감시 모드(`--watch`)** 를
사용합니다.

---

## 2. 감시 도구 및 실행 모드

`scripts/orca_worker_watch.py` 는 1회성 점검과 상시 감시 모드를 모두 지원합니다.

### 2.1 사용법

| 명령 | 목적 | 설명 |
| --- | --- | --- |
| `python3 scripts/orca_worker_watch.py` | 1회 점검 | 현재 워커 상태를 1회 점검하고 즉시 종료 |
| `python3 scripts/orca_worker_watch.py --watch` | 상시 감시 | 기본 주기(10초)로 감시를 지속 수행 |
| `python3 scripts/orca_worker_watch.py --watch --interval 15 --max-iterations 20` | 주기·횟수 지정 | 15초 간격으로 최대 20회 반복 점검 |
| `python3 scripts/orca_worker_watch.py --watch --min-commits 1` | 완료 대기 | 모든 워커가 1커밋 이상 달성하면 정상 종료 (0) |
| `python3 scripts/orca_worker_watch.py --watch --stall-threshold 180` | 정체 임계치 조정 | 180초 동안 변화 없으면 정체 후보로 표시 |
| `python3 scripts/orca_worker_watch.py --json` | 기계 판독 | JSON 형식으로 상태 및 관측 이력 출력 |

### 2.2 종료 코드 계약

| 종료 코드 | 의미 | 설명 및 조치 |
| :---: | --- | --- |
| **0** | 정상 / 완료 | 모든 워커 정상 진행 중, 목표 커밋 수(`--min-commits`) 도달, 또는 최대 반복 완료 |
| **1** | 차단 신호 감지 | 신뢰창, 설문, 인증 정체, 실패 정체 등 사람 개입이 필요한 차단 발생 (즉시 중단) |
| **2** | 도구 오류 | Git 또는 Orca CLI 실행 실패 등 예외 발생 |

### 2.3 로그 절제 (Quiet Diff Output)

상시 감시 모드는 배경 로그가 불필요하게 불어나는 것을 방지하기 위해 **직전 주기 대비 상태 변화가 없는 경우 출력을 생략**합니다. 워커의 커밋/미커밋 수, 차단 여부, 정체 후보 전환 등 상태가 변경된 워커만 출력합니다.

## 3. 판정과 조치: 차단 vs 정체 후보

감시 도구는 사람 개입이 필요한 **확정 차단**과 시간 경과 관찰인 **정체 후보**를 명확히 구분합니다.

| 관측 | 표시 | 분류 | 판정 및 조치 | 종료 코드 |
| --- | --- | --- | --- | :---: |
| 터미널에 차단 신호 감지 | `[차단:승인 대기]` 또는 `[차단:실패 정체]` | 확정 차단 | 사람 개입 필요. 다음 Task 를 Dispatch 하지 않고 즉시 해당 터미널을 읽어 해제 | **1** |
| 커밋/미커밋 변화 없음이 임계 시간(기본 300초) 초과 | `[정체후보]` | 정체 관찰 | 확인 필요. 터미널을 읽어 정상 조사/빌드 중인지 확인 (차단으로 단정하지 않음) | **0** |
| 커밋 0 · 미커밋 0 (임계 시간 이내) | `[진행]` (참고 노트) | 조사 단계 | 초기 조사 단계일 수 있으므로 정상 진행 | **0** |
| 커밋 수 증가 또는 미커밋 변경 발생 | `[진행]` | 정상 진행 | 조치 없음 | **0** |
| `worker_done` 수신, 커밋 0 | - | 완료 아님 | 완료 처리 금지, 원인 확인 후 재작업 Task | - |

> **주의**: 정체 후보(`[정체후보]`)는 차단 신호가 아니므로 **종료 코드 1을 반환하지 않습니다.** 코디네이터는 정체 후보를 발견하면 터미널을 직접 읽어 실제 정체 여부를 판단합니다.

## 4. 감시 주기

| 시점 | 필수 조치 |
| --- | --- |
| Dispatch 직후 | `orca terminal read` 로 도달 확인 1회 + `orca_worker_watch.py` 1회 |
| 작업 진행 중 | `--watch` 상시 감시 모드 배경 실행 (또는 최대 3분 간격 1회 점검) |
| 사용자에게 진행·완료·차단을 보고하기 전 | 반드시 1회 확인 |
| `worker_done` 수신 후 | 커밋 수 및 산출물 확인 1회 |

3분을 넘겨 감시가 비면 그 구간은 감시하지 않은 것으로 기록합니다. 코디네이터가
자기 작업(측정, 편집, 병합)을 하는 동안에도 이 주기는 면제되지 않습니다.

## 5. 차단 유형별 해제

| 유형 | 화면 신호 | 해제 |
| --- | --- | --- |
| 권한 요청 | `Do you want to proceed?` 와 선택지 | 명령을 읽고 범위 내이면 `2`(대화 내 상시 허용), 범위를 벗어나면 `4` 후 Capsule 재검토 |
| 파일 편집 승인 | 첫 편집에서 멈춤 | 기동 직후 `terminal send --text $'\x1b[Z'` 로 예방 |
| 신뢰 대화창 | 폴더 신뢰 확인 | `orca_prepare_worktree.py` 로 예방, 발생 시 승인 |
| 인증 정체 | `not signed in`, 티어 오류 | Gemini 계열은 `agy` 로만 기동. CLI 교체 |
| CLI 설문 | 만족도 질문 | 건너뛰기 입력 (`terminal send --text '0'`) |

권한 요청을 승인할 때는 **명령이 Capsule 의 허용 범위 안인지 먼저 읽습니다.**
승인 자체가 범위 확대 권한이 되어서는 안 됩니다.

### 5.1 권한 요청 자동 승인 연계

권한 프롬프트 해제는 `scripts/orca_auto_approve.py` 를 병행하여 자동화할 수 있습니다.

```bash
python3 scripts/orca_auto_approve.py <터미널 핸들> [<터미널 핸들> ...]
```

---

## 6. 감시는 터미널 폴링이 아닙니다

기본 수단은 `python3 scripts/orca_worker_watch.py` 입니다. `orca terminal read`
는 도달 확인, 차단 해제, 정체 판정 세 경우에만 씁니다. 터미널 출력은 정보량
대비 비용이 가장 높으므로 상태 확인 목적으로 반복해 읽지 않습니다.
