> **관련 문서**: [`agent_worker_launch_reference.md`](agent_worker_launch_reference.md), [`.agents/skills/orca-section-coordination/SKILL.md`](../../.agents/skills/orca-section-coordination/SKILL.md)

## 1. 감시는 지시가 아니라 상시 의무입니다

Dispatch 한 순간부터 그 워커는 감시 대상입니다. 사용자가 진행을 물었을 때
비로소 확인하는 것은 감시가 아니라 보고입니다. 사용자가 차단을 먼저 발견하면
코디네이터 실패로 간주합니다.

---

## 2. 감시 주기

| 시점 | 필수 조치 |
| --- | --- |
| Dispatch 직후 | `orca terminal read` 로 도달 확인 1회 + `orca_worker_watch.py` 1회 |
| 그 이후 | **최대 3분 간격**으로 `orca_worker_watch.py` 1회 |
| 사용자에게 진행·완료·차단을 보고하기 전 | 반드시 1회 |
| `worker_done` 수신 후 | 커밋 수 확인 1회 |

3분을 넘겨 감시가 비면 그 구간은 감시하지 않은 것으로 기록합니다. 코디네이터가
자기 작업(측정, 편집, 병합)을 하는 동안에도 이 주기는 면제되지 않습니다.

---

## 3. 판정과 조치

| 관측 | 판정 | 조치 |
| --- | --- | --- |
| 종료 코드 1 또는 `[차단]` 행 | 차단 | 다음 Task 를 Dispatch 하지 않고 즉시 해당 터미널을 읽어 해제 |
| 커밋 0 · 미커밋 0 이 5분 이상 | 정체 의심 | 터미널을 직접 읽어 조사 단계인지 확인 |
| 커밋 0 · 미커밋 증가 | 정상 진행 | 조치 없음 |
| `worker_done` 수신, 커밋 0 | 완료 아님 | 완료 처리 금지, 원인 확인 후 재작업 Task |

---

## 4. 차단 유형별 해제

| 유형 | 화면 신호 | 해제 |
| --- | --- | --- |
| 권한 요청 | `Do you want to proceed?` 와 선택지 | 명령을 읽고 범위 내이면 `2`(대화 내 상시 허용), 범위를 벗어나면 `4` 후 Capsule 재검토 |
| 파일 편집 승인 | 첫 편집에서 멈춤 | 기동 직후 `terminal send --text $'\x1b[Z'` 로 예방 |
| 신뢰 대화창 | 폴더 신뢰 확인 | `orca_prepare_worktree.py` 로 예방, 발생 시 승인 |
| 인증 정체 | `not signed in`, 티어 오류 | Gemini 계열은 `agy` 로만 기동. CLI 교체 |
| CLI 설문 | 만족도 질문 | 건너뛰기 입력 |

권한 요청을 승인할 때는 **명령이 Capsule 의 허용 범위 안인지 먼저 읽습니다.**
승인 자체가 범위 확대 권한이 되어서는 안 됩니다.

### 4.1 권한 요청은 탐지만 해서는 안 됩니다

**탐지와 해제를 분리하면 감시가 병목이 됩니다.** 2026-08-27 세션에서
`orca_worker_watch.py` 는 차단을 매번 정확히 잡아냈으나 해제가 코디네이터의
수동 입력에 묶여 있었습니다. 코디네이터가 장시간 명령을 전경에서 돌리는 동안
워커가 5분 넘게 서 있었고, 사용자가 세 번 먼저 발견했습니다.

해제까지 자동화하십시오.

```bash
python3 scripts/orca_auto_approve.py <터미널 핸들> [<터미널 핸들> ...]
```

8초 주기로 각 터미널을 읽어 권한 프롬프트를 찾고, **안전 명령 접두사에
한해서만** 자동 승인합니다. 위험 패턴(`rm -rf`, `git push`,
`DROP`/`DELETE`/`UPDATE`/`INSERT`, `docker compose down|restart|up`,
`chmod 777`, 외부 쓰기 요청)과 안전 목록 밖 명령은 승인하지 않고 `[보류]` 로
출력해 코디네이터 판단으로 넘깁니다. 자동 승인은 범위 확대가 아니며 Capsule 의
`allowed_write_files` 는 그대로 강제됩니다.

**발생 자체를 줄이는 예방책도 함께 씁니다.**

| 조치 | 효과 |
| --- | --- |
| Antigravity `~/.gemini/antigravity-cli/settings.json` 의 `permissions.allow` 에 `command(python3)`, `command(uv run)`, `command(git)` 등 접두사 사전 등록 | 다음 워커 기동부터 해당 접두사는 묻지 않음 |
| 워커에게 조사 코드를 `python3 -c` 인라인 대신 파일로 써서 고정 접두사로 실행하도록 지시 | 접두사가 하나로 수렴해 승인이 1회로 끝남 |

사전 등록은 **이미 떠 있는 워커에는 적용되지 않습니다.** 기동 전에 해 두십시오.

---

## 5. 감시는 터미널 폴링이 아닙니다

기본 수단은 `python3 scripts/orca_worker_watch.py` 입니다. `orca terminal read`
는 도달 확인, 차단 해제, 정체 판정 세 경우에만 씁니다. 터미널 출력은 정보량
대비 비용이 가장 높으므로 상태 확인 목적으로 반복해 읽지 않습니다.
