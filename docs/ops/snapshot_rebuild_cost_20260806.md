# 상위 N 스냅샷 재집계 비용 측정

> **작성일**: 2026-08-06
> **버전**: v1.0.0
> **상태**: 측정 완료. 개선안 2건 기각, 주간 재집계 적용 완료(6절)
> **대상**: `src/app/services/ranking_snapshots.py`

---

## 1. 배경

챗봇의 콜드 첫 질의가 약 2초입니다(`docs/design/sse_first_token_20260805.md` 4.2절). 원인은 `_snapshot_scope` 가 **날짜 필터가 붙는 순간 사전 집계 스냅샷을 포기**하고 실시간 집계로 넘어가는 데 있습니다.

"2026년", "최근" 같은 흔한 표현이 곧 날짜 필터이므로, 날짜 축을 가진 스냅샷을 미리 만들어 두면 콜드 경로가 사라집니다. 그 타당성을 재기 위해 현재 재집계 비용을 측정했습니다.

## 3. 기각 1: 날짜 축 확장

플래너가 만드는 날짜 창은 대체로 유한한 정형 집합입니다(오늘 / 어제 / 이번 주 / 지난달 / 최근 N일 / 연·월 창). 명시 날짜 쌍만 임의입니다. 따라서 정형 창 7개 정도를 축으로 두는 설계가 가능해 보였습니다.

**비용이 허용하지 않습니다.** 7개 창을 더하면 조합이 15에서 105로 늘고, 현재 조합당 33.7초 기준 재집계가 **약 59분**이 됩니다. 매일 02:00 에 한 시간을 쓰는 것은 받아들일 수 없습니다.

조합당 비용을 먼저 크게 낮추지 않는 한 이 방향은 성립하지 않습니다.

---

## 4. 기각 2: SQL 손상값 필터 제거

`exclude_corrupted` 는 `NOT LIKE '%<U+FFFD>%'` 를 GROUP BY 전에 전 행에 겁니다. 선행 와일드카드라 인덱스를 쓰지 못합니다. 게다가 파이썬 쪽 `is_corrupted_display_text` 가 어차피 다시 걸러내므로 중복으로 보였습니다.

**첫 측정은 3.6배 개선으로 나왔으나 오측이었습니다.** LIKE 질의를 먼저 돌려 버퍼 풀이 데워진 뒤 비교 대상을 잰 탓입니다. 순서를 뒤집고 각 2회 실행 후 2회차를 채택해 다시 쟀습니다.

| 차원 | LIKE 제거 | 현재(LIKE) | 차이 |
| --- | ---: | ---: | ---: |
| `bidwinnr_nm` | 771ms | 806ms | 4% |
| `dminstt_nm` | 1,361ms | 1,740ms | 22% |
| `bid_ntce_nm` | 163,369ms | 166,954ms | 2% |

이 정도 이득으로는 폴백 분기를 추가할 근거가 되지 않아 구현을 되돌렸습니다.

> **교훈**: 같은 테이블을 훑는 두 질의를 연달아 비교하면 앞선 질의가 버퍼 풀을 데워 뒤 질의가 유리해집니다. 순서를 뒤집어 재확인해야 합니다.

| 방안 | 기대 효과 | 비용·위험 |

| `bid_ntce_nm` 차원 폐기 | 비용 완전 제거 | 공고명 상위 N 답변 기능 상실 |
| 증분 집계 | 근본 해결 | 설계·구현 규모가 큼 |

### 6.1 적용: `bid_ntce_nm` 주간 재집계 (2026-08-06)

공고명 상위 N 은 전 기간 누적 순위라 하루 만에 뒤집히지 않습니다. 위험이 가장 낮은 방안이라 이것을 적용했습니다.

**요일로 판정하지 않습니다.** 크론이 도는 시각의 시간대에 따라 건너뛰거나 두 번 도는 날이 생깁니다. 대신 **해당 차원 스냅샷의 나이**를 보고 `WEEKLY_REBUILD_INTERVAL_DAYS`(7일)를 넘었을 때만 다시 집계합니다. 시간대와 무관하게 자기교정되고, 호출부(야간 스케줄)를 손댈 필요도 없습니다.

건너뛴 차원의 기존 스냅샷은 지우지 않습니다. 지우면 조회가 실시간 경로로 떨어져 오히려 느려집니다. 한 번도 집계된 적이 없으면 주기와 무관하게 만듭니다.

| 지표 | 이전 | 이후 |
| --- | ---: | ---: |
| 야간 재집계 | 506.2초 | **135.8초** |
| 감소폭 | | **73%** |

예상(3분의 1)보다 큰 폭입니다. `bid_ntce_nm` 전체 조합이 167초였고 카테고리 4개까지 더하면 370초여서, 이 차원 하나가 야간 비용의 대부분을 쓰고 있었습니다.

대가는 공고명 순위가 최대 7일 낡을 수 있다는 것입니다. 누적 순위의 성격상 답변이 달라지지 않습니다.

인덱스 추가는 되돌리기 어려운 변경이며 저장 공간에 영향을 주므로, 위 방안으로 부족할 때 검토합니다. 남은 비용의 대부분은 카테고리별 그룹핑(19~47초)이며 `(category, 이름컬럼)` 복합 인덱스가 그 지렛대입니다.

## 7. 참고

콜드 첫 질의 2초는 **사용자 지표 기준으로는 이미 목표 안**입니다. SSE 첫 토큰 P95 는 2.66초로 목표 3초를 충족합니다. 이 문서의 개선은 여유를 넓히는 작업이지 미달을 메우는 작업이 아닙니다.
