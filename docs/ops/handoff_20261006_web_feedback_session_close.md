## 1. 다음 과제 상세

### 9. 로그인 회원 화면 실사용 확인

- 상세 화면(`src/app/templates/bids/detail.html`)은 진입 시 `POST /api/v1/evaluations/recommend` 를 자동 호출해 최저가·AI 예측가·최상가와 근거 문장을 보여 준다(`9a48ba39`).
- 운영 DB 에 시험 계정을 만들지 않기로 했으므로(설계 5.2) 코디네이터는 비로그인 경로(401, 회원정보 안내)만 확인했다. 사용자가 실제 계정으로 로그인해 가입 정량 원자료 자동 기입, 신인도 평점 선택, 세 금액, 하한율 미제공 안내를 확인해야 한다.
- 시연 환경에는 `scripts/seed_demo_member.py`(ALLOW_DEMO_SEED=1 필요) 로 원자료가 채워진 시험 회원을 만들 수 있다.

### 10. 사정률 실측 분포 주입

- 추천 API 는 지금 이론 범위(기초금액 ±2%/±3%) 로 최저가·최상가를 계산하고 `rate_source='theoretical'` 를 낸다(`src/app/services/evaluation_recommendation.py` 의 `compute_price_bounds`, 사정률 범위를 인자로 받는 순수 함수).
- 8번으로 `bid_prearng_prices` 와 `institution_sajeong_rate_stats` 가 채워졌다(3장). `src/app/services/sajeong_rate_stats.py` 의 `lookup_sajeong_rate_range(수요기관명, category)` 결과(min_rate/max_rate, 사용 scope, 표본 수)를 `compute_price_bounds` 에 넘기고 `rate_source='measured'` 와 근거 문장(발주처/시·도/업종 대체 여부, 표본 수)을 내도록 연결한다. 표본이 없으면 지금처럼 이론 범위로 둔다.
- 설계 5.3 의 정의(최저가 = 사정률 최저 예정가격 × 통과 구간 하한, 최상가 = 사정률 최고 예정가격 × 통과 구간 상한)를 지킨다.

### 11. 예비가격 발주처 연결과 매칭률

- 예비가격 API 응답에는 수요기관명이 없다. `bid_prearng_prices.dminstt_nm` 을 `bid_announcements` 의 (공고번호, 차수, category) 로 채우는 연결과, 그 매칭률 측정이 필요하다. 이것이 없으면 10번의 발주처 단위 분포가 비고 시·도·업종 대체로만 동작한다.
- 근거: [prearng_price_collection_feasibility_20261006.md](../analysis/prearng_price_collection_feasibility_20261006.md) 7.1, 12장.

## 4. 운영 주의

- app 컨테이너는 `--reload` 없이 `src/` 를 바인드 마운트한다. Python 변경을 병합하면 `docker compose restart app` 후 실행 중 서비스에 HTTP 로 확인한다. 템플릿만 즉시 바뀌어 라우트와 어긋날 수 있다(이 세션에서 실제로 발생).
- 호스트에서 수집 스크립트를 돌릴 때는 `uv run --env-file .env` 로 실행한다. 그렇지 않으면 서비스 키가 빈 값이라 401 이 난다.
- 백업 `snapshot_20261006_124421` 에 원문 보관소(`qualification_sources.tar.gz`, 860건) 가 처음 포함됐다.
