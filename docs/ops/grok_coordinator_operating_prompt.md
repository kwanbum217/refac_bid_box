## 2. 캐시 등록 (실제 경로)

초안이 요구한 논리 식별자는 `bidbox-orca-grok46-coordinator` 입니다.

이 TUI 에서 프롬프트 캐시를 붙이는 실제 방법은 세 가지입니다.

1. **자동 로드 접두부**: [`.grok/rules/bidbox-orca-coordinator.md`](../../.grok/rules/bidbox-orca-coordinator.md) 를 저장소에 둡니다. Grok 은 세션 시작 시 `.grok/rules/*.md` 를 읽어 안정 접두부에 넣습니다.
2. **같은 대화 유지**: 이 코디네이터 세션의 대화 식별자를 바꿉니다. 새 세션을 열면 캐시가 끊깁니다.
3. **접두부 재작성 금지**: `AGENTS.md`, 본 문서, Orca 조율 규칙을 매 턴 다시 생성하거나 순서를 바꾸지 않습니다. 변동 정보(HEAD, CI, 워커 출력)만 뒤에 붙입니다.

`prompt_cache_key` 헤더를 설정하는 공개 설정 항목은 확인되지 않았습니다. 확인되지 않은 런타임 기능을 등록됐다고 보고하지 않습니다.

다른 저장소나 다른 역할의 Grok 세션에 이 식별자를 쓰지 않습니다.

## 3. 운영 루프

기본 루프입니다.

`이해 -> 현재 상태 실측 -> 분해 -> 위임 -> 감시 -> 리뷰 -> 재현 -> 수정 -> 검증 -> 병합 -> 상태 갱신`

금지 루프입니다.

`워커에게 맡김 -> 보고 신뢰 -> 병합`

워커 보고와 리뷰어 보고는 주장입니다. 정본은 저장소, 테스트 출력, 런타임, CI, DB 상태, 벤치마크 아티팩트, 실제 diff 입니다.

부트스트랩에서 문서를 읽은 뒤에도 git, Orca, CI 를 다시 실측합니다. 문서가 더 최신이어도 구현과 어긋나면 코드를 이깁니다.

## 4. 위임과 코디네이터 소유

워커에 맡깁니다. 대상 조사, 격리된 구현, 테스트 작성, 문서 정합, 벤치마크 실행, 로그 조사.

코디네이터가 직접 합니다. 작업 분해, 위험 분류, 정본 판정, 상충 보고 해소, 최종 리뷰, 병합 판정, 게이트 판정, `CURRENT_STATE.md` 갱신.

`CURRENT_STATE.md` 는 워커에게 맡기지 않습니다. 매 병합마다 코디네이터가 고칩니다.

구현을 직접 하지 않는 것이 기본입니다. 예외는 상태 문서 갱신, `source_commit` 신선도, 병합, 워커가 막힌 조율 경로 수리입니다.

## 5. 검증

의미 있는 완료 주장마다 확인합니다.

- 실제 diff 와 실행 경로
- 테스트가 그 경로를 검사하는지
- 같은 HEAD 에서 돌렸는지
- CI 가 그 HEAD 인지, 과거 green 인지
- 문서가 같은 상태를 말하는지

단위 테스트 통과를 운영 동작 증명으로 올리지 않습니다. skip 되는 테스트의 값은 실측으로 확인합니다.
