## 4. CI 복구 — 세 번의 왕복

### 4.1 빨간 CI 위에 병합이 쌓여 있었습니다

세션 초입에 CI 가 **3회 연속 실패** 중이었고 그 사실을 모른 채 병합·푸시를
계속했습니다. 로컬 전량 테스트(SQLite, macOS)만 보고 판단했기 때문입니다.
**Windows 러너와 Tailwind 재현성은 로컬에서 재현되지 않습니다.**

### 4.2 실패하면서 내용을 숨기는 검사가 추적을 막았습니다

`validate_doc_links.py --quiet` 가 **건수만 출력**해 어느 링크가 깨졌는지 알 수
없었습니다. 그동안 코디네이터의 추정 세 가지(금지 문자, 경로 길이, 대소문자
충돌)가 전부 빗나갔습니다.

**관측 가능성을 먼저 고친 것이 전환점이었습니다.** 실패 상세를 항상 출력하도록
바꾸자 다음 CI 실행이 `해석 경로: D:\tests\...` 를 스스로 지목했습니다.

### 4.3 원인 두 가지

| 실패 | 원인 |
| --- | --- |
| 경로 구분자 4건 | 테스트가 OS 구분자를 그대로 단정. 운영 코드의 POSIX 정규화가 옳아 **테스트**를 `as_posix()` 로 고침 |
| Tailwind 재현성 | 템플릿 변경(`hover:bg-slate-50/50`)이 CSS 산출물에 미반영된 드리프트 |
| 루트 기준 절대 링크 | **`PureWindowsPath("/scripts/x.py").is_absolute()` 가 드라이브가 없어 False.** 절대 경로 분기를 못 타고 드라이브 루트로 해석됨 |
| 비밀 파일 권한 | Windows 에 POSIX 권한 비트가 없어 `chmod(0o600)` 후에도 `0o666`. 단정을 POSIX 한정으로 |

## 7. R-15 해소 — `--setup skip` 이 더 이상 필요 없습니다

사용자가 Orca 앱에서 설정 스크립트를 `pnpm install` 에서 **`npm ci`** 로 바꾸고
실행 시기를 **기본 건너뛰기**로 지정했습니다.

```text
scripts.setup = npm ci
setupRunPolicy = skip-by-default
```

`--setup skip` 없이 워크트리를 만들어 금지 산출물 네 종이 모두 생기지 않고
`node_modules` 도 설치되지 않음을 실측했습니다. **게이트 9 는 방어선으로
그대로 둡니다** — 저장소 밖 로컬 설정이라 다른 기계에서는 다시 오염될 수
있습니다. `orca.yaml` 로 옮기면 버전 관리 대상이 됩니다(미착수).
