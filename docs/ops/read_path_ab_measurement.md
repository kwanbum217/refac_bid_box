## 1. 개요 및 목적

2026-09-18 회차에서 낙찰 목록 직렬화 시 공고 일괄 선채움(N+1 제거)을 적용(병합 `419274cd`)하여 동시성 c10 P95 레이턴시가 큰 폭으로 개선(219.69ms -> 79.16ms)되었습니다.
그러나 당시 측정은 병합 전(워커 3대 기동 중)과 병합 후(유휴 상태)의 측정 시점이 달라, 선채움과 무관한 대조군 경로(공고 목록, 비교 통계)도 함께 감소하여 순개선 크기를 명확히 확정하지 못했습니다.

본 가이드는 동일 머신, 동일 시각에 선채움을 켠 상태(A)와 끈 상태(B)를 교대로 반복(최소 3 왕복) 실측하여, 배경 부하 잡음을 제거하고 낙찰 목록 순개선 효과를 엄밀하게 확정하기 위한 표준 실행 절차를 규정합니다.

## 2. 측정 대상 경로 구성

측정 대상 경로는 총 8개이며, 정본 사양에 따라 대조군과 실험군으로 엄격히 분리하여 판정합니다.

| 구분 | 경로명 | 엔드포인트 URL | 설명 |
| --- | --- | --- | --- |
| **대조군** | 공고 목록 1쪽 | `GET /api/v1/bids?page=1` | 공고 목록 첫 페이지 (선채움 무관) |
| **대조군** | 공고 목록 50쪽 | `GET /api/v1/bids?page=50` | 깊은 페이지 오프셋 (선채움 무관) |
| **대조군** | 공고 목록 용역 필터 | `GET /api/v1/bids?cat=Servc&page=1` | 카테고리 필터링 (선채움 무관) |
| **대조군** | 대시보드 통계 | `GET /api/v1/bids/stats` | 비인증 기본 통계 (선채움 무관) |
| **대조군** | 공고 대비 낙찰 비교 통계 | `GET /api/v1/bids/compare-stats` | 공고-낙찰 비교 분석 (선채움 무관) |
| **실험군** | 낙찰 목록 1쪽 | `GET /api/v1/bids/results?page=1` | 낙찰 목록 첫 페이지 (선채움 직접 적용) |
| **실험군** | 낙찰 목록 50쪽 | `GET /api/v1/bids/results?page=50` | 낙찰 목록 깊은 페이지 (선채움 직접 적용) |
| **실험군** | 홈 컨텍스트 | `GET /api/v1/bids/home` | 최근 낙찰 목록 포함 (선채움 직접 적용) |

- **대조군 판정 기준**: 선채움 여부와 무관하므로 A와 B에서 레이턴시가 통계적으로 동일(오차범위 ±5% 또는 ±5ms 이내)해야 측정이 유효합니다.
- **실험군 판정 기준**: 선채움이 켜진 A 경로가 B 경로(단건 쿼리 폴백) 대비 유의미한 레이턴시 단축을 입증해야 합니다.

## 3. 선채움 토글 플래그 사양

운영 기본값은 항상 켜짐(`True`)이며, 실측 시 환경변수로 제어합니다.

- **설정 위치**: `src/app/core/config.py`의 `Settings` 클래스
- **환경변수명**: `READ_PATH_PRELOAD_ANNOUNCEMENTS`
- **기본값**: `True` (운영 동작 무변경 보장)
- **적용 지점**: `src/app/api/v1/bids.py`의 `_serialize_results` 함수
  - `True`: `preload_matching_announcements` 일괄 조회 수행 (쿼리 1회)
  - `False`: 선채움 생략 -> 행별 `matching_announcement` 단건 쿼리 폴백 (최대 2N회)

## 4. 실측 실행 절차 (코디네이터 전용)

실제 측정은 저장소가 조용한(quiet) 상태에서 코디네이터가 수행합니다.

### 4.1. 사전 점검 (Dry Run)

실제 서버에 부하를 주기 전, 드라이런으로 하니스의 대상 URL 및 실행 계획을 점검합니다.

```bash
uv run python scripts/benchmark_read_path_concurrency.py --dry-run
```

드라이런 출력에서 8개 대상 경로와 A/B 교대 3 왕복 순서, 컨테이너 재시작 명령이 정상 표시되는지 확인합니다.

### 4.2. 컨테이너 재시작 명령 규격

각 변체 전환 시 환경변수를 주입하여 앱 컨테이너를 재시작합니다.

- **A 변체 (선채움 활성화, 기본값)**:
  ```bash
  READ_PATH_PRELOAD_ANNOUNCEMENTS=true docker compose up -d --no-deps --force-recreate app
  ```
- **B 변체 (선채움 비활성화, 단건 폴백)**:
  ```bash
  READ_PATH_PRELOAD_ANNOUNCEMENTS=false docker compose up -d --no-deps --force-recreate app
  ```

컨테이너 재시작 후 `http://127.0.0.1:8000/docs` 응답을 확인하여 헬스 상태를 확인합니다.

`docker compose up` 에는 `-e` 옵션이 없습니다. 값은 셸 환경변수로 주입하며, `docker-compose.yml` 의 `app` 서비스가 `READ_PATH_PRELOAD_ANNOUNCEMENTS=${READ_PATH_PRELOAD_ANNOUNCEMENTS:-true}` 로 컨테이너에 전달합니다. 변수를 지정하지 않으면 운영 기본값인 `true` 입니다. `--force-recreate` 가 없으면 환경변수만 바뀐 경우 compose 가 컨테이너를 그대로 두어 변체 전환이 적용되지 않습니다.

### 4.2.1. 준비 대기 규격

변체 전환 후에는 고정 시간을 기다리지 않고 `GET /api/v1/health/ready` 가 200 을 돌려줄 때까지 폴링합니다(상한 180초). 2026-09-19 첫 회차에서 5초 고정 대기 때문에 B 변체 전량(경로 8종 각 100회)이 연결 실패로 버려졌습니다. 컨테이너 재생성은 30초 안팎이 걸립니다.

표본이 0건인 경로가 하나라도 있으면 하니스는 그 회차를 요약하지 않고 즉시 실패합니다. 빈 값을 `-` 로 표시한 채 진행하면 측정 실패가 결과표에 조용히 섞입니다.

### 4.3. 워밍업 규격

각 변체 전환 직후에는 DB 커넥션 풀 연결 수립 및 앱 메모리 워밍업을 위해 대상 경로마다 **3회의 단일 요청 워밍업**을 선행합니다. 워밍업 단계에서 발생하는 지연시간은 본 측정 표본에 포함하지 않습니다.

### 4.4. A/B 교대 반복 실행 (최소 3 왕복)

시간대별 시스템 부하 잡음을 배제하기 위해 A와 B를 교대로 측정합니다.

- **실행 순서**:
  1. `[왕복 1]` A (선채움 ON) 재시작 -> 워밍업 3회 -> c10 100회 측정
  2. `[왕복 1]` B (선채움 OFF) 재시작 -> 워밍업 3회 -> c10 100회 측정
  3. `[왕복 2]` A (선채움 ON) 재시작 -> 워밍업 3회 -> c10 100회 측정
  4. `[왕복 2]` B (선채움 OFF) 재시작 -> 워밍업 3회 -> c10 100회 측정
  5. `[왕복 3]` A (선채움 ON) 재시작 -> 워밍업 3회 -> c10 100회 측정
  6. `[왕복 3]` B (선채움 OFF) 재시작 -> 워밍업 3회 -> c10 100회 측정

- **자동 실행 명령**:
  ```bash
  uv run python scripts/benchmark_read_path_concurrency.py \
      --mode ab \
      --rounds 3 \
      --concurrency 10 \
      --auto-restart \
      --json artifacts/read_path_ab_result_$(date +%Y%m%d).json
  ```

## 5. 결과 판정 기준

### 5.1. 대조군 유효성 판정

- **검증 항목**: 공고 목록(1쪽, 50쪽, 용역 필터), 대시보드 통계, 비교 통계
- **합격 조건**: 모든 대조군 경로에서 A와 B의 P95 차이가 ±5% 이내 또는 ±5ms 이내여야 합니다.
- **불합격 시 조치**: 대조군 경로의 지연시간이 5% 이상 크게 요동치는 경우 외부 호스트 부하나 디스크 I/O 잡음이 개입한 것이므로 해당 회차 측정을 무효화하고 저장소가 조용한 시간대에 재측정합니다.

### 5.2. 실험군 순개선 확정

- **검증 항목**: 낙찰 목록 1쪽, 낙찰 목록 50쪽, 홈 컨텍스트
- **계산식**:
  $$\text{순개선(ms)} = \text{P95}_{A,\text{median}} - \text{P95}_{B,\text{median}}$$
  $$\text{개선율(\%)} = \frac{\text{P95}_{A,\text{median}} - \text{P95}_{B,\text{median}}}{\text{P95}_{B,\text{median}}} \times 100$$
- **기대 수준**: 낙찰 목록 1쪽 기준 단건 폴백(B)의 P95(약 200ms 이상) 대비 일괄 선채움(A)이 P95 80ms 안팎으로 50% 이상의 개선율을 안정적으로 유지해야 합니다.
