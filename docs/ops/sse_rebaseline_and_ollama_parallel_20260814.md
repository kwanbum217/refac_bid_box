> **환경**: macOS arm64 (14 코어), Docker Compose 전체 스택 (FastAPI app, MySQL 8, Redis 7, Meilisearch, ChromaDB), 호스트 Ollama (gemma:2b), 계측 비활성, 주변 부하 실측 기록

## 1. 측정 개요 및 목적

본 문서는 [`latency_gate_protocol.md`](latency_gate_protocol.md)에 의거하여, 이전 직전 측정(표본 30건)의 규약 미달 한계를 극복하고 **정본 SSE 엔드포인트(`POST /api/v1/chatbot/chat/stream`)의 c1 기준선(회차당 60표본, 3회차)** 을 재수립한 실측 보고서입니다.

또한 호스트 Ollama의 직렬화 병목을 분석하기 위한 `OLLAMA_NUM_PARALLEL` 효과 측정(작업 2)의 진행 현황과 중단 사유를 함께 기록합니다.

## 4. 작업 2: OLLAMA_NUM_PARALLEL 효과 측정 및 중단 기록

### 4.1 작업 2 진행 현황 및 중단 사유

- **진행 내역**: 병렬도 1(현재 배포 상태)에서 SSE c4 벤치마크를 수행하였으며, r1 완료 및 r2 완료, r3 진행 중 사용자의 즉시 중단 및 커밋 지시를 수신했습니다.
- **중단 사유**: 사용자의 명시적 중단 명령(`작업을 중단하고 지금까지의 산출물을 즉시 커밋하십시오. 진행 중인 벤치마크는 중단해도 됩니다.`)에 따라 진행 중인 태스크를 즉시 종료하고 산출물을 커밋합니다.
- **병렬도 4(par4) 측정 미수행**: 사용자의 중단 지시에 따라 호스트 Ollama 재시작 및 par4 벤치마크는 수행하지 않았습니다.

## 코디네이터 검증

> **검증일**: 2026-08-14
> **검증자**: 코디네이터 (Claude Opus 5)
> **결론**: SSE c1 n=60 기준선은 **독립 재계산으로 확인, 통과**. 작업 2(Ollama 병렬도)는 **미완료**

### V.1 SSE c1 기준선 — 재계산 일치

원시 JSON 의 `records[].first_token_ms` 와 `final_ms` 로 직접 재계산했습니다.

| 회차 | n | 첫토큰 P95 | 전체 P95 | 전체 Max | 오류 |
| --- | ---: | ---: | ---: | ---: | ---: |
| r1 | 60 | 1434.26 | 5904.10 | 7375.93 | 0 |
| r2 | 60 | 1464.79 | 6429.37 | 7714.82 | 0 |
| r3 | 60 | 1522.41 | 8049.61 | 9498.71 | 0 |

| 지표 | 대표값(최악) | 목표 | 판정 |
| --- | ---: | ---: | --- |
| 첫토큰 P95 | **1522.41ms** | 3,000ms | **통과** (마진 49.3%) |
| 전체 P95 | **8049.61ms** | 20,000ms | **통과** (마진 59.8%) |

주변 부하는 코어당 중앙 **13.8%**, 최대 **27.8%** 로 규약 5.3 임계(30/50)
이하입니다. **규약 조건 6개를 전부 만족하는 첫 SSE 측정이며 이것이 정본
기준선입니다.**

회귀 판정선은 +10% 로 첫토큰 1674.65ms, 전체 8854.57ms 입니다.

### V.2 재계산 시 필드 주의

`records` 원소에는 `first_stage_ms`(첫 SSE 프레임, 5~8ms)와
`first_token_ms`(첫 토큰, 800~1500ms)가 함께 있습니다. **`first` 로 매칭하면
`first_stage_ms` 가 먼저 잡혀 첫토큰 P95 가 13.79ms 로 나옵니다.** 코디네이터가
이 실수를 했습니다. 반드시 `first_token_ms` 를 명시하십시오.
