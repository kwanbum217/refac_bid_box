## 2. 문제 진단

### 2.1 학습 특징 10개 중 4개가 상수

용역 20,000행 표본 실측입니다.

| 특징 | 고유값 | 표준편차 | 판정 |
| --- | ---: | ---: | --- |
| `log_price` | 18,367 | 1.6720 | 정상 |
| `month_sin` / `month_cos` | 11 | 0.68 / 0.71 | 정상 |
| `weekday_sin` / `weekday_cos` | 6 | 0.52 / 0.77 | 정상 |
| `notice_duration` | 1 | 0.0000 | **상수** (공고 미조인 시) |
| `inst_hist_rate` | 1 | 0.0000 | **상수** |
| `inst_rate_mean_30d` | 1 | 0.0000 | **상수** (위 값 복사) |
| `inst_rate_std_90d` | 1 | 0.0000 | **상수** |
| `price_ratio` | 1 | 0.0000 | **상수** |

목표와의 상관은 최댓값이 0.138 이었습니다. 모델 문제가 아니라 특징에 신호가 없었습니다.

### 2.2 `price_ratio` 가 상수인 원인

`features.py` 는 `base_price` 키를 찾는데 `dataset.py` 는 `base_amount` 로 내보냅니다. 별칭이 없어 `base_price` 가 항상 `price` 로 폴백했고 `price_ratio = price / price = 1.0` 이 됐습니다.

별칭을 추가해 고쳤으나, **이 특징은 학습에서 제외했습니다.** 기초금액은 제도상 예정가격의 1.1 배로 고정되어 표준편차 0.0165, 목표 상관 0.053 에 그칩니다. 독립 정보가 없습니다.

### 2.3 금액 계열 전반에 신호 없음

용역 41,199 건 실측입니다.

| 항목 | 값 |
| --- | ---: |
| `base_amount / presmpt_prce` 중앙값 | 1.100 |
| 같은 값 표준편차 | 0.0165 |
| `winning_rate` 와의 상관 | 0.053 |
| `winning_rate == sucsf/base*100` 일치율 | 4.8% |

낙찰률의 분모를 조인된 공고에서 복원할 수 없습니다. 금액 컬럼으로는 낙찰률을 설명하지 못합니다.

## 3. 해결: 기관 이력 연결

### 3.1 단독 예측력 (누수 없음)

용역 773,045 건, 기관 20,811 개, 2012-12-18 ~ 2025-03-19 구간입니다. 각 행에 대해 **자기 자신과 미래를 제외한** 같은 기관의 과거 평균만 사용했습니다.

| 최소 이력 | 적용 행 | 목표 상관 |
| ---: | ---: | ---: |
| 1건 | 752,234 (97.3%) | 0.5477 |
| 5건 | 694,420 (89.8%) | 0.5749 |
| 20건 | 596,469 (77.2%) | 0.5983 |

이 값 하나만으로 R2 **0.3296** 입니다. 전체 평균으로 예측하면 -0.0005 입니다.

최소 이력은 **5건**을 채택했습니다. 20건은 상관이 0.02 높아지는 대신 적용 범위가 12.6%p 줄어듭니다.

### 3.2 성능 제약 해소

행당 COUNT + AVG 쿼리는 149.9ms 로, 773,045 행이면 32시간입니다. 이 때문에 이전 검토에서 연결을 보류했습니다.

pandas `shift(1).expanding().mean()` 으로 바꾸니 **3.2초**입니다. 제약은 방식의 문제였습니다.

### 3.3 train/serve 정의 단일화

AGENTS.md 6항에 따라 양쪽이 같은 정의를 써야 합니다.

| 경로 | 구현 | 소요 |
| --- | --- | ---: |
| 학습 | `attach_institution_history` — 프레임 전체 배치 | 3.2초 / 773,045행 |
| 추론 | `institution_win_rate_stats` 표 조회 | 0.19 ms / 건 |

두 경로 모두 정의는 "해당 기관의 기준 시점 이전 낙찰률 평균"입니다. 추론용 표는 그 정의의 현재 시점 값이며 야간 스케줄에서 갱신합니다(35,408개 기관, 21초).

## 4. 결과

### 4.1 카테고리별 최종 지표

전체 데이터, 개찰일 기준 최신 20% 홀드아웃입니다.

| 카테고리 | 표본 | 선택 모델 | RMSE | MAPE | R2 |
| --- | ---: | --- | ---: | ---: | ---: |
| 용역 | 773,045 | LightGBM | 3.7082 | 2.448 | **0.3764** |
| 물품 | 784,266 | LightGBM | 4.8040 | 3.953 | **0.3480** |

### 4.2 후보 모델 비교

선택은 학습 구간 내부 K-Fold 로만 하고, 홀드아웃은 보고용으로만 씁니다. 홀드아웃으로 고르면 그 점수가 선택 편향으로 부풀려집니다.

| 카테고리 | 모델 | CV avg_r2 | 홀드아웃 r2 |
| --- | --- | ---: | ---: |
| 용역 | Ridge | 0.2863 | 0.3374 |
| 용역 | **LightGBM** | **0.3559** | **0.3764** |
| 용역 | CatBoost | 0.3532 | 0.3743 |
| 물품 | Ridge | 0.1547 | 0.2131 |
| 물품 | **LightGBM** | **0.2800** | **0.3480** |
| 물품 | CatBoost | 0.2772 | 0.3382 |

CV 순위와 홀드아웃 순위가 일치합니다. 선택 절차가 정상 동작합니다.

### 4.3 확정한 설계 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 특징 | 8개 (상수 3개 제외) | 위 2.1, 2.3 실측 |
| 모델 | LightGBM (CatBoost, Ridge 후보 유지) | 위 4.2 |
| 선택 기준 | 학습 구간 내부 K-Fold `avg_r2` | 선택 편향 제거 |
| 분할 | 개찰일 기준 최신 20% | 시계열 데이터 |
| 이력 최소 표본 | 5건 | 위 3.1 |
| 승격 임계값 | R2 +0.005 이상 **그리고** RMSE 또는 MAPE 개선 | AGENTS.md "압도할 때만" |

## 5. 승인 대기: 서빙 모델 교체

**추론 API 가 아직 레거시 모델을 씁니다.** 같은 용역 홀드아웃 3,000건 공정 비교입니다.

| 모델 | RMSE | MAPE | R2 |
| --- | ---: | ---: | ---: |
| 레거시 `ssh_hist_premium` (현재 서빙) | 6.2481 | 6.4055 | **-0.8234** |
| 재학습 LightGBM | 3.7082 | 2.4480 | **+0.3764** |

R2 가 음수라는 것은 **전체 평균을 답하는 것보다 나쁘다**는 뜻입니다.

원인은 레거시 모델이 `inst_hist_rate` 에 전혀 반응하지 않기 때문입니다. 값을 0.85 부터 0.95 까지 바꿔도 출력이 `0.9352071071666782` 로 동일합니다.

교체하면 서비스가 내놓는 예측값이 전부 달라집니다. 되돌리기 어려운 사용자 노출 변경이라 승인을 받고 진행합니다.
