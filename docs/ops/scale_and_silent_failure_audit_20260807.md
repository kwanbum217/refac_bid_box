## 1. 감사 이유

2026-08-07 하루에 나온 세 건은 모두 **"동작은 하는데 규모나 실패 상황에서
무너지는"** 유형이었고, 발견 경로가 전부 우연이었습니다.

| 결함 | 성격 | 발견 경로 |
| --- | --- | --- |
| `_diff_index` 이차 복잡도 | 소규모에서만 통과 | 색인이 30분간 멈춰 스택을 떠 봄 |
| `DEFAULT_MAX_DOCUMENTS = 10` | 이식값이 운영 규모와 4자릿수 차이 | 야간 태스크 호출부를 우연히 확인 |
| ChromaDB 검색 실패를 빈 리스트로 삼킴 | 실패가 성공처럼 보임 | 코드 주석에 기록된 8/5 사고. 닷새간 방치 |

같은 패턴이 더 있는지 훑었습니다. 대상은 원본에서 이식된 하드코딩 상수,
`except` 가 빈 값을 반환하는 지점, `limit` 이 붙은 조회입니다.

## 2. 발견

### 2.1 LLM 계획 수립 실패가 로그 없이 폴백 (수정 완료)

`src/app/services/planner.py:447` 이 Gemini 호출 실패를 그대로 삼키고 `None` 을
반환했습니다. 규칙 기반 폴백은 정상 설계이지만, 키 만료나 할당량 소진이 조용히
지나가면 **계획 품질이 내려간 것을 아무도 모릅니다.** 8/5 ChromaDB 사고와 같은
계열입니다.

`logger.exception` 을 넣었습니다.

### 2.2 증분 색인의 전량 폴백 비용 (해결, 2026-08-11)

`src/app/services/kb_builder.py:117`은 기존에 색인 조회가 실패하면
전량 재구축으로 떨어졌습니다. 안전한 선택처럼 보이지만 **KB가 50만 건이 된
지금은 비용이 다릅니다.**

| 상황 | 결과 |
| --- | --- |
| 이전 (500건) | 폴백해도 수십 초 |
| 현재 (499,195건) | 폴백하면 **약 2.7시간 재임베딩** |

`collection.get()` 의 일시적 실패 한 번이 야간 배치를 3시간짜리로 바꿉니다. 또한
폴백 경로는 `incremental=False` 라 이번에 넣은 삭제 상한 가드를 우회합니다.

`collection.count()`와 페이지별 `collection.get()`을 최대 2회 시도하고, 계속
실패하거나 빈 페이지·ID/메타데이터 불일치가 나오면 기존 컬렉션을 보존한 채
중단하도록 수정했습니다. 조회 실패는 데이터가 바뀐 것이 아니므로 전량 재구축의
근거로 사용하지 않습니다.

빈 컬렉션이나 해시·포맷 메타데이터가 없는 구형 컬렉션은 운영 장애가 아니라 비교
기준 자체가 없는 상태이므로 기존 전량 동기화 동작을 유지합니다. 컬렉션을 먼저
삭제하는 재구축은 명시적 `full=True`에서만 수행합니다.

### 2.3 `top_k` 기본값이 흩어져 있음 (해결, 2026-08-11)

| 위치 | 값 |
| --- | ---: |
| `src/rag/schemas.py` | `DEFAULT_VECTOR_TOP_K = 5` |
| `src/rag/vector_store.py` | 공용 상수 사용 |
| `src/rag/engine.py` | 공용 상수 사용 |
| `src/app/services/tools/semantic_search_tool.py` | 공용 상수 사용 |

운영 색인 499,005건에서 시드 42의 정답 질의 100건을 `top_k=10`으로 한 번
검색해 같은 결과 순위로 컷오프를 비교했습니다.

| 컷오프 | 적중률 | `top_k=5` 대비 |
| ---: | ---: | ---: |
| 3 | 95.0% | -2.0%p |
| **5** | **97.0%** | 기준 |
| 10 | 98.0% | +1.0%p |

별도 50건 동일 표본 지연 확인에서 P95는 `top_k=3` 194.0ms, `top_k=5`
202.0ms, `top_k=10` 190.7ms로 단조 증가하지 않았습니다. 이 정도 차이는 실행
잡음 범위이고, 5에서 10으로 늘릴 때 적중은 1건만 추가되지만 LLM에 전달할 최대
문서 수는 두 배가 됩니다. 따라서 운영값 5를 유지하고 스키마·계획·비동기 래퍼·
도구의 기본값을 `DEFAULT_VECTOR_TOP_K` 하나로 모았습니다.

측정 스크립트는 한 실행에서 top-1/3/5/k 적중률과 평균·P50·P95를 함께 출력해
후속 색인 규모 변경에서도 같은 기준으로 재검증할 수 있게 했습니다.

### 2.4 `DEFAULT_INST_RATE` 등 하드코딩 상수 잔존 (미결, 타 세션 영역)

`src/ml/features.py:23` 의 `DEFAULT_INST_RATE = 0.925` 를 비롯한 상수들이

지목합니다.

다만 현재는 `features.py` 단일 함수 안에 있어 train/serve skew 는 없습니다.
**더 중요한 문제는 값 자체입니다.** 0.925 는 2026-05-26 낙찰하한율 레짐 전환
이전 기준이고, 학습 데이터도 전부 구 제도 기준입니다.

용역 모델은 다른 세션 영역이라 손대지 않았습니다. 해당 세션에서 판단하십시오.
