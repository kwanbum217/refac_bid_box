### 2.4 B·k·T 를 사용자 입력으로 받는 이유

**규칙 레지스트리에 넣지 않았습니다.** 실측으로 확정할 수 있었던 것은 별표 식별
문자열과 낙찰하한율 둘뿐입니다. 가격배점 B 와 계수 k 와 통과점수 T 는 별표마다
다른데 공고 데이터에 들어 있지 않고, 참고 자료의 배점표로는 실측 하한율이
재현되지 않습니다. 추측한 값을 박으면 전 별표에 틀린 점수가 나갑니다.

따라서 공고문 배점표를 사용자가 입력하며, 셋 중 하나라도 없으면
`MISSING_SCORE_TABLE` 로 점수만 차단하고 하한율 기반 최저 투찰금액과 예정가격
시나리오는 계속 제공합니다.

회귀 테스트 3건으로 고정했습니다.

### 4.2 인증이 필요합니다

`/bids/{id}` 와 `/api/v1/evaluations/analyze` 둘 다 로그인을 요구합니다. 소유권
격리 때문이며 설계대로입니다. 브라우저 확인 시 로그인이 선행돼야 합니다.

- **Codex 워커는 명령마다 승인 대화창을 띄우고 거기서 멈춥니다.** `orca_worker_watch.py` 와 하트비트로는 잡히지 않아 `[진행]` 으로 보입니다. 터미널 끝을 직접 읽어야 하며 `p` 키로 반복 승인을 엽니다. 이번 세션에서 luna 가 5분 56초 멈춘 것을 사용자가 먼저 발견했습니다

- 워커가 `worker_done` 전송에 실패하거나(Orca 연결) 작업 도중 종료되는 경우가 잦았습니다. 산출물이 완성돼 있으면 코디네이터가 게이트로 검증하고 Task 를 마감하되 그 경위를 커밋과 결과에 남깁니다
- 캡슐의 `allowed_write_files` 누락으로 워커가 세 번 막혔습니다(마이그레이션, 라우터 등록, 되돌리기). **되돌리는 것도 쓰기**라는 점을 잊지 마십시오
