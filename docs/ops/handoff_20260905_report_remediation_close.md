## 6. 이 세션이 확인한 것

### 6.1 기계 게이트만으로는 부족합니다

**독립 리뷰가 게이트를 전부 통과한 산출물에서 결함 네 건을 잡았습니다.**

| 대상 | 리뷰가 찾은 것 |
| --- | --- |
| C-01 | `ci_windows` 를 워크플로 정의만 근거로 closed 선언 |
| O-05 | 템플릿이 정본에서 파생되지 않고 드리프트 테스트가 자기 비교 |
| X5 1차 | 파일별 `os.replace` 는 세트 원자성이 없음 |
| X5 2차 | 같은 버전 재승격에서 `rmtree` 가 공개 세대를 제자리 삭제 |

마지막 둘은 같은 Task 에서 연속으로 나왔습니다. 첫 리뷰가 없었다면 부재 구간만
닫고 세트 원자성은 열린 채로 병합됐을 것입니다.

### 6.2 `worker_done` 계약이 다섯 번 깨졌습니다

| 워커 | 빠뜨린 것 |
| --- | --- |
| V1 (Gemini) | 수명주기 메시지 |
| X4 원 (grok) | 보고 파일 |
| X5 1차 (Gemini) | 커밋 SHA 를 지어냄 (앞 7자리만 일치) |
| Y1 (Gemini) | 보고 파일 |
| W2 (Gemini) | 낡은 수치와 마커 누락으로 `verdict=blocked` |

**CLI 종류와 무관합니다.** Capsule 고지문에 이미 적혀 있는데도 반복됐습니다.
후반 Task 부터 `ground_truth` 에 "파일 작성과 메시지 전송 둘 다", "commit 은
`git rev-parse HEAD` 출력 그대로" 를 못박자 Z1·Z2 는 한 번에 통과했습니다.
**문서 조항이 아니라 지시문에 박아야 지켜집니다.**

### 6.3 배경 실행은 워커를 정체시킵니다

Y1 이 `pytest` 와 `opencode run` 을 배경으로 띄우고 완료 알림을 기다리다
멈췄습니다. 그 알림은 오지 않습니다. 이후 Capsule 에 **배경 실행 금지** 를
넣었고 재발하지 않았습니다.

### 6.4 코디네이터 Capsule 결함이 게이트 실패로 세 번 돌아왔습니다

| 결함 | 결과 |
| --- | --- |
| `-m 'not data_assets'` 마커 누락 | W2 의 `verdict=blocked` |
| 존재하지 않는 `tests/test_arq_worker.py` 지정 | W2 가 실행하지 못함 |
| Z1 검증에 전량 테스트 미포함, 분할 상한 테스트가 범위 밖 | 병합 후 모듈 상한 초과 회귀 |

**검증 명령은 대상 테스트만 적지 말고 전량을 포함하십시오.** 파일을 늘리는
Task 라면 분할 상한 테스트가 쓰기 범위에 있어야 합니다.

### 6.5 한 브랜치에 여러 Task 를 쌓지 마십시오

X4 브랜치에 네 Task 의 커밋이 쌓여 게이트 2 와 6 이 구조적으로 실패했습니다.
게이트는 Capsule 하나와 보고들을 브랜치 전체 diff 와 대조합니다. 다중 보고
지원을 넣었어도 **보고마다 작성 시점이 달라 낡은 수치가 남는** 문제는 닫지
못했습니다. 재작업은 같은 브랜치에 쌓되, 성격이 다른 Task 는 브랜치를 나누는
편이 낫습니다.
