# LLM 협업 워크플로

> **작성일**: 2026-07-31
> **상태**: 설계

---

## 1. 목적

refac_bid_box는 최종 프로젝트로, 담당자의 발표와 학습이 중요합니다. LLM 에이전트가 모든 코드를 혼자 완성하지 않도록, **담당자가 직접 작성해야 하는 영역**과 **LLM이 보조하는 영역**을 명확히 분리합니다.

---

## 2. 역할 분담

| 구분 | 담당자 직접 작성 | LLM 보조 작성 |
| --- | --- | --- |
| **핵심 ML 로직** | 특징 엔지니어링(`inst_hist_rate`, 임베딩), 모델 학습/평가, 낙찰가 예측 규칙 | 타입 정리, 예외 처리, 기존 모듈 연결 |
| **데이터 파이프라인** | DB join 설계, 정제 기준, 데이터 품질 판단 | bulk insert, parquet I/O, 스크립트 자동화 |
| **RAG/챗봇** | 검색 전략, 프롬프트 설계, 의도 분류 규칙 | API 클라이언트, 캐싱, 비동기 래핑 |
| **실행/검증** | 마이그레이션 결과 해석, 모델 성능 평가 | 테스트 자동화, 실패 원인 분석, 보고서 정리 |

## 4. 작업 시작 절차

1. 작업 전 [`SKILLS.md`](../../SKILLS.md)의 MANDATORY STARTUP SEQUENCE 수행.
2. 해당 작업이 "담당자 직접 작성" 영역인지 확인.
3. 핵심 로직은 담당자에게 먼저 작성 기회 제공.
4. LLM은 연결·검증·테스트 보조.
5. 완료 후 [`changelogs/`](../changelogs/)에 이력 추가.
