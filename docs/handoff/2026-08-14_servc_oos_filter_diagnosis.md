## 2. 가장 강한 제약 조건 특정 및 원인 분석

### 2.1 단일 최대 탈락 조건: S3 -> S4 공고 조인 (106건 탈락)

전체 탈락 194건 중 **54.6%(106건)** 가 **공고 조인 단계(S4)** 에서 발생했습니다. 라벨 보유 유효 표본(1,303건) 기준 탈락률은 **8.14%** 입니다.

```sql
-- 조인 조건 (src/ml/dataset.py:187-191)
ON a.bid_ntce_no = r.bid_ntce_no
AND a.bid_ntce_ord = SUBSTR(CONCAT('000', r.bid_ntce_ord), -3, 3)
AND a.category = r.category
```

### 2.2 공고 조인 탈락 106건의 원인 분석

1. **차수 정규화 및 카테고리 불일치 여부 확인**:
   - 탈락 106건의 `bid_ntce_no` 로 `bid_announcements` 전수 조회를 수행한 결과, 공고번호 자체가 일치하는 행이 **0건**이었습니다.
   - 즉, 차수(`bid_ntce_ord`) 포맷 불일치나 카테고리(`category`) 오기 때문이 아니라, **공고 자체가 DB에 수집되지 않은 상태**입니다.

2. **일자별 편중 관측**:
   - 2026-08-07 개찰분에서 63건의 공고 미매칭(166건 중 63건 탈락, 잔존 103건)이 집중 발생했습니다.
   - 공고 수집기의 기본 수집 윈도우(`collector_service.py:77`)가 전일 하루 기준이라, 개찰일 이전에 공고된 건 중 백필 윈도우 밖의 공고가 일부 누락된 것으로 확인됩니다.

3. **조건의 필수성 검토**:
   - **이 조건은 OOS 검증에 반드시 필요합니다.** 서빙 모델(`servc_institution_v1`)은 공고의 기초금액, 계약방법, 제도 필드(`raw_data`) 등 34개 특징을 필수로 요구합니다. 공고가 없으면 모델 추론 입력 자체가 완성되지 않습니다 (`train/serve skew` 방지 원칙).
   - 따라서 이 필터를 임의로 완화(`require_announcement=False`)해서는 안 됩니다.

구간만 덮었으므로 그 직전 미완일이 남았고, 08-03 에 공고된 건이 08-07 에
개찰되면서 조인 실패 62건으로 집중됐습니다(4.1절 08-07 행의 유효율 61.45%).

따라서 조치는 필터 완화가 아니라 **공고 백필 1일**입니다.

```bash
.venv/bin/python scripts/backfill_from_g2b.py --start 20260803 --end 20260803
```

기대 효과는 조인 실패 106건 중 상당수 회수이며, 회수분은 즉시 유효 OOS 로
편입되어 게이트 도달 일수를 줄입니다. 실행 전 사용자 승인이 필요합니다
(외부 API 호출과 DB 쓰기).
