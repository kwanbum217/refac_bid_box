## 1. 이 세션이 남긴 가장 중요한 것

**규약이 없으면 성능 판정은 측정 조건 선택으로 결정됩니다.** 직전 세션이
"G3 판정이 표본 수에 따라 뒤집힌다" 를 미해결로 남겼고, 이 세션은 그 원인이
표본 수 자체가 아니라 **게이트 규약의 부재**임을 확인해 규약을 제정했습니다.

정본은 [`../ops/latency_gate_protocol.md`](../ops/latency_gate_protocol.md)
입니다. 앞으로 모든 레이턴시 측정은 이 문서를 따릅니다.

| 규정 | 값 | 근거 |
| --- | --- | --- |
| 표본 수 | `n >= 오염요청수 x 60` (예측 600, SSE 60) | 지연 이벤트 2회까지 P95 오염 없음 |
| warmup | 동시성 수만큼, 표본 제외 | 냉시동 배치가 표본에 들어감 |
| 반복·대표값 | 3회 이상, **최악값** | 중앙값은 3회 중 2회 통과로 통과가 됨 |
| c10 기준 | P95 100ms 이하 | G3 |
| 초과율 | 관측 0.5% 이하 **그리고** Wilson 상한 1.0% 이하 | 관측 0건일 때 Wilson 은 표본 수만의 함수 |
| 주변 부하 | 코어당 중앙 30% / 최대 50% 이하, **값을 기록** | 부재는 증명 불가, 부하는 측정 가능 |
| 소급 | **제정 이전 측정은 통과·미달 양방향 무효** | 한쪽만 무효면 유리한 쪽 고르기 |

## 2. 성능 결과

### 2.1 예측 API — 게이트 통과

`PREDICTION_GC_MODE=freeze` 를 기본값으로 채택했습니다.

| 지표 | 채택 전 | 채택 후 |
| --- | ---: | ---: |
| c10 최악 P99 | 108.55ms | **59.32ms** |
| 100ms 초과 (1,800 요청) | 21건 | **0건** |
| c10 P50 | 39.47ms | 38.96ms (대가 없음) |
| c1/c2/c4 최댓값 | 71~93ms | **21~43ms** |

원인은 generation-2 GC 였고 `gc.freeze()` 가 모델 가중치를 영구 세대로 옮겨
순회 대상에서 제외합니다. 회수 자체는 유지되므로 10분 지속 부하 RSS 가
평평합니다.

**정본 기준선**은 주변 부하를 기록한 재확인 측정값입니다.

| 동시성 | P50 | P95 | P99 | Max | 회귀 판정선 (P95 +10%) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| c1 | 12.37 | 15.47 | 17.56 | 20.85 | 17.02 |
| c2 | 17.17 | 19.79 | 25.32 | 30.39 | 21.77 |
| c4 | 28.29 | 33.46 | 39.45 | 42.76 | 36.81 |
| **c10** | **42.45** | **56.45** | **62.08** | **73.01** | **62.10** |

`batch-disable` 은 **기각**했습니다. 초과 30건으로 기본(21건)보다 나쁩니다.
코드는 남아 있으나 운영에 쓰지 마십시오. `threshold` 는 보류입니다.

### 3.2 워커 지시 도달을 확인하십시오

**`dispatch --inject` 는 Antigravity CLI 에서 재현적으로 실패합니다.** 이 세션에서
두 번 모두 `ok: true` 를 반환하고 Task 가 `dispatched` 로 바뀌었지만 프롬프트는

전달하는 것입니다. 절차는 플레이북 5.2 절에 있습니다.

않으므로 관측 수단이 `orca terminal read` 하나입니다. **`ps` 로 프로세스가 살아
있는 것은 진척의 근거가 아닙니다.**

워커 워크트리는 `orca worktree create` 로 만드십시오. `git worktree add` 로 만든
트리는 Orca 사이드바에 나타나지 않아 사용자가 워커 작업을 볼 수 없습니다.

### 9.4 워커 기동에서 확인된 사실

반영하지 못했으므로 다음 세션이 옮겨 적으십시오.

| 방식 | 결과 |
| --- | --- |
| `agy` + `dispatch --inject` | **실패 3/3.** `ok: true` 인데 프롬프트가 빔 |
| `agy` + `terminal send` | 성공하나 부팅 타이밍 의존. 1~2회 재전송 필요 |
| **`agy --model <id> -i "<프롬프트>"`** | **성공.** 프롬프트가 프로세스 인자라 유실 지점이 없습니다. **권장 경로** |
| `opencode` 대화형 + `--variant` | `--variant` 미지원. 도움말 출력 후 즉시 종료 |
| `opencode run --prompt "..."` | `--prompt` 미지원. 프롬프트는 위치 인자입니다 |
| `opencode run -m <id> "<프롬프트>"` | 단발 호출 성공. 에이전트 작업은 산출 없음 |
| `cerebras/gemma-4-31b` | **분당 토큰 한도 초과.** `opencode.json` 의 `instructions` 가 AGENTS.md+SKILLS.md(16.4KB)를 매 세션 자동 로드하는 것이 겹칩니다 |
| `opencode/deepseek-v4-flash-free` | 산출 없음 |

**무료 풀 두 곳이 원인은 달라도 결과가 같았습니다.** 플레이북 4.2 의 "무료 풀은
임계 경로 금지" 를 유지하십시오. 주력은 `gemini-3.7-flash-high` 입니다.

`consumer_fenced` 로 코디네이터가 Run 바인딩에서 분리될 수 있습니다. Task 생성이
갑자기 거부되면 `orca orchestration run-use --id <run_id>` 로 재바인딩하십시오
(`--run` 이 아니라 `--id` 입니다).

### 9.5 워커 검증 기록 갱신

**워커 6건 전부, 코디네이터 자신 7건에서 오류가 나왔습니다.**

4장 표에 다음을 추가합니다.

| 워커 | 잡은 것 |
| --- | --- |
| P10 Gemini | **요약 보고 2건의 판정이 서로 반대**(폐기 대 회수)였고 첨부 해시도 감사 대상 브랜치의 원본 커밋이었습니다. 문서 본문이 정본이며 폐기가 맞습니다 |

4.1 절에 다음을 추가합니다.

| 오류 | 내용 |
| --- | --- |
| 워커 해시 착각 | 보고된 `70bd666` 을 산출물로 보고 체리픽. 실제는 감사 대상 브랜치 커밋. 충돌을 보고 워커가 범위를 어겼다고 잘못 판단 |
| `first_stage_ms` 오선택 | 필드를 `first` 로 매칭해 첫 SSE 프레임(5~8ms)을 첫 토큰으로 계산. "13.79ms 는 불가능" 이라고 잘못 보고 |

**교훈 둘입니다.** 워커 보고의 해시는 `git -C <워크트리> log --oneline main..HEAD`
로 워크트리에서 직접 확인하십시오. 그리고 **요약 보고를 판정 근거로 쓰지 말고
근거가 붙은 산출물 문서를 읽으십시오.** 요약이 문서와 어긋나면 문서가 맞습니다.
