## 3. 미해결 — G3 판정이 흔들립니다

**이것이 다음 세션의 첫 질문입니다.**

| 표본 수 | c10 P95 | 판정 |
| ---: | ---: | --- |
| 100~120 | 중앙값 107.6ms | 미달 |
| 600 | 38~44ms | 통과 |

같은 코드가 표본 수에 따라 통과와 미달을 오갑니다. 드문 GC 이벤트가 작은
표본에서 P95 자리에 들어앉고 큰 표본에서 P99 로 밀려나기 때문으로 보이나
검증되지 않았습니다. **어느 쪽도 G3 통과 선언의 근거로 쓰지 마십시오.**

중단된 P1d Task (`task_a9d1d8e99437`) 가 이 질문을 다룹니다. 사양은 Orca 에
남아 있습니다. 요지는 셋입니다.

- n=100/300/600/1000 을 각 5회 이상 반복해 표본 수 효과를 분리
- P95 대신 **100ms 초과율**을 요청 단위로 산출 (표본 수에 흔들리지 않는 지표)
- Phase 7 게이트에 표본 수 규약이 문서화돼 있는지 확인. 없으면 그 자체가 구멍

### GC 튜닝 후보 (미조사)

`gc.disable()` 이 꼬리를 없앤다는 것은 확인됐습니다(P99 77.7 -> 41.0ms). 그러나
운영 채택 전 다음을 조사해야 합니다. 지연만 재고 채택하면 메모리 문제를
사게 됩니다.

| 후보 | 조사 항목 |
| --- | --- |
| 모델 로드 직후 `gc.freeze()` | c10 P95/P99, 10분 연속 부하 RSS 추이 |
| `gc.set_threshold` 조정 | 같음 |
| 배치 스레드 한정 `gc.disable` + 주기적 수동 collect | 같음 |
