## 3. 공고서참조의 실체

운영 DB `procurement.bid_announcements` 용역 공고 전량 집계입니다.

| 공고 연도 | 용역 공고 | 공고서참조 | 적격심사제 명시 |
| --- | ---: | ---: | ---: |
| 2015 ~ 2024 | 1,752,915 | 1,752,915 (100%) | 0 |
| 2025 | 211,708 | 146 | 37,205 |
| 2026 | 154,122 | 20 | 24,378 |

- 발주기관 기재 관행이 아니라 수집 출처 차이의 흔적입니다.
- `sucsfbidMthdCd` 는 전 기간에 있고, 2025년 이후 356,655건에서 **코드 하나가 계열 하나에만 대응**했습니다.
- 공고서가 꼭 필요한 것은 적격심사제 계열(`낙030001`) 227,606건(13%)뿐입니다.
- 첨부 공고서는 2015년 것도 내려받을 수 있습니다(HWP 5.x). 하지만 본문 기준이 개정 전 또는 타 기관 고시(예: 환경부 건설폐기물 평가기준)라
  현행 별표 14종에 바로 대응할 수 없습니다. 최근 공고서참조 표본 두 건은 다수공급자계약·카탈로그 공고였습니다.

설계안 전문(3단계, 결정 사항 4개)은 artifact 로 게시했습니다: `https://claude.ai/code/artifact/e401e985-665c-4235-829a-0c954ef83dee`

## 5. 업종제한사항과 면허제한정보 API

### 5.1 현재 DB

- 업종제한사항 전용 컬럼은 없습니다. `procurement` 스키마의 제한 관련 컬럼은 `servc_inst_verify.rgn_lmt_nm`(지역) 하나뿐입니다.
- `raw_data` 에는 `indstrytyLmtYn`(여부)만 있습니다. 최근 3만여 건에서 Y 는 공사 7,661/8,739, 용역 7,062/11,336, 물품·외자 0 입니다.
- 수집기(`src/app/services/api_collector.py:32`)는 목록 API 네 개만 호출하며, 목록 응답에는 제한 업종명이 없습니다.

### 5.2 면허제한정보 API 실측 (호출 11회)

별도 등록 API 가 아니라 기존 `BidPublicInfoService` 의 오퍼레이션이며, 기존 인증키로 정상 응답했습니다.

- 주소: `https://apis.data.go.kr/1230000/ad/BidPublicInfoService/getBidPblancListInfoLicenseLimit`
- 응답: `bidNtceNo`, `bidNtceOrd`, `lmtGrpNo`, `lmtSno`, `lcnsLmtNm`(예: `정보통신공사업/0036`), `permsnIndstrytyList`, `indstrytyMfrcFldList`, `rgstDt`, `bsnsDivNm`

| 조회 | 결과 |
| --- | --- |
| `inqryDiv=1` 2026-09-11 하루 | 정상, 1,549건 |
| `inqryDiv=1` 2026-09 한 달 | 정상, 14,667건 |
| `inqryDiv=1` 2015-06-01 하루 | 정상, 1,365건 |
| `inqryDiv=1` 2020-01-06 하루 | 정상, 1,855건 |
| `inqryDiv=2` 공고번호만 | 오류 `08 필수값 입력 에러` |
| `inqryDiv=2` 공고번호 + `bidNtceOrd` | 정상 |

같은 서비스의 `getBidPblancListInfoPrtcptPsblRgn`(참가가능지역, `prtcptPsblRgnNm`)도 같은 방식으로 동작했습니다.

**확인하지 못한 것:** 기간 조회 한 번의 최대 허용 기간, `lmtGrpNo` 그룹 간 의미(AND/OR), 전량 수집 시 호출 수와 일일 트래픽 한도.
과거 전량은 수백만 행으로 추정합니다.
