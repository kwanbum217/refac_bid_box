## 6. 완료 기준을 교체한 근거 (2026-08-14 코디네이터 실측)

1회차의 "개찰 최신 시각 미전진" 은 수집 결함이 아닙니다. **원래 기준이
수집 계약과 구조적으로 충돌합니다.**

### 6.1 창 결정 규칙상 전진이 불가능합니다

`src/app/services/collector_service.py:137` 이후 로직입니다.

```python
gap_start = latest + timedelta(days=1)
if gap_start > yesterday:
    return yesterday_str, yesterday_str, False
```

`latest` 가 어제(`20260813`)이면 `gap_start` 가 오늘이 되어 어제를 넘으므로 창이
`[어제, 어제]` 로 고정됩니다. 어제 개찰의 최대 시각은 이미 DB 에 있으므로 같은
창을 다시 수집해도 **최신 시각은 정의상 전진할 수 없습니다.** 당일(`20260814`)
개찰은 아직 공시되지 않아 0건입니다.

### 6.2 지연 공시분은 정상 회수됩니다

개찰일과 적재일(`collected_at`)을 교차한 실측입니다.

| 개찰일 | 08-13 적재 | 08-14 적재(1회차) |
| --- | ---: | ---: |
| 2026-08-10 | 404 | +1 |
| 2026-08-11 | 642 | +2 |
| 2026-08-12 | 409 | +2 |
| 2026-08-13 | 272 | +6 |

창이 `20260813~20260813` 이었는데도 개찰일 08-10~08-12 행이 새로 들어왔습니다.
즉 `api_collector.py:204` 의 `inqryDiv=1` 은 개찰일 기준이 아니라 공시·등록일
기준이며, **뒤늦게 공시된 과거 개찰 결과도 회수됩니다.** 영구 누락 가설은
기각합니다.

### 6.3 따라서 옳은 지표는 건수입니다

최신 시각은 창 결정 규칙에 종속돼 움직이지 않을 수 있지만, 건수는 실제로
회수된 양을 반영합니다. 1회차 결과 +17건은 수집이 동작했다는 증거입니다.
