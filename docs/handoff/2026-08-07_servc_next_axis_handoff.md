## 2. 1순위였던 축: quantile 아래 하이퍼파라미터 재탐색 (기각)

> **2026-08-07 종료.** 운영 쌍대 검정에서 기각했습니다. **재시도하지 마십시오.**
> 상세는 [`servc_hyperparam_quantile_20260807.md`](../design/servc_hyperparam_quantile_20260807.md).

| 단계 | 결과 |
| --- | --- |
| 좌표 하강 21회 | 완료 |
| 시드 재현성 검정 | 실체 있음 (시드 3개 -0.0035~-0.0038, 산포의 4.6배) |
| 재학습 `v_20260807_110637_435` | 완료. 레지스트리에만 등록 |
| 운영 쌍대 8,995건 | **기각.** MAE 1.4050 -> 1.4188, t=5.14 |
| 집단별 | 6개 집단 중 challenger 우세 **0개** |
| 되돌림 | `CATEGORY_HYPERPARAMS` 원복 완료 |

### 2.1 확정된 사실

**용량 최적점은 목적함수와 무관합니다.** 두 목적함수 모두 31 < 63 < 127 <
255 > 511 로 순서가 같고 255 에서 최소입니다. 목적함수를 바꿨다는 이유만으로
용량 축을 다시 훑지 마십시오.

### 2.2 왜 뒤집혔는가

`tune_servc_hyperparams.py` 는 조기 종료를 걸지 않고 `_train_lightgbm` 은
`early_stopping(10)` 을 겁니다. `learning_rate` 를 낮추면 더 많은 트리로
보상해야 하는데, 탐색에서는 `n_estimators=2000` 이 보상했고 운영에서는 조기
종료가 그 전에 잘랐습니다.

**원인은 제거했습니다.** `tune_servc_hyperparams.py` 의 `evaluate` 가 운영
3단계를 그대로 따릅니다. 학습 구간을 시간순 80/20 으로 가르고, 뒤 20%를
`eval_set` 으로 조기 종료해 트리 수를 정한 뒤, 그 트리 수로 학습 구간 전량을
재적합합니다. 검증 연도는 평가에만 씁니다.

**이 수정 이전 탐색 결과의 절대값은 새 경로와 비교할 수 없습니다.** 시행
시간은 학습이 2회로 늘어도 25% 증가에 그칩니다(실측 39.5초 -> 49.4초).

그래도 **이 축을 다시 여는 것은 권하지 않습니다.** 경로를 맞춘 것이지 여지가
있다는 증거가 생긴 것은 아닙니다. 교차 이력이 먼저입니다.

### 2.3 레지스트리 주의

`ml_registry/servc_institution_v1/v_20260807_110637_435` 를 재판단용으로
남겼습니다. **`promote_model.py status` 가 이 버전을 "승격 조건 통과" 로
표시하지만 학습기 지표만 본 판정입니다. 운영 쌍대에서 기각됐으므로 승격하지

## 3. LightGBM + CatBoost 앙상블 (2026-08-09 기각)

> **2026-08-07 측정.** 구현 전에 여지부터 쟀고 결과는 부정적입니다.
> 측정: [`scripts/eval_servc_ensemble_headroom.py`](../../scripts/eval_servc_ensemble_headroom.py)

2025년 96,141건, 2024년까지 학습, 운영 카테고리 설정 그대로입니다.

| 모델 | MAE | RMSE | R2 | 0.5%p 적중 | 학습 |
| --- | ---: | ---: | ---: | ---: | ---: |
| LightGBM | **1.3593** | 2.7777 | 0.6656 | **59.93%** | 25초 |
| CatBoost | 1.5835 | 2.7825 | 0.6644 | 44.34% | 15초 |
| 반반 평균 | 1.4404 | **2.7351** | **0.6757** | 54.50% | — |

잔차 상관은 **0.9389** 로 한계 0.95 아래입니다. 그런데도 **반반 평균이
LightGBM 보다 MAE 0.0811 나쁩니다.**

### 3.1 앙상블은 제곱오차에서만 이깁니다

RMSE 와 R2 에서는 반반 평균이 둘 다를 이기고, **운영 지표인 MAE 와 0.5%p
적중에서는 집니다.** 구조적인 이유가 있습니다.

| 모델 | 목적함수 | 겨냥 |
| --- | --- | --- |
| LightGBM | `quantile(0.5)` | 조건부 중앙값 |
| CatBoost | 기본 RMSE | 조건부 평균 |

둘을 평균하면 중앙값 겨냥이 희석됩니다. 용역 잔차는 0 에 몰린 비대칭 분포라
평균 쪽으로 밀리는 것이 곧 MAE 손해입니다.

**"CatBoost 가 R2 0.6994 로 이겼다" 는 과거 관찰은 R2 함정의 재현이었습니다.**
이 프로젝트에서 세 번째입니다. 잔차가 비대칭이면 중심을 위로 민 모델이 R2 에서
유리합니다.

### 3.2 CatBoost L1 목적함수 (2026-08-09 기각. 앙상블 축 종결)

미측정으로 남겼던 갈래를 쟀습니다. 근거 정본은
[`docs/design/servc_ensemble_catboost_l1_20260809.md`](../design/servc_ensemble_catboost_l1_20260809.md),
측정은 `eval_servc_ensemble_headroom.py --catboost-loss MAE` 입니다.

**목적함수 불일치라는 진단은 맞았습니다.** CatBoost 단독이 MAE 1.5835 ->
1.4809, 0.5%p 적중이 44.34% -> 59.73% 로 좋아져 LightGBM 적중률(59.93%)에
거의 닿았습니다. 반반 평균의 손해도 -0.0811 에서 -0.0397 로 절반이 됐습니다.

**그런데 여지는 여전히 없습니다.** 가중치를 0.00~1.00 까지 0.05 간격으로
훑자 MAE 가 단조 감소하고 최적이 LightGBM 100% 였습니다. 가중치를 검증
연도에서 고르는 오라클 상한조차 단일 최고 대비 **+0.0000** 입니다. CatBoost 를
어떤 비율로 섞어도 손해입니다.

상관 0.9322 에서 독립 오차 성분이 작은데 그 모델이 MAE 에서 0.12 열등합니다.
거의 같은 방향으로 틀리는 열등한 모델을 섞으면 열등함만 옮겨옵니다.

**예상이 하나 틀렸습니다.** 목적함수를 맞추면 두 모델이 닮아 상관이 오를
것으로 봤는데 0.9389 -> 0.9322 로 미세하게 내렸습니다.

**`train_and_register` 의 MAPE 단일 선택 구조는 손댈 필요가 없습니다.**

## 4. 기관 x 소분류 교차 이력 (2026-08-09 기각)

**잔차 사전 신호에서 닫혔습니다.** 특징을 만들지도, 재학습하지도 않았습니다.
근거 정본은 [`docs/design/servc_inst_clsfc_cross_20260809.md`](../design/servc_inst_clsfc_cross_20260809.md),
측정은 `scripts/eval_servc_inst_clsfc_cross.py` 입니다.

4.1 이 지시한 순서(오라클 -> 재현성 -> 실용)를 그대로 밟았고 **오라클은 처음
통과했습니다.** 하한율·낙찰방법·소분류 세 축은 오라클에서 이미 음수였는데,
교차는 네 해 모두 양수였습니다(+0.0247~+0.0384, 최소 표본 20 / 중앙값).

**그런데 실용 단계에서 12개 조합 전부 음수입니다.**

| 연도쌍 | 최소 10 | 최소 20 | 최소 50 | 최소 100 |
| --- | ---: | ---: | ---: | ---: |
| 2023 -> 2024 | -0.0129 | -0.0095 | -0.0087 | -0.0024 |
| 2024 -> 2025 | -0.0188 | -0.0132 | -0.0145 | -0.0068 |
| 2025 -> 2026 | -0.0046 | -0.0048 | -0.0045 | -0.0013 |

임계값을 올리면 손해가 줄지만 그것은 개선이 아니라 아무것도 하지 않는 쪽에
가까워지는 것입니다. 재현성은 연도쌍 0.62~0.65 로 안정적이되 기각된 소분류
단독(0.803)보다 낮습니다.

**교차가 기관 단독을 오라클에서조차 못 이겼습니다** (+0.0316 대 +0.0558).
셀을 잘게 쪼개면 임계값을 넘기는 행이 줄어 적용 범위가 좁아지고, 늘어난
해상도가 그 손실을 메우지 못합니다. 2026년 56,338행이 셀 23,761개로 나뉘고
20건 이상은 285개(행 비중 17.5%)뿐입니다.

**특징으로 넣는 형태도 같은 벽입니다.** `features.py` 가 만들 수 있는 교차
이력은 서빙 시점에 과거만 쓰므로 실용 단계와 같은 형태이고, 그 단계가 전부
음수입니다. `features.py` 는 손대지 않았습니다.

### 4.1 함께 얻은 것

**중앙값 오프셋이 평균보다 모든 조합에서 낫습니다.** 운영 지표가 MAE 이고
목적함수가 `quantile(0.5)` 이므로 당연한 결과인데, 앞선 기각들은 평균
오프셋으로 쟀습니다. 소분류 단독은 통계량을 바꾸자 오라클 부호가 -0.1525
에서 +0.0083 으로 뒤집혔습니다. **그런데도 실용 결론은 그대로였습니다**
(-0.0013). 통계량 선택이 문제가 아니었습니다.

**잔차 후처리 계열이 다섯 축에서 전부 닫혔습니다.** 하한율, 낙찰방법, 소분류,
기관, 기관 x 소분류입니다. 셀 오프셋은 그 해의 사정이지 구조가 아닙니다.
새 셀 정의를 하나 더 떠올렸다면 같은 이유로 닫힐 가능성이 높습니다.

### 4.2 남은 것

**미측정 축이 남아 있지 않습니다.** 마지막이던 CatBoost L1 목적함수도
2026-08-09 에 기각했습니다(3.2).

**남은 개선은 새로운 정보를 가져오는 쪽에서만 나옵니다.** 현재 특징 집합
안에서 짜낼 신호가 없다는 것은 `servc_general_service_signal_20260807.md`
(잔차 최대 상관 0.105)와 `servc_loss_function_20260807.md` 8.7(0.076)이
이미 각각 확인했고, 이번 측정이 셀 구조 쪽에서 같은 결론을 냈습니다.

새 정보를 붙이려면 G2B API 재수집 범위부터 정해야 하며, 이는 측정이 아니라
수집 설계 과업입니다. 착수 전 담당자와 범위를 합의하십시오.
