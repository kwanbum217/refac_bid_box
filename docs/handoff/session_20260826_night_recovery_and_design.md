### 4.3 pre-commit 이 워커 3대를 동시에 막았습니다

`CURRENT_STATE.md` 의 `source_commit` 이 HEAD 보다 5 커밋 넘게 뒤처지면 규칙 검증이
실패하고 pre-commit 이 **모든 커밋을 거부**합니다. 코디네이터가 세션 중 문서를
여러 번 병합하는 동안 이 조건이 성립해 워커들이 커밋하지 못했습니다.

워커 B 는 이를 정확히 진단하고 "본 태스크 범위 밖" 이라며 손대지 않았습니다.
**올바른 판단입니다.** 워커가 범위를 넘어 정본 문서를 고치는 쪽이 더 나쁩니다.

조치는 코디네이터가 `source_commit` 을 갱신해 `main` 에 병합한 뒤 **그 커밋을 각
워커 브랜치에 병합**하는 것입니다. 워커 워크트리는 자기 브랜치를 HEAD 로 보므로
main 갱신만으로는 풀리지 않습니다.

```bash
git -C <워크트리> merge main --no-edit
```

**문서를 여러 번 병합하는 세션에서는 워커를 띄우기 전에 `source_commit` 을 먼저
갱신하십시오.** 코디네이터가 "워커 작업이 끝난 뒤 한 번에 갱신하겠다" 고 판단한
것이 이 차단을 만들었습니다.
