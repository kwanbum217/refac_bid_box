# 입찰공고 백필 재개 안내

## 1. 배경

`bid_announcements` 가 건설·용역에서 10년치 대량 결손 상태였습니다. 낙찰정보(`bid_results`)는 온전합니다.

공고가 없으면 예정가격·기초금액을 학습 특징으로 쓸 수 없어, 용역 조인율이 5.2% 에 그쳤습니다.

원인은 마이그레이션 실패가 아닙니다. 원본 `bid_box` 도 같은 DB(`127.0.0.1:3307/procurement`)를 보며, 애초에 공고 수집이 완료된 적이 없습니다.

## 3. 재개 명령

덩어리 단위로 커밋되어 있고 유니크 제약(`bid_ntce_no + bid_ntce_ord + category`)이 중복을 막으므로, **아래를 그대로 다시 실행해도 안전**합니다. 이미 받은 구간은 적재 단계에서 걸러집니다.

```bash
cd /Users/kwanbum/Documents/korea_IT/lanhchain_ai_vision/refac_bid_box

# 1) 건설 공고 (2021-08-18 부터 이어서)
.venv/bin/python scripts/backfill_from_g2b.py \
    --category Cnstwk --fetch-type announce --since 20210818

# 2) 용역 공고 (전 구간 미착수)
.venv/bin/python scripts/backfill_from_g2b.py \
    --category Servc --fetch-type announce --since 20150101

# 3) 건설 낙찰 2025~
.venv/bin/python scripts/backfill_from_g2b.py \
    --category Cnstwk --fetch-type result --since 20250101

# 4) 용역 낙찰 2025~
.venv/bin/python scripts/backfill_from_g2b.py \
    --category Servc --fetch-type result --since 20250101
```

**예상 소요: 약 1시간 10분** (덩어리당 약 3분, 잔여 약 23덩어리)

## 6. 함께 발견한 미해결 항목

### 6.1 수집기 필드명 오류

`api_collector.py` 가 계약체결방법을 `cntrctMthdNm` 으로 읽는데, G2B 실제 필드명은 `cntrctCnclsMthdNm` 입니다. 이 때문에 `cntrct_mthd_nm` 컬럼이 0% 입니다.

**다만 고쳐도 예측은 나아지지 않습니다.** 아래 6.2 참조.

### 6.2 기존 모델 3종의 라벨과 학습 이력 불일치

| 모델 | 라벨상 담당 | 실제 학습 데이터 | 검증 |

`ssh_hist_premium` 은 폴드 5개 중 3개가 R2 0.9999999999999998 입니다. 특징 `lower_rate` 가 결과에서 파생된 값으로 보이며, 저장된 하한율 표 8,199개 값 중 62.2% 가 하한율로 불가능한 범위(0.5 미만 또는 1.0 초과)이고 최댓값이 2억 1,500만입니다.
