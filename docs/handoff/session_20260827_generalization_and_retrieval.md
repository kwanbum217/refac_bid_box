## 3. 이 세션이 발견한 운영 결함

2026-08-27 백필 뒤 이를 빠뜨려 낙찰 결과 9,798건이 DB 에만 있고 KB 에 없는
상태가 됐고, 그 상태로 측정해 72회차를 무효로 만들었습니다.

| 후속 갱신 | 이 세션 처리 |

| `institution_stats`, `ranking_snapshots` | **수행 완료** |
| ChromaDB KB 색인 | **수행 완료** (21,065건) |
| **Meilisearch 검색 색인** | **미수행. 4.1절 참조** |

백필 스크립트에는 색인 누락 경고를 출력하도록 넣었습니다(`3237666`).

### 3.2 개체 질의의 암묵적 연월이 기간 필터로 승격 (수정 완료)

공고명의 사업연도·대상월이 게시 기간 hard filter 로 승격되어 정답을
배제했습니다. `2026년 9월분 학교급식물품` 의 9월은 급식 대상 월인데
`date_from=2026-09-01` 이 붙어 검색 결과가 0건이 됐습니다.

개체 지정 질의에서는 **명시적 기간 한정 표현일 때만** 필터로 쓰도록 고쳤습니다.
회귀 테스트 3건을 추가했고 통계 질의·명시적 기간·상대 기간은 전부 보존됩니다.

### 3.3 근사 중복 제목에서 지역명 변별 실패 (미해소)

`2026년 조림지 풀베기사업 2차(동부지구)` 질의에서 지역명만 다른 근사 중복

`collected_since` 창을 쓰면 됩니다.

### 4.3 3순위 — 재측정

**1·2 를 끝낸 뒤에 하십시오.** 검색 경로가 안정된 상태에서 판정해야 재측정을
반복하지 않습니다.

원인 A 수정만으로도 기대되는 변화입니다.

| 지표 | 현재 판정 | 원인 A 수정 반영 시 | 원인 B 까지 해소 시 |
| --- | ---: | ---: | ---: |
| 문항 통과 | 21/24 | 23/24 | 24/24 |

| 과잉거절 | 12.5% (미달) | 4.2% (기준선) | 0% (충족) |

**과잉거절은 판정에서 유일하게 미달인 필수 기준이며, 이 두 결함으로 전부
설명됩니다.** 판정 기준(설계서 5장)은 바꾸지 마십시오.

측정 절차는 이 세션에서 검증된 순서를 그대로 쓰면 됩니다.

1. 저장소 clean 확인, 동결 SHA 기록
2. fixture 근거 유효성 확인 (`has_result=True` 이고 본문에 낙찰금액 포함)
3. 호스트 부하 코어당 중앙 30% 이하 확인
4. e2b 3회 -> `OLLAMA_MODEL` 교체 및 **컨테이너 실측 확인** -> 30초 대기 -> e4b 3회
5. 종료 후 `.env` 를 `gemma4:e2b` 로 복원

각 모델 10분 내외입니다. 설계서의 45분 예상보다 훨씬 빠릅니다.

### 4.4 4순위 — P50 기준 재정의

`scripts/orca_auto_approve.py` 입니다. 안전 명령 접두사만 자동 승인하고 위험
패턴은 보류해 코디네이터 판단으로 넘깁니다. 사용법과 예방책은
[`orca_worker_supervision_spec.md`](../ops/orca_worker_supervision_spec.md)
4.1절입니다.

**이 세션의 실패에서 나왔습니다.** 감시 도구가 차단을 매번 정확히 잡아냈는데도
해제가 코디네이터 수동 입력에 묶여 있어 워커가 5분 넘게 섰고, 사용자가 세 번
먼저 발견했습니다. 원인은 두 가지였습니다.

1. 탐지만 자동화하고 해제를 사람에게 남겼다
2. 코디네이터가 308초짜리 명령을 전경에서 돌려 응답하지 못했다

**1분 이상 걸릴 수 있는 명령은 배경으로 돌리고 전경은 감시 응답에 비워
두십시오.**

### 6.2 Antigravity 권한 사전 등록

`~/.gemini/antigravity-cli/settings.json` 의 `permissions.allow` 에 접두사 7개를
추가했습니다(`python3`, `python`, `uv run`, `git`, `rg`, `sed -n`, `npm`).
**이미 떠 있는 워커에는 적용되지 않으므로 기동 전에 해 두십시오.**

같은 파일의 기존 허용 목록에 **Slack 봇 토큰이 평문으로 든 명령이 한 줄**
