## 4. 운영 교훈

### 4.1 question 을 worker_done 으로 오인해 터미널을 닫았다

메시지 소진과 회수(`release-worker` + `terminal close`)를 한 명령에 묶어 실행했다. 소진된 메시지가 `question` 이었는데 회수가 이어서 실행됐다. `release-worker` 는 종료 코드 1로 거부했지만 `terminal close` 는 그대로 실행됐다. **소진 출력의 type 을 확인한 뒤 별도 호출로 회수할 것.** 회수 명령은 `release-worker` 성공(exit 0)일 때만 `terminal close` 를 잇도록 `&&` 로 연결할 것.

### 4.2 병합 결과 시험은 종료 코드로 커밋을 막아야 한다

`92c52812` 는 병합 결과 시험 1건 실패를 출력만 하고 커밋·푸시했다. 이후 병합 스크립트는 시험 실패 시 `merge --abort` 후 중단한다. 상세는 메모리 `merge-commit-must-gate-on-test-result`.

### 4.3 재작업이 길어지는 브랜치

마감일·금액·정렬은 리뷰 7회 중 6회 fail 했다. 매 회차 새 경계 사례(정렬 표현의 마감 창, 단위 없는 수, 낙찰 통계 금액 기준, 낙찰 결과 마감 창, 낙찰 결과 금액 정렬 축)가 나왔다. 모두 "낙찰 결과 테이블에는 마감일·추정가격 열이 없다"는 한 사실에서 파생됐다. 처음 Intent 에 테이블별 열 존재 표를 넣었으면 회차를 줄였을 것이다. 다음 조건 추가 과제부터 Intent 에 "조건 x 테이블 적용 가능 여부" 표를 넣을 것.

### 4.4 통합 브랜치 충돌 해소

묶음 병합은 통합 워크트리 `chat-bundle-N` 에서 코디네이터가 `--no-ff` 로 병합하고 충돌을 푼다. 워커는 정책상 git merge 가 막혀 있다. 커밋 전에 코디네이터 Capsule(`orca_taskctl.py coordinator-capsule`)을 만들고 `git config --worktree orca.capsule` 로 지정해야 scope guard 를 통과한다. 묶음 3 에서는 main 이 이미 지운 함수(`_strip_institution_scope`)를 브랜치 쪽이 수정해 충돌이 났고, 호출처가 없음을 확인한 뒤 브랜치 쪽 정의를 버렸다.
